# Gods response and punishment receipts

These private Event 012 receipts provide concrete `.604` and `.605` descriptions after the transaction fields have been cleaned up.
They do not expose the hidden relationship history or add category counters.
Strength and Wrath remain the two Gods values displayed by the decision categories.

`gods_of_africa_capture_response_report` runs in participant COUNTRY scope while its active contract still has a family.
Its caller sets temporary `gods_of_africa_report_kind`, `gods_of_africa_report_amount`, and `gods_of_africa_report_balance`, then invokes `gods_of_africa_capture_response_report = yes`.
These inputs contain the applicable history-kind constant, paid amount, and balance after the action.
All inputs are explicit and have no default.
It stores four required normal variables: `gods_of_africa_last_response_kind`, `gods_of_africa_last_response_family`, `gods_of_africa_last_response_amount`, and `gods_of_africa_last_response_balance`.
For a truck/artillery-family response it also snapshots the frozen `gods_of_africa_demand_mobile_type` into `gods_of_africa_last_response_mobile_type` before demand cleanup.
Each capture clears the previous optional subtype first, so a later non-mobile response cannot inherit it.
The concrete response-family resolver reads this receipt subtype only; absent or malformed subtype resolves as unknown rather than trucks.
It pays nothing, changes no contract, sets no timer, and increments no history counter.
If there is no active family to snapshot, it writes no receipt.
Ordinary demand cleanup preserves these fields so the triggered report can read them.

Example after a successful partial transaction and balance reduction:

```text
set_temp_variable = { gods_of_africa_report_kind = constant:gods_of_africa_history_kind.partial }
set_temp_variable = { gods_of_africa_report_amount = gods_of_africa_paid_amount }
set_temp_variable = { gods_of_africa_report_balance = gods_of_africa_demand_remaining }
gods_of_africa_capture_response_report = yes
```

Full compliance and accepted substitutes capture the family actually paid with a zero remaining balance.
Refusal and expiry capture a zero payment and the unpaid balance before clearing the contract.
The `.604` selector distinguishes all five cases and uses only these latest-response fields.
It does not substitute an entire private history ledger for one response.
No `.604` response event is generated by a negotiation extension or a permanent-defiance action in the existing dispatcher, so those actions are not falsely presented as one of these cases.

The punishment transaction records political power, stability, and `has_war_support` before its effects, then stores signed after-minus-before changes before queuing `.605`.
This includes defensive relief and native clamping, so a preparation that offsets a charge is reflected by the receipt instead of presenting a nominal unmitigated loss.
The existing frozen `gods_of_africa_last_punishment_tier` supplies the actual capability-limited outcome after any catastrophe downgrade.
Catastrophe wording also checks the current Event 013 gateway result.
`gods_of_africa_punishment_report_population_loss` starts at zero for each punishment and is assigned only from the exact population helper's existing receipt when that helper actually runs.
It cannot repeat the previous population-wave amount merely because the historical `gods_of_africa_last_population_wave` still exists.
The population-loss path captures its calling participant before selecting a state and uses that event target for both the shared helper's target-country input and the receipt/idempotence flag.
It does not use the outer event's ROOT, which can be the host during owner-driven expiry or defiance review.
The applied-loss and result temporary outputs are initialized by the caller before the shared helper, so the actual receipt survives its return and is available in the participant scope.
This corrects country attribution without adding a civilian debit, Deaths update, or disaster call.

Local-consequence fields store a measured resistance increase or the state where an infrastructure/factory sabotage effect was invoked.
Building text says the state was targeted, because selecting a state and invoking damage does not establish that a building existed and suffered a new measurable loss.
The transport exemption is copied before the existing preparation flag is cleared.
Missing state selections and zero resistance increases publish no corresponding local-consequence claim.
The affected state's ID is held by the participant and rendered through its variable namespace, following the existing Charter and Migration localisation patterns.
The report body requires all three native-stat delta fields before appending numeric results, so lifecycle reset does not revive an old tier with fabricated zero changes.

`gods_of_africa_clear_report_receipts = yes` clears the eleven private response/punishment fields and four local-consequence flags in COUNTRY scope.
It runs during enrollment reset, invalid-participant archival, and unifier-loss cancellation.
It has no input, output receipt, default, payment, or world iteration.
It does not clear pending flags or historical punishment-tier fields owned by the existing lifecycle helpers.
Equipment amount text uses whole counts, manpower names its native pool, fuel and political capital retain fractional precision, and state resource rights are described as a concession rather than invented fractional equipment units.

Set temporary `gods_of_africa_family_to_check` from the relevant family field, then invoke `gods_of_africa_family_is_equipment = yes`.
It classifies infantry, mobile/artillery, armour, aircraft, transport, and support equipment, with no default input.
The source uses it to normalize full and partial equipment quotes with the existing documented modulo helper.
Fuel, manpower, political capital, and resource rights are outside this classifier.
For example, a 55-aircraft contract has a 27-aircraft partial payment and an exact 28-aircraft residual, instead of a fractional aircraft payment.
This preserves the full contract price while making each physical shipment integral.
The existing infantry, support, aircraft-token, convoy, and train dispatcher branches use native `send_equipment`, with their prior affordability predicates, infantry ledger, and support consequence preserved.
The aircraft token's DLC/version-family coverage and the remaining mobile/artillery subtype are separate accepted-scope work, not established by receipt rendering.
