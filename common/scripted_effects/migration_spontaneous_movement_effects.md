# Spontaneous migration movement owner

This file is the authoritative owner for spontaneous civilian movement generated by sustained flight pressure. It is state-scoped and is reached only from the existing sparse `global.migration_active_displacement_states` registry job.

## Dynamic request contract

The owner measures current state population as `state_population_k * constant:chaos_meter_deaths.people_per_k`. It derives `protected_origin_floor = live_population * protected_origin_share`, `movable_population = max(live_population - protected_origin_floor, 0)`, and `requested = flight_pressure * request_pressure_share`. The request is rounded and clamped first to `maximum_request_people`, then to `effective_minimum` and `movable_population`. `effective_minimum` equals `minimum_request_people` unless the live movable pool is smaller, in which case it is lowered to the movable pool. No historical total or fixed per-state amount is used.

The state must have material flight pressure, a valid human owner and controller, at least the configured live population floor, and an expired or absent cooldown. `last_date` and `cooldown_until_date` are state variables, so a same-date retry or save/reload cannot replay the transaction.

## Exact movement sequence

1. Save the current state as `civilian_transfer_origin` and save its owner as `migration_spontaneous_origin_owner`.
2. Call `migration_destination_selection_preflight_closed_border_rejection`. It counts only directly adjacent foreign states that pass the normal safety, route, owner/controller, capacity, and war gates while a valid closed, violent, or forced-return reception policy is the sole blocker. It saves the destination and rejecting owner only when the count is exactly one.
3. Call the existing `migration_select_general_safe_evacuation_destination`. Its complete weighted selector evaluates the internal-safe pool first and executes the foreign-safe fallback only when the internal total is zero. It may bind only a directly adjacent destination with selector-owned route, safety, food, reception, and authoritative reception-policy proof.
4. On a bound destination, enter the saved `civilian_transfer_origin` state scope, set the exact request, protected origin floor, route proofs, and `civilian_transfer_route_deaths_requested = 0`, then call `civilian_transfer_execute_transaction` exactly once. The origin scope preserves the existing resolver's `PREV` adjacency proof contract.
5. The shared transfer measures the real origin debit, credits only route survivors, and validates `debit = route_deaths + survivor_credit`. Safe spontaneous movement requests zero route deaths, so the normal route has `debit = survivor_credit` and no Deaths entry.
6. Only after a valid positive survivor credit, call `migration_record_displaced_cohort` with that exact credit. Bind the actual destination state using `migration_bind_cohort_destination`, then apply that same credit once through `migration_apply_reception_delta` in the destination state. No requested amount is recorded as a cohort before the debit.
7. Compare destination `OWNER` with the saved origin owner. Equal owners use `constant:humanitarian_pressure_source.internal_displacement`; a foreign owner uses `constant:humanitarian_pressure_source.cross_border_flight`.
8. Subtract the measured exact origin debit from origin flight pressure and the parallel state flight ledger, clamp at zero, and reduce any trapped ledger only by the measured debit. If both ledgers are empty, the shared active-state registration can retire normally.

When the selector has a zero pool, including closed borders or zero-capacity routes, no transfer or cohort record occurs. The owner calls `migration_spontaneous_movement_trap_request`, which adds only `max(requested - existing_trapped_population, 0)`. It then calls `migration_spontaneous_movement_record_closed_border_rejection` only when the adjacent prepass found exactly one otherwise-valid foreign destination whose authoritative reception policy was the sole blocker. Multiple, zero, malformed, or independently unsafe candidates remain unattributed. Retry attempts therefore do not duplicate trapped population. The population authority is untouched and movement is never converted into death.

## Public wrapper migration

`migration_request_internal_displacement` and `migration_request_cross_border_flight` retain their public names and one-shot request variables. They now delegate to `migration_spontaneous_movement_submit_request`, which queues exact flight pressure and registers the sparse state but does not create a cohort. The registered-state owner is the only spontaneous exact-transfer path. Organized evacuation and deportation remain separate decision-owned contracts.

## Constants and tuning table

Constants live in `common/script_constants/migration_spontaneous_movement_constants.txt`.

| Constant | Purpose |
| --- | --- |
| `cooldown_days` | Minimum days between registry-owned attempts for one state |
| `minimum_flight_pressure` | Material-pressure gate for spontaneous movement |
| `request_pressure_share` | Fraction of current flight pressure moved per attempt |
| `minimum_request_people` | Normal lower bound for a cohort request |
| `maximum_request_people` | Normal upper bound for one cohort request |
| `protected_origin_share` | Live population share retained at the origin |
| `minimum_origin_population_k` | Minimum `state_population_k` required by the sparse owner |

The constants are campaign tuning values and do not encode historical casualty or migration totals.

## Event targets and cleanup

`civilian_transfer_origin`, `migration_spontaneous_origin_owner`, `migration_destination_selection_actor`, `migration_route_destination`, `civilian_transfer_route_destination`, `migration_spontaneous_closed_border_destination`, and `migration_spontaneous_closed_border_actor` are regular event targets used only for the current effect chain. After selection, the owner saves the selected state under the canonical transfer target before entering the physical origin. The owner sets `migration_destination_selection_actor` to the origin owner and raises the temporary `migration_destination_selection_actor_override_proven` guard while the prepass and selector run. The selector refreshes the actor from ROOT for ordinary callers and therefore cannot reuse a stale actor target. These are not global targets and require no global-target cleanup. The destination selector owns the route target and its normal state-local food and reception proofs; `migration_spontaneous_movement_cleanup_destination_proofs` clears both proofs through that target at every owner exit, including failed or trapped exits. The closed-border prepass targets are chain-local and are never persisted as scope pointers. The owner clears only its persisted cooldown variables when the state registration retires; the shared state cleanup remains responsible for removing flight/trapped state and registry membership.

The durable rejection receipt stores ids rather than scope pointers: `migration_spontaneous_rejection_origin_state_id`, `migration_spontaneous_rejection_destination_state_id`, `migration_spontaneous_rejection_actor_id`, `migration_spontaneous_rejection_origin_owner_id`, `migration_spontaneous_rejection_source`, `migration_spontaneous_rejection_blocker`, `migration_spontaneous_rejection_amount`, `migration_spontaneous_rejection_generation`, and `migration_spontaneous_rejection_transaction_id`. Its blocker is the destination owner's authoritative `migration_reception_policy`; selector hazards, route facts, and capacity remain owned by their existing predicates and are not reclassified as policy causes.

The normal proof variables do not carry a durable destination-state id, so an old save cannot be safely repaired by guessing or by scanning states. No extra migration hook is needed: the existing registered-state processor reaches the owner, every new selector binding overwrites the current destination proofs, and the terminal cleanup clears them before the chain ends. A whole-world cleanup pass is intentionally not added.
