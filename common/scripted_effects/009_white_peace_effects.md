# Event 009 White Peace Effect Call Contract

This event-owned contract records scope, persistent inputs, caller-owned temporary outputs, and lifecycle for `common/scripted_effects/009_white_peace_effects.txt`. Temporary variables first created in a returning scripted effect or trigger do not serve as a reliable return channel. Every direct caller below allocates the temporary slot before calling the helper, and the same output is preallocated again at each outer boundary that consumes it after return.

## Public entry points

`prepare_white_peace_runtime_context` runs in COUNTRY scope from the shared Settings precheck and from Event 009 entry `.1`. It reads the current war state and caller's Event Settings/tier state. On a valid selection, it writes persistent `global.white_peace_*` results and regular event targets for `white_peace_primary`, `white_peace_partner`, `white_peace_report_primary`, `white_peace_report_partner`, and `event_cluster_actor`. The caller must preserve the prepared event targets when reusing that context. Its temporary stage, branch, pair-cap, selected-pair, and score values are internal and are copied into persistent result variables before return.

`apply_white_peace_current_context` runs in COUNTRY scope after entry revalidation. Its inputs are `global.white_peace_selected_branch`, `global.white_peace_selected_stage`, `global.white_peace_selected_pair_cap`, and the selected event targets. Its durable outputs are the global settlement counts, actual-major result, capped Chaos delta, history/evolution changes, and the participant flags established by successful pair application. The pair-cap loop owns and resets its cursor and stop variables within the effect.

`fire_white_peace_report_event` consumes the actual settlement count and major-involvement globals after `apply_white_peace_current_context` returns. It sends the matching aggregate result to each country carrying `white_peace_human_report_pending`, or one observer news event if the current invocation had no human participant, then clears the queue and the invocation flag. The entry clears both before preparation. The invocation indicator is the COUNTRY boolean flag `white_peace_current_invocation_has_human`.

`white_peace_report_failed_manual_request` is the shared Settings precheck callback. Its caller supplies the current global `white_peace_skip_reason`, the manual-event trigger marker, the saved requester event target, and the existing requester flags. It copies the reason to the original human requester, sets the one-report receipt before `.6`, and records no settlement or success history.

These arrays are private to their respective selector bodies; they are not returned to the caller. Their nested `add_current_*_to_weighted_pool` helpers mutate the already allocated caller slots while filling them.

## Input preservation and lifecycle

`white_peace_stage` is an input to `select_white_peace_branch` and is not reset between stage calculation and branch selection. `white_peace_select_major_pair` is assigned immediately before each primary-selection helper reads it. The primary and partner arrays are explicitly cleared before each candidate collection. The per-country human report queue is cleared at `.1` entry and again after dispatch, so the flag cannot route a later all-AI chain to a prior participant.

## Bounded validation model

`docs/plans/009_white_peace_plans/source_models/009_white_peace_helper_output_lifetimes.py` executes the actual branch, stage, selector, and capped loop helper bodies with conservative helper-frame cleanup. Its tests cover base, Stage I single, Stage I multi, Stage II major, Stage III broad, pair/result attribution, multi-human report queues, mixed human/AI routing, and AI-only observer news. The model's native RNG stubs choose requested branches only when the current source weight is positive and pick the first source-built candidate scope. Its settlement stub only removes an isolated pair and updates counts. It does not emulate HOI4 scope/RNG/runtime or certify the timed-out probability comparison.
