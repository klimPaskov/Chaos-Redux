# Event 006 post-report host response orchestration

`independence_wave_host_response_complete_country_opening` counts one completed country opening for the active report plan. `independence_wave_host_response_skip_invalid_country_opening` finds the callback's selected Event 006 country row and consumes it once if its opening receipt has become invalid. When the opening counter reaches zero, `independence_wave_host_response_dispatch_after_openings` asks the host-response builder for one receipt per distinct state-losing Event 006 host, then schedules hidden router `.63` for every queued host. The router closes an invalid receipt or a deterministic AI action of `none` immediately.

The report's `independence_wave_country_opening_report_pending` flag remains raised through the country openings and host event options. `can_liberation_release_reset_plan` already checks this flag, so the committed shared state, owner, role, primary-host, and protected-host arrays stay available until all queued host responses finish. If the `.2` option has no valid opening cohort to queue, it starts host dispatch directly and keeps the report barrier until the host queue closes. A committed SCN-008 release prepares the same country-opening receipt before firing `.2`; the explicit Join conversion plan is rejected by the queue builder.

Each human tier event has a 13-day option timeout, so its first safe option eventually closes the receipt. Hidden `.63` checks the same receipt before it routes to the tier event, and closes an invalid host receipt immediately. AI hosts resolve through `.63` using deterministic tier and current-ledger logic; no country-scope period scan or weighted option pool is added.

`independence_wave_host_response_complete_current_host` consumes one matching host receipt and decrements the queue. An invalid `.41` opening option or host option calls the matching skip effect so a stale receipt cannot hold the barrier open. `independence_wave_host_response_finish_plan` runs after the final host or a fail-closed empty queue, removes only this plan's actor and host receipts, clears queue arrays, and releases the shared report/reset barrier. Persistent host crisis outcomes, bilateral ledgers, claims, and host response totals remain available for later Event 006 systems.

The report/reset barrier also prevents another shared plan from replacing the plan arrays while the opening and host callbacks are outstanding. This serial queue can delay a subsequent wave until the human report, opening, and host options resolve or time out. The event modding wiki documents the default and explicit `timeout_days` behavior; MCP event analysis is still partial under workspace-wide helper/lifecycle deferral, so delayed callback delivery and save/reload behavior remain unproved. The user owns live-game validation.
