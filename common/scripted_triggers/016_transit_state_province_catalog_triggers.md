# Transit state/province membership query

`brilliant_scientist_transit_load_state_province_catalog` is a pure STATE-scoped query for the complete province membership of its current state.
It uses numeric `[This.GetID]`; the opaque state dynamic variable `id` is not used as a map ID.
The boolean return is always true to allow temporary evaluation, while `transit_catalog_loaded` reports whether a matching catalogue leaf was loaded.
Do not use the boolean return alone as endpoint eligibility.

| Input/output | Contract |
| --- | --- |
| Input scope | Current valid STATE; no payer or implicit ROOT assumption. |
| `transit_catalog_state_id` | Temporary numeric state ID, reset then obtained through documented GetID/meta_trigger. |
| `transit_state_province_ids` | Temporary integer array, cleared then filled with sorted exact source membership. |
| `transit_catalog_loaded` | Temporary status zero/one, reset on every invocation; zero for unknown or unmatched IDs. |

The caller must create each consumed temporary output before this query.
This includes the array itself, which may otherwise be lost when a nested helper returns.
The generated balanced dispatcher visits one matching leaf, performs no global/state iteration and never pastes an undefined helper name for a missing ID.
IDs are immutable source geometry, not balance tuning.

```text
clear_temp_array = transit_state_province_ids
set_temp_variable = { transit_catalog_state_id = constant:transit_catalog.zero }
set_temp_variable = { transit_catalog_loaded = constant:transit_catalog.zero }
if = {
	limit = { brilliant_scientist_transit_load_state_province_catalog = yes }
	# Consume outputs here only after checking loaded equals one.
}
```

The query writes no regular variable, flag, history, inventory, building or payment.
It changes neither state/payer scope nor current ownership/control.
It stores no supply-node list, so current native node/control/health predicates must evaluate the returned candidates independently.
Destroyed or newly built nodes do not require geometry regeneration.
Geometry changes require regeneration from a new verified MCP map revision.

The source input is `docs/testing/event016_transit_catalog_20261008/state_membership.json`.
Run `python .tools/build_event016_transit_state_catalog.py --check` to verify exact generated bytes.
An explicit `--extract <artifact> --sha256 <returned-digest>` validates the full artifact's raw bytes and required map checks before capturing a membership input; an existing different input is not silently overwritten.
`--write` regenerates the three runtime files from the retained input.
The static data source is `016_transit_state_province_catalog_data.txt`; shared map-ID bounds are `common/script_constants/016_transit_catalog_constants.txt`.

The existing player-triggered CXT probe evaluates its current capital state's membership and records numeric ID, count and loaded status without granting content.
The full private commissioning remains accepted and queued with its separate node, route, payment and partial-construction requirements.
Current metadata/load behavior is source-model evidence; native GetID expansion, scope behavior and runtime building/network semantics require separate engine acceptance.
