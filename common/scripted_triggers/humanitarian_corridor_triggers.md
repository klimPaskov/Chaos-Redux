# Corridor predicate boundaries

The exact origin STATE owns the contract IDs, requester/counterpart, operation and generation.
Ordinary decisions bind ROOT as requester during preparation; sparse spontaneous callers supply the validated actual origin-owner target and explicit override.
Persisted requester identity, not ambient ROOT, governs later war/faction/owner/controller comparisons.

`humanitarian_corridor_front_is_preparable` proves current food, positive population, native infrastructure/rail/bombing facts and all supported hazards, including trapped population, persecution, camps, contamination, fallout, outbreak, zombie and disaster channels.
It does not prove paid services/capacity or authorize movement.
`humanitarian_corridor_origin_is_valid` and `humanitarian_corridor_front_is_preparable` evaluate their state-only checks only inside an `if` whose limit proves a populated, valid STATE (and, for the origin predicate, the saved requester event target).
A pointer that is unset or resolves to the caller's country scope therefore returns false without evaluating state-only triggers or the requester event target.
`humanitarian_corridor_front_destination_is_safe` adds a current valid receiver capacity revision and the existing optional-load spare check: load absent, or load strictly below capacity.
Relief at exactly full capacity is excluded; missing load retains the existing defined zero-load default.
Before evacuation, a positive whole amount satisfying `load + amount <= capacity` already implies this spare check.
Post-finalizer receipt recording does not retest this wrapper or consumed headroom, so a full positive exact-fit evacuation remains recordable after arrival.

`humanitarian_corridor_origin_cohort_is_current` requires the exact unique active origin-hosted cached row, full amount equality with the offer, current actor authority, flight reservations and protected live population.
`humanitarian_corridor_full_request_headroom_is_valid` adds receiver policy and full amount plus current load no greater than current capacity; exact fit passes.
Effects also resolve the real current row before acceptance and movement, so cached counters alone never authorize a transaction.

COUNTRY `humanitarian_corridor_offer_is_valid` is preparatory pending identity/deadline validity, including matching origin/front/requester/operation/cohort/generation.
COUNTRY `humanitarian_corridor_offer_can_be_accepted` adds operational whole-row/headroom proof for evacuation.
Relief retains its existing destination safety/capacity admission branch and does not acquire evacuation paid preparation or cohort requirements.
`humanitarian_corridor_operation_is_valid` describes an accepted live contract, not proof of population movement or achievement completion.
Post-finalizer recording uses measured conserved transaction/projection identity rather than the moved origin row or consumed headroom.

Country pulse, state-control, war/peace and terminal cleanup remain sparse and exact-ID driven.
`humanitarian_corridor_incoming_mirror_matches_live_contract` is a COUNTRY trigger proving the mirror's positive origin/generation, active origin contract and actual counterpart identity without requiring a still-open response deadline.
Expiry uses it before touching an origin; a stale generation can clear only its receiving-country mirror and cannot expire a newer origin contract.
Outgoing pulses likewise compare actual requester and generation before operating on the origin.
No trigger installs services, grants route proof, scans the world or changes the three canonical famine/migration visible values.
