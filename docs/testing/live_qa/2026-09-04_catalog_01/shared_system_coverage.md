# Shared-system live coverage

All cases below are pending the clean-startup gate.
The mechanics guide supplies the initial coverage requirements; owning system documentation and runtime registrations must be checked before each case.
Each accepted case needs a save identity, observed result, fresh-log result and suitable evidence reference.
Forced CXT setup proves the inspected feature behavior only; natural eligibility requires a separate case.

| --- | --- | --- |

| Chaos Meter | All five tabs; tier transition; history update; contamination state details; condemnation and death totals | Five-tab sequence and populated detail views |
| Event Log | All five tabs; filter, sort and toggle; actor identity; multiple details windows; evolution records; terminal-branch controls | Populated log and fitting detail windows |
| Clusters | Availability, member eligibility and skip reasons; one global pacing advance; member records; detail navigation; enable persistence | Cluster detail with actual member outcomes |
| Triggerable scenarios | Reconcile all registered scenarios; type and four intensity stops; launch gates; actual setup; repeat launch behavior; mutually exclusive outcomes in separate saves | Scenario control plus resulting mod feature |
| Famine and migration | State ledgers, stages, relief and reception decisions; map modes; population accounting across committed transfers | Ledger, state map and relevant decision tooltips |
