# Event 009 Accepted Decisions and Dispositions

This record separates the accepted design changes in the 2026-10-05 release audit from source evidence and validation limits.

## Accepted and Implemented

**Isolated one-on-one wars:** The parent accepted the isolated one-on-one safety boundary under the user's G6 design-authority instruction on 2026-10-05. The pair trigger now requires each selected country to have no active enemy besides its proposed partner. Stages I and III still settle several separate safe wars. The earlier multi-country, one-overcrowded-war route is removed because Event 009 cannot prove that the other war participants are safe under the target model. See `common/scripted_triggers/009_white_peace_triggers.txt` and the revised source spec.

**Immediate settlement and result delivery:** The parent accepted immediate settlement before player or observer notification to avoid stale global context, option-click races, and success history before an effect. `chaosx.nr9.1` now applies the selected safe war inside its immediate block. Each human-controlled participant receives one acknowledgement report after the effect, using the aggregate result variant for the chain. When every settled participant is AI, the chain sends one global news event after the effect. The report variant follows the number and type of settlements that actually succeeded.

**One report per affected human:** The parent accepted G2's per-player popup budget on 2026-10-06. The prior first-recipient target omitted other human belligerents in the same war or separate wars settled in one chain. Each applied pair now marks both human endpoints in a per-country pending-report queue. After the chain settles, one bounded country loop sends the same aggregate result to each marked human and clears the queue. `.1` clears stale pending flags at invocation start. All-AI chains still send exactly one observer-news event and no participant report.

**One report per affected human:** The parent accepted G2's per-player popup budget on 2026-10-06. The previous first-recipient target omitted other human belligerents in the same war or separate wars settled in one chain. The pair effect now sets one transient pending-report flag on each human endpoint and marks the current invocation as human-involved. After settlement, one bounded country loop sends the same aggregate result to each marked human, then clears the flags. `chaosx.nr9.1` also clears stale queue flags at invocation start. All-AI chains continue to send exactly one observer-news event and no participant report.

**Reuse the Settings-selected pair:** The parent source review found that unconditional preparation in `.1` could reroll the pair selected by the Settings precheck. That reroll could break `event_cluster_actor` attribution and make the visible report/news names refer to a different selection. `.1` now reuses a ready context with both selected country targets intact, and prepares only when the context is not ready or either target is missing. The existing transaction-time `can_pair_receive_white_peace` check still revalidates the selected partner immediately before settlement. A failed revalidation produces the existing no-safe-pair feedback without recording a settlement or success history. This preserves one weighted selection per valid manual entry and keeps the event-log actor, applied pair, and result names aligned.

**Forced invalid entry:** The user's G7 direction requires a forced invalid Event 009 entry to explain why it cannot proceed or find a valid candidate. The implementation preserves the safe major-stage restriction. A player-controlled root with no eligible candidate receives `chaosx.nr9.6`, which reports a plain reason and states that no peace was imposed. The 1936 USA case with Italy-Ethiopia as the only war remains `major_locked` until the Stage II evolution and existing war-pressure threshold permit a major settlement.

The direct `.1` root handles invalid entry. The Settings dispatcher now calls `white_peace_report_failed_manual_request` after the shared precheck blocks dispatch. The callback snapshots the current reason onto the original human requester, sets the existing one-report receipt, and sends `.6` without marking the event as dispatched or altering repeatable history.

**Continuous No Winner survival:** The parent directed an achievement fix rather than weakening the 180-day continuous-survival requirement. The delayed check now tests a carried partner event target and both countries' watch flags. Narrow event-driven callbacks clear the watch on capitulation, annexation, or subject-status transitions, so later liberation cannot restore eligibility. The hooks live in `common/on_actions/009_white_peace_on_actions.txt` and do not poll the world.

**Survival-watch re-arming boundary:** The parent required re-arming to remain impossible until the day-180 survival check is complete. The country cooldown is 181 days to outlast the delayed 180-day check by one day. This timing change keeps another settlement from restoring a cleared watch at the exact callback boundary and changes no Chaos amount or settlement strength.

**Circular achievement count:** The parent accepted retaining the three separate wars criterion and removing the redundant five-pair alternative. Under the isolated one-on-one rule, each successful pair settlement is one separate war, so the five-pair path could never unlock later than the three-war path. The owned achievement helper and tuning table now use only `broad_conflicts_required = 3`, and the parent updated the shared tooltip to match.

**Evolution settings:** The parent directed that actual branch behavior follow the shared Event Settings evolution contract. Each stage's existing war-pressure threshold remains required, and its matching `is_current_evolution_enabled` gate must also pass after the caller sets the event id, evolution type, stage, and tier in temporary caller storage. Disabled Stage I multi, Stage II major, and Stage III broad branches have zero weight and cannot be re-enabled by old global unlock flags. The base isolated minor settlement remains available when all three evolutions are disabled. No new tier or war-pressure threshold was introduced.

**Observer news image:** The parent accepted a global news event for successful AI-only settlement chains. A generated opaque monochrome 397x153 scene is available at `gfx/event_pictures/009_white_peace/news_event_009_white_peace.dds`, registered as `GFX_news_event_009_white_peace` in `interface/009_white_peace_event_images.gfx`. Its manifest and DDS round-trip evidence are in `docs/assets/009_white_peace/`.
