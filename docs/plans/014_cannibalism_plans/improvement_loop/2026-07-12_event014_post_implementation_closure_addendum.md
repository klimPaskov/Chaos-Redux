## Accepted-required item 1: constituent technology union

Working label, not final localisation: Constituent Technology Union

### Player-facing promise

When a warlord is actually absorbed, the surviving unified country keeps its current technology and gains every compatible technology researched by that constituent. Earlier absorptions must never be undone by a later donor. When mutually exclusive industry technologies conflict, the receiver keeps its established branch and gains every other compatible donor technology. An autonomous, resistant, or challenging warlord does not surrender technology until a later effect actually absorbs that country.

This behavior applies to both unified destinations:

- CBL created from the selected ordinary host
- the original ZZZ country after its in-place Wendigo Hannibal transformation

### Final live implementation and closure evidence

`common/scripted_effects/chaosx_dynamic_effects.txt` now defines `union_compatible_researched_technologies_from_donor`. The recipient is current country scope and the donor is the regular event target `technology_union_donor`. The helper iterates `event_target:technology_union_donor.researched_techs`, checks `has_tech = var:technology_union_entry`, and grants a missing token with `set_technology = { var:technology_union_entry = 1 popup = no }`.

The current call-site wiring covers all three required transfers:

- `cannibalism_create_unified_country_from_selected_host` saves the selected ordinary host as the donor and calls the helper from CBL before annexation.
- `cannibalism_absorb_current_warlord_into_unified_host` saves the current warlord as the donor and calls the helper from the live unified destination before later annexation. The destination can be CBL or transformed ZZZ.
- `cannibalism_absorb_primary_warlord_donor_into_wendigo` saves the primary warlord as the donor and calls the helper from the original ZZZ merge host before annexation.

The loop is additive for compatible researched technology tokens. It does not clear a receiver technology, does not copy a persistent array, suppresses research popups, and skips the transfer when a warlord remains autonomous, resistant, or challenging.

The current source specifications and package validation record the shared helper, donor event target, all three call sites, additive accumulation, and research-slot preservation. The earlier technology-union architect handoff is retained unchanged as a historical checkpoint. It is superseded by this disposition and the promoted source documentation.

### Required closure contract

Retain the engine-native array and token pattern. Do not replace it with a hand-maintained technology allowlist or a chain of `inherit_technology` calls.

The official dynamic-variable documentation states that `researched_techs` returns the array of researched technologies. The official effect documentation defines `for_each_loop`, `has_tech`, and `set_technology`. The approved Kaiserreich reference at `common/scripted_effects/00_transfer_technology_effects.txt` uses the same native structure. That structure is the correct basis for additive transfer.

Closure requires all of these rules:

1. Iterate the donor's live `researched_techs` array at the moment of absorption.
2. Test the receiver with `has_tech = var:technology` before granting each token.
3. Grant missing technologies with `set_technology = { var:technology = 1 popup = no }`.
4. Never call `inherit_technology` repeatedly for later donors.
5. Never clear a receiver technology.
6. Never lower or recalculate research slots.
7. Never create a persistent copied array.
8. Execute before donor slot cleanup and annexation.
9. Execute only inside a successful absorption transaction.
10. Keep the generic technology-loop helper free of Event 014 state so other systems can reuse it.
11. Keep the full public contract in `common/scripted_effects/chaosx_dynamic_effects.md` aligned with the helper.
12. Document that `set_technology` executes any technology `on_research_complete` payload for newly granted tokens. The recipient `has_tech` check prevents the payload from repeating for technology already owned.

### Mutually exclusive and special technology rule

No compatible researched technology category may be silently excluded. This includes doctrines, hidden technologies, and ordinary technology tokens granted through special-project content.

The approved Kaiserreich helper explicitly guards the flexible versus streamlined production-line pair and the concentrated versus dispersed industry families. The live shared helper uses the same required compatibility behavior. Mutually exclusive technologies cannot coexist, so the recipient's established branch wins and every other compatible donor technology transfers. The implementation must still run a focused conflict fixture before acceptance:

- receiver owns one member of a mutually exclusive family
- donor owns the conflicting member
- receiver and donor each own unrelated technologies that the other lacks

The expected result is that the receiver keeps its established incompatible branch, gains the donor's unrelated missing technologies, and loses nothing it already owns. Do not replace the skipped incompatible branch with research bonuses or an equivalent reward.

Completed special projects are separate from `researched_techs`. This contract transfers researched technology tokens, including ordinary tokens granted by project content when they appear in the donor array. It does not transfer prototypes, facilities, scientists, project progress, or completion state. That boundary is not a fallback from the Event 014 technology requirement. The live original ZZZ country preserves its own technology and special-project state because the Wendigo transformation occurs in place on the same country scope.

### Balance and AI contract

The union grants only technology already possessed by a country that is actually absorbed. It grants no free research points, no ahead-of-time bonus, no research speed, and no technology from autonomous or hostile warlords. Its strength is bounded by constituent acquisition and is appropriate for the intentionally overpowered completed unification routes.

There is no AI choice inside the helper. Existing disposition AI determines whether absorption occurs. The technology transfer must be deterministic once absorption succeeds.

### Acceptance proof

Implementation is accepted only after evidence covers all of these scenarios:

1. Ordinary CBL host has technology A and later donor has disjoint technology B. CBL ends with A and B.
2. A second later donor has technology C and overlaps B. CBL ends with A, B, and C without popups or duplicate side effects.
3. Repeating the same donor token set is idempotent.
4. The original Wendigo country has technology W and its primary warlord donor has technology D. Transformed ZZZ ends with W and D.
5. A later submitted warlord adds another technology to transformed ZZZ without removing W or D.
6. An autonomous, resistant, or challenging warlord transfers nothing before a later real absorption.
7. CBL keeps `constant:cannibalism_unification.starting_research_slots`. Transformed ZZZ keeps its existing research-slot count.
8. A donor slot can be cleaned and reused after the transfer without changing technologies already stored on the unified country.
9. A mutually exclusive technology fixture proves that the receiver keeps its established branch and still gains every unrelated compatible donor technology.
10. The in-place Wendigo transformation proves that original ZZZ keeps its existing special-project state while donor researched technology tokens are added.
