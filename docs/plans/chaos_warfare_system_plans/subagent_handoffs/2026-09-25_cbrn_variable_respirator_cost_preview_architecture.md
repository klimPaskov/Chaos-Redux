# CBRN variable respirator payment architecture audit

Disposition: accepted and queued for the two timed actions; immediate emergency preview remains unresolved. The user explicitly selected click-time reservation with unused-crate refunds for Occupied Population and Protective Aid on 2026-09-25. This is a read-only source audit for the three assigned decisions; the parent owns implementation, MCP evidence, final review, and commits. No gameplay, localisation, asset, or constant was changed here.

The user-approved cost overhaul requires each consumed payment exactly once in a decision cost row, with the correct texticon and an amount equal to the real debit. It also forbids an extra worldwide daily or weekly iteration. Under the current payment timing, `cbrn_emergency_state_mask_distribution` has a plausible exact quote at click time, subject to engine validation of cost-row localisation. The two timed decisions cannot guarantee that a click-time number equals a later debit without changing when payment or target selection occurs.

For all three deliveries, `required = round(max(0, (target_fraction × requirement − current_effective_crates) ÷ new_effective_fraction) × clamped_local_cost_multiplier)`, when `new_effective_fraction > 0`. Otherwise the request is zero. `requirement = state_population_k × civilian_crates_per_population_k`. The distributor caps each model's take to stock still required and that model's live `num_equipment@...`, so actual debit is `min(required, sum of the five usable model stocks)` at the instant of execution, assuming the five model stocks are nonnegative. Its order matters for model-ledger output, though the total is the same (`cbrn_protection_effects.txt:1167-1189,1196-1363`. Vanilla `documentation\dynamic_variables_documentation.md:558`. Vanilla `documentation\effects_documentation.md:1252-1264`). Local multiplier includes state urban/capital, low infrastructure, active disruption, non-core status, and source-country flags, technology, simplified-filter policy, and designer effects before its final clamp (`cbrn_protection_effects.txt:1082-1160`). The existing state snapshot is recomputed by an effect before every debit: it initializes missing ledgers, rebuilds the five-model crate sum, derives requirement, fitting/filter efficiency, and effective coverage (`cbrn_protection_effects.txt:501-543,759-792,881`). A preview based only on saved `cbrn_civilian_mask_effective_coverage` may therefore differ.

## Proposed helper map and migration

1. A proposed `cbrn_preview_requested_state_distribution_stock` scripted **trigger** would run in the targeted state scope with `ROOT` as paying country and temporary inputs for target fraction, base cost, fitting effectiveness, and new filter condition. It would use trigger-valid temporary arithmetic to mirror the snapshot inputs and multiplier order, write temporary `cbrn_distribution_preview_required` and `cbrn_distribution_preview_debit`, then return true. It must read actual per-model `num_equipment@...`, use no regular-variable writes or event targets, and never call a stockpile effect. Existing `cbrn_protection_triggers.txt` is the natural owner. This is local CBRN logic, not a new shared registry. The vanilla trigger docs support temporary arithmetic and comparison (`documentation\triggers_documentation.md:2110-2133,7440-7448,7482-7499`) and the offline Data structures page documents trigger-side temporary calculations (`paradox_wiki\Data structures - Hearts of Iron 4 Wiki.md:481-486`). Its exact temporary-output visibility across scripted-trigger and cost-localisation boundaries remains unproved.
2. An emergency wrapper could supply its four existing constants and use the preview in `custom_cost_trigger` and the cost-row localisation computation for this one immediate state decision. Migrate native PP `cost` to the same custom row only if necessary, explicitly debit PP once in `complete_effect`, and set `ai_hint_pp_cost` if a custom row replaces native PP. The offline Decision modding page states that a custom cost itself deducts nothing and cannot coexist with native `cost` (`paradox_wiki\Decision modding - Hearts of Iron 4 Wiki.md:284-335`). Vanilla `common\decisions\AFG.txt:490-499` shows a custom Command Power row with its hidden click-time debit. Keep stock execution in the existing distributor and use the quote only as display/affordability evidence, not as an extra debit. Preserve partial-stock distribution if that behavior is accepted. If full cost is required, that is a gameplay change for the parent.
3. For the occupied and external-aid cards, the same preview can give a *current estimate* for decision guidance, but it cannot satisfy an exact click-time cost row while the stock debit remains in `remove_effect`. Exactness requires a parent-selected mechanic change: charge or reserve a fixed whole mask amount at click and define cancellation/refund/target-change behavior, or defer player confirmation/payment until completion through a separate action. Neither route is silently interchangeable with the present program. For the national occupied card, target flags are also created only after clicking. A pre-click preview would have to reproduce the bounded `every_controlled_state` selection and full later revalidation, and state iteration order affects allocation after reserves are exhausted. No worldwide daily/weekly hook is needed or proposed.

No new tuning number is needed. Preserve `cbrn_mask_distribution`, `cbrn_protection_program_effect`, `cbrn_mask_filters`, `cbrn_mask_scale`, and multiplier bounds in `common\script_constants\cbrn_system_constants.txt`. A new constant would be justified only if the parent accepts a different upfront payment policy. Emergency and occupied previews need no persistent event target or cleanup. Existing occupied target flags are cleared on finish/cancel (`cbrn_protection_decision_effects.txt:237-255`). External aid uses regular targets within its completion chain (`cbrn_occupation_decisions.txt:359-363`, `cbrn_occupation_effects.txt:165-178`). Any upfront reserve design needs explicit receipts and cancellation cleanup, which this audit does not specify or approve.

## Uncertainty and validation for the owner

- **Feasible at source level, unverified in engine:** exact current emergency stock math can be reconstructed without mutations. Prove that `custom_cost_text`/its blocked form can evaluate targeted `FROM` and a trigger-calculated temporary output on the same render pass. The wiki documents dynamic temporary localisation (`paradox_wiki\Localisation - Hearts of Iron 4 Wiki.md:729-749`) but does not prove this precise cost-row evaluation/lifetime. The Data structures page warns that temporary outputs from scripted triggers may not survive outside the called block (`:435-442`). If they do not, calculate inside a dedicated scripted-localisation trigger rather than relying on a temp created by `custom_cost_trigger`, then compare boundary scenarios against the actual distributor.
- **Not feasible without changed timing:** occupied program and external aid cannot show a guaranteed exact future debit at selection. Their later availability rechecks, stock changes, target condition/control changes, and cancellation are real branches, not merely presentation gaps. Do not present a click-time estimate as an exact paid cost.
- **Meaningful validation after implementation:** immediate state with zero stock, one mask, exactly required stock, excess stock, fractional request rounding, all five variants, stale saved coverage, simplified-filter policy, non-core target, and multiple local multipliers. Compare preview to `cbrn_distribution_consumed_crates` for the same snapshot. For timed alternatives, validate click, cancellation, target invalidation, stock depletion, and changed controller. Check PP and factory presentation only once in the row and verify the gas-mask texticon resolves. This audit ran no gameplay, MCP, render, or live-game validation. The parent explicitly owns MCP and the user owns live-game checks. No in-scope focus, event, GUI, map, or weighted helper was designed here.
