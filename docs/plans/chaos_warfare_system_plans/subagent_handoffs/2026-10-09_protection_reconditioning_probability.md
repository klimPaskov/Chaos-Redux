## Validity, ranking, repetition, and risk

Both outcomes have positive weight, so neither is starved or impossible within the complete local pool. The safe branch dominates conditionally at 80%; the defective branch remains a live 20% outcome. The recovery-input sweep found no rank reversal, but it did not vary either constant weight. No entry-level trait, threshold, eligibility trigger, or external factor modifies these weights.

The random list is invoked from a repeatable decision. The offline Decision Modding and Effects references say decisions use a fixed random seed by default, so a repeated decision can repeat the same random-list choice within one game. The decision source contains no `fixed_random_seed = no`. Treat 20%/80% as the exact per-list weighted distribution, not as proof that repeated activations produce a 20% empirical defect rate. If independent reconditioning rolls are intended, consider adding `fixed_random_seed = no` to `cbrn_recondition_old_masks`; retaining the default preserves deterministic repetition.

No sequence analysis was run because this is a native random list, not a complete custom weighted pool with transitions or cadence.
