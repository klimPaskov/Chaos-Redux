## Contradictions, stale instructions, and parent decisions

The parent should decide whether to remove or retain these compatibility constants in a separate gameplay-owned task.

The previous document treated six HQ labels as available and `hazard_pioneer_formation` as a separate fielded role. Current `cbrn_hq_support.txt` defines three consolidated sections; `hazard_pioneer_formation` remains a non-researchable technology whose bonuses affect the primary protection category, while `cbrn_gas_mask_decon_detachment` remains an actual support sub-unit. The parent should review any other document or localisation that still presents a distinct Hazard Pioneer company.

The old document called `cbrn_convene_institutional_review` a one-time migration decision, but that entry is absent from the current decision source. This is an open migration coverage question for the parent; the documentation now describes only the actual startup and CXT effect call sites. No prompt file was assigned or edited, and the current document no longer instructs future agents to implement the retired five-policy or paid-commission route. The four registered milestone icons have no current source consumer found in this bounded inspection; adding a dedicated UI remains a proposal, not an accepted implementation claim.

No duplicate document was merged or deleted because the parent assigned one mechanic document and this handoff only. No unresolved design claim was promoted to the accepted spec.
