# Timed respirator reservation architecture

Disposition: **accepted and queued**. The user explicitly selected selection-time reservation, an exact respirator payment in the decision cost row, refund of unused crates on cancellation or target invalidation, and completion limited to the reservation on 2026-09-25. The parent assigned this read-only architecture pass; gameplay implementation and final evidence remain queued with the parent. Existing partial-stock behavior is preserved by reserving only what is actually available at selection.

## Current transaction and evidence

`cbrn_supply_occupied_population` is a country decision with a 30-day timer. Its `complete_effect` marks eligible controlled states; its `remove_effect` loops flagged states and calls `cbrn_complete_occupied_state_distribution`; its `cancel_effect` only clears the country flag and state markers. Its `cancel_trigger` currently includes live mask stock, so reserving the last crate would cancel its own timer. See `common/decisions/cbrn_protection_decisions.txt:287-335` and `common/scripted_effects/cbrn_protection_decision_effects.txt:236-262`.

`cbrn_deploy_protective_aid` is a 21-day `state_target = any` decision. Selection adds a timed state flag. Completion binds the exact state and calls the external distributor. Cancellation clears the state flag. Its current country supply trigger includes live stock **and available factories**, so both stock removal and factory commitment can self-cancel the active project. Its current state trigger rejects its own active project flag. See `common/decisions/cbrn_occupation_decisions.txt:308-405`, `common/scripted_effects/cbrn_occupation_effects.txt:102-195`, and `common/scripted_triggers/cbrn_occupation_triggers.txt:477-511`.

The common distributor refreshes state coverage, derives needed effective crates, grosses up for fitting/filter condition and local logistics, then rounds `cbrn_distribution_stock_required`. It debits five models in this order: reconditioned, basic (`_1`), improved (`_2`), advanced (`_3`), sealed (`_4`). It records civilian model ledgers, fitting points, weighted filter condition, replacement demand, and country totals. The external wrapper also writes aid history, donor export, recipient receipt, opinion, and achievement proof. See `common/scripted_effects/cbrn_protection_effects.txt:1082-1409` and `common/scripted_effects/cbrn_occupation_effects.txt:102-160`.

The current control-transfer callback invokes `cbrn_transfer_state_civilian_mask_ledger` only when a state already has positive distributed civilian crates; that helper clears the occupied target flag. An escrow-only state can therefore miss the callback. See `common/on_actions/chaosx_on_actions.txt:23-42` and `common/scripted_effects/cbrn_protection_effects.txt:1847-1857`.

## Helper map and scope contract

| Proposed helper | Scope and inputs | Outputs, side effects, and call sites |
| --- | --- | --- |
| `cbrn_quote_occupied_state_mask_reservation` | State scope, country `ROOT`; uses the occupied distribution target/cost constants, current state population and mask ledgers, donor modifiers, and stock availability supplied by the caller. Pure trigger-compatible arithmetic. | Temporary rounded need and capped allotment. Called from country cost-row scripted localisation, affordability trigger, and selection effect's per-state loop. Do not mutate snapshots inside a trigger. |
| `cbrn_quote_external_state_mask_reservation` | Target state `FROM`, donor `ROOT`; same arithmetic with external supplier modifiers. | Temporary rounded need and capped allotment for that one target. Called from aid cost row, affordability trigger, and selection effect. |
| `cbrn_reserve_mask_models_for_state` | State scope; donor is `ROOT` for own occupation or bound regular event target for external aid; input is allotted integer crates and reservation kind. | Debit available stock **once**, oldest first, and write five regular state receipt variables plus a persistent donor pointer and active flag. Set a temporary actual-reserved total from the five real debits; require it to equal the quoted allotment. Separate receipt namespaces for occupied distribution and external aid. Do not use a global event target for these independent concurrent projects. |
| `cbrn_distribute_reserved_masks_to_state` | State scope with an active receipt, valid target, and donor pointer. | Reuse the common distribution coverage/fitting/filter/model accounting, replacing only its stock reads/debits with five receipt balances. Recompute live need, take at most each model's receipt in the same order, update real delivery ledgers and proof, then refund every unconsumed model and clear the receipt. Called by the two existing completion wrappers. |
| `cbrn_refund_occupied_state_mask_reservation` / `cbrn_refund_external_state_mask_reservation` | State scope; reads the stored donor pointer and five model receipts. | Return each nonzero model to the donor stockpile, refresh donor snapshot, clear all five values/pointer/active flag. Idempotent when receipt absent. Called from decision `cancel_effect`, invalid-state completion branch, and control-transfer hook. |
| `cbrn_active_occupied_program_remains_valid` / `cbrn_active_external_aid_remains_valid` | Country/target state respectively; pure triggers. | Used only by in-flight `cancel_trigger`. Exclude live stock, committed factory availability, and the project's own active flag. Keep true invalidation conditions: existence/capitulation or lost program authority for country; population, foreign controller, non-core status, emergency/gap as accepted target policy for aid; controlled non-core status and target gap for occupation. |

The state receipt is authoritative because an occupied program can reserve separately for many states and a donor can run several aid targets simultaneously. Each state stores the exact model count removed for that particular decision. The occupied program's country flag remains a concurrency guard, not the escrow balance. The donor pointer should be a state-scoped regular variable holding the donor country scope; temporary variables and regular event targets cannot persist through 21 or 30 days. All receipt variables and flags must be cleared together after delivery or refund. A state can carry separate occupied and external namespaces during a control transition, so both refund helpers must be idempotent.

## Quote and payment order

For each eligible state, calculate the existing distribution's need using the same target, source modifiers, urban/infrastructure/disruption factors, effective-coverage gap, fitting effectiveness, and filter condition. Preserve its **per-state** `round_temp_variable` step before summing a national quote. Clamp negative or zero-efficiency cases to zero. The raw national need is the sum of these rounded state needs, then the country payment is `min(raw need, sum of the five real donor model stocks)`. External aid uses the single selected state's rounded need and the same stock cap. This is partial payment, not a full-stock prerequisite. Allocate the national capped amount through the same controlled-state order used to create the receipts, stopping when the cap is exhausted. The cost row shows the **actual capped reservation**, not theoretical unmet need.

Use a trigger-compatible quote helper with temporary variables. The offline Data structures page at lines 483-486 and 820-835 explicitly shows `all_country` accumulating unscoped temporary values through an `if` per item; installed `documentation/triggers_documentation.md:890-897` confirms `all_controlled_state` for a country. Thus `all_controlled_state = { if = { limit = { eligible } ...add_to_temp_variable... } }` can sum the national quote without a world pulse. Do not include a false-returning child trigger that could stop `all_` traversal early. Existing `common/scripted_localisation/condemnation_response_costs.txt` calculates cost-row variables in `defined_text.trigger`; use the same pattern for the quote row so localisation does not depend on temps left by a separate `custom_cost_trigger` evaluation. Existing `localisation/english/020_black_plague_response_l_english.yml:61-62` demonstrates `FROM` values in targeted custom-cost rows.

Both decisions currently have native Political Power cost. The offline Decision modding page at lines 305-335 says a custom cost row does not debit resources and cannot be combined with a regular native cost. Therefore move Political Power into the custom row alongside a respirator texticon and manually debit Political Power in `complete_effect` exactly once. Gate the same inclusive PP/positive-quote requirements from both `available` and `custom_cost_trigger`; set `ai_hint_pp_cost` to the existing fixed PP amount. Preserve the factory commitment and explain it in the full cost tooltip. Use existing constants (`cbrn_protection_decision_cost.occupied_distribution_pp`, `cbrn_occupation_decision_cost.protective_aid_pp`, existing distribution constants); no new balance constants are required. The quoted amount is reevaluated at click, then the real per-model stock debit and receipt write occur before the timer's active marker is set. After a successful positive receipt, apply PP and mark the project active. A zero actual debit must leave no active timer receipt or charge; the parent must verify engine handling if decision `complete_effect` begins despite a stale UI quote.

At completion, check the receipt first, then current target validity. For a valid state, recompute current need and apply the common distributor's accounting from the **receipt pool only**. Every model debit branch in `cbrn_distribute_requested_masks_to_state_internal` must switch to receipt consumption for these two callers; no second `add_equipment_to_stockpile` negative amount is allowed. Completion may deliver fewer crates if the state gap shrank or logistics improved. Refund all residual model counts after distribution, then clear the target marker and receipt. For an invalid state, deliver nothing, refund all five models, clear marker and receipt. Preserve resistance/compliance effects and external aid history only when usable crates are positive. The external donor's current-stock/factory gate must not reappear inside completion, or an already-paid escrow can be stranded.

On `cancel_effect`, refund every occupied-program state receipt before clearing target markers and country active flag; aid cancellation refunds its exact `FROM` state receipt before clearing its project flag. An exhausted *unreserved* stockpile is never an in-flight cancellation reason. If one of several occupied states becomes invalid while others remain, refund that state's receipt when invalidation is observed, and let the remaining program finish. Existing 30-day completion can perform this refund even if no event-driven invalidation hook exists for a non-control change; if the user expects immediate return for every invalidation type, the parent must identify narrow event hooks rather than add a global daily/weekly loop.

For control transfer, broaden `on_state_control_changed` so a state with either reservation active flag enters a separate refund branch **regardless of whether it has distributed civilian crates**. That refund branch must not be swallowed by the existing `fallout_world_rewrite_callbacks_are_allowed` plus positive-ledger gate: an escrow can exist while the old civilian ledger is zero. Refund through the stored donor pointer before `cbrn_transfer_state_civilian_mask_ledger` or another cleanup clears `cbrn_occupied_distribution_program_target`. The state can then process its ordinary civilian ledger transfer. The transfer path must also clear the aid project flag if its exact state is invalidated. Keep both receipt namespaces safe if both are present. The event target pointers `cbrn_old_state_controller` / `cbrn_new_state_controller` in that callback are short-lived and do not replace the persistent donor pointer.

## Edge cases and implementation checks

- **Partial stock:** Sum the five concrete models actually removable, cap the quote, and reserve only that amount; later states can remain uncovered as today. The national row shows the total committed now. If available stock is positive but per-state rounding yields zero everywhere, make selection unavailable rather than display a zero equipment charge and run an empty timer.
- **Multiple aid targets:** Each state's own five receipt variables and donor pointer are separate. The existing `cbrn_occupation_external_aid_project_active` prevents duplicate aid on one state; it must not block completion of its own project.
- **Rounding:** Keep `round_temp_variable` per state, then add; do not round the national sum only. Model receipts and equipment stock must be integer counts, while usable civilian coverage may remain fixed point after dividing by the logistics multiplier.
- **Target changes:** On control transfer refund immediately through the widened callback. At timer end or cancellation, a missing/changed controller, newly core state, zero population, closed gap, or missing emergency must never consume the receipt. Decide explicitly whether aid should continue if an alert ends while a real occupied protection gap remains; current selection requires both, but current cancel trigger does not recheck either. Do not silently choose a new policy.
- **Reentrancy:** Write active receipt flags only once the model debits and quantities are complete; no second selection can overwrite an active state receipt. Refund clears counts before or atomically with returning stock so a repeated cancellation/transfer callback cannot mint crates. Country program remains single-instance via `cbrn_civilian_distribution_program_active`.
- **Donor disappearance:** `add_equipment_to_stockpile` is country-scoped. If a donor no longer exists when refund runs, a stock refund destination may be unavailable; record that exact engine limitation and avoid crediting the current controller or another country as an invented fallback.
- **Snapshot parity:** The current distributor refreshes persistent state snapshots at delivery, whereas cost-row triggers cannot run the effect-only refresh. A pure trigger quote must derive current requirement/coverage from state population and the underlying five civilian ledgers, fit points, and filter condition, or the parent must establish a reliable synchronized snapshot invariant. Reading possibly stale `cbrn_civilian_mask_requirement` / `cbrn_civilian_mask_effective_coverage` alone is not proof that the row equals the click-time charge. See `cbrn_refresh_state_civilian_mask_snapshot` at `common/scripted_effects/cbrn_protection_effects.txt:759-883`.
- **UI atomicity:** The source proves dynamic custom-cost text and manual payment, but not an atomic lock between row render and click. Recompute the same quote in the selection effect and make its actual debited five-model receipt the payment record. Validate cost-row parity for changing stock, state population, coverage, and multiple simultaneous projects in the game's consumer; do not claim an exact displayed amount if those conditions diverge between evaluations.

## Migration, validation, and limits

Modify only the two decision definitions, their own scripted-effect/trigger/localisation owners, the shared distribution backend, and the bounded control-transfer callback. Extract the common quote arithmetic from the distributor instead of copying the 100-plus-line formula into each decision; preserve its model order and state ledger update path. Document new helpers in the matching `common/scripted_effects/cbrn_scripted_effects.md` and trigger docs; if a generic dynamic helper is added, also update `common/scripted_effects/chaosx_dynamic_effects.md`. No new global on-action, administrative decision, focus, GUI, map edit, or AI weight change is proposed.

Meaningful parent validation: compare the row to five actual stock debits at selection; run two aid targets from one donor with partial stock; cancel each independently; transfer a state with an escrow but zero distributed crates; change the target's controller/core/gap before completion; shrink and grow demand during the timer; verify total delivered plus refunded equals total reserved by model; verify neither completion path makes a second stock debit; and check that a stock-empty donor does not self-cancel an active paid timer. The parent owns MCP evidence, code review, implementation, and game-consumer uncertainty. This handoff adds no gameplay code and performs no live-game test.
