# Event 016 existing-mesh rig and action recovery — 2026-08-27

## Scope and authorization

This recovery pass reused the existing approved meshes and did not regenerate, remesh, image-generate, or replace any base model geometry. The user explicitly authorized bounded manual Blender rigging, weighting, firearm placement, skeletal action authoring, and contact correction on 2026-08-27 because the prior provider outputs were not acceptable. The manual recovery script is `.tools/3d_pipeline/manual_recovery/recover_existing_units.py`.

The script loads each existing approved checkpoint, keeps the visible source mesh, creates a bounded HOI4-compatible armature, assigns at most four nearest-bone influences per vertex, bakes real multi-frame skeletal actions, and writes a dated candidate checkpoint and JSON report. It never calls Meshy, creates a new mesh, or uses transform-only animation as a replacement for a skeletal action. The clone rifle is the existing approved vanilla rifle checkpoint and is joined only as an already-approved firearm attachment; its 391 vertices are not regenerated.

## Firearm and locator boundary

The clone firearm uses the existing approved vanilla rifle geometry, measured trigger/support contact coordinates, a single stable `Spine02` influence for the joined rifle, and baked two-hand IK. This avoids the earlier wrist-driven vertical swing while preserving the rifle mesh. The clone muzzle and cartridge locators are parented to the stable torso attachment after the join. The robot retains its existing arm-mounted gun and has `muzzle` and `muzzle_left` locators. Alien retains its integrated pistol and a manual `muzzle` locator. Portal has only a locator because the preserved source mesh has no visible firearm.

The manual recovery pass does not bind particles, lights, sound definitions, or runtime entity consumers. Existing sourced-audio and counter handoffs remain the parent-owned inputs; no synthesized audio or guessed firearm effect binding was added. This is deliberate because a locator and an animation export are not sufficient proof of a complete in-game firing consumer.
