## Callback limits and unresolved decisions

**Project identity is unsupported by the inspected callback surface.** `on_project_completion` exposes `FROM` as a project, but the installed `documentation/triggers_documentation.md` lists only `has_project_flag`, `hidden_trigger`, and `meta_trigger` for SPECIAL_PROJECT scope (lines 524–528). The country trigger `is_special_project_completed = sp:<id>` proves that the country has completed an ID; it does not prove that ID is the *current* `FROM` project. The present Mengele callback runs a country-wide Prototype reconciliation for any project completion. Reusing that pattern for later stages could settle an earlier matching project during an unrelated completion and cannot safely distinguish a stale Rocketry alternative. Parent must verify a supported current-project identity route or obtain a user decision on a different design. Do not add a completed-state polling or source-only approximation as an exact callback.

**Electronics technology identity is also unresolved.** The offline Technology modding page at lines 129–138 documents a per-technology `on_research_complete` block, and vanilla uses it (for example `common/technologies/support.txt:167`). The installed on-action sources and offline On actions page document `on_project_completion`, but no global technology-completion on action was found. Vanilla `radio_detection`, `centimetric_radar`, and `phased_array` are in `common/technologies/electronic_mechanical_engineering.txt:218,373,429`; their definitions do not carry an Event 016 callback. The radar project callback alone cannot observe later research. Overriding those vanilla technologies or using a later country-state check would change the integration contract and needs a user decision; this handoff authorizes neither.

**Already active paid timer:** `mengele_event016_active_project_stage_entries^index` and its cost arrays identify a live paid decision. The accepted plan does not specify whether native completion should cancel/refund it, let it finish, or convert it. The settlement gate must fail while that matching active receipt exists; leave timer behavior **unresolved for user decision**. Never clear the arrays or refund from a native callback without that decision. The existing decision `cancel_effect` and `remove_effect` own those paths.
