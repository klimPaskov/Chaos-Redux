## Runtime contract

The report requires a resolved context briefing, a resolved assistant conflict, enabled Evolution I chronology, a live host or active Kruger State, and the pending flag. The resolver clears the pending flag before applying any reward, and the resolved guard prevents duplicate project stages or repeated policy deltas. The report uses computation Theory as the first family, so the existing project ledger and first-Prototype queue remain the only project-history owners.

Transfer and sovereignty formation copy pending and resolved receipts. A disabled Evolution I cannot leave the report pending. World-end state blocks scheduling and presentation.
