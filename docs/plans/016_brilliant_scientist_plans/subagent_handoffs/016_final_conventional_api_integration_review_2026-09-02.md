## Findings and dispositions

### R1 — Completed but unhealthy inherited conventional knowledge was skipped — corrected

Before correction, `brilliant_scientist_apply_project_inheritance_outputs` restored completed history but reached the new neutral grant only through `brilliant_scientist_enable_project_stage_modifiers` under `brilliant_scientist_project_is_operational`.
That trigger excludes suspended, damaged, and dismantled families (`common/scripted_triggers/016_brilliant_scientist_triggers.txt:466`).
The transfer path explicitly carries current stages and health arrays (`common/scripted_effects/016_brilliant_scientist_effects.txt:1989`), then calls inheritance (`:2068`).
Consequently, a completed suspended Computation transfer retained the old country's learned package but denied an unentitled new holder its inherited package and slot until recovery.

The parent inserted the private conventional bridge immediately after authenticated inherited history and before the project-health branch (`common/scripted_effects/016_brilliant_scientist_project_effects.txt:1128`–`:1136`).
The bridge takes the exact current family/stage, records known Event 016 provenance, and changes neither native family/index/requested stage nor health arrays.
Only exact Deployment/Weaponization of the six conventional families passes the API gate.
An inherited completed suspended/damaged/dismantled family therefore supplies its learned output without enabling a physical project, creating a facility, or replaying one-shot stage rewards.
A stage-zero dismantled ledger does not manufacture a completed package from unrelated historical flags.
The healthy branch's later repeat bridge is idempotent.
**Retest: source-accepted.**

### R2 — Sovereignty's total-slot floor could absorb an existing learned slot — corrected

The former same-tag floor compared total slots directly with ordinary starting slots, currently three.
For example, a base-one country with one learned Computation slot had two total slots and was set to three, while the same sovereign establishment without Computation also reached three.
The parent confirmed that the intended floor is the ordinary establishment plus the separately learned slot, not a total minimum that includes it.

`brilliant_scientist_apply_formation_research_floor` now computes starting three plus one when either existing native or neutral slot marker is active, and sets the computed integer only when the country is below it (`common/scripted_effects/016_brilliant_scientist_country_effects.txt:661`).
Both fresh-country initialization (`:689`) and same-tag transformation (`:1110`) use it.
The OR over the two markers adds the gain once; the helper does not write either marker and never lowers a larger program.
Fresh split: floor three before inherited knowledge, then one neutral slot gives four.
Already learned same-tag or reinitialized country: floor four, followed by idempotent reconciliation with no additional slot.
Larger existing totals remain unchanged.
**Retest: source-accepted.**

## Action affordability, payment, and cancellation

Selection and `custom_cost_trigger` use the same named affordability query per action.
Light is 20 Command Power, 75 Support Equipment, 250 fuel, and two temporarily occupied civilian factories.
Standard is 25 Command Power, 100 Support Equipment, 500 fuel, and two factories.
Synthesis uses the standard physical payment but requires and occupies three factories.
Heavy is 40 Command Power, 200 Support Equipment, 1,500 fuel, and three factories.
Source: `016_brilliant_scientist_technology_action_constants.txt:14`, payment/refund effects `016_brilliant_scientist_technology_action_effects.txt:10`–`:44`, and affordability triggers `016_brilliant_scientist_technology_action_triggers.txt:53`–`:81`.

Exact Command Power/fuel/factory amounts pass inclusive NOT-less-than tests; integer equipment stock at the required count passes the existing exclusive count-minus-one test.
One fewer equipment item, insufficient fuel, Command Power, or available factories blocks selection and the cost predicate together.
Military-industry requirements are separate nonconsumed requirements; neither trucks nor manpower are silently spent or refunded.
Each decision pays in `complete_effect`, supplies output in native `remove_effect`, and returns the same initial consumables through its matching `cancel_effect`.
Targeted decisions cancel on invalid target; all cancel on loss of the action's system availability, including world end/terminal lock.
Learned capabilities are intentionally not cancelled merely because Kruger leaves or its native project becomes unhealthy.
Native cancellation ends factory commitment and excludes `remove_effect`; no second custom refund scheduler or shared mutable payment receipt was introduced.
Payment/refund helpers are not advertised as arbitrary idempotent public APIs: their once-per-timer ownership belongs to the native decision lifecycle.
Existing preparation durations/cooldowns remain separate from the neutral grant and unchanged by it.
No probability distribution or AI affordability behavior is certified by this source trace.
