## Files

- `docs/plans/016_brilliant_scientist_plans/016_krg_biological_stockpile_delivery_addendum.md` defines the proposed Event 016-owned ledger, production decision, native CBRN callback boundary, transfer and formation receipts, defeat cleanup, localisation, AI, and validation contract.

## Finding

The current Event 016 bridge restores biological project history, native delivery technologies, containment ideas, and the confirmed-use hook, but it has no KRG quantity ledger. A single Event 016 decision or flag would be unsafe because native CBRN systems own reservations, equipment debit, consumption, condemnation, contamination, retaliation, and Fallout accounting.

## Historical proposed implementation order

1. Promote the addendum into the relevant Event 016 specification and KRG decision documentation.
2. Add Event 016 constants, variables, receipts, production action, transfer/formation cleanup, localisation, and route AI in an isolated Event 016 tranche.
3. Separately review and implement one narrow native CBRN reservation/outcome callback that can debit or return the Event 016 charge exactly once.
4. Run the static and targeted scenario matrix in the addendum, then rerun the KRG country/project-force audit.

## Boundary and risks

- No free stockpile or placeholder production action is approved.
- No Event 016 helper may infer an offensive release from research, readiness, staging, authorization, failed delivery, or attacker accident.
- Transfer during an in-flight native reservation must reject safely or preserve the native actor pointer; an orphaned reservation is not acceptable.
- Defeat, terminal, dismantling, and failed formation cleanup must clear Event 016 quantities without deleting native CBRN history.
- The seven reusable 3D unit packages remain intentionally deferred.

This handoff records design evidence only. No new gameplay, model, asset, localisation, spreadsheet, or live-game validation was performed in this tranche.
