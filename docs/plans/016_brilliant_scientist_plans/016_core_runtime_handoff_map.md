These are presentation extensions rather than new routes or rewards. Optional future scenarios, broader country-specific flavour, expanded report/news presentation, quantitative balance evidence, live acceptance, and dedicated 3D packages remain outside this acceptance.

## Event 019 provider integration contract

The reusable Event 019 provider API is documented in `docs/events/019_infantry_spawn/systems/triggerable_scenario.md` and implemented in `common/scripted_effects/019_infantry_spawn_unit_registry_effects.txt`. - `kruger_clone_infantry` for clone formations and clone identity history.
- `kruger_robot_frame` for autonomous robot formations and power or network history.
- `kruger_paleogenetic_beast` for dinosaur or megafauna formations and reserve, feed, handler, and transport history.
- `kruger_xenobiological_assault` for engineered organisms and their selected control channel, containment, and failure history.
- `kruger_exotic_guard` for alien-interface or exotic-arm formations and artifact or interface history.

The adapters retain Event 016 project stage, capacity, equipment, sustainment, containment, route, and achievement receipts while satisfying Event 019 family/provider identity freeze, parent isolation, derivative setup, public package, management, report, and cleanup contracts. Portal and temporal consumers remain native Event 016 units unless a later accepted design explicitly expands provider scope. Bespoke 3D entities remain deferred.
