## Historical blocking and material findings

> The following F1-F4 sections are historical findings from the pre-correction audit. Their required actions describe the patch that was applied and are not current work items.

### Historical F1. `.6` used a decision/focus AI key inside event options

Severity: high; AI-equivalent requirement not met.

Both options in `chaosx.nr16.6` use `ai_will_do` at `events/016_brilliant_scientist_directorate_outcomes.txt:166-170,176-180`. Event options use `ai_chance`; the offline Event Modding reference states this contract at `paradox_wiki/Event modding - Hearts of Iron 4 Wiki.md:151-156`, and vanilla event options use the same structure.

Consequently the intended context-biased publication versus classification choice is not implemented through the supported event-option weighting surface. The focused HOI4 event inspection did not surface this defect because its result was workspace-partial and its validation flag was false; the artifact is recorded under validation limits.

Required action: replace the two event-option weight blocks with supported `ai_chance` blocks and validate the option probabilities under public-science, strategic-security, assistant-school, classified-service, wartime, and peacetime contexts.

### Historical F2. Persistent receipt was written after the one-day transfer window

Severity: critical; explicit cross-transfer guarantee can fail.

`brilliant_scientist_dispatch_breakthrough_report` checks the persistent character receipt but, on dispatch, writes only the country-local reported-family array, latest-family variables, and `brilliant_scientist_breakthrough_report_active`, then schedules `.6` one day later at `common/scripted_effects/016_brilliant_scientist_breakthrough_effects.txt:12-28`.

The per-family flag on `KRG_warren_kruger` is not written until the player or AI resolves `.6`, through `brilliant_scientist_record_breakthrough_public` or `_classified` at `common/scripted_effects/016_brilliant_scientist_breakthrough_effects.txt:100-140`. The scheduled event requires its original country still to be the current host or active KRG at `events/016_brilliant_scientist_directorate_outcomes.txt:155-162`.

If Kruger transfers or KRG formation changes the carrier during that one-day interval, the old country's event can fail its trigger while no character receipt exists. A recipient that rebuilds its local project arrays can therefore replay the family report. This directly contradicts `016_brilliant_scientist_spec_part_1_core.md:303` and `016_brilliant_scientist_spec_part_3_project_portfolio.md:11`.

Required action: commit an identity-persistent pending or delivered receipt atomically with dispatch, migrate or retarget the pending report to the verified carrier, and clear or finalize that pending state only through an explicit resolution path. Validate a transfer and a KRG formation between dispatch and presentation.

### Historical F3. One active report silently dropped another family's first Prototype

Severity: critical; the one-report-per-family guarantee can fail without transfer.

The dispatcher rejects every new family while `brilliant_scientist_breakthrough_report_active` is set at `common/scripted_effects/016_brilliant_scientist_breakthrough_effects.txt:16`. It neither records a pending receipt nor queues a later attempt. The dispatcher is called only when a stage actually changes, through `common/scripted_effects/016_brilliant_scientist_project_effects.txt:89-105,560-585`.

This is reachable in one effect chain: `brilliant_scientist_sync_native_project_prototypes` evaluates four reused native project families sequentially at `common/scripted_effects/016_brilliant_scientist_project_effects.txt:1095-1131`. If more than one completed native project is synchronized from Theory, the first family activates `.6`; subsequent families advance to Prototype but their dispatch is discarded. Because their stage has already changed, the later stage-output bridge does not retry them.

Required action: use a real pending-family queue or a persistent per-family pending receipt, dispatch the next report after the previous one resolves, and rebuild the queue safely after transfer/formation. Validate two native projects synchronized in one call and two project completions on the same day.

### Historical F4. New context and report history was not part of exact KRG inheritance

Severity: medium; persistent UI/history and documentation claim are partial.

The exact inheritance helper at `common/scripted_effects/016_brilliant_scientist_country_effects.txt:134-320` copies the established Directorate variables, facilities, institutions, evolution policy flags, temporal ledger, origin evidence, and modifiers. It does not copy the new `brilliant_scientist_context_*`, `brilliant_scientist_assistant_*`, `brilliant_scientist_breakthrough_*`, `brilliant_scientist_last_breakthrough_*`, or `brilliant_scientist_last_breakthrough_project_family` country state.

Already-written Kruger character flags still prevent replay after a resolved report, but the new carrier loses the context settlement and latest public/classified report displayed through scripted localisation at `common/scripted_localisation/016_brilliant_scientist_directorate_scripted_localisation.txt:27-28,262-283`. This conflicts with the persistent-record wording in `docs/events/016_brilliant_scientist/overview.md:15-17` and `docs/events/016_brilliant_scientist/systems/projects.md:43-45`.

Required action: define which new history is intentionally carrier-visible, copy only that durable state during formation/transfer, and update the mechanic docs if context history is deliberately host-local.
