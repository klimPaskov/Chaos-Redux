# Technical boundaries and blockers

This is an implementation handoff boundary map. It is not validated Clausewitz or evidence that an adapter already exists.

## First native check

The current Event 094 uses `set_equipment_fraction = 0.5` in the visible event option. The native effect may be the best baseline operation if installed documentation and controlled before/after stock tests prove every required identity and issued-equipment boundary. Do not replace a suitable native operation with a large custom reflection framework merely because the design discusses dynamic coverage.

However, this pass did not establish that operation's installed-version behavior, rounding, variant coverage, reservation treatment, or population-independent side effects. A token name or online search snippet is insufficient. Obtain both offline-wiki and installed documentation evidence and inspect actual vanilla and mod usages before choosing the implementation.

## Transaction contract

The event needs a stable incident identity, selected country, current enabled tier, selected semantic categories, object or roster snapshots, one-time rounding outcomes, and actual result receipts. Preparation is read-only. A committed item cannot apply again through a delayed report, duplicate dispatcher delivery, nested owner callback, save load, or cluster coalescing.

All categories use the pre-incident state. Build conflicts before selection and application. A stockpile alias, a person represented in several rosters, or a population operation with an unavoidable manpower debit cannot be treated as an independent second quantity.

Prefer preflight and at-most-once application over a fictional universal rollback. Once an owner has committed an irreversible result, retain its actual receipt. A later failure must be reported and isolated, not repaired by applying the earlier loss again. Never declare a partial result complete.

The private transaction state must not depend on a globally shared temporary target which another nested event can overwrite. Parent and child boundaries need explicitly initialized outputs and exact scope rules. A scope variable's presence is not proof that its stored country still exists.

## Population helper boundary

The supplied `apply_exact_state_civilian_population_loss` contract accepts a log-Deaths flag. The design requires that flag to be zero. The helper's reported applied loss is measured before minus after, rather than an assumed requested amount. The caller must initialize its output temporaries and provide the full input contract on every call because the helper clears public inputs.

Use the actual neutral owner implementation after verifying it. Do not reuse the example's cannibalism reason as the disappearance reason. Do not call a Deaths-registering wrapper and then subtract the Deaths total afterward. Do not subtract population separately and invoke the helper again merely to obtain a receipt.

The documented positive recruitable-manpower-credit reconciliation does not prove that every manpower side effect is neutral. Population/manpower combination testing remains mandatory. A protected population floor is not part of the design except a genuine documented native constraint. Any such constraint must be reported as a deviation from ideal half coverage.

## Precision and workload

State demographic measures, exposed people counts, and native `_k` units need explicit conversion and round-trip tests, especially for very large populations. Do not hide overflow with an arbitrary demographic cap. Do not iterate once per person or once per physical item.

Use bounded native object iteration or a verified dynamic family operation. The number of saved state records or equipment identities must not be silently truncated to a convenient fixed list. Presentation may summarize, but calculation coverage may not shrink with the summary.

Country, state, object, and roster identities must survive save loading without relying on their current array index. Use the project's date conversion helper for encoded date variables. Native `days` fields remain ordinary day counts. Do not add a raw duration directly to an encoded date.

## Shared surfaces

The root identity `chaosx.nr94.1` and existing owner event file are observed precedents. New resolver, report, decision, history, achievement, and super-event identifiers must be reserved after inspecting current registries. The number 094 is not a free super-event slot. Event 016's overview already uses visible super-event 94 for its own Strategic Singularity package.

Keep Event 094's target preparation aligned with the dispatcher before history recording. Shared history and Event Details changes belong to the shared owner, not an event-owned custom GUI worker. Preserve the shared event timer, minor-repeatable weight rules, cluster lifecycle, settings controls, and other event roots.

Use native technology inspect/render/compare routes if research implementation touches a technology graph. Do not convert a progress-loss problem into a graph rewrite. Use the correct MCP event, decision, script, and probability routes where they are exposed, retaining actual supported schema and evidence.

## Release blockers

Mandatory baseline stock coverage, accurate research-progress handling, core population accounting, complete ordinary-character handling, and enable-control correctness cannot be waived by reporting a smaller implemented subset as the full event. Optional owner-specific resources may remain unavailable with a documented coverage disposition, but the named user requirements remain visible requirements.

The Wu, Kruger, and Devil connections are not implemented until reconciled with their owners. Final super-event text/audio and canonical asset inputs are unresearched production gates. Probability, independent improvement-loop, completion-audit, save, multiplayer, and user-owned live evidence remain open.
