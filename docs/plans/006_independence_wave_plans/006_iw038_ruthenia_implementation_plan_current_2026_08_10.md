# IW-038 Ruthenia implementation plan

## Scope

IW-038 reuses the registered vanilla `RUT` country and the fixed state 73 Carpathian Ruthenia anchor.

The package belongs to `REG-04`, uses reservation group `RG-73`, and must remain unavailable until the full setup, force, identity, asset, AI, decision, focus, host, cleanup, and final-validation contracts pass.

Ordinary vanilla-created Ruthenia remains unchanged.

Event 006 content is installed only when `RUT` is dormant, IW-038 is the frozen selected package, state 73 is reserved and transferred by the shared release transaction, and the Event 006 origin checkpoint succeeds.

Event 005 Ukraine and Galicia-Ruthenia state claims remain separate origin systems and must respect the frozen Event 006 state and tag reservation.

## Existing content boundary

The vanilla `RUT - Ruthenia.txt` history file remains authoritative for ordinary country creation and may be used by the new country.

The Event 006 adapter must not overwrite the vanilla history file, country definition, technology setup, or non-Event-006 releases.

Ruthenia has a vanilla character roster but no meaningful owned national focus tree.

The Event 006 origin therefore receives the full shared `independence_wave_focus_tree` rather than a bespoke tree or additive carrier.

The Event 006 checkpoint may retire implausible or generic vanilla character consumers only inside the Event 006 origin and recruit the sourced male IW-038 roster once.

Character recruitment and retirement belongs to the country event checkpoint, not a scripted effect or on-action helper.

Vanilla Czechoslovak release, OOB, player-switch, subject, focus, and AI assumptions must be reviewed against the Event 006 origin flag.

The package must not copy or replace the vanilla Czechoslovak focus tree or event files merely to add an origin guard.

Any compatibility patch must be a narrow Chaos Redux-owned gate with evidence that ordinary vanilla Ruthenia still follows its original path.

## Package identity and visible mechanics

The two package values are `independence_wave_rut_civic_concord` and `independence_wave_rut_mountain_security`.

Both values use the shared 0 to 100 package scale, are initialized from Ruthenia-specific script constants, are clamped after every change, and are displayed with their current values and the exact shared stable threshold in `independence_wave_rut_mountain_compact_category`.

The category description is the authoritative visible ledger surface and must update dynamically without a bespoke scripted GUI.

Shared administration, security, diplomacy, host, network, league, and ambition constants remain in their existing common tuning files.

The Ruthenia constants file contains only package-specific initial values, value deltas, timers, route effects, and AI scores that cannot be expressed by an existing shared constant.

The founding mission succeeds only when both values reach the stable threshold, state 73 and the capital remain controlled, the complete package remains active, and one route government has been installed.

The route set is:

- constitutional autonomy, centered on lawful self-government, municipal guarantees, and negotiated former-host relations
- agrarian compact, centered on village institutions, land settlement, and Rusyn community representation
- socialist councils, centered on rail workers, forestry labor, and elected district councils
- mountain emergency command, centered on pass security, border guards, and a temporary military administration

Every route changes both package values, shared country and host ledgers, ideas, AI strategy, diplomacy, and later ambition behavior.

## Shared-focus hooks

Five idempotent package helpers are called from existing full-framework focuses under an exact `original_tag = RUT` and active IW-038 package guard:

- `independence_wave_rut_focus_convene_provisional_assembly`
- `independence_wave_rut_focus_guarantee_mountain_communities`
- `independence_wave_rut_focus_integrate_border_guards`
- `independence_wave_rut_focus_settle_former_host_ledgers`
- `independence_wave_rut_focus_open_carpathian_corridor`

Each helper owns one completion flag and suppresses duplicate rewards when the corresponding decision completed first.

No new national focus tree is created.

## Decisions and costs

The package uses one founding mission and ten paid projects.

Projects cover depots, guards, community registries, former-host settlement, four route governments, durable sovereignty, and the regional network corridor.

Every paid project requires capital control, the active IW-038 package, no other active package project, a concrete shared material cost, and its route, host, network, or stability prerequisites.

Timed projects apply their result on completion and a bounded penalty on cancellation or timeout.

Project helpers are idempotent across decision and focus consumers.

No project is a political-power store, passive checklist, free-unit loop, or reward-dust action.

## Forces and AI

The package uses the existing p38 force mapping after it is verified against the package trigger.

The intended profile is mountain-frontier defense with integrated local guards, secured depots, terrain units, and a professional officer or border-command path selected by the mapping.

No naval or air inheritance is granted to the landlocked compact.

The package owns route-aware AI strategy layers for mountain survival, former-host restraint, settled regional participation, and emergency defense.

Decision and focus AI uses centralized score constants and must receive a mandatory probability audit before content attestation.

## Host, network, league, and ambition

The former host is the actual frozen release host rather than a hardcoded Czechoslovak scope.

The dormant-tag preflight expects state 73 and the current release host, normally Czechoslovakia in the 1936 setup, but no runtime package effect may substitute `CZE` for the frozen former-host target.

The host lane supports peaceful settlement when the former host survives and a local fallback when it does not.

Network participation opens only after founding settlement and changes package values, recognition, network standing, league cohesion, and shared reserve through exact tooltips.

Ruthenia is registered as a Carpathian or Ruthenian regional ambition participant.

Any future Ruthenian formable family remains fail-closed until its exact carrier, member, territory, consent, identity, and grouped state-puzzle contract is accepted.

IW-038 admission must not invent a formable tag or bypass the shared formable registry.

## Identity assets

All visible characters are real sourced men who were alive and role-plausible in 1936.

Grounded portraits use the accepted source-placeholder workflow: attributed source, exact head-and-shoulders crop, deterministic 156 by 210 candidate, independent identity and framing review, uncompressed BGRA DDS, and Event 006-scoped wiring.

No advisor, high-command, dossier, or small portrait icon is created.

Every new or replaced IW-038 flag is researched first and reconstructed with native ImageGen as a flat flag.

Historical variants require cited geometry, color, and symbol evidence.

No flag may be a fabric scene, painterly artwork, modern state design presented as interwar, or invented historical symbol.

## Central admission gates

1. state 73 map and host-survival checks pass
2. dormant `RUT` preflight and Event 005 collision checks pass
3. setup, final validation, and cleanup adapters exist
4. the p38 force mapping and exact runtime force receipt agree
5. the full shared focus contract and five idempotent hooks pass inspection
6. the mission and ten decisions have costs, failure handling, AI, cleanup, and final localisation
7. the sourced male roster and flat flag family are wired and documented
8. the former-host, network, league, ambition, and route systems have visible effects
9. normal allocation, SCN-008, and Join Wave exact-preflight branches agree
10. package, focus, decision, localisation, probability, asset, map, documentation, and completion audits pass

Until then, IW-038 remains a registry row with zero allocation weight.
