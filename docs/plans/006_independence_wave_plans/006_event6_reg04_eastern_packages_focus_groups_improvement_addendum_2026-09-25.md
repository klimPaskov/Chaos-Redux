No Soviet Collapse focus or origin flag is reused. There is no new tag, release admission, formable, GUI, event chain, portrait, flag, or new icon family in this plan.

## One-time companion and cleanup rules for KAR/CRI

For each of the four branch/payment pairs, award the companion only when **both** the matching focus history and existing successful paid receipt are true. If payment precedes the focus, the branch completion helper awards it; if payment follows, the existing decision `remove_effect` calls the same bounded helper after payment and receipt publication. The helper checks exact package, active Event 006 origin, controlled capital, matching choice, receipt, and absence of its durable marker, then applies only the one ledger delta and sets `independence_wave_kar_language_appeals_focus_companion_awarded`, `independence_wave_kar_ski_guard_focus_companion_awarded`, `independence_wave_cri_land_hearings_focus_companion_awarded`, or `independence_wave_cri_service_rolls_focus_companion_awarded`. The opposing branch never receives the bonus. Cancellation, timeout, insufficient resources, or merely opening a decision cannot award it.

The existing package cleanup clears local paid receipts and ledgers. Companion markers must follow completed focus history: preserve them while any retained carrier still has those completed focuses; clear them alongside a full-framework `load_focus_tree = { keep_completed = no }` reset in `independence_wave_assign_focus_framework`. If cleanup also removes the full tree, the parent must verify when its focus history is discarded before clearing markers. Repeat generations must not pair a stale focus completion with a newly paid decision for a second bonus. Preserve the current `independence_wave_inventory_the_state` adapters and their `up to` tooltip wording; add a conditional tooltip note when a ledger gain crosses the stable threshold and swaps the contested idea, without promising that transition on every completion. No event log or catalog row changes are caused by focus-only reward text, but the parent must align package docs after implementation.
