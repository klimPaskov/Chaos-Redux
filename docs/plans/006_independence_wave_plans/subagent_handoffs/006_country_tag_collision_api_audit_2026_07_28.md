## Existing patterns

- Event 006 has a clear source-of-truth chain: CSV registry → static script-constant arrays → collections and exact scripted triggers → origin lifecycle effects → package dispatch/readiness gates. Preserve that chain when adding a broad API alias.
- The new `chaosx_country_*` collection namespace is the correct shape for a reusable API. It avoids inventing an impossible long country tag such as `CHAOSX_EVENT6`; the engine still consumes three-character tags from the arrays.
- The broad API draft correctly includes all 165 direct declarations, but only the collection names are namespaced. Its Event 006 views still depend on the unprefixed `independence_wave_country_groups` category, and no gameplay consumer currently calls the new collections. Treat it as a public wrapper draft, not completed runtime integration.
- The historical `.tools/audit_hoi4_country_tags.py` is the closest complete scanning pattern because it parses country definitions, aliases, cosmetic blocks, `set_cosmetic_tag` calls, localisation, history filenames, flags, ZIP members, and non-Event 006 Chaos surfaces. Its current reserved-name edit and current all-Chaos exclusions need correction before reuse.
- The vanilla Country creation page establishes the relevant hard rules: tags are unique three-character identifiers, history filenames begin with the tag, country files are linked from `common/country_tags`, and flags/localisation use the same tag namespace. Vanilla documentation provides the `original_tag`, `tag`, `country_exists`, `has_cosmetic_tag`, `set_cosmetic_tag`, `change_tag_from`, and release constructs used by the current scripts.

## Risks and blockers

### Confirmed blockers

- The current all-Chaos snapshot has eight direct external country-definition collisions and additional extended-surface collisions listed above. The narrowed zero-collision report is not evidence for the user's all-Chaos requirement.
- `ZIN` is registered by Chaos Redux and by Workshop `3199436992`; it is not an OS-reserved name. The current audit tool's `ZIN` reservation rationale must be corrected while `AUX` remains prohibited.
- Random Events Mod `3199436992` is currently excluded by the parent audit but is one of the direct collision sources. Excluding it requires explicit user approval; the parent task's wording does not grant that exception.
- Event 014 `CBB`/`CBD`/`CBG`, Event 005 `IJX`/`IKX`/`ILX`/`IMX`/`INX`, and Event 014 `CBE` are outside the narrowed protected set but collide on installed surfaces.
- Parent remap files are uncommitted and several old history/flag/leader assets are deleted while new ones are untracked. A final scan before the parent finishes the migration will produce mixed-state evidence.

### Ordinary risks

- Country tags, history filename prefixes, flags, localisation keys, cosmetic tags, and event references are separate engine surfaces. A direct registry pass cannot prove collision-free runtime loading.
- The 17 unresolved Event 006 rows intentionally have no standalone history or localisation. They must remain gated by package readiness and must not be silently promoted during a tag rename.
- Shared Event 006 carriers `CHU` and `BIA` are intentional two-package reservations; a broad API consumer still needs package/origin/anchor/content gates and must not treat collection membership as permission to load content.
- The current public API draft has no gameplay consumers yet, and its Event 006 views still source the old unprefixed static category. This is a wiring gap, not evidence that the API is runtime-proven.
