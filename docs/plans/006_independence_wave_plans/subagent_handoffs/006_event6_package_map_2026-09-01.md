## Existing patterns

The accepted central pattern separates package adapter presence from content attestation. A package can have a loader, weight row, setup helper, focus route, decision surface, and cleanup without becoming selectable or executable.

The accepted IW-179, IW-173, IW-184, and IW-182 weight wrappers set independence_wave_execution_package_id and require has_independence_wave_runtime_package_content_attestation_for_execution_id before loading and scoring. IW-177 at package_region_effects_registry.txt:3885-3893 omits this early guard. The shared scorer later sets the execution id and rechecks attestation, so the current omission does not create a positive weight or admission bypass.

The safe bounded hardening is therefore limited to IW-177 wrapper parity. It should set the IW-177 execution id before its limit and add the existing attestation predicate beside can_plan_independence_wave_package_iw_177. It must not add FIJ to central attestation, deterministic Join, or a content-ready flag.

The package-local FIJ setup follows the accepted reuse pattern. It does not add a duplicate FIJ country or state history file, uses the vanilla FIJ flag family, applies dynamic forces after release, and removes package-owned decisions, ideas, ledgers, route flags, and temporary leadership during cleanup.
