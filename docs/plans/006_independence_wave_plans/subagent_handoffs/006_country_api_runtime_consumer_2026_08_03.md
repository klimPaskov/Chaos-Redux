# Event 006 country API runtime consumer

Date: 2026-08-03 (Europe/Kyiv).

## Scope

This bounded tranche wires an existing public `chaosx_country_*` collection into the Africa priority-member identity surface. It does not add a tag, create a country, promote a package, or alter an origin owner.

## Implementation

`africa_priority_member_uses_independence_wave_country_collection` in `common/scripted_triggers/012_africa_priority_member_triggers.txt` requires the current country scope to be present in both `collection:chaosx_country_independence_wave_owned` and `collection:chaosx_country_africa_overlap_non_overlay`. The intersection is the Event 006-owned African carrier view. The helper is ORed into the existing explicit identity predicates, so the established seven-carrier behavior remains source-readable and unchanged.

The helper is used only by `africa_priority_member_uses_independence_wave_country_tag`, which feeds the focus-surface safety predicate. Africa package registration still requires its own origin receipt, package id, promotion approval, supported carrier identity, and viable compact base. `africa_priority_member_focus_surface_is_protected` still rejects active Event 006 and Soviet Collapse origins, and meaningful existing trees are not replaced.

## Syntax basis

The collection input and `collection_contains` form follow the vanilla `script_collection_input.md` and `triggers_documentation.md` examples. `country = THIS` is the supported current-country target form for a country-scope trigger. The named collections are active views over declared arrays; dormant rows remain absent until a country scope exists.

## Validation and boundary

The current Event 006 allocator, scenario, Statehood Ledger, strict flag, and scoped Event 006/Soviet tag audits remain the authoritative checks. This tranche does not claim live Africa registration, focus rendering, save/load, or package admission. No old pasted flag-log text was used.
