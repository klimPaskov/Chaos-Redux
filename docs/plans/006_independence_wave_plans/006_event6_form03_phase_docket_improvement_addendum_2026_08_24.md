## Design problem

The accepted Event 006 decision contract says that a category never shows every possible action, only the current founding phase is expanded, obsolete emergency actions disappear, weaker actions are replaced by mature versions, and active mission caps remain meaningful.

The 2026-08-24 decision audit found 87 Event 006 category roots, 56 roots with more than six structural child actions, and no complete scenario proof that the six-visible-primary-action review threshold holds. `independence_wave_form03_low_countries_category` has 23 current child actions and is the largest such category on an admitted, complete package surface.

Structural density is not itself a defect. FORM03 already uses one-shot flags, route predicates, carrier identity, sovereign-associate status, state ownership, ratification outcomes, and three active-work locks. The missing accepted requirement is a current state-by-state receipt proving that these gates produce a readable action docket. A patch is permitted only where that receipt finds a real overlap.

## Exact mechanic contract

### Phase 0: static visibility receipt before any gameplay edit

The decision owner must evaluate all 23 current child actions under every scenario listed below and record four states for each action:

1. Not visible.
2. Visible but unavailable.
3. Visible and startable.
4. Currently active and retained for timer continuity.

The receipt must distinguish actor type. AFX or AGX carrier scenarios cannot be combined with BEL, HOL, or LUX sovereign-associate scenarios because those scopes expose different action families.

The implementation threshold is no more than six simultaneously startable primary actions in a valid actor scenario. An already active timed action remains visible even when its underlying phase advances. A mandatory pending member or delegation response also remains visible until answered or invalidated. These continuity rows must be reported separately and may not be hidden merely to improve the count.
