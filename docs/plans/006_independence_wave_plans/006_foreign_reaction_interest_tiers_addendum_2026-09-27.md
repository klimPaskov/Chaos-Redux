# Event 006 foreign reaction interest tiers — proposed addendum (2026-09-27)

**Disposition: unresolved proposal.** The accepted seven-part Event 006 specification authorizes foreign reactions by local neighbor, regional power, great power, and existing Independence Wave country, with interest from the factors in Part 2 and high-interest targeted events only. This document proposes the missing selection and response contract; its scores, cutoffs, caps, event identifiers, and petition terms have no recorded acceptance. The parent must settle the material choices in the decision table before gameplay implementation and then record the acceptance basis. Event 006 remains **HOLD / PARTIAL**.

## The playable gap

The committed public report `chaosx.nr6.2` dispatches opening events `.41`/`.42`, then the former-host response queue dispatches `.60`–`.63`; the remnant options leave `independence_wave_host_response_outside_guarantee_opportunity_open` on the host. Current `independence_wave_send_diplomatic_mission` and `independence_wave_seek_regional_guarantee` let a released state initiate diplomacy, but no general post-wave foreign actor judges the new map, and no consumer turns the remnant flag into a petition or guarantee offer. The current audit records the same gap (Part 2 lines 623–644, [2026-09-27 completion refresh](subagent_handoffs/006_event6_completion_audit_refresh_2026-09-27.md)). A foreign reaction should let a neighboring government choose its border posture, a regional power decide whether to mediate or compete, a great power price access and precedent, and an earlier wave state choose solidarity or rivalry. Those choices must alter the same bilateral, recognition, patron, and network facts that later play already reads.

The proposal adds one bounded post-report reaction pass and one remnant petition path. It does not add a new focus route, country, formable, super-event, map transfer, or scripted GUI. Ordinary decisions and the existing Statehood Ledger remain the management layer; the foreign events are the one-time political response to a committed wave.

## Candidate provenance and interest

Construct candidate *pairs* `(foreign actor, released country)` from the current report's committed Event 006 country and generation receipts, never from a free-standing all-country search. The accepted Part 1 origin rule excludes Event 005, Join conversions, failed plans, and unrelated pre-existing countries from the released-country cohort. The actor must exist, be sovereign or have a separately designed diplomatic capacity, be distinct from the released country and its former host, and still have the recorded relationship at dispatch. A former host uses `.60`–`.63` and bilateral host decisions even if it is also a neighbor, major, patron, or earlier wave country. This precedence prevents one government receiving a host option and an incompatible foreign option about its own secession.

Candidate sources, unioned once per actor and target:

| Source | Concrete receipt or bounded lookup | Eligible interest basis |
| --- | --- | --- |
| Local contact | Countries neighboring the released country's owned states, filtered at the state/country boundary after commit; inspect province/state adjacency for any disputed edge | Shared frontier, active claims, immediate security, a documented trade corridor or minority relationship |
| Package contact | Exact actor references in the admitted package's researched patron-interest, claim, access, or regional profile, where such references have source and live-country validity | Strategic access, bases, resources, old legal claim, regional balance, colonial precedent; a package lacking this profile cannot silently acquire a guessed sponsor |
| Existing bilateral relationship | The released country's aligned patron-country entries, current guarantee/faction relationship, or a prior diplomacy target with an intact generation receipt | Already committed support, rivalry, recognition, trade, or defense obligations |
| Independence Network | The aligned global Event 006 member-country and generation arrays, including later League members only when their membership/charter is current | Solidarity, rivalry, rescue duty, common ambition, and League goal |
| Former-host contact | A living host's current guarantor, faction leader, or explicit diplomatic partner where an exact relationship can be read without enumerating every country | Host containment, mediation, or remnant protection; the host itself is excluded as a foreign actor |

The parent should verify the exact state-adjacency and relationship iterators against installed documentation and the current engine, then use only the bounded paths that actually exist. A static actor registry is an acceptable way to supply package contacts if it is authored per admitted package and states its provenance; an all-major or all-country iteration in a daily/weekly hook is not the proposal. Package-authored contacts must be checked against living tags at dispatch, so historical tag assumptions do not become universal reactions. Unknown minority, trade, colonial, or ideological relationships contribute nothing until an accepted package profile or live script fact supports them. Part 5's regional overlays suggest *types* of interest, not automatic country-specific attitudes. No historical country-specific reaction is asserted here.

Use the accepted regional overlays as research prompts, never as an unsourced diplomatic lookup table. Northern and Western Europe can foreground debt, naval assets, ports, and legal continuity; Mediterranean and Iberian packages can foreground port security and domestic ideological blocs; Balkans and Danube packages can foreground overlapping claims, mixed populations, rail and river control; eastern European packages can foreground army-district division, minority treaties, and former-imperial legal claims; Volga and Far Eastern packages can foreground railway reach and long supply routes; Caucasus and Mesopotamian packages can foreground mandate, oil, mountain, and corridor stakes. These are Part 5 design categories, not assertions that a named 1936 foreign government held a particular claim or supported a particular local movement. The package owner must provide the source for any named faction, treaty, symbol, or border memory before that detail enters an event.

**Recommended score model for review, not an accepted tuning table:** calculate a nonnegative per-pair `interest` from four independently inspectable families: direct stake (border, active claim, live guarantee or threat); recorded relationship (patron channel, diplomatic contact, host tie, Network/League duty); strategic fit (access, reachable supply route, resources/base already in the package profile, documented regional balance); and political fit (current ideology, recognition posture, charter goal, precedent profile). Apply overextension and collision penalties for active war, impossible access, hostile patron commitment, or a settlement already completed. Keep each family's contribution and reason code in a temporary score record; centralize accepted values in Event 006 script constants. Do not use an undifferentiated `is_major` bonus as proof of interest. A great power with no registered contact or route does not qualify solely because it is a major.

For a concrete initial tuning *proposal* to test, assign direct stake **4**, recorded relationship **3**, strategic fit **2**, political fit **1**, and overextension or conflict **−3**; count each fact at most once in its strongest family and cap each family so several flags for the same relationship cannot inflate it. Recommend detailed events at **score 6 or above**, one ordinary detailed event per actor per wave, selected from that actor's eligible released-country pairs. Ties prefer a live defense obligation, then a common border, then the committed release order and stable country ID. A lower score receives one wave summary or the existing opt-in decisions. These numbers are candidate anchors only, not a probability, approval, or implementable balance conclusion. The auditor must evaluate the actual accepted weights and complete candidate manifest before any numerical balance claim.

Tier is a presentation/choice profile after eligibility, not four disjoint candidate scans. An existing active Event 006 country uses the solidarity/rivalry profile; otherwise a major with recorded strategic contact uses the great-power profile, a regional stakeholder with a registered balance/access role uses the regional profile, and a direct neighbor uses the local profile. If one actor meets several descriptions, the single event presents the highest-priority obligation and may mention the secondary reason. A major that is also a neighbor still pays attention to its border. A role does not grant a reward by itself.

## Reaction sequence and ownership

1. The report option freezes the committed Event 006 country list and generation IDs already used by the opening queue. The foreign system reads that cohort only after all opening responses and distinct host responses have resolved or failed closed; it does not rebuild a candidate pool from a later map state or a new wave.
2. The current host queue's final callback hands the plan ID and report/reset barrier to a foreign queue builder. If no foreign actor qualifies, the builder closes immediately and releases the barrier. The parent must review the existing barrier code before changing ownership; the current host finalizer clears it, so an unconditional foreign event scheduled *after* that clear would allow an overlapping plan.
3. Build a de-duplicated actor/target table from the sources above, validate country and generation IDs, record reason families and score, then select the highest eligible target for each actor. Do not dispatch to the former host as a foreign actor. Reserve an actor-wave receipt before scheduling any event; no second source path can dispatch the same actor/target or actor-wave response.
4. Schedule the foreign router after the host final callback, with a short deterministic separation proposed as one day. Each human actor receives the tier event; AI resolves the same actions through a deliberate policy function unless the parent accepts option weights after an auditor pass. Invalid actor, replaced generation, concluded war, incompatible route, or already settled bilateral outcome consumes its receipt without an effect.
5. Final option or timeout writes one outcome receipt and the target-specific consequences through shared helpers, decrements the queue once, clears temporary actor/target pointers, and releases the report/reset barrier only after every scheduled response is resolved or invalidated. A 13-day human timeout matching the host family is a proposed pacing default; exact timeout remains open to parent review.
6. Repeat waves create a new wave key. Durable diplomatic relationships persist where gameplay intends them to; pending offers, event targets, queue arrays, dispatch markers, and unaccepted petition windows belong to their original wave and must not leak into the new one. A dead or voluntarily reunited released country invalidates its pairs. The same actor may react again to a later distinct wave, but cannot farm the same bilateral recognition/guarantee result without a genuine relationship change.

Working event reservations, subject to the parent's global ID collision check: hidden `chaosx.nr6.64` foreign router; `.65` local neighbor, `.66` regional power, `.67` great power, `.68` existing-wave actor; `.69` remnant petition recipient and `.70` host reply or failure notice if a second-stage event proves necessary. The owner may consolidate `.69`/`.70` into a targeted decision when that is clearer, but must preserve the same bilateral transaction and human response. Do not treat reserved numbers as accepted content.

## Choice and consequence contract

Each choice names the target, current reason for interest, immediate cost or exposure, expected relationship effect, and any condition that could prevent payment. No route may create territory, a war goal, a guarantee, or patron influence from a private text choice without the corresponding script transaction and visible consequence.

For a concrete cost baseline, use the existing **light diplomatic** affordability/payment pair (`can_pay_independence_wave_diplomatic_light_cost` / `independence_wave_decision_pay_diplomatic_light`) for liaison or ordinary recognition, and the existing **standard diplomatic** pair for formal mediation, guarantee, and a remnant petition. Those pairs already consume command attention and either convoys or trains according to the actor's stockpile (`common/scripted_effects/006_independence_wave_decision_effects.txt:153-219`; `common/scripted_triggers/006_independence_wave_decision_triggers.txt:343-360`). The parent must confirm they are valid in a non-Event-006 foreign actor and host scope before reusing them, and must display the same route-specific payment in event/decision tooltips. A guarantee also accepts a real defensive obligation; material aid must debit the specific equipment, convoy, factory, or access channel already priced in the patron decision family before recording patron influence. If an actor cannot pay or reach the target, the action is unavailable and the noncommittal stance remains. This is a proposed reuse of current tuning, not approval of a new numeric cost.

| Profile | Distinct player stances | Consequence and failure boundary |
| --- | --- | --- |
| Local neighbor | Recognize or open liaison; sponsor border talks; prepare containment or support the host; decline involvement | Recognition moves the target's bilateral status and recognition value once. Mediation changes the live host/border ledger only when both sides remain valid. Containment increases security concern and may improve host relations but does not declare war. A claim collision or active war can close the friendly options. |
| Regional power | Guarantee or mediate; invest in a reachable corridor; balance a rival patron; withhold support | A guarantee requires capacity, access, and a valid target and creates the actual guarantee relationship. Investment pays a transport/economic burden and, if sponsor-like, books a patron channel. Rival balancing changes access/influence rather than giving free aid. An unreachable corridor blocks the investment. |
| Great power | Extend recognition and limited aid; negotiate a channel-specific patron offer; organize containment or support a host; abstain | Recognition is not a free base or automatic client route. Arms, credit, trade, intelligence, and base/transit offers use the matching existing patron ledgers and released-country consent path. Containment is diplomatic/strategic first; armed intervention requires a later, separately gated decision with war legality, route, supply, commitment, and escalation cost. |
| Existing Event 006 country | Recognize and share institutions; propose Network/League aid or rescue; seek arbitration over rivalry; stand aside | Solidarity raises standing and the target's recognition only when support is actually given. A League rescue needs a current charter duty and capacity; refusal can lower standing. Rivalry uses claims and settlement facts, not an invented hostility flag. A captured client cannot exercise an independence-only charter path. |

Foreign-initiated recognition must not stack with `independence_wave_send_diplomatic_mission` (`common/decisions/006_independence_wave_decisions.txt:601`) or the Network's coordinated recognition (`:879`). Foreign guarantees must share a single bilateral receipt and real relationship with `independence_wave_seek_regional_guarantee` (`:734`), including its patron-recognition channel on an unsuccessful ask. A foreign offer arriving while a paid targeted decision is active should settle that same target on completion or defer the offer; it must not consume the player's cost and then grant the same reward twice. A formal guarantee already present makes a new guarantee stance unavailable. Patron offers write to the per-sponsor aligned ledger in `common/scripted_effects/006_independence_wave_effects.txt:1664-1701` and allow the released country to accept, limit, counter, or refuse before dependency rises. League solidarity uses current member/charter receipts and standing helpers, not a parallel league score.

**Host remnant petition.** The `.62` option flag is an opportunity, not a guarantee. Proposed host action: a visible, time-limited targeted petition decision available only to the generation-matched living remnant, legal-continuity or regional-identity route, and a reachable high-interest foreign actor from the same bounded candidate registry. The host spends diplomatic capacity and accepts a visible concession or defense obligation appropriate to its route; no automatic free protection follows the click. One chosen recipient receives a guarantee/mediation/refusal choice, with explicit diplomatic and military commitment cost if it guarantees. An AI host petitions only when its current war/threat state makes protection useful and a viable recipient exists. If a human host takes no action, the opportunity expires with no foreign guarantee. If the recipient refuses, is at war with the host, dies, loses access, or already guarantees it, resolve the petition once, clear the pending receipt, and leave a readable outcome; allow a second attempt only if a distinct accepted cooldown and cost are later chosen. Remnant guarantees protect the *host*, not a released country, and must never be booked as recognition of the released country.

## AI, timing, and evidence scenarios

The preferred baseline is deterministic actor selection and deterministic AI policy from current obligation, war, access, capacity, ideology/charter, and bilateral state. AI may recognize or mediate at modest interest; guarantees need credible military capacity and access; patron offers require a viable channel and tolerable dependency; intervention requires a separate explicit crisis gate. A regional AI already guaranteeing the target does not offer another guarantee. An earlier-wave AI under a defensive charter values rescue, while a captured client or war-exhausted member avoids a costly pledge. None of these statements supplies accepted numerical weights.

If the parent implements score weights, `ai_chance`, decision `ai_will_do`, MTTH, a random target, or a custom weighted pair pool, route a **read-only baseline** through `chaosx_ai_probability_auditor`, beginning with `hoi4.probability_inspect` on the exact mod-relative source or declared pool manifest. Use `hoi4.probability_evaluate` for named cases, `hoi4.probability_sweep` across proposed cutoffs and ties, `hoi4.probability_sequence` only for a complete pool and declared cadence, and `hoi4.probability_render` for a reviewer-readable rank/threshold view. After an owner-applied patch, require `hoi4.probability_compare` on the same saved scenarios and valid before/after sources. Decision willingness scores must not be reported as action probabilities; unknown factors and incomplete actor pools remain unresolved.

## Presentation, log, and cleanup

Use four title/description directions with dynamic actor, released country, host, and reason: frontier anxiety for neighbors, balance and transit for regional powers, commitments and precedent for great powers, and solidarity/rivalry for earlier wave states. Remnant text should make the host's legal or regional identity visible and distinguish an opportunity to petition from an obtained guarantee. Write options as stances with clear effects and costs; do not invent a real leader, diplomatic quotation, minority claim, or historical bilateral motive. The Part 5 regional overlays and verified package profiles may guide tone after their specific source is checked. The existing `GFX_report_event_006_asset_001_wave_summary` and `GFX_report_event_006_asset_002_host_crisis` are candidates for the ordinary and remnant windows, respectively, subject to parent review of their actual 210×176 consumers and content. If neither matches, record a new 210×176 report-image requirement for explicit acceptance and then route production through `chaos-redux-event-assets`; no asset is authorized by this proposal alone. No animated art or new window is justified by this one-time reaction layer.

The public wave report is logged once as Event 006. Publish a distinct foreign-reaction history item only for a consequential **public** recognition, guarantee, formal mediation, intervention commitment, or League rescue; store wave ID, dated actor, target, tier, action, and outcome so Event Log history and Event Details can name both sides. Private patron bargaining, refusal, or failed offer appears to the involved countries but does not create global history spam. The Event 006 actor mapping should identify the released country for an independence consequence and the foreign actor as counterpart; a remnant guarantee instead names the surviving host as beneficiary. If the current shared log schema supports only one actor, the parent must define a supported counterpart field or keep the counterpart in the localised detail text; do not overwrite the primary actor pointer. Summary news groups low-interest attention by wave/region and describes only settled public outcomes, not rejected private offers. Event Details should show the current consequences and later resolution, while the existing Statehood Ledger continues to display recognition, patron dependency, and Network/League values from shared helpers. The parent owns these shared UI/log changes and their MCP visual review.

Clear pending event flags, generation-specific actor/target arrays, stored event targets, temporary score/reason records, dispatch and outcome receipts, and host petition opportunity on resolution, expiry, invalidation, voluntary reunion, annexation, or incompatible next wave. Keep durable bilateral recognition and actual guarantees until ordinary relationship rules remove them. Reset must never erase a completed relationship merely to make the next wave eligible again. No global persistent target should be introduced unless the chosen queue cannot carry an exact country reference; any global target must have a named cleanup owner.
