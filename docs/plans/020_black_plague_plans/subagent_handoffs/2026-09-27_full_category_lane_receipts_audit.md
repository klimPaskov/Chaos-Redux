# Event 020 state-response receipt and lane audit

**Disposition: unresolved lane design, with one owner-applied source fix reviewed.** The six-lane priority table in [the interaction addendum](../2026-09-27_shared_response_interaction_and_cost_budget_addendum.md) is still a proposal. This handoff records current source receipts, lifecycle, and starvation limits for the 26 shared ordinary state decisions and 11 dedicated state-action families. I made no gameplay, localization, specification, asset, or workbook changes.

## Scope and count

The source defines 26 shared ordinary state decision IDs in common\decisions\020_black_plague_shared_response_decisions.txt:101-646 and 12 raw dedicated decision IDs in common\decisions\020_black_plague_response_decisions.txt:74-676. The ordinary and accelerated Emergency Hospitals IDs are mutually exclusive by countermeasure progress and share one active project and outcome helper, so the requested count is 37 action families across both files, or 38 raw decision IDs.

The separate Royal Node strike, Crown Strike and Seal Royal Burrows launchers are outside those 37 families. Crown and Seal activate two native missions. The Evolution V Hold and Refuge starts and missions are also outside the 37 selected-state families. They still occupy the same category and must be included in any full-category row count.

## Findings by severity

**Critical, fixed by the parent in the current shared source.** Before the parent patch, all 26 shared ordinary timers set black_plague_shared_action_active in complete_effect, then their cancel_trigger evaluated NOT black_plague_shared_state_target_is_usable. That start-only helper itself required the active flag to be absent, so the source made the running action satisfy its own cancel predicate. Offline Decision modding says a true cancel_trigger ends the timer without running remove_effect and runs cancel_effect instead. Cancellation clears the active record, sets a 30-day shared cooldown, and does not refund the start payment. This was source-derived behavior, not live-tested behavior.

The parent changed all 26 ordinary cancel sites at common\decisions\020_black_plague_shared_response_decisions.txt:117-643 to use black_plague_shared_active_state_action_is_invalid. The parent also fixed the Royal Node timer at line 664 with a separate rat-held continuation helper. The ordinary helper at common\scripted_triggers\020_black_plague_shared_response_triggers.txt:17-37 checks underlying target invalidity, the existing 14-day failed-mobilization flag, missing active/action/owner receipts, owner mismatch, and loss of direct-response eligibility. It no longer mistakes a running action for an invalid target. It checks that the action variable exists but does not compare its value with each ordinary decision’s action constant. The per-state active gate prevents a second shared action from starting on a valid state, and I found no normal source path that can swap that value while the current action remains valid. The finish helper also requires the active flag and matching owner before applying an outcome. The Royal Node helper at lines 127-140 additionally checks that the state remains tracked, rat controlled by a current rat-country controller, the Royal Node, accessible, on a military route, running the exact strike_royal_node action, and owned by the active action’s country.

The same review found two owner-side cleanup changes in common\scripted_effects\020_black_plague_shared_response_effects.txt:473-491. Cancellation now clears a rejected start’s country pending token even when no state active record was created, and successful finish clears the action scale. These were parent changes, not mine.

**High, unresolved recovery starvation.** The disease pulse runs every seven days and phase transition checks run after that pulse. The incubation target can be 14 to 42 days. A recovering state can become Cured once recovery has lasted 84 days and load and exposure are below their cure ceilings. Three shared recovery outcomes take longer than that earliest cure window: Restore Local Administration takes 90 days, Rebuild Hospitals and Transport takes 120 days, and Support Surviving Households takes 120 days. Their effects run at timer expiry. A shared action is canceled when the state becomes Cured, so these outcomes can be lost if cure is reached first.

The dedicated action cancel predicate also treats Cured as invalid at common\scripted_triggers\020_black_plague_response_triggers.txt:665-679. Canceling any dedicated project writes black_plague_response_failed_mobilization for 14 days at common\scripted_effects\020_black_plague_response_action_effects.txt:270-324. That state flag blocks both decision families through black_plague_response_state_can_accept_actions at common\scripted_triggers\020_black_plague_response_triggers.txt:72-79 and black_plague_shared_state_target_is_usable at common\scripted_triggers\020_black_plague_shared_response_triggers.txt:9-13. The reset for a fresh episode clears episode receipts but does not clear these timed cooldowns. This can suppress the next response after rapid re-exposure.

Another concrete possible starvation appears in severe infection. Emergency Hospitals takes 56 days, or 35 on the accelerated variant. Distribute Treatment Reserves takes 7 days and is available when mortality is high and treatment coverage is low. Both can qualify in the same severe-state fixture. They currently occupy separate dedicated civil and treatment lanes and can run concurrently, but the proposed single Clinical Access lane would combine them. If the hospital variant remains first in that lane, urgent treatment can be hidden for five to eight disease pulses. The Vector and Sanitation lane also combines 56-day Sewer Clearance with 35-day Burial and Sanitation. Its priority order is not yet exact enough to prove that high-mortality burial work remains reachable before phase change. These are risk scenarios supported by current triggers and durations. They are not claims that every campaign reaches the stated values.

**High, current source exceeds the proposed list ceiling.** The addendum’s source-predicate census reports 8 to 15 concurrent Event020 state starts across the two files under its named fixtures, with 4 in the bounded Cured case. Those are source-predicate upper scenarios, not runtime save observations. Its local shared-only matrix is therefore not a sufficient six-row cap. The same addendum says separately active biological and weaponization systems can add more rows, so a universal six-row category guarantee is still unproven.

**Medium, current result flags do not all make safe per-state lane receipts.** Port and Hub Inspections both qualify on the same eligible coastal hub today. Air Reconnaissance and Armored Clearance both qualify on former rat ground today. The proposed Port-then-Hub and Air-then-Armored sequences need new stage predicates even though the completion flags already exist. Most shared result flags do not currently block repeating the decision after cooldown, so treating them as one-time “completed” markers changes repeatability. Stronger Prevention Law is country scoped and persists through cure. Sentinel Surveillance is country scoped and timed. Remove Emergency Restrictions has no unique result receipt. Its effect only clears existing restrictions and adds Stability, so a six-lane sequence cannot advance from a completion flag that is never written. Foreign Medical Mission checks a country flag at common\scripted_triggers\020_black_plague_shared_response_triggers.txt:261-266, but its shared completion helper writes only a state flag. I found no country-scope writer for that flag in common or events.

## Lane contract and starvation recommendations

The proposed lane ownership is useful as a display map, but it is not a complete priority contract yet. Current triggers do not enforce Port Inspections before Transport Hub Inspections or Air Reconnaissance before Armored Clearance. Both members in each pair can qualify together. If accepted, the stage check should use the target state receipt and reset at the same cure or episode boundary. The parent should not use the country-wide prevention-law flag or the expiring country surveillance flag as a selected-state receipt.

Contained must retain Maintain Containment and Controlled Reopening as two visible choices when both are valid. They are a real tradeoff, and one action’s result flag should not make the other disappear. Remove Emergency Restrictions needs an explicit repeatability rule before it can be the Civic Recovery lane’s top item. It has no completion flag.

On severe states, the priority must expose Treatment Reserves ahead of longer hospital work when mortality is high and treatment coverage is below threshold. The vector lane should expose Burial and Sanitation when mortality is high rather than let a longer Sewer Clearance project suppress it. In Recovery, the 90- and 120-day reconstruction decisions need a design response to the 84-day earliest cure hold. Reprioritizing alone cannot guarantee completion if a decision’s phase eligibility expires or its cancellation predicate fires on cure. Either the accepted priority contract must preserve the response before that deadline, or the owner must revisit its timing or post-recovery eligibility in the design. Those changes are outside this read-only audit.

The shared ordinary AI path targets eligible states independently of the human board selector. The target trigger uses black_plague_response_state_is_selected_or_ai_target, and the shared custom affordability helper allows is_ai = yes. Keep the six-visible-row presentation rule separate from AI target selection. AI weights do not tell the player whether the lane queue will preserve an essential response.

## Recommended implementation contract after design acceptance

In common\decisions\020_black_plague_shared_response_decisions.txt and common\decisions\020_black_plague_response_decisions.txt, implement the accepted six-slot cap at the shared state action visibility layer. Keep active timed decisions and the Hold, Refuge, Crown, and Seal mission paths in their own lifecycle gates. Do not apply a player-selected-state limit to AI state targeting.

In common\scripted_triggers\020_black_plague_shared_response_triggers.txt, explicitly stage black_plague_shared_port_inspections before black_plague_shared_inspect_transport_hubs and black_plague_shared_air_reconnaissance_sweep before black_plague_shared_armored_clearance, using the selected target’s completion receipts. Both pairs are simultaneous today. In common\scripted_effects\020_black_plague_shared_response_effects.txt, keep those receipts through phase changes and clear them at the accepted episode boundary.

Resolve black_plague_shared_remove_emergency_restrictions in the shared trigger/effect files by deciding whether it is repeatable or one-time per cured episode. If one-time, add a state-scoped receipt and clear it at cure or the next episode. Keep black_plague_shared_prevention_law_active as a country receipt only if the effect is meant to block the law for every state in that country. For black_plague_shared_foreign_medical_mission_active, align the country-scoped availability check with the actual state-scoped completion receipt or remove the mismatched gate.

Before accepting one action per lane, settle exact priorities in Clinical Access and Vector and Sanitation. Treatment Reserves must remain available during high mortality even when Emergency Hospitals is active. Burial and Sanitation should remain available when the phase is about to advance. Recovery outcomes whose 90- to 120-day timers exceed the 84-day earliest cure hold need an explicit accepted timing or eligibility solution. Any such change belongs in the named Event020 addendum or accepted spec, not in this receipt audit.

## Other required audit notes

**Category lifecycle.** The shared selected-state decisions live in chaosx_disease_containment_category, which attaches disease_containment_header_scripted_gui. The state target control is a separate map-only decision. Prepared, infected, contained, recovery, cured, and rat-history actions use separate phase and route triggers. On cure, the shared state receipts and cooldown clear in the response pulse. On a fresh Threatened episode, dedicated episode receipts reset. Target loss, cure, rat takeover, and world end cancel or clear active dedicated projects. No user-supplied save or runtime state was used.

**Cognitive load and visible values.** The addendum census exceeds six starts in every stressed phase before the proposed integrated cap. The lane table still lacks exact within-lane choices for urgent clinical and vector actions, and the mix of temporary active effects, permanent results, and missing results makes a generic “unfinished action” rule unsafe. The GUI inspection and render routes for countrydecisionview and disease_containment_board_window each timed out after 180 seconds. I have no image evidence for title, spacing, clipping, row costs, click regions, selected-state values, or whether each displayed value’s meaning and consequence are clear. The header GUI source is linked, but source review is not a visual acceptance result.

**Mission quality.** None of the 37 state-action families is a native mission. They are state-targeted timed decisions with days_remove, start payment, a completion remove_effect, and invalid-target cancellation. Success applies the listed action result. Cancellation clears active lanes and adds the 14-day failure cooldown without a refund. There is no separate partial-success timer result except the Clean City Rats, Sewer Clearance, and Demolition outcome branches. Crown Strike and Seal Royal Burrows are separate native mission families with their own target markers, owner records, 180-day timers, success, timeout, and cancellation. Their owners and mission lifecycles remain outside this audit’s 37-family lane queue.

**Costs and requirements.** The 26 shared ordinary decisions pay scaled support equipment, trucks, and fuel while committing factories and Response Capacity, for five true cost types. Port Inspections, Relief Corridor, and Evacuate Threatened Perimeter add trains. Restrict Troop Routes and Seal All Transport add Command Power. Those rows have six types and all exceed the four-type budget. The inspected shared inline cost rows use support, motorized, fuel, factory, and Response Capacity icons. Train and Command Power rows add their matching resource tokens. Current shared rows show five or six cost values before duration, which exceeds the three-value inline display guidance. The 11 dedicated families currently use two immediate payment types plus a factory and Response Capacity commitment, for four true cost types. Their custom cost rows display three icon-backed values. The hover uses the Response Capacity texticon and separates on-hand manpower, trucks, trains, convoys, and other requirements from payment. Current dedicated rows use the corresponding support-equipment, fuel, train, infantry-equipment, stability, Command Power, and Medical Reserve icons. Both files also declare native factory modifiers while the custom cost rows show factory icons. Without a production render, I cannot verify whether the factory commitment appears twice in the native row. The shared payment redesign remains unresolved in the named addendum. The receipt contract must not silently change accepted payments.

**Localisation and tooltip gaps.** The named decisions have title/description and custom-cost localisation keys. Their shared cost hovers now explain payment timing and commitments. They do not provide a per-lane stage receipt or explain why a lower-priority action is hidden because no such lane logic exists yet. The foreign-mission country flag scope mismatch and Remove Emergency Restrictions missing result need an owner decision before their future tooltips can describe completion accurately.

**Exploit and cleanup risks.** Remove Emergency Restrictions can repeat after cooldown without a unique result receipt while adding its completion Stability effect again. Several shared actions can also repeat after cooldown because their result flag does not block the start trigger. Port and Hub, Air Recon and Armored Clearance are not currently staged. The parent’s new invalidation helper preserves the 14-day failed-mobilization cross-lane lockout, which was already present because the old start-only helper also rejected that state flag. That cross-lane behavior is retained, not newly introduced by the patch.
