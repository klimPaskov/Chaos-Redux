# Weaponized Black Plague native raid migration

Disposition: accepted for implementation under the user's explicit 2026-09-27 direction to make the one-payload Black Plague attack a native raid and remove its unnecessary attack fuel cost. The user-approved CBRN overhaul already requires two CBRN raid categories, the same native path for human and AI operations, and no decision-based attacks. The Event 020 biowarfare specification says a completed payload uses biological raids rather than a separate event button (`docs/specs/020_black_plague_specs/specs/020_black_plague_spec_part_3_cure_spread_and_biowarfare.md:408–434`).

The existing `black_plague_weaponization_deliver_payload` targeted decision is a second attack path and must be retired from `common/decisions/020_black_plague_weaponization_decisions.txt`. Its 14-day attack timer, one `plague_bomb_1`, 60 support equipment, and 35 Command Power move to one new native raid type under the existing `biological_raids` category. The raid uses native air-base origin, assigned tactical or strategic bomber requirements, exact state targeting, native `essential_equipment` for both payload and support equipment, and native `command_power`. It has no attack-specific fuel debit, fuel gate, or one-factory timer. The programme still pays for payload production: its four posture/approach decisions each commit one factory, the stockpile-expansion decision commits two factories and consumes production resources, and project completion grants the first real payload. There is no separate human-facing staging or preparation decision.

The raid's own definition identifies the weapon and supplies preparation and outcome chances. Human and AI use the same native raid type and outcome callback. Native `success_levels` starts in `RAID_INSTANCE` scope; successful and critical results use hidden actor events `chaosx_nr20_weaponization.9` and `.10` to carry the exact actor, victim, and target state as event targets, revalidate current target and authorization, and call the existing Event 020 weaponized exposure runtime once only on a qualifying release. Failure and limited success retain their native loss, experience, and history effects without an unconfirmed disease release. The accepted release then records the existing outbreak history, achievement, public Condemnation, and report; failed or canceled raids cannot fabricate an exposure or farm the award. Native equipment reservation and Command Power allocation are never debited again in scripted effects, and no unverified cancellation refund is promised. Final-gate failure uses neutral outcome text. Existing programme stockpile expansion, accident monitoring, defensive conversion, and payload-destruction actions remain available.

The general `plague_strike` raid in `common/raids/biological_raids.txt` reserves 100 payload units and resolves an ordinary Plague agent episode. Event 020's project and expansion produce one `plague_bomb_1` and use a distinct Black Plague exposure state machine, so they need a dedicated raid type within the same Biological Raids category rather than an unusable 100-unit substitution. The installed `common/raids/_documentation.md:167–180` supports multiple native essential-equipment entries and says they are collected after raid creation; vanilla `paratrooper_raids_custom.txt:52–67` and the mod's `plague_strike` provide field and outcome precedents. The raid source must keep exactly the two CBRN category IDs after migration.
