## Existing patterns

Chaos Redux's closest pattern is `deaths_state_map_mode` and `contaminated_states_map_mode` in `common/map_modes/chaosx_state_map_modes.txt`. They use a state top layer for borders/status and a bottom layer for fill, wrap state evaluation in `FROM`, centralize fixed-point colors in `state_map_modes_constants`, and expose viewer-gated detailed tooltips through scripted localisation. The new famine mode follows the same stage/border pattern. The migration mode follows the same state-layer pattern but currently duplicates the same role color on both layers; using the top layer for route/status border and the bottom layer for primary role fill would communicate more dimensions within the engine's two-layer limit.

The vanilla mapmode documentation at `C:/Program Files (x86)/Steam/steamapps/common/Hearts of Iron IV/common/map_modes/documentation.md` confirms that scripted mapmodes have only `top` and `bottom` layers, state/country/state-controller types, flat RGB-alpha colors, optional thickness/highlight, text labels, and `update_daily`. It explicitly does not provide a scripted route-arrow layer. The existing mapmode docs also record that state-clipped textures, patterns, particles, and active selector state are unsupported. This means route/cohort movement must be represented by state endpoint colors, border status, and scoped tooltip text, not by drawing paths.

The two-mode privacy pattern is sound: public viewers receive qualitative stage/role text, while the state owner or controller receives exact ledgers. Keep this gate, but distinguish state reception load from owner-country capacity/load and ensure all authorized variables have safe defaults or an active-state guard.

A comprehensive migration tooltip cannot truthfully show a persistent cohort destination/status from the current mapmode-readable state alone.
