## Findings resolved during independent review

### Normal retry priority and whole-request coverage

The initial retained-row retry called the preparable foreign selector directly, skipping the required normal internal-first path.
The added normal retry initially checked headroom only after a normal target had already been drawn, leaving result one when that target could not accept the whole row.
That could stall a retained row and could not establish complete internal coverage when one inadequate internal neighbor was mixed with an adequate one.

Final `migration_spontaneous_reception_try_normal_destination` sets the exact current whole amount before the general normal selector.
`migration_destination_selection_reception_available` tests current load plus that amount against current valid capacity before both normal passes, with absent load zero and malformed negative load rejected.
Every undersized state therefore contributes no weight, while every adequate internal candidate remains in the complete first pool.
Only zero normal result reaches prospective selection, and a later failed retained-row attempt also clears result rather than stranding the branch.
The optional amount survives both normal pools and is consumed after the general selector finishes.
Fresh and retained callers both supply it.

### Protected-floor output lifetime

The physical transaction read a protected-population temporary computed by a nested scripted trigger without caller-owned storage.
The Boolean gate still checked the floor, but source preservation alone did not guarantee the transaction could read the computed value after return.
Final `humanitarian_corridor_execute_evacuation` predeclares that unprefixed output before resolver/headroom predicates run and passes it to the physical owner.
The source checks follow offline Data structures line 440 and the accepted helper-output contract, not a claim that every undeclared engine output deterministically disappears.

### Shared pulse after terminal cleanup

Pulse entry clears the existing shared country marker and due date.
The previous matching terminal cleanup could remove one direction without rearming the other, despite retaining its independent identity.
Final `humanitarian_corridor_rearm_surviving_country_identity` validates an exact surviving incoming or outgoing identity and uses only the existing pulse interval.
It is called from both generation/origin-matching terminal sides and stale-local cleanup.
It does not grant admission or mutate another origin's contract.
No surviving identity clears scheduling, while either surviving exact identity preserves scheduling.

### Private pointer after authoritative row removal

The parent identified that core terminal row removal did not clear the new private spontaneous pointer.
Final pruning requires positively aligned IDs, a positive saved ID absent from native array membership, explicit reconciled local live count zero, no ambiguous/misaligned marker, and no matching active contract.
It clears only the private pointer.
It does not delete or resize a row, clear pressure or create a replacement cohort.
Present/malformed/ambiguous rows remain with the existing reconciliation owner.

Independent follow-up found that a present nonpositive private ID could invoke the core resolver's implicit-current-row fallback.
Final pointer-priority entry checks positivity before calling that resolver, and the present-invalid branch does not fall through to adoption or new-row creation.
The resolver's positive request is not cleared at return, so the explicit current-ID comparison remains legitimate.

### Preserved relief and source hygiene

The malformed preparable-front comment fragment observed during implementation was removed before final source review.
The parent also identified lost legacy spare-capacity behavior when shared front safety was factored.
Final `humanitarian_corridor_front_destination_is_safe` retains valid real capacity and the original optional absent-load or load-less-than-capacity condition.
Evacuation still requires the stronger load-plus-full-positive-request test.
Post-finalization receipt does not retest consumed pre-move headroom, so exact fit remains recordable.

A pending negative-load concern was withdrawn after direct final-source reading.
The strict whole-request country block already rejected negative stored load, so no duplicate guard was required or introduced.
