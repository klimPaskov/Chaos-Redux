## Primary findings

1. The current corridor source has no durable exact front/counterpart contract and no attack setter. `fm_negotiate_corridor` currently proves a trapped origin state plus an arbitrary neighboring controller at `common/decisions/famine_migration_decisions.txt:1999-2092`, and the mission repeats a generic `has_war_with` neighbor test at `:121-194`.
2. `on_state_control_changed` is exact for a state/controller transition but is only a route-reassessment signal. `on_war_relation_added` is exact for the two countries entering a war but is only a country-level reassessment signal. Neither proves that the requester attacked the corridor origin or front.
3. `on_nuke_drop` is the strongest currently available native exact attack callback. Vanilla documents `ROOT` as the launcher country and `FROM` as the nuked state, and the project famine hook uses that same scope at `common/on_actions/chaosx_famine_migration_on_actions.txt:73-92`. It is conclusive for a nuclear attack only after comparing `FROM` with the persisted origin/front and `ROOT` with the persisted requester/attacker. The current hook does not perform that comparison and only supplies a boolean actor proof to the pressure adapter.
4. Vanilla exposes no generic ordinary-combat callback carrying both an attacked state and the attacking country. `on_army_leader_won_combat` and `on_army_leader_lost_combat` expose a leader and owner country but no exact target state; Event 019 explicitly documents ordinary combat callbacks as unsuitable for same-battle proof.
5. Strategic bombing has no project-owned receipt with a responsible bomber actor. Air Winter can prove an exact state loss after its owner effect applies it, but `days_since_last_strategic_bombing` is only state-local recency and `state_civilian_population_loss_target_country = OWNER` identifies the victim owner, not the bomber. This is a proxy for bombing aftermath, not attack proof.
6. Native naval-invasion and paradrop callbacks do carry exact target state and attacker scopes, and project-owned border-war and raid resolvers carry exact target/actor scopes. They are conclusive only for those specific attack owners and only when the owner calls the corridor adapter before clearing its receipt context. They do not create a generic combat or strategic-bombing API.
7. The exact blocker for ordinary land combat and ordinary strategic bombing remains: no current owner callback supplies `(exact origin/front state, attacking country, attack receipt, date)` to the famine system. The achievement must fail closed for those paths until such an owner API exists.

## Existing patterns

The safest existing pattern is owner-first attribution followed by a thin shared adapter. Air Winter computes and applies a state-local exact loss, then calls `famine_migration_adapt_air_winter_state` with the applied amount. The famine pressure adapter validates a positive request and actor-proof bit, but that bit is only a proof-of-input boolean and is not an attacker identity.

Event 019 is the best combat precedent because it freezes both state IDs and a nonce before calling `start_border_war`, gives the attacker and defender distinct callback endpoints, and validates the frozen pair before resolving. Event 018 uses the same owner-context principle for a resource dispute. A corridor adapter should copy the persistence and idempotence discipline, not attach itself to the generic `on_border_war_lost` hook.

The project biological, battlefield, chemical, and operative resolvers are already receipt-shaped APIs. They save actor, victim, exact target state, and date at the owner boundary. If the design treats one of those actions as an attack against a humanitarian corridor, the smallest integration is one owner-side call immediately after the exact native variables are saved and before the resolver clears or redirects them.

No current project effect named as a generic strategic-bombing receipt, combat receipt, or bombing actor receipt was found. `famine_migration_request_bombing_pressure`, Air Winter recency, Chaos Meter strategic-bombing cause totals, and state civilian-loss effects are downstream consequences or proxies and must not set the Achievement 4 disqualifier.

## Smallest exact adapter call sites for the parent

1. Persist the exact corridor contract before any receipt can arrive. The origin state should own the origin state ID, front state ID, counterpart country ID, requester/expected attacker country ID, lifecycle status, and a generation or nonce. The existing architecture names these fields; the current decision does not yet persist them.
2. Implement the proposed origin-state helper `famine_migration_mark_corridor_attack_disqualified` as an idempotent consumer of an owner receipt. It should accept the callback target state, attacker country, reason, date, and receipt/generation proof, require `contract_active` plus `accepted`, `operation_pending`, or `mission_active`, compare the target ID only with the stored origin/front IDs, compare the attacker ID only with the stored requester/expected attacker ID, then set reason/date/flag/status and invoke centralized cleanup. It must never search `any_state`, `every_state`, `any_country`, or infer from `has_war_with`.
3. Wire `on_nuke_drop` first because it already has the exact native producer scope. Preserve the launcher identity from `ROOT` before entering `FROM`, call the helper from the exact nuked state with reason `nuclear_strike`, and leave the existing nuclear pressure and reassessment calls intact. 4. If the acceptance rule counts invasions or paradrops as attacks, add one narrow on-action call per native callback. For `on_naval_invasion` and `on_paradrop`, consume the target-state scope with `ROOT` as attacker; for `on_units_paradropped_in_state`, consume `ROOT` as target state with `FROM` as attacker. 5. For a corridor-owned border war, call the helper from the attacker-side `start_border_war` callback before Event 019/018/011 cleanup clears the exact state pair. 6. For a project raid or operation that the rule intentionally counts, call the helper immediately after the owner resolver saves its exact actor and target variables. Pass the exact `target_state`, `actor_country`, explicit attack reason, result policy, and date. Keep failed-delivery versus actual-release semantics explicit; a receipt must not be silently broadened by a generic “attempt happened” proxy.

## Risks and blockers

### Confirmed blockers

- The current corridor decision does not persist an exact front state, counterpart, requester, or attack generation. The architecture handoff proposes those fields, but they are not yet gameplay source of truth.
- No generic ordinary-combat receipt exposes exact target state plus attacking country.
- No vanilla or project-owned ordinary strategic-bombing receipt exposes responsible bomber country. Air Winter and Chaos Meter only provide victim-state aftermath/proxy data.
- Generic `on_border_war_lost`, `has_border_war`, `has_border_war_between`, `on_war_relation_added`, and control loss cannot prove a player attack against this corridor.
- The current `on_nuke_drop` callback is exact for launcher and nuked state, but the famine adapter currently reduces actor proof to a boolean and never calls the corridor disqualifier. The launcher must be preserved before nested state scope changes.
- Project raid and border-war receipts are conclusive only within their owner contracts. No current call site connects them to the famine corridor, and the parent must decide which project attack types count.
- MCP Event analysis is bounded/partial because the workspace is large, and the map artifact contains unrelated existing locator diagnostics. These artifacts are evidence, not gameplay runtime proof.

### Ordinary risks

- A defender-side and attacker-side callback can both fire for a project border war, so nonce, role, generation, and one-shot terminal guards must prevent duplicate disqualification.
- Cleanup can clear event targets or state variables before the adapter runs; the owner must call the adapter at the receipt boundary.
- Failed raid delivery and successful release have different semantics. The corridor rule must name which result is an attack rather than treating every resolver invocation as proof.
- A state-control change can occur after an attack and should invalidate or clean the route without overwriting the earlier exact attack reason/date.
- A future country callback may be bounded to the requester/counterpart pair, but it must not enumerate the world to reconstruct a missing receipt.
