## Existing patterns

### Core Condemnation behavior

`condemnation_add_source` initializes absent optional fields to zero and computes death scaling as `condemnation_civilian_deaths / condemnation_gain.civilian_deaths_divisor`, multiplied and capped before visibility and severity multipliers. Therefore a death value is useful only when it is an exact measured physical-death amount owned by the caller.

The core stores aggregate source buckets, recent gain, recent civilian deaths, contamination pressure, last source metadata, and a compact source log of source type, context, gain, and date. It does not retain state, cohort, custody, relief, survivors, action generation, or a repeat key.

`condemnation_victim_country` is accepted as a country scope pointer and becomes `condemnation_last_victim` only when the pointer exists and is not the condemned actor. It does not scale the gain and does not preserve a state or cohort identity.

The core repeat block checks `condemnation_recent_use` only when `condemnation_source_is_weapon_use > normal`. The source-is-weapon value is derived only from chemical, biological, nuclear, final-silence, and related weapon contexts. Famine contexts stay at the normal tier, and the recent-use flag is only set for weapon contexts. A famine repeat key cannot be added by simply setting the existing weapon flag.

### Exact movement and Deaths ownership

`famine_migration_transfer_civilians_exact` measures the actual origin debit, clamps the requested route deaths to that debit, derives survivors, credits the destination, and registers route deaths once through the Deaths contract. The transfer returns exact route deaths, survivors, actual debit, and conservation values to the caller.

`famine_migration_execute_forced_transfer_exact` is the owner-level wrapper around that contract. It validates transaction identity and idempotency, resolves and binds the cohort, performs the one exact transfer, and calls deportation Condemnation only in the positive-survivor branch. It explicitly sets Condemnation deaths to zero and never emits a second Deaths entry.

The cohort resolver stores regular event targets for the origin, host, owner, and destination and exposes the exact cohort id and amount to the immediate caller. Those facts are real at forced-return, pushback, and deportation callsites, but the public Condemnation API has no cohort or state fields to consume them.

### Durable food-state mortality

`famine_migration_apply_famine_mortality` calculates exposure, vulnerability, access, policy, environment, governance, and relief factors for a registered state and calls the exact population-loss helper once with reason `chaos_meter_deaths_reason.famine`. It then stores `famine_migration_last_famine_deaths_applied` and adds `famine_migration_total_famine_deaths` on the state.

The extraction action stores a state-local `famine_migration_extraction_generation` from the global achievement generation counter. The generation is used by achievement processing, not by Condemnation, and it is not paired with the actor who activated extraction. A delayed starvation callback therefore cannot infer a responsible actor from the current ledger without a new durable binding contract.

## Famine-specific scaling and repeat assessment

- Death scaling is directly available only where the caller owns an exact measured death amount. Forced return and violent pushback meet that condition through `famine_migration_transfer_route_deaths`. The current deportation owner has an exact zero route-death output, so zero is correct. Deliberate starvation and concealment are action-time records with no action-time deaths, and relief obstruction records trapped population rather than deaths.
- Visibility is represented by the wrappers' fixed public or hidden values, but the callsites do not carry an exposure state that could truthfully move between hidden, suspected, discovered, and public. Changing the value without an exposure proof would be a balance choice, not an owner fact.
- Intent is strongest for deliberate extraction, closure/trapping, forced movement, route pushback, and concealment because the decisions prove those actions. Relief obstruction currently proves border closure and trapping, not a blocked verified relief offer. The adapter's relief context is therefore stronger than the available fact unless the relief-donor/offer owner supplies a receipt.
- Targeted-cohort facts are present in the movement and closure callers as exact cohort IDs, owners, hosts, destinations, and amounts. The public API does not accept them, and its source log has no cohort field. Passing a cohort amount as deaths would be false.
- Repeat-use is not patchable by setting `condemnation_recent_use`, increasing `condemnation_repeat_use`, or changing `condemnation_source_is_weapon_use`, because those are weapon-specific core mechanisms. Deportation has a transaction id and the extraction path has a state generation, but neither is consumed by Condemnation. Forced return/pushback have cohort transaction facts but no separate famine action generation. Relief obstruction and concealment have no repeat identity.
- A narrow compatible owner-side pre-scaling is possible only if the owner already has an exact, documented input and the public API's `condemnation_base_gain` is intentionally treated as pre-scaled. The current contract has no centralized famine targeted-cohort or repeat formula, so no formula or balance target should be invented in the wrapper. A true famine-specific repeat/targeted-cohort multiplier requires a reviewed core API extension with explicit optional fields and fail-closed behavior.

## Risks and blockers

### Confirmed blockers

- The installed tool inventory exposes `hoi4.probability_*` tools but no callable `chaosx_ai_probability_auditor`. The required `hoi4.probability_inspect` call was attempted with `source.path` and failed by timeout after 180 seconds. This handoff contains no probability artifact or balance claim.
- `condemnation_add_source` has no accepted state, cohort, targeted-population, survivor, custody, relief-offer, intent, action-generation, or famine repeat-key inputs. Inventing temporary variable names at wrappers would not make the core consume them.
- The deliberate-starvation callback occurs before mortality, and `famine_migration_extraction_generation` is not paired with a responsible actor. Generic later famine totals cannot be attributed to the extractor without a durable receipt.
- The relief-obstruction decision has trapped-cohort facts but no verified relief donor, offer, withheld delivery, or exact relief amount. It cannot currently prove the spec's blocked-verified-relief condition.
- Concealment has no durable action generation linked to later mortality or record suppression. Generic famine deaths cannot be assigned to the concealment actor.
- Forced return and violent pushback route deaths are already recorded by the exact transfer owner. A second Deaths call would violate one physical death/one ledger entry ownership.
- `common/scripted_effects/condemnation_sanctions_effects.md` does not exist. Any Condemnation API extension will need a documentation owner and should not be treated as documented by the adapter markdown.

### Ordinary risks

- Victim-country semantics are not uniform across paths: the affected state owner, cohort owner, source owner, destination/reception owner, or relief counterpart may be the correct counterpart depending on the approved Condemnation semantics. The API only stores a non-self country pointer and does not preserve state/cohort identity.
- The achievement generation counter is global and monotonic, while the responsible action is state-local. It is useful as a binding component but is not itself a per-actor repeat key.
- The concealment state flag appears to have no clear path in `common`, so repeated concealment of one state is blocked by state flag rather than represented as a Condemnation repeat event.
- Fixed adapter gains are currently the only non-death scaling for famine paths. Any pre-scaling through `condemnation_base_gain` must use exact owner facts and an approved formula, not a guessed balance target.
