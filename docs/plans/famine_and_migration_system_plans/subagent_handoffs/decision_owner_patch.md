## Before and after behavior

Decision-owned movement no longer treats missing `famine_migration_route_unsafe` as route proof. `famine_migration_decision_prove_route_contract` requires a saved exact destination, valid source and destination states, positive border and transport proofs, adjacency, infrastructure, current control, non-hostile controller, safe destination food/hazard/camp/contamination/outbreak predicates, current destination capacity validity, and reception admission. `famine_migration_decision_prove_exact_return_route_contract` uses the persisted historical origin and proves exact adjacency, control, infrastructure, current destination capacity, and destination policy. It deliberately does not infer that a forced-return origin is safe; route deaths come only from the explicit proven danger predicates.

`fm_mission_prevent_reception_collapse` now requires the exact hosted cohort, state reception load, country capacity/load, and the durable arrival exposure receipt. Completion, breach timeout, and cancellation no longer resolve origin infection at resolution time and do not consume the dead `famine_migration_exposure_proven` flag. The receipt stores cohort ID, origin state ID, host state ID, generation/transaction, and outbreak exposure captured at the exact arrival transaction. Current-origin recovery or unrelated host infection cannot create or erase that historical fact.

`fm_open_reception` is now a state-targeted action using `any_controlled_state`. Its available and target gates require a valid controlled positive-population state with infrastructure, food security, and hazard/camp/contamination/outbreak safety. A paid action converts `state_population_k` to people, requests shelter at `people * 0.40` and basic medical/sanitation service at `people * 0.10`, never lowers a larger existing service, registers the exact state, and marks/recalculates the shared capacity service. It does not submit a country-wide capacity or prove a route. The visibility branch opens when capacity is absent or invalid, even while displaced population already exists, so bootstrap is not a capacity catch-22.

`fm_controlled_medical_reception` remains gated by the exact exposure receipt and may expand the exact state's medical service to its live reception load. It is not the only capacity bootstrap. `fm_distribute_arrivals`, integration, resettlement, transit, return, and mission paths use the public capacity validity/recompute seams; no decision branch writes a factory-derived absolute capacity.

Departure and reception policy are persisted separately by `famine_migration_decision_set_policy`. The displayed `famine_migration_border_policy` remains a derived compatibility value for existing presentation/core consumers. The decision-owned lanes use the role-correct dimension as follows:

After initialization, gameplay gates read only the internal dimensions. The external destination selector still needs migration to `famine_migration_reception_policy`; see unresolved dependencies.

Closing reception no longer manufactures trapped population from an already-hosted cohort and no longer writes a duplicate condemnation receipt. `fm_close_border` applies the real reception policy and political/war-support consequence only. A later exact rejected movement callback must register any trapped obligation against its exact origin, cohort, counterpart, amount, and generation. That callback is not present in the exclusive decision surface, so this owner fails closed rather than duplicating core logic. `fm_enforce_closure` remains a physical forced-return/pushback transaction, with exact destination, measured transfer, reception debit, and one condemnation call on proven route deaths.

## Cycle and closure behavior

`famine_migration_decision_preflight_destination_history` initializes the aligned history registry and rejects a destination already visited by the exact cohort. It is called by ordinary distribution and transit before the exact transfer; missing or misaligned history fails closed. Voluntary/forced historical return, terminal integration, and resettlement are explicit exceptions. The core weighted selector's internal and foreign passes, selector visibility/availability/target gates, and AI need the parent-owned cohort-history plus destination-generation/cooldown API before they can prove the same exclusion before weighting; the owner preflight is not a substitute for that core seam. The existing after-the-fact achievement disqualifier remains observability only.
