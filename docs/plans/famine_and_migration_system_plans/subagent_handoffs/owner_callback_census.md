## Primary findings

1. `famine_migration_apply_pressure_request` in `common/scripted_effects/chaosx_famine_migration_effects.txt:977` is the shared fail-closed adapter endpoint. `famine_migration_pressure_request_is_valid` in `common/scripted_triggers/chaosx_famine_migration_triggers.txt:30` requires a valid state, a positive amount, a non-unknown source, and positive actor proof. A future owner should call one of the source-specific `famine_migration_request_*_pressure` wrappers only after it owns and records the exact state transaction; no missing surface below currently satisfies all four inputs.
2. `famine_migration_transfer_civilians_exact` at `common/scripted_effects/chaosx_famine_migration_effects.txt:1172` is the one exact movement endpoint. It debits the origin once, accounts route deaths, credits survivors, and updates the cohort host at `:1296-1301`; callers must not add a second population debit.
3. The seven report sprites already have a non-event-ID carrier: the famine decision-category scripted GUI. No new event ID, event-pool entry, pacing pulse, or new shared scripted GUI is required. The only current owner callback that selects one of the seven scenes is nuclear evacuation in `on_nuke_drop`; the other six selector effects have no call sites.
4. The CXT §4.11 extension contract is satisfied for the famine/migration general-system fixture, not for the missing gameplay owners. The package has a hidden idea carrier, an idempotent `_apply` effect, bounded startup registration, and a guarded tag-specific daily repair path.
5. The requested achievement producers remain blocked by missing durable proof, not by missing setter names. Protected internment, protected forced labor, and corridor attack setters have no authoritative call site; annexation currently only disqualifies; cohort arrays overwrite host/destination instead of recording visits; medical flags have no invalidation producer.

## Existing patterns

- Positive adapter pattern: owner applies the exact civilian loss, exposes state/amount/actor, and then calls a thin adapter. `famine_migration_adapt_camp_state` (`famine_migration_adapter_effects.txt:85-114`) consumes `camp_site_last_month_deaths` plus `genocide_responsible_country`; `famine_migration_adapt_chemical_state` (`:120-133`) consumes `cbrn_occupation_last_civilian_deaths` plus `cbrn_occupation_responsible_country`; neither applies a second population loss.
- Positive lifecycle pattern: the callback scope is documented and narrow. `on_nuke_drop` uses `FROM` as the state and derives one exact amount before `famine_migration_request_nuclear_pressure`; `on_state_control_changed` uses `FROM.FROM` as state only for reassessment/cleanup.
- Positive annexation timing precedent: Event 006 and Event 015 save annexer/victim event targets before the annexed country disappears. This is a timing precedent, not evidence that famine cohorts are currently durable across annexation.
- Negative pattern to preserve: generic country callbacks, cluster queues, scenario IDs, random continents, date-based bombing recency, occupation-law switches, and dynamic modifiers do not meet the exact state/amount/actor contract.
