## Cleanup, exploit risk, and remaining limits

Reserve dispersion selects its source at decision start from eligible Soviet-owned/controlled registered depots, saves it as `sov_nuclear_bombs_disperse_source_state`, and marks it with `sov_nuclear_bombs_disperse_source`; it does not choose a new source at completion. Success transfers exactly one assigned device from that locked source to `sov_nuclear_bombs_selected_state`, reconciles the ledger, and clears the source/destination selection. Expiry with invalid endpoints records cancellation and clears both endpoints; `cancel_trigger` and `cancel_effect` handle actor, phase, destination, or source invalidation. The start-time failure branch also clears the selected state and now spends no logistics cost.

One source-availability limit remains outside the permitted write set: `sov_nuclear_bombs_event_has_disperse_source` in `common/scripted_triggers/023_sov_nuclear_bombs_event_triggers.txt` checks for any assigned source but cannot exclude the player-selected destination. If the only assigned depot is the selected destination, the decision can appear available; source selection then finds no distinct source, fails closed, charges nothing, and cleans up. A future change to that trigger would be needed to disable the button before selection in this edge case; no out-of-scope trigger file was edited.

No repeatable free-device, equipment-farming, war-goal, core, or cooldown exploit was identified in the inspected decision/mission paths. The dispersion transaction preserves the one-device ledger. No whole-world loop or new decision family was added. The response mission's separate moratorium transition clears its active flag only behind the shared no-active-project gate; the Back Down path no longer does so.
