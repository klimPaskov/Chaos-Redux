## Exact risks for owner disposition

1. **Critical: in-flight reservation can be transferred and then committed twice in accounting.** `sov_nuclear_bombs_mark_site_transferred` unconditionally moves `site_reserved` to global/site transferred (`runtime_effects:937–965`). Both Event 5 post-transfer and ordinary control callbacks can call it (`:1504`, `:1627`) while `native_delivery_pending` is set. The pending-country predicate checks flags/context but not positive global, actor and source-site reserved balances (`runtime_triggers:218–252`). A later accepted callback subtracts one reserved bucket in `sov_nuclear_bombs_commit_reserved_device` (`runtime_effects:483–486,514–536`) after it may be zero. Negative reserved values and an expended/transferred double count can result. `refresh_ledger_reconciliation` checks the algebraic total but not nonnegative bucket invariants, so a zero-sum error can appear “clean.” If state target ownership changes, `on_nuke_drop:90–97` can instead reject the callback and leave pending forever. **Disposition: unresolved implementation defect. Parent must preserve an in-flight reservation transaction across custody change or explicitly resolve it before moving custody, then prove both callback orderings.**
2. **High: callback provenance and recovery are insufficient for an exactly-once claim.** `on_nuke_drop` matches launcher, state and target owner/controller but carries no request nonce. The country nonce only protects the later receipt. An unrelated Soviet native nuke against the same state during the Event 23 pending window could satisfy the callback predicate. `action_native_stockpile_before/after` are recorded (`runtime_effects:652,773`) but never compared. If `launch_nuke` does not callback, pending blocks new actions and `clear_action_context` refuses refund (`:790–814`). `on_daily_SOV` has no timeout/recovery path. **Disposition: unresolved. Parent needs a source/engine-supported provenance or conservative dispute/recovery contract, plus same-scenario callback evidence. No fallback was applied here.**
3. **High: native custody and ledger custody can diverge while reconciliation reports clean.** `mark_site_transferred` moves the ledger first, then checks holder/SOV `num_of_nukes`. Insufficient native bombs only sets global `sov_nuclear_bombs_native_custody_reconciliation_disputed` (`runtime_effects:954–1009`). The dispute flag is not consumed or cleared by the ledger arithmetic check (`:75–117`). Breakaway operationalization can set capability from transferred ledger even when native removal was disputed (`:857–932`), and return-to-SOV logic has a native grant branch (`:1102–1185`). **Disposition: unresolved. Parent should make dispute a first-class gate/invariant and prove native stockpile reconciliation before any transfer/return grant.**
4. **High: ordinary custody classifications can be wrong or stale.** `mark_site_transferred` sets `breakaway_physical` and `event5_custody_episode_recorded` for all callers (`runtime_effects:1051–1052`). An ordinary Soviet-to-non-breakaway foreign transfer calls that helper (`:1619–1627`) and has no later classification step, so it can be mislabelled as breakaway/Event 5. The episode flag is read by the Scattered Arsenal achievement trigger (`023_sov_nuclear_bombs_achievement_triggers.txt:92`) and Event Details status (`023_sov_nuclear_bombs_scripted_localisation.txt:337`), so the label is consequential. Later foreign-to-foreign rebind updates holder and recorded owner/controller without reclassification (`:1629–1649`). Soviet recovery waits for an explicit recovery action (`:1190–1215`), which may be intentional for physical custody. An ownership-only transaction without a controller change also lacks a verified on-action route. **Disposition: unresolved implementation and design proof. Parent should separate transfer accounting from episode classification, specify whether recovery is always manual, and cover owner-only changes if the accepted contract requires them.**
5. **Medium: Event 5 snapshot generation and coverage.** `snapshot_event5_release_tranche` increments generation and sets global pending before knowing whether it found a registered state (`runtime_effects:1434–1451`). Zero-state tranches have no local clear. The reconciler records the current *global* generation instead of the state's stored snapshot generation (`:1471,1573`), so overlapping tranches can misstate the transaction. The inspected direct call sites precede four release operations, but separate Event 5 direct `transfer_state_to` paths and Part 6's wider country capability snapshot are not covered by these state snapshots. **Disposition: unresolved scope/transaction gap. Parent should reconcile the Event 5 path inventory against the accepted spec before claiming full integration.**
6. **Medium: shared profile ordering is an unproven runtime dependency.** Humanitarian's `on_nuke_drop` clears Event 23 profile flags (`humanitarian_runtime_on_actions.txt:168–171`), while Chaos meter's `on_nuke_drop` reads them (`chaosx_on_actions_chaos_meter.txt:196–209`). The source file order suggests the intended sequence but neither the narrow MCP event trace nor consulted vanilla docs proves handler ordering. **Disposition: unsupported runtime analysis. Parent should verify consumer ordering or use a shared one-shot profile receipt that both consumers can read before cleanup.**
7. **Validation gap: probability and map scenarios.** The current `probability_inspect` discovers four dynamic candidates but supplies no actual scenario probabilities. The prior `chaosx_ai_probability_auditor` handoff has older hashes. Dynamic selected sites and route geometry were not individually inspectable from a static Moscow map query. **Disposition: blocked on same-revision specialist scenario audit and user-owned live validation. Do not reuse the older probability totals as post-patch proof.**

## Helper architecture and cleanup map

No new helper is recommended solely for tidiness, and no gameplay file was edited. The existing map is: `sov_nuclear_bombs_stage_shared_action` (SOV/actor scope. Selected global state target, action type/route/outcome inputs. Output action state pointer/ID, target and nonce. Side effect reservation. Called by test/demonstration/strike/accident orchestration). `sov_nuclear_bombs_reserve_device_for_action` and `sov_nuclear_bombs_commit_reserved_device` (actor scope. State/source and action inputs. Global/actor/state ledger transfers. Called by shared action and native confirmation). `sov_nuclear_bombs_snapshot_event5_release_tranche` (releasing country scope. Event 5 release target input. Pending state snapshots. Called at four Event 5 release sites). `sov_nuclear_bombs_reconcile_event5_state` and `sov_nuclear_bombs_reconcile_state_control_change` (state scope. Actual post-transfer owner/controller inputs. Custody/holder and ledger side effects. Called from on-actions). `sov_nuclear_bombs_confirm_native_delivery` (SOV scope. Pending action plus `FROM` correlation supplied by on-action. Receipt/ledger commit). `sov_nuclear_bombs_cleanup_annexed_actor` (annexed country scope. Clears actor-only flags, targets and projects but deliberately does not resolve pending native delivery).

Constants/tuning already live in `common/script_constants/023_sov_nuclear_bombs_constants.txt` (`sov_nuclear_bombs_tuning`, `sov_nuclear_bombs_ledger`, `sov_nuclear_bombs_custody`, action and outcome categories). No new numbers or tuning table are proposed by this audit. A future recovery timeout should not be invented before the native callback semantics and accepted disposition are established. Maintain selected state and source state as distinct save-backed references, retain short-lived targets only for the effect chain, and clear global targets and pending markers only after a proven commit/refund/dispute transition. The migration priority is to repair the existing transfer/commit/callback helpers and their direct Event 5/on-action call sites. Do not create a central router or move the larger system into a new abstraction.
