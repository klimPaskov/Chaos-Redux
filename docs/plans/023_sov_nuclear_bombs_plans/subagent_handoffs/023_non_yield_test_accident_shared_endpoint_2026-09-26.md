A true-yield accident requires a rare catastrophic low-integrity physical severity gate. Event 23 owns that gate, action authorization, reservation, exact target selection, nonce, and commit. ## True-yield precedence audit

The current Event 23 runtime sets both `sov_nuclear_bombs_shared_test_context` and `sov_nuclear_bombs_shared_accident_context` for a detonating test accident. `chaos_meter_on_nuke_drop` already chooses the accident Chaos/death/fallout branch ahead of the ordinary test branch, but `chaos_meter_register_nuclear_condemnation` previously chose test before accident. It therefore classified a true-yield accident as `experiment_site` with test visibility and minor severity. The shared condemnation helper now checks accident first and records its existing discovered `observer_report` and mass-death accident severity. An ordinary test without accident context still follows the same test branch. The non-yield endpoint sets accident context around that same shared condemnation call.

Parent follow-up identified a later `sov_nuclear_bombs_atomic_delivery_context` branch as a possible overwrite for a true-yield `action_type = accident` without test context. At inspection, that branch already had `NOT = { has_country_flag = sov_nuclear_bombs_shared_accident_context }`, so it could not overwrite the accident classification in the inspected source. The branch has nevertheless been moved into the same exclusive `else_if` chain after accident, test, and demonstration. Accident context now structurally prevents the atomic-strike assignment, even with `atomic_delivery_context = yes` and no test or demonstration flag. An ordinary atomic strike without those three special contexts still executes the same combat classification and target-population/capital severity checks.
