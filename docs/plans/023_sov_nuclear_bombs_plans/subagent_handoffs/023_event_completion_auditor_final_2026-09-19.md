## Confirmed implementation gaps (not just missing evidence)

1. **I1 — Accepted test outcome and consequence separation is incomplete.** Part 3 (`spec_part_3_testing_secrecy_and_foreign_reaction.md:132-166`) requires readiness/site/profile-sensitive weighted outcomes, a partial-yield branch, and accident consequences distinct from a combat strike. Current `common/script_constants/023_sov_nuclear_bombs_constants.txt:301-309` and `common/scripted_effects/023_sov_nuclear_bombs_event_effects.txt:748-769` have only flat 70/20/10 success/failure/accident weights; no partial yield. Successful/accidental tests and demonstrations use native `launch_nuke` (`common/scripted_effects/023_sov_nuclear_bombs_runtime_effects.txt:616-632`), then shared `on_nuke_drop` applies the generic nuclear-use Chaos counter, strike death reason, fallout, condemnation, air contamination, and humanitarian pressure (`common/scripted_effects/chaos_meter_effects.txt:5984-6124`; `common/on_actions/humanitarian_runtime_on_actions.txt:125-153`). The shared path is not duplicate application, but it is the wrong profile for a noncombat test/accident. Failed detonation returns an intact reservation (`runtime_effects.txt:593-603`), while Part 3 specifies a consumed/unusable device; the exact disposition needs an explicit accepted decision rather than an implicit simplification.
2. **I2 — Exactly-one-device custody is stranded.** `constant:sov_nuclear_bombs_ledger.one` is literally 1 (`common/script_constants/023_sov_nuclear_bombs_constants.txt:500-507`). Transfer/operationalize conditions require `site_* > one` (`common/scripted_effects/023_sov_nuclear_bombs_runtime_effects.txt:827-839,907-916`), so a site holding exactly one operational, assigned, reserved, or transferred bomb cannot move through those paths. The same strict gate occurs in test-site, breakaway, return, and joint-custody predicates (`common/scripted_triggers/023_sov_nuclear_bombs_event_triggers.txt:559-579,890-959`; `common/scripted_effects/023_sov_nuclear_bombs_event_effects.txt:2663-2675`). This violates Parts 2/6/7 conservation and Scattered Arsenal reachability.
3. **I3 — General custody control changes are not reconciled.** The state-control hook only calls the Event 5 reconciler for a pending snapshot and the reactor handler for a pending reactor (`common/on_actions/023_sov_nuclear_bombs_on_actions.txt:28-40`). A registered Event 23 storage site changing owner/controller outside a pending Event 5 tranche has no corresponding bounded custody reconciliation here, despite Part 6 (`spec_part_6_soviet_collapse_integration.md:22-61,393-406`) and the accepted custody contract. Native SOV detonations without an Event 23 pending request likewise do not enter the Event 23 combat-use receipt path (`on_actions.txt:73-99`; `common/scripted_effects/023_sov_nuclear_bombs_event_effects.txt:823-892`), so event-owned stock/achievement attribution remains unresolved.
4. **I4 — Stage III/IV world gates are narrower than accepted.** Part 5 (`spec_part_5_evolutions_and_exchange.md:139-154,198-216`) permits Stage III when two majors have operational nuclear capability, and Stage IV when two operational nuclear majors exist or an exchange is active. Current `common/scripted_triggers/023_sov_nuclear_bombs_event_triggers.txt:321-340` additionally requires an Event 23-specific flag, active exchange, or enemy use; a peaceful but valid two-major rival state cannot itself advance. The flag is set by later receipt/use paths (`common/scripted_effects/023_sov_nuclear_bombs_runtime_effects.txt:148-150`; `common/scripted_effects/023_sov_nuclear_bombs_event_effects.txt:889,1678`), not by merely detecting two operational majors. This can block the accepted immediate high-Chaos opening and downstream AI eligibility.
5. **I5 — The super-event does not prove an answered exchange.** `common/scripted_effects/023_sov_nuclear_bombs_runtime_effects.txt:124-169` records the first major receipt, then accepts a second receipt when **actor OR target differs**. Two SOV strikes on two different nuclear majors therefore satisfy `major_receipt_minimum` without any answering major strike. `common/scripted_triggers/023_sov_nuclear_bombs_event_triggers.txt:307-319` and `common/scripted_effects/023_sov_nuclear_bombs_event_effects.txt:1716-1738` then trigger the one-time super-event. This contradicts the accepted multi-major exchange/answer meaning, although the single-event registration and nonterminal boundary are present.
6. **I6 — Pending reactor verifier has a scope error.** `common/scripted_effects/023_sov_nuclear_bombs_event_effects.txt:319-369` runs in country scope and uses `sov_nuclear_bombs_event_pending_reactor_site_is_valid = yes` directly at line 341 while construction is incomplete. That predicate requires a state scope and `has_state_flag = sov_nuclear_bombs_reactor_site_pending` (`common/scripted_triggers/023_sov_nuclear_bombs_event_triggers.txt:241-248`). The false waiting branch instead clears the pending marker/target; the native job is not cancelled, so entitlement, later completion, and duplicate-queue behavior are not proven. The architect handoff's `implemented and reconciled` status is not supported by current code.
7. **I7 — Scattered Arsenal achievement has weaker proof than accepted.** Part 10 (`spec_part_10_achievements_acceptance_and_closure.md:95-117`) requires at least two breakaway crises and one negotiated, joint, or monitored dismantlement resolution. `common/scripted_triggers/023_sov_nuclear_bombs_achievement_triggers.txt:90-102` checks actor count, generic `sov_nuclear_bombs_custody_resolution_recorded`, zero remaining transfer/missing, and integrity, but no qualifying nonviolent resolution receipt. Generic resolution can satisfy a stricter accepted achievement.
8. **I8 — Demand delay and foreign support are still shallow.** Target response `.120.c` sets delayed and immediately resolves (`events/023_soviet_nukes.txt:277-285`); its resolver marks response pending, then clears the ultimatum/target/deadline context (`common/scripted_effects/023_sov_nuclear_bombs_event_effects.txt:1388-1393,1435-1447`). It does not extend the same recorded deadline within the accepted 14–45-day envelope. Foreign-support response `.120.f` only sets a response flag, while the resolver sets internal integrity/credibility flags, with no named foreign actor or support transaction (`events/023_soviet_nukes.txt:307-315`; `event_effects.txt:1380-1387`). These are narrower than Parts 4/9 and near-completion C2/C4.
9. **I9 — Opening test-site choice bypasses its safety predicate.** `common/scripted_effects/023_sov_nuclear_bombs_event_effects.txt:150-169` first chooses any noncapital registered storage state, then only uses `sov_nuclear_bombs_event_state_is_valid_test_site` if the first selection failed. The actual predicate excludes border conflict, resistance, contested ownership, high population, and other conditions (`common/scripted_triggers/023_sov_nuclear_bombs_event_triggers.txt:181-202`). Later revalidation may fail closed, but the accepted opening is not a valid bounded site selection and can strand the player in an avoidable unusable state.
