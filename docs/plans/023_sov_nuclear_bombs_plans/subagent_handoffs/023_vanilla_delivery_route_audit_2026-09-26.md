## Existing patterns
Event 23 has a single shared action effect. The event effects stage an action context and call it for the ordinary action path, test outcome, prepared strike, retaliation, and dismantlement. The shared effect distinguishes synchronous non-detonating commits from detonations, holds a pending reservation, calls the native `on_nuke_drop` callback contract, and avoids a second consequence path. The native effect invocation is real, but the surrounding Event 23 eligibility test is not equivalent to the native raid's unit-selection and success model.

The installed vanilla `launch_nuke` documentation describes the effect as a detonation against a province or a province in a state, optionally consuming a nuke and selecting its type. Current vanilla uses the same effect inside the outcome effects of `nuclear_strike`. This is evidence that the effect is a valid detonation/payload route. It is not documentation that the effect starts a raid, assigns bombers, computes their reach, or validates the player UI's delivery gates. The separate console command documentation at `console_commands_documentation.md:1086-1090` explicitly describes the console command as launching without conditions; that console command is not the scripted effect and must not be conflated with it.
