## Existing patterns and evidence interpretation

The five recipient roots (`undead_zombies`, `rabid_zombies`, `parasitic_zombies`, `necrotic_zombies`, and `mutant_zombies`) contain `provider/shared_humanoid_lineage.json`. The representative undead file records copied provider GLB/FBX artifacts and hashes at lines `2-58`, explicitly forbids `static_mesh_only`, `missing_actions`, and `reused_geometry` at lines `60-64`, and records the owner Meshy task lineage at lines `125-247` with provider `@meshy-ai/meshy-mcp-server` version `0.4.0`. This is useful provider source evidence, but it is not final-action acceptance because the final action reports state that the provider rig was not used and the actions were locally authored.

The intermediate import reports show that provider actions once entered the Blender working rig. For example, `undead_zombies/blender/reports/import_animation_chaosx_undead_zombies_idle.json:40,150-153` names a provider skeletal transfer from `provider/shared_humanoid/animation_idle_provider.glb` and source action `Armature|Idle|baselayer`; equivalent attack and death reports identify their provider files and source actions at lines `40,150-153`. There is no equivalent provider move import report, matching the job’s explicit local move entry. These imported working candidates were not the final accepted runtime actions.

The manifests and runtime handoffs claim `ready_for_user_live_validation` and “real skeletal actions,” but the same manifests explicitly describe the local Blender route at `manifest.md:15-16`. Older `provider/lineage.md:3-5`, `blender/reports/production_status.md:3-5`, and `validation/export_reimport_status.md:3-5` still say `not_started_blocked` or that no final bytes/reimport proof exist, while newer action/reimport files exist. File timestamps confirm the contradiction: the blocked status files are from 2026-08-20, while the final action reports, reimport JSON, and runtime `.anim` files are from 2026-08-21. The newer explicit source-policy reports are the decisive reason for REDO, not the stale status files.

The runtime/entity wiring pattern is structurally valid and mirrors the vanilla entity/animation layout, but the user’s quality gate is stricter than the vanilla alias convention. Parent-owned runtime changes must therefore preserve the file/ID shape while replacing semantic aliases with distinct provider/professional actions and retaining a final per-role lineage record.

## Risks and blockers

### Confirmed blockers

- All 28 specialized canonical runtime actions have final evidence that identifies local Blender authoring or a semantic local creature action route; none can be classified PASS under the user’s rule.
- The humanoid `move` action has no provider action ID and is explicitly local in every humanoid `job.yaml`.

- `chaosx_zombies` has no evidence root at `docs/assets/002_zombie_outbreak/models_3d/zombies/`, so geometry, rig, provider lineage, Blender authoring route, reimport, and visual evidence cannot be verified.
- The current entity files use semantic aliases for four additional state roles in every model, which the user explicitly rejects even though vanilla uses similar syntax.
- Provider/reimport status documents and manifests are internally stale or contradictory. The final action source-policy files are newer and explicit, so they take precedence for this quality audit.

### Ordinary risks

- Shared provider action artifacts must not be silently treated as final recipient output. Each recipient needs a trace from source task/action and artifact hash through retarget/import to the final `.anim`.
- A locally authored 24-bone or winged-biped rig may be technically importable and visually plausible while still being unusable as proof for `meshy_animate`; provider rig task lineage is a separate acceptance requirement.
- The demonic reimport report shows a 23-bone armature while the action reports describe semantic keyed bones; this route needs an explicit provider/professional rig contract before any reuse decision.
- Mechanical previews prove that frames render and reimport but do not constitute independent professional animation or live HOI4 playback validation.
