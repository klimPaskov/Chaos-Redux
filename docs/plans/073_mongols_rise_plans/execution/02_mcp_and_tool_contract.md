# MCP and tool contract

## What was actually available here

The local container could read supplied files, create planning files, and run package-level checks. Web browsing was used for a small institutional historical research set. The GitHub connector was used read-only to inspect repository metadata, listings, the existing Event 073 script, and a project wiki snapshot.

The supplied config and profiles describe a richer local environment. They do not make those tools available in this conversation. No Hearts of Iron IV, Meshy, Blender, portrait production, or collaboration spawn action was available to execute here.

Codex Native tool discovery exposed functions requiring an outer turn token. No such token was supplied. No token was invented, no native execution was attempted with a fake credential, and no successful spawn is claimed.

## Discover before invoking

In the implementation environment, inspect the current tool registry and read the exact live schema before using a capability. Bind the skill's intended action to the actual exposed tool name. A name written in a skill or old config is not proof that the tool exists now.

Do not fabricate MCP results, screenshots, hashes, routes, model selectors, API endpoints, authentication, or validation logs. Do not substitute a generated UI picture for a native GUI render.

## GUI workflow

Create an honest reference layout before implementation. Inspect the existing parent windows and event-owned attachment points. Bind required formable-puzzle templates and review their state-manifest workflow. Implement within the permitted Event 073 ownership boundary.

Run native inspection and render matched fixture states. Required fixtures include opening, campaign, invalid target, settlement, cut route, arrears, succession, fragmentation, and recovery. Begin at 1920 x 1080 and UI scale 1, then check supported resolution and scaling boundaries. Use actual tool schemas for the available fixture and rendering functions.

A separate comparison tool is not assumed. Matched before-and-after inspection is sufficient when that is the actual supported workflow. Automatic rewriting is optional. Existing visual defects remain blockers regardless of whether a rewrite tool is used.

## Subagent workflow

Use fresh narrowly scoped role contexts with `fork_turns="none"` where the collaboration interface supports that field. Read the actual profile first. Some researcher and spreadsheet roles intentionally limit broad project reading. Respect those boundaries rather than forcing every role through unrelated files.

The parent owns integration and acceptance. A worker result is a proposal or evidence report until reconciled. The mandatory improvement-loop planner must actually run in an environment with that role available. Its prepared prompt in this package is not an executed review.

## Debug boundary

The debug-playtest skill was read. Its presence does not authorize unrequested desktop control, live game mutation, or a background test run. Follow the user's actual implementation and testing authorization when using it later. This package does not claim any debug session.
