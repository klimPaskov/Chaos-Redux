# Implementation stages

## Stage 0: bind the local evidence

Read current local project instructions, the owning skills, their required reference files, the accepted Event 073 specification index, and this package's source and conflict records. Inventory the current Event 073 implementation and its consumers. Bind country identities, the Karakorum site, regional state sets, unit-category mechanics, and the current relationship and achievement frameworks.

Deliver an evidence record with the actual local commit and map version, tag reuse decisions, all required bindings, current tool availability, and narrow blockers. Do not silently replace an unavailable core feature with a weaker one. Do not claim all source references were read when some remain unavailable.

Exit when the actor, lifecycle, territorial meaning, and feasible military rule are explicit. Asset research can begin in parallel once its source requirements are understood. No live implementation is included in the current package.

## Stage 1: build the opening vertical slice

Implement one accepted baseline opening using the established namespace and event engine. Prove refusal, subject handling, one-time commitment, an accounted cavalry grant, safe reception, and the first legal campaign offer. Keep world and country systems intact.

Deliver actual entry and refusal tests, stockpile and personnel ledgers, actor logging, save-reload proof, and a playable first campaign. Do not expand the full tree while the opening still duplicates units or creates a supply disaster.

## Stage 2: prove military identity and the campaign loop

Implement the mounted category, template families needed by the opening, persistent defensive weakness, Momentum, first settlement, reserve use, and anti-farming. Add the military asset vertical slice early enough to test model and sound feasibility.

Deliver measured combined combat stats, available normal recruitment, AI template selection, actual supply behavior, one victory reward, one failed offensive, and one recovery. The custom model's unfinished production remains an explicit open requirement rather than a forgotten placeholder.

## Stage 3: complete the political spine

Implement Authority, the three political routes, succession preparation, the staged idea budget, and the first Karakorum stages. Expand path anchors only when each focus has a distinct purpose. Keep the early conquest route short.

Deliver route commitment tests, meaningful different outcomes, an actual kurultai, and a loss-of-authority response. The exact capital move cannot pass until its map capability is proven.

## Stage 4: regional campaigns and khanates

Implement the reviewed regional state sets, flexible route availability, lawful settlements, and complete regional country packages. Begin with northern China and Central Asia, then extend to the western, Persian, northern, and southern routes. This is an implementation sequence, not a mandatory player conquest order.

Deliver viable khanate and direct-rule outcomes, complete regional continuation, ownership and tag-collision tests, existing-country preservation, and a human-controlled khanate test. Every promised route remains required.

## Stage 5: tribute and connected empire

Implement accountable agreements, actual transfers, arrears, joint campaigns, Silk Roads sections, and the full Karakorum project. Connect political promises to concrete obligations.

Deliver donor and recipient accounting, invalid-target rollback, disconnected-but-loyal behavior, route suspension and repair, and a finished economic capstone. No unsupported resource stockpile or invisible access shortcut is accepted.

## Stage 6: Evolutions, late play, and collapse

Implement all three pre-fire packages and active upgrades, universal rule, major crisis stages, fragmentation, meaningful successors, and recovery. Use the existing Evolution scheduler and mapped Chaos sources.

Deliver all tier combinations, casualties-before-upgrade proof, no duplicate entitlement, small-failure versus continental-collapse distinction, durable containment, and successor continuation. The campaign remains playable after its major capstones.

## Stage 7: presentation and achievements

Complete every required report, news image, flag, icon, portrait handoff, model, animation, sound, super-event, GUI state, and achievement consumer. Finalise text only after research and rights gates. Expand every asset family into concrete consumers and close each row.

Deliver native-size reviews, actual GUI and focus-tree inspection and rendering, correct DDS outputs, static fallbacks, sourced final text and audio, positive and negative achievement tests, and live runtime asset evidence.

## Stage 8: independent reviews and final iteration

Run the provided role profiles with narrow ownership. The improvement-loop planner is a mandatory actual near-completion review. Reconcile its findings with focus, decision, AI, country, localisation, and completion audits. Parent review does not substitute for an unexecuted independent role.

Keep iterating until accepted requirements and evidence are satisfied. Record dispositions for each finding. Blocked work remains blocked. Do not mark completion based on elapsed time, file count, or a successful static parser.

## Stage 9: user live-game acceptance and documentation

Obtain the required live-game review on the actual final runtime files. Preserve evidence, source provenance, and known limitations. Update authoritative documentation and catalog through the established workflow only when the event's achieved status justifies the change.

A successful package validator does not prove implementation. A successful implementation test does not automatically prove native-size readability, audio rights, or user acceptance. Each proof has its own gate.
