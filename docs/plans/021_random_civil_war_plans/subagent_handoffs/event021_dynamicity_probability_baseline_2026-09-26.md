## Dynamicity findings and recommended follow-up (not applied)

At the baseline snapshot, the working tree contained the per-crisis limits under review: `random_civil_war_capacity.maximum_multifront_states = 5`, `maximum_planned_fronts = 5`, and `event021_parent_tuning.maximum_major_belligerents = 5` / `maximum_minor_belligerents = 3`. These were used by connected-region closure (`event021_parent_expand_connected_region`, parent effects around lines 1357–1363), front-plan validation (around line 1738), side-count clamping (`event021_parent_initialize_opposition_actor`, around lines 2525–2545), same-tag node admission (around line 4576), and scenario frozen-state capture (around lines 6177–6184). The later constants/effects hashes changed during this audit, so this handoff does not claim those limits remain in the later working tree; source inspection of the baseline does not establish campaign balance impact.

Recommended source follow-up: derive connected-state expansion, eligible side counts, and aligned front-plan array cardinality from the live candidate/state/route pools instead of those per-crisis ceilings, while preserving the explicit `maximum_generation = 2`, global active-theater caps (2/3/4/5/6/8 by stage), global active-front caps (4/6/8/10/12/16 by stage), and bounded registration/review/critical/scenario scheduling. Keep global capacity, generation, manual Maximum semantics, and scenario batch timing distinct from per-crisis ceilings.

Recommended manual-pool follow-up: make each successful lower-intensity draw unavailable to subsequent draws, or remove all remaining tickets for that selected country, while preserving its initial ticket ratio. The fixed four-entry removal combined with candidate weights above four can leave repeated tickets in the pool, and the current eligibility trigger has no selected-country exclusion. Validate this with `SCN-01`–`SCN-03` and repeat-focused traces before treating it as a runtime defect or changing behavior.

Recommended analyzer follow-up: after the HOI4 connection passes version/health/task-negotiation preflight, start with `hoi4.probability_inspect` on the current exact sources; bind only matrix-approved scenario inputs; supply complete candidate pools and all current external factors; evaluate the named TGT/ARC/SCN/decision/mission/MTTH/STR/CLU cases; sweep only declared input ranges; use sequence only with a complete manifest, cadence, transitions, caps, reset/removal, and terminal states; and render ranking, timing, sensitivity, sequence, comparison, and unresolved views where returned evidence warrants them. Pair any later weighted-source patch with `hoi4.probability_compare` using identical named scenarios. No balance target or weight change is recommended from this unresolved baseline.
