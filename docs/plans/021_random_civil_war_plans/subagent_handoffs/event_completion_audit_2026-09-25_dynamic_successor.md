## Dynamicity audit and concrete findings

1. **No fixed campaign country roster or opponent count found in the reviewed selection path.** The target pool is maintained from registered countries, live eligibility and weight with a country-local membership receipt (`common\scripted_effects\021_random_civil_war_lifecycle_effects.txt:23-91`). The successor enemy list comes from the predecessor's live `every_enemy_country`, excludes the successor and same-crisis fronts, and deduplicates each current enemy (`common\scripted_effects\021_random_civil_war_external_war_effects.txt:29-59`). The two fixed `declare_war_on` type tokens are engine enums, not static country or state mappings (`events\021_random_civil_war_external_war_events.txt:33-55`). Actual count reconciliation and opponent ordering after annexation/save-load are not validated.
2. **The Event 006 list is authored identity data, not a campaign roster, but selection has an order bias.** Event 006 owns 32 package IDs, their carrier/tag mappings and historical anchor definitions (`common\scripted_effects\006_independence_wave_event021_adapter_registry_effects.txt:9-65`). Event 021 iterates that array and requires current host ownership/control, population, infrastructure, no capital/reservation/front collision, and live carrier preflight before admission (`common\scripted_effects\021_random_civil_war_parent_effects.txt:146-230`). It stops at the first admitted package in authored array order. That does not freeze which countries exist or are eligible, but the order could starve later simultaneously valid packages. Whether that priority matches accepted package-frequency and regional-variety expectations is unmeasured, not proved by the 32-ID static audit. Do not replace this with a fixed country roster.
3. **No arbitrary half-territory or half-army split found in the normal reviewed opening.** The anchor score uses current population, factories, logistics, ports, infrastructure and core status, then connected owned/controlled states are reserved with viability checks and a five-state safety cap (`common\scripted_effects\021_random_civil_war_parent_effects.txt:1248-1342`; `common\script_constants\021_random_civil_war_constants.txt:323-340`). The force share begins from severity tuning, then changes for local units, command/ideology, population, depot/arsenal, external war and equipment availability before it multiplies current divisions and `manpower_k` (`common\scripted_effects\021_random_civil_war_parent_effects.txt:2164-2336`). The generic helper's 0.25/0.30/0.20 defaults are tuning fallbacks when inputs are absent, but its only found callsite is after the parent sets the live request values (`common\scripted_effects\021_random_civil_war_effects.txt:660-700`; parent effects `:2302-2336`). The one-state route uses a fixed bounded one-division token, not a territorial partition. Actual state, force, equipment and remnant results still require executed fixtures.
4. **Scenario percentages are live-count budgets, not fixed participant counts.** Low/Medium/High multiply the currently eligible count by configured shares and draw without replacement. Maximum enumerates every currently eligible country at player confirmation, preflights plans, and commits only frozen rows (`common\scripted_effects\021_random_civil_war_parent_effects.txt:6527-6706`; eligibility at `common\scripted_triggers\021_random_civil_war_parent_triggers.txt:418-440`). The only `every_country` pass here is the expressly requested manual scenario, not a default whole-world on-action. A frozen-plan failure remains a visible skipped receipt, but no live evidence shows whether every actually valid Maximum candidate commits or whether the result fits a playable frame. Safety caps and batch sizes are ceilings, not intended fixed actor or country quotas.
5. **P1 source risk: old prompt can address a later same-opponent queue.** `event021_external_prompt_receipt_valid` compares country-local mutable `random_civil_war_external_prompt_crisis_id` to the country's current crisis and matches only the event-local opponent target (`common\scripted_triggers\021_random_civil_war_external_war_triggers.txt:110-129`). A later queue can overwrite the country-local crisis ID. The fallback in `event021_external_advance_queue` checks a current queue, in-flight flag and opponent match but not the prompt crisis ID at all (`common\scripted_effects\021_random_civil_war_external_war_effects.txt:121-147`). If an old `.2` remains open while a new crisis queues the same enemy, the old choice or default decline may consume or act on the new head. This is a source-permitted stale-receipt risk, not an observed engine exploit. Require an immutable event-instance/crisis guard and a repeat-crisis same-opponent, save/load, default-close and queue-advance fixture before calling this fallback complete. The existing EXT-01–09 matrix does not by itself certify this rollover.
6. **Presentation edge, not an invented war goal.** A missing relation can be queued when `can_declare_war_on` is true even if the opponent no longer owns and controls a successor core or claim (`common\scripted_triggers\021_random_civil_war_external_war_triggers.txt:99-108,131-149`). The event may then show only decline. EXT-03 explicitly permits skipping an invalid row or human decline, so this is not proven spec noncompliance, but the prompt wording and serialized continuation need a live fixture. `declare_war_on` advances the queue without a separately observed post-declaration war relation (`events\021_random_civil_war_external_war_events.txt:37-55`), another runtime acceptance check rather than proof of failure.
