## Finding and patch

The Evolution I secondary-front gate previously required territory, divisions, and front capacity but did not require a second actor route. `event021_parent_try_secondary_front` then assigned a different archetype by fixed rotation from the source claimant. This could manufacture an additional actor on a large map when no second leader, institution, or route receipt existed, violating FRT-04 and the evidence-receipt contract.

The current implementation now uses three linked controls:

- `event021_parent_secondary_front_candidate` requires the original host's live route-evidence count to support the next belligerent as well as the host and global caps.
- `event021_parent_has_unreserved_secondary_route` requires a live ideological, legal, regional, or command route that has not already produced a belligerent.
- `event021_parent_prepare_secondary_route` selects only such a route, while `event021_parent_reserve_current_archetype` and `event021_parent_reserve_pending_secondary_route` reserve routes only after the corresponding opening succeeds.

Event 006 and same-tag receipts are excluded from the ordinary secondary `start_civil_war` split because those routes require their dedicated identity adapters. A failed secondary split consumes neither a route receipt nor a front id.

Event 006 now has a separate package-owned additional-front transaction. It admits one complete unused package from the original government host, requires a host-owned noncapital unreserved package anchor, proves package setup and an actual war before registration, increments the same belligerent cap, and owns a narrow rollback and lifecycle pointer that cannot tear down or misidentify the ordinary primary claimant.
