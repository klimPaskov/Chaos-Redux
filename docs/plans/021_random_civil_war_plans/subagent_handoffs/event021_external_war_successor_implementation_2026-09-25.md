# Event 021 dynamic external-war successor adapter

Date: 2026-09-25.

Disposition: **implemented in source; runtime verification remains Needs Testing**. Design acceptance is recorded in `docs/specs/021_random_civil_war_specs/021_random_civil_war_external_war_successor_addendum.md` and rests on the user's explicit relation-only fallback and human event-prompt decisions.

## Changed implementation surfaces

- `common/scripted_effects/021_random_civil_war_external_war_effects.txt` snapshots live external opponents before predecessor annexation, queues dynamic scope pointers, dispatches one human prompt at a time, and cleans the queue on completion, invalid adoption, or terminal cleanup. An unrelated opening rollback preserves a pre-adoption snapshot only during its live adoption-pending phase, or a fully valid post-adoption queue; stale receipts clear. Queue clearing reconciles the current target pool; receipt-only cleanup supports annex teardown without duplicating target-count decrements.
- `common/scripted_triggers/021_random_civil_war_external_war_triggers.txt` validates predecessor/successor identity, crisis receipts, current opponent identity, live relations, current controlled core or claimed states, and declaration eligibility. `event021_external_queue_blocks_new_crisis` provides the dynamic pending-queue gate.
- `common/scripted_triggers/021_random_civil_war_triggers.txt` applies the queue gate to automatic and manual target eligibility and recurrence. `common/scripted_triggers/021_random_civil_war_parent_triggers.txt` applies it to direct parent opening, dormant Event 006, recurrence-window, and manual-scenario candidate eligibility.
- `common/scripted_effects/021_random_civil_war_effects.txt` rejects entry to the shared state-opening transaction while the live queue receipt blocks the host. `common/scripted_triggers/021_random_civil_war_triggers.txt` repeats that check in final opening-plan validation against the saved host scope.
- `common/scripted_effects/021_random_civil_war_parent_effects.txt` releases a cluster reservation before target preparation when a live external-war queue blocks the country, records the dynamic continuity-pending skip reason, and prevents stale ready receipts from entering the transaction. Rollback preserves a pre-adoption snapshot only while the successor-roster and government-role pending flags and crisis identity remain valid; post-adoption preservation requires the independent successor queue receipt. Stale receipts clear, and membership refresh follows transaction cleanup.
- `common/scripted_effects/021_random_civil_war_lifecycle_effects.txt` clears a queue-bearing annexed country's receipts during bounded annex cleanup after its target-count membership has already been removed.
- `events/021_random_civil_war_external_war_events.txt` presents a decline option plus dynamically valid core and claim declaration choices. The AI path fails closed.
- `localisation/english/021_random_civil_war_external_war_l_english.yml` resolves the current opponent name in the title, body, options, and effect descriptions.
- `common/scripted_effects/021_random_civil_war_parent_effects.txt` calls the snapshot at scripted successor promotion and pre-annex preparation; `common/on_actions/021_random_civil_war_cxt_on_actions.txt` starts the queue only after successful successor adoption.

There are no hard-coded country tags, war IDs, fixed opponent counts, or per-country war-goal mappings in this adapter. The two selectable goal identifiers, `take_core_state` and `take_claimed_state`, are generic vanilla war-goal types present in the installed `common/wargoals/00_invasion.txt`; each option's visibility, current opponent, and eligible owned/controlled state set are resolved from live scopes when the prompt is shown and revalidated when selected.

## Parent scope review and fixes

The scripted-systems architect's read-only review found two nested-scope comparisons that used the wrong `PREV` binding. The parent changed snapshot-context and same-crisis-front checks to compare `random_civil_war_host_country_scope` against the explicitly saved predecessor event target. A later read-only regression review found that an existing cluster/scenario reservation could bypass the queue at the shared transaction and final opening-plan checks, and that rollback refreshed membership before clearing its reservations. The parent added both live queue checks and moved the rollback refresh after eligibility receipts are cleared. A fresh read-only review then found a stale cluster reservation could be rejected at transaction entry but still cause rollback to discard the valid continuity queue. Dispatch now skips and releases that reservation before preparation, records `external_continuity_pending`, and rollback preserves a pre-adoption snapshot only during its explicit adoption-pending phase or a valid post-adoption queue. The reviewer found no opening bypass through the shared transaction or final-plan checks and no double decrement; it also caught a missing phase check in the snapshot-validity predicate. The extra dispatcher refresh is idempotent through the candidate receipt. These are source findings, not engine/runtime proof.

The prompt receipt now checks the live crisis receipt and current queued opponent. Queue advancement from an invalid or stale event also requires the saved event opponent to match the current queue head, preventing an older event from discarding a different current opponent. The queue gate also covers the external Event 035 adapter through the shared parent-opening predicate. While any queue lifecycle flag remains active, the successor is held out of all Event 021 automatic, recurrence, Critical, manual-scenario, reserved transaction, and final plan-validation entry gates. The live target weight and aggregate candidate count are recomputed when the hold starts and when queue cleanup releases it; rollback performs this refresh only after clearing transaction and scenario receipts. The annex lifecycle removes stale queue receipts without repeating its independent candidate-count decrement. Save/load and delayed-popup runtime behavior still require testing.
