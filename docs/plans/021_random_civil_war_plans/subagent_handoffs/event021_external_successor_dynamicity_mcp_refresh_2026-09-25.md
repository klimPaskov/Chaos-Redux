## Dynamicity review disposition

The systems architect's first read-only pass raised a possible same-opponent prompt overwrite if an older event card remained open while a later prompt replaced country-local values. The follow-up audited every current-repository read/write and caller, then retracted that blocker for normal Event 021 paths: dispatch is the sole writer, refuses to run while `random_civil_war_external_prompt_in_flight` is set, sets that flag before firing the prompt, and ordinary queue cleanup preserves the prompt receipt while the flag is live. All automatic, scenario, recurrence, shared-transaction, and final-plan entry paths reject the live quarantine. A later crisis therefore cannot replace the prompt data through normal dispatch until the existing prompt resolves or default-closes.

The annex callback's `FROM` scope is the disappearing country. When that country owns an unresolved prompt, annex cleanup clears its queue and snapshot receipts but preserves the in-flight crisis/opponent receipt; absent an in-flight prompt, cleanup clears both prompt fields. The event-level visibility predicate accepts the live in-flight flag. Option triggers are evaluated when the event opens, so a card opened before a target changes may keep its old choices visible. Each choice's hidden effect reruns the complete live goal predicate before `declare_war_on`; a stale choice therefore cannot declare and instead runs current-state queue advancement. Newly fired stale cards omit invalid declaration choices. This establishes source-level fail-closed behavior without a static timeout, but not a dynamic refresh of already-visible buttons. It does not prove how the engine preserves an already-open event through save/load, annexation, or later tag release; those remain live test cases.
