## Repair the region framework and stop expansion

An independence front must receive the territory the transaction actually transfers, and its government opponent must survive that same transfer.
An anchor-only receipt cannot establish either fact when native `release = TAG` moves every source-owned core of that tag.
The footprint includes source-owned states controlled by someone else, and native release removes the source's cores on transferred states.
An explicit owner/controller assignment to the anchor afterwards does not reverse those other transfers or core losses.

The existing dynamic candidate appender records only the anchor and increments the count once.
The optional adapter hardcodes the host pending count and actor opening count to one.
The primary adapter consumes `global.random_civil_war_plan_state_count`, but its complete native footprint must be established upstream rather than trusting a generic anchor plan.
Frozen scenario rows copy these incomplete memberships, and the active remnant proof excludes only the supplied row span.
The current live capital-connected and division-reserve proof is valuable, but its input must become the full transfer set.

Use one complete footprint contract in primary, optional, active, and frozen Maximum setup.
Do not materialize only an anchor, strip cores temporarily to restrict release, switch release commands, return extra states after releasing, or exclude every multi-state package.
Reject an individually unsafe complete footprint before mutation and retain the existing bounded retry/no-side behavior where appropriate.
Do not add mechanics, country packages, tags, replacement trees, GUI, animation, super-events, or 3D assets.
Human Event 006 countries remain vulnerable under Event 021's normal grace and lineage rules.

## Freeze the real territory transaction

Let S be the exact donating country, C the registered static carrier, A the registered anchor, and L the resolved living recipient when present.
For dormant birth, N is every current state owned by S and cored by C, regardless of controller.
T, the transfer set, is the unique union of N and the explicitly authorized anchor A.
Any additional explicit transfer already required by the accepted package route must also be frozen into T before proof.
Native release is allowed only for dormant birth and only from S to C.

For living reuse, native N is empty because release must not run.
Build the explicit transfer set from the Event 006 registered homeland/territory publisher and the exact accepted Event 021 region, intersected with S's current ownership, plus A when it requires transfer.
Include the full authorized source-owned regional membership, including the registered carrier-core homeland where that route requires it.
Do not infer a living actor's unrelated national cores as new independence entitlement or collapse a larger regional plan to A.
Freeze L's existing owned states separately as recipient baseline B.
States already held by L belong to B, contribute to current viability, and are not charged to S as new transfers.
The actor's post-transaction ownership is B union T, while the source debit is exactly T.
The birth/reuse distinction is a proposed explicit transport contract that the parent must review against each admitted package's existing territory rules.

For every state in T snapshot state identity, prior owner, prior controller, whether S had a core, whether C and L had a core when applicable, package-territory disposition, membership in source/recipient front receipts, and existing Event 021 state provenance.
Record whether native release or an explicit assignment will change its owner, controller, or cores.
Snapshot package-setup additions affecting cores as separate reversible deltas.
Keep all receipt columns aligned to the same state offset/count.
The receipt belongs to `(crisis_id, source_front_id, new_front_id, generation, transaction_nonce)` and the exact source/recipient objects, not a tag alone.

Use separate memberships for all transferred ownership and the controlled homeland that supports capital, industry, supply, and forces.
An uncontrolled core must appear in N and T.
It contributes no held population, factories, depot, port, or force budget.
It must retain its old controller after native release unless a separate accepted and frozen effect authorizes a change.
The required anchor must be source owned and controlled before transfer.
Unrelated third-party occupation rejects the complete candidate under Part 2's territory rule.
A state controlled by an already registered opponent in the same crisis may remain an occupied ownership entry only if the existing war contract supports the recipient's relationship to that controller.
If that relationship is unproved, reject that candidate before release.
Never omit the occupied state from N, seize control from its occupant, or add an external war to make the footprint fit.

The controlled homeland must reach its valid capital through the accepted region topology.
Use connected mainland states and the package's already authorized island/coastal grouping with actual ports and supported supply access.
Scotland's Shetland membership must remain recorded even when it cannot qualify as a land-connected supply contributor.
Do not invent maritime adjacency, count occupied states as a corridor, or grant arbitrary ports.
An island package needs its existing geography-specific viability contract, not a universal land-only filter.

Reserve T, the actual recipient or dormant carrier identity, the package/reservation group, and the exact required front capacity together after proof.
Use ownership keyed to the transaction nonce for reservations, including frozen Maximum receipts.
No row may borrow another row's state/tag holding.
Do not place dormant birth's host pointer in the actor column as if it were a resolved recipient.
Store an explicit birth disposition and carrier identity instead.

## Prove the source remnant and resource debit against T

The source's residual ownership is its current owned set minus every successful or still-committing transfer in this transaction.
Failed earlier rows contribute no debit.
Protect the source's current government capital and its connected controlled homeland component.
Reject a native footprint containing that capital, a protected remnant state, another front's reserved/owned state, or another scenario's holding.
Primary opening also proves the complete source remnant before government profile, registration, origin, or map mutation.
Active review retains the accepted current-capital rule and its current connected-remnant and division-reserve calculations.

The same proof must check the existing centralized population, industry, infrastructure, supply, relevant port, and force minima against the actual residual homeland.
Count only currently held usable territory.
Use current source-front identity and generation rather than the historic original host after succession.
Do not replace this with `num_owned_states > count`, a stale total, or the number of excluded anchors.
No fixed per-crisis state, actor, division, or package-size ceiling is introduced.

Derive the actor's civil-war force budget from its complete controlled footprint, registered package profile, Event 021 severity, local population/industry, actual depots, unit locations/loyalty, source military condition, ports/airfields, supply, foreign support, and current accepted evolution context.
Freeze the planned division/template allocation, manpower in documented thousands, equipment by actual token/variant, fuel, convoy, air, and naval debits or explicit package-local grants.
Retain the source's current protected reserve and subtract only newly allocated resources.
A reused actor's old resources are baseline, never a new entitlement or rollback refund.
Use existing force/allocation tuning and package profiles, with dynamic counts and bounded arithmetic, rather than peaceful-release grants or a universal percentage of national stockpiles.
Landlocked or occupied-base entries cannot create naval or air entitlement.

The parent must pass this budget into the Event 006 package-only setup before any force grant.
Setup territory level and `random_civil_war_opening_state_count` use the complete verified receipt count rather than one.
Also publish a separate held-state count for resource/supply calculations so occupied ownership does not inflate strength.
Verify source debits and actor deltas after application, including documented native rounding.
An allocation that cannot preserve the reserve or cannot be exactly accounted for is rejected before release or remains blocked pending the missing native proof.

## Commit, rollback, and later front accounting

Freeze and prove first, then reserve and revalidate, then apply and verify, then publish actor/front/war success.
Set the mutation nonce before release so synchronous callbacks can identify the in-flight transaction.
Callbacks must not publish partial state membership, start settlement, or let nested work overwrite its journal.
After native release compare the entire source ownership delta and recipient acquisition delta to T, not merely whether A changed owner.
Core changes must match the source-core snapshot and any explicit package delta.
Controller changes must match the recorded native/explicit disposition for each state.
An unexpected extra core state, wrong recipient, failed anchor assignment, failed setup, missing war, or reserve shortfall cannot publish success.

Rollback restores every transferred state's previous owner and controller, then its exact previous source-core status.
Re-add S's core only where the snapshot says it existed and was lost.
Remove a rollback-time source core where the transaction added it but the prior snapshot was false.
Reverse transaction-added/removed recipient cores and restore prior Event 021 state provenance and front membership.
Restore prior valid capitals and journaled resource deltas without confiscating L's pre-existing territory, units, equipment, technology, characters, or tree.
Do not assume annexation restores cores or original controllers.
Do not use blanket actor annexation as compensation for living reuse.
Remove only nonce-stamped spawned units and reverse exactly proven transfers, including native rounding and any callback effects.
If compensation cannot be proved, retain the journal and mark rollback unresolved rather than clearing evidence or claiming a restored world.

Clear fresh consumption/applied receipts before each attempt.
Set them only for the exact row mutated in this invocation.
An already used/rejected row or stale prior receipt cannot authorize rollback of somebody else's successful release.
Restore failed row reservations/counters only from its own holding receipt.
Preserve successful earlier rows, later rows, untouched Event 006 lifecycle fields, and the bridge's borrowed state.

Registration copies all verified territory into actor ownership/provenance receipts and the exact front-state map.
Keep current controlled membership separate from immutable opening ownership and per-state pre-release snapshots.
The existing state-control callback must refresh the affected registered state/front even when it is a non-anchor native release state.
Its native scope is new controller ROOT, old controller FROM, changed state FROM.FROM.
Use that state's exact crisis/front/nonce provenance to find the owner, without a periodic country/world scan.
A change of controller does not rewrite opening ownership or resource history.

Settlement/reconstruction act on complete registered membership and current ownership, and preserve unrelated recipient baseline territory.
A front's defeat never annexes another front or consumes unrelated original-tag country holdings.
Succession preserves crisis lineage and exact source-front/state records, then future reviews resolve the current donating government afresh.
Failed-opening rollback restores pre-release cores exactly.
Successful settlement uses the accepted outcome's independence/autonomy/reintegration core policy and records native source-core loss explicitly, rather than automatically restoring old cores as a hidden compensation step.
The parent must reconcile that successful-outcome policy with Part 3 before claiming settlement fidelity.
