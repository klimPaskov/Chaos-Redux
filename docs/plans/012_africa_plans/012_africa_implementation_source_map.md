## Authority and completion gate

The authoritative design package is `docs/specs/012_africa_specs/`, second
edition. All 45 files in that package have been read before implementation.
Matrix rows are acceptance criteria. The machine-readable disposition ledger is
`012_africa_acceptance_ledger.csv` in this directory.

The original brief file named in the provenance record, `Pasted text(3).txt`, is
not present in the repository. The accepted second-edition specifications and
the current goal prompt remain sufficient to implement the package, but an
independent hash comparison against that missing file cannot be repeated.

No Event 12 completion claim is valid until every accepted row is either:

- `implemented`, with source and task-specific validation evidence;
- `merged`, with the exact parameterised implementation that preserves the
  row's choice, risk, AI behaviour, and payoff;
- `queued`, with a concrete reason and no placeholder gameplay presented as
  complete; or
- `rejected`, with an explicit design reason approved by the user.

The ledger was created with every row accepted and pending as the pre-implementation baseline. It contains 809 rows, and its dated reconciliation handoffs record later implementation evidence without changing the accepted design criteria:

## Registry resolutions

### Event and cluster

- Event ID remains `12`.
- Entry event remains `chaosx.nr12.1`.
- Event type remains Minor Fire-Once.
- Automatic eligibility begins at Chaos tier 4.
- Formables retains stable cluster ID `6` and remains a repeatable cluster layer
  so later formable events can join it.
- Formables unlocks at tier 3, matching the accepted source record. Event 12
  itself has a tier-4 member minimum, so the cluster can be visible before this
  member becomes eligible.
- Event 12 is the required Formables member with `Severe` danger.

This replaces the live placeholder values of tier 0 and Low without changing
the stable cluster ID.

### SCN-011

`SCN-011`, Africa Is One, remains a non-playable technical reservation. It does
not bypass Event 12 eligibility, create a sandbox setup, or count for Event 12
achievements. Its UI and documentation must describe it as reserved; it must
not be represented as completed scenario content. Any later playable scenario
requires a separate accepted addendum.

### Evolution layers

- Baseline: opening at tier 4.
- Evolution I: logged tier-4 layer.
- Evolution II: logged tier-5 layer.
- Evolution III: logged tier-6 layer.
- Requested Evolution IV: post-unification world-order escalation, not a second
  logged tier-6 evolution.

### Focus-tree ownership

The selected host's original tag, politics, completed national progress, and
host identity must be retained. A full Event 12 tree may replace the active tree
only after additive shared-focus feasibility has been checked against current
engine behaviour. A controlled event-owned replacement is accepted by the
specification when a meaningful additive branch is impossible; it is not
permission to erase completed effects or the host-origin ledger. The final
choice and exact engine evidence belong in the focus architecture handoff.

### Country and polity identities

The 215 polity rows are a controlled candidate pool, not a requirement to spawn
215 tags. The sixteen priority rows require full packages. Other candidates
remain unavailable until their route, region, viable territory, institution,
local support, access, overlap settlement, and distinct gameplay role are
proved. Promoting a Tier A candidate commits implementation to a full package;
an empty country tag is not a disposition.

Existing Event 6 or vanilla identities are reused where compatible, including
Asante (`DOX`), Oyo (`DSX`), Kanem-Bornu (`DUX`), Luba (`DYX`), Lunda (`DZX`),
Kilwa (`EMX`), Zulu (`EQX`), and vanilla Kongo identity handling. Reuse does not
count as an Event 12 country package until Event 12 politics, mechanics, forces,
League role, refusal behaviour, and post-settlement play are implemented.

## Non-negotiable runtime contracts

- Protection precedes accession and integration.
- Positive opinion alone never changes relationship state.
- No opening continent-wide annexation or core grant.
- Member relationship transitions use explicit state helpers and preserve
  clauses, obligations, history, and cleanup.
- Shared action families are parameterised; there are no host-specific copies
  of the same store.
- Recurring whole-world daily, weekly, or monthly iteration is prohibited.
- Player and AI use the same material costs, target validity, action caps,
  partial outcomes, and cleanup contracts.
- Voluntary diaspora return requires consent, rights, safe transport, housing,
  jobs or education, and locally accepted development.
- High-chaos human identities remain grounded. Nonhuman and supernatural actors
  are visibly impossible actors, not human African caricatures.
- Other continents cannot enter world-order play until each has a unique,
  implemented package.

## Historical initial live-state audit

At the start of this implementation, live Event 12 consisted only of the empty
entry event and placeholder localisation. The active runtime had no Event 12
preflight, host selector, League state, actions, focus tree, country packages,
AI, achievements, GUI, assets, evolutions, super-events, or complete catalog
wiring. The acceptance ledger therefore began with zero implemented rows.

This is a historical baseline, not the current implementation audit. The
current row-by-row status is in `012_africa_acceptance_ledger.csv`, with the
2026-07-24 reconciliation and unresolved contradictions recorded in
`subagent_handoffs/012_africa_acceptance_ledger_reconciliation_2026_07_24.md`.

The worktree also contains unrelated changes belonging to other tasks. Event 12
changes must remain path-scoped, and any shared-file edit must be reviewed
against the pre-existing diff before it is committed.

## Required closing evidence

Completion requires focus, decision and mission, country-package, localisation,
text and sensitivity, documentation, improvement-loop, and event-completion
audits; task-specific balance scenarios; asset manifests and animation review
packages; super-event source and licensing records; event-log and Event Details
wiring; and an updated workbook followed by the canonical CSV export command.
