## Findings sorted by severity

### P1 — inbound E013 route can be selected without being affordable

`natural_disaster_route_inbound_relief` in `common/decisions/013_natural_disasters_decisions.txt:4547` has an `available` block that checks the recorded inbound-relief state and that the state still has an open recovery card. `natural_disaster_can_route_inbound_relief` is used for `custom_cost_trigger`/display only. Vanilla decision documentation and the decision skill both establish that custom-cost text selection does not gate decision availability. The completion effect then deducts manpower, fuel, and either convoys or trains and secures the route without a matching affordability preflight.

The helper in `common/scripted_triggers/013_natural_disasters_triggers.txt:1535` checks the state, manpower, fuel, stability, war support, and one route-specific transport option. The corresponding cost/effect path is in `common/decisions/013_natural_disasters_decisions.txt:4547–4660`. Therefore the source permits an underfunded route action to execute; exact engine behavior for each short inventory/stockpile (including clamping or partial removal) is not established by this read-only source audit. Recommended fix for the owning implementation pass: add the helper to `available` and fail closed in the completion effect before any debit or route flag. Do not alter E013’s separate neighbor-relief price as part of that fix.

### P2 — E012 protection `_blocked` text colors all base costs red as one group

`gods_of_africa_protection_cost_blocked` in `localisation/english/012_africa_gods_l_english.yml:130` colors all three base values red whenever `gods_of_africa_host_can_fund_protection` is false. That boolean can fail because only one stockpile, political power, or the earmarked reserve threshold is short. This makes affordable amounts appear unavailable. The custom-cost trigger correctly chooses normal versus blocked copy at the host level, but the blocked copy should identify only the unaffordable spendable value(s), or avoid per-value red styling if the source cannot determine them separately.

### P2 — E012 cost feedback is verbose and repeats resource names without icons in `_tooltip`

The visible normal and blocked protection cost keys (`012_africa_gods_l_english.yml:129–130`) include multiple prose lines in addition to the compact cost values. The `_tooltip` at line 131 repeats literal names such as “infantry equipment,” “fuel,” and “political power” instead of using their texticons. The main spendable values do use the correct icons (`£infantry_equipment_text_icon`, `£fuel_texticon`, `£pol_power`, and dynamically convoy/train icon keys). Keep the inline row concise and icon-first; put the reserve threshold, optional shipment selection, DLC-dependent relations, and cooldown explanation into concise hover/effect copy without repeating bare resource names or the full price.

### P2 — E012 protection target list can expand beyond the six-action density ceiling

`gods_of_africa_protect_partner` targets the registered participant array (`common/decisions/012_africa_gods_decisions.txt:870`), and `max_participants` is 64 (`common/script_constants/012_africa_gods_constants.txt:30`). Eligible participants remain targetable independently of host funding, as intended, but the source does not cap simultaneous eligible protection rows. This is a potential high-density target list, not a visually confirmed overflow: the available GUI MCP routes require a named scripted-GUI window/scenario, and these are standard decision rows with no attached scripted GUI. Parent review should decide whether this target list needs a narrow local display/phase limit or another existing category-lifecycle solution; do not infer actual rendered row layout from source alone.

### P2 — E013 full neighbor-relief price has five spendable types

The separate neighbor-relief action spends manpower, support equipment, trucks, convoys, and fuel (five types) at `common/scripted_effects/013_natural_disasters_effects.txt:6881–6985`, with current values held in `common/script_constants/013_natural_disasters_constants.txt:1034–1138`. Its normal cost localisation uses the correct texticon for each value. This exceeds the general decision-skill four-spendable-type ceiling, while the user explicitly directed that E013 relief retain its complete current price and penalties. No cost was removed or reinterpreted. This is an explicit unresolved policy/design conflict for the parent to resolve; this audit does not authorize changing the E013 price.

### P3 — E013 blocked cost copy also over-colors values

The E013 neighbor-relief and inbound-route blocked cost strings turn all spendable values red when the combined eligibility/affordability helper fails. As with E012, the combined gate can fail for a non-resource condition or one short resource. The route’s dynamic normal/blocked localisation does select the correct train/convoy icon, but its all-red treatment does not distinguish which amount is unavailable.

### P3 — optional E012 shipment selection is automatic and convoy-preferred

When the logistics-support branch is active, the protection effect sends 20 convoys if the partner has fewer than 20 and the host has more than 60; only otherwise does it consider 20 trains under the corresponding shortage/host-stock check (`common/scripted_effects/012_africa_gods_effects.txt:3425–3667`, tuning in `common/script_constants/012_africa_gods_constants.txt:286–331`). At most one transport type is spent and the host retains the reserve floor. The player-facing copy says “convoy or train” but does not explain that convoy takes precedence if both shortages are present. Add a brief clarification if this automatic priority is intended to be visible.
