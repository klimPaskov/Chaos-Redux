# Event 012 Gods of Africa Decision and Mission Audit

**Disposition:** partially reconciled after the dated source audit; current source review and partial event MCP evidence only.

**Scope and ownership:** Event 012 is the Gods of Africa subsystem owned by Africa Is One; this audit does not assign it to Event 070. The reviewed scope includes Event 012 decisions, triggers, and effects; the Event 013 neighbor-relief decision/effects adapter; the Migration shelter/medical-capacity adapter; their current localization; and the prior Event 012 architecture and adapter handoffs.

**Audit result:** the registered-participant protection target, peace/reliability/cooldown/reserve gates, base price, transport floor, and owner-specific cleanup are present in source. The generic Event 013 target and payment-order findings below describe the audit snapshot and were corrected by the parent afterward. The four-cost-type cap was explicitly limited by the user to Event 012 protection, with Event 013 relief kept at its existing price as a separate choice. The host category can still exceed six simultaneously exposed actions, and presentation, activation postconditions, probability, and runtime evidence remain unresolved. The original auditor changed no source.

## Parent reconciliation after the dated audit

The user accepted AAT-gated mutual market access and enemy intelligence, split Event 013 relief into its own Foreign Disaster Relief choice, capped only Event 012 protection, and preserved Event 013's complete existing price. Event 012 now charges three base types and may add one shortage-checked convoy or train shipment. The common-defence reserve must cover the infantry shipment and is reduced by that amount. The cost row identifies the reserve and conditional shipment. Event 013 remains a distinct choice with its existing manpower, support equipment, truck, convoy, fuel, stability, war-support, and temporary construction costs.

The generic Event 013 decision now excludes unresolved-territory cards in its target gate, rechecks donor affordability and recipient eligibility in the completion path, selects an actionable card before payment, and sets inbound flags only after successful selection. This corrects the generic no-card charge path in source. The targeted Gods adapter also selects before charging. The later `activate_mission` call still has no postcondition check, so successful mission activation and cleanup remain runtime and owner-lifecycle questions.

Accordingly, finding 1 is corrected in current source, and finding 2 is superseded by the user's explicit separation of the Event 013 choice, not by a reduction or concealment of its price. Findings about category density, ordinary decision-window fit, the Event 012 adapter's activation postcondition, mission copy, and quantitative or live-game acceptance remain unresolved. The old recommendations below are dated audit proposals and are not current authorization to reprice Event 013 or redesign the category.

## Severity-ranked findings

1. **Historical High finding, corrected in current source — Event 013 owner decision could charge without selecting a live card.** At audit time, the target gate did not exclude unresolved-territory cards and the generic completion path paid before selection. The current target gate excludes those cards, the completion path rechecks affordability and recipient eligibility, and the selector runs before payment or inbound flags. This closes the identified no-card charge path at source level. The subsequent mission activation still lacks an execution result or postcondition check.

2. **Historical High finding, superseded by explicit user design — the audited protection action combined Event 012 and Event 013 prices.** The user capped only Event 012 protection and kept Event 013 relief as a separate Foreign Disaster Relief choice at its existing full price. The current Event 012 action has three base cost types and at most one conditional transport type, with the common-defence reserve disclosed and separately reduced by the infantry shipment. Event 013 retains its full manpower, support-equipment, truck, convoy, fuel, stability, war-support, and temporary construction costs. No price was hidden, waived, or repriced.

3. **High — host decision category can exceed six simultaneous primary actions.** The host category has eight priority-action definitions, with the source gates allowing up to six priority actions together in a compatible focus/need state. A registered, reliable, affordable, non-defiant participant at peace with the host can also satisfy `gods_of_africa_protect_partner` while those six priority actions are exposed, so source permits at least seven choices before counting other host target decisions. The participant target array is bounded at 64, and the protection decision is target-specific. This is a source-permitted density finding; no decision-render MCP route was available to observe the actual in-game category layout or target-row presentation.

4. **Medium-high — protection custom-cost presentation is incomplete and unaffordable targets are filtered away.** `gods_of_africa_protect_partner` uses `custom_cost_trigger = gods_of_africa_active_host_is_valid`, while affordability is enforced by its `available`/`target_trigger` shared helper. As a result, unaffordable partners are removed from the target set rather than kept visible with a clear blocked explanation. Localization contains `gods_of_africa_protection_cost` but no matching `_blocked` or `_tooltip` key. The offline Decision Modding reference calls for the normal, blocked, and tooltip keys for custom costs; actual in-game fallback behavior was not runtime-tested.

5. **Medium — protection outcome feedback and decision-window fit remain open; transport disclosure was corrected by the parent.** The current cost row identifies the conditional 20-convoy or 20-train shipment, host floor, and common-defence reserve reduction. The effect tooltip describes the service families and persistence, but the available source review does not prove which service succeeded or why another skipped, and the tooltip's length and outcome detail have no ordinary decision render. No claim of clipped text or a missing material charge follows from the old audit snapshot.

6. **Medium — Event 013 mission consequences and duration are not clearly stated to the player.** The owner mission is a 45-day, state-specific recovery delivery. On timeout it applies -1% stability and -1% war support, marks the delivery misdirected/degrades the recovery card, and clears its route/receipt state, but the mission description does not state the 45-day window or those failure consequences. The Event 013 cost tooltip also writes the stability and war-support values as literal prose instead of using their texticons and dynamic constants.

7. **Medium balance watch — repeat protection can incrementally reconstruct a capital.** The service applies one infrastructure level when the participant owns and controls its capital and infrastructure is below 5, with no separate construction cost or damage-repair requirement. The price, cooldown, reserve-ledger gate, and infrastructure cap bound the effect, so this is not an unbounded loop; repeated successful protection can nevertheless buy incremental capital infrastructure up to the cap. Confirm that this is intended balance rather than a consequence needing a tighter eligibility condition.

8. **Low — Migration cleanup cannot prove writer identity when values are identical.** Migration cleanup matches the stored state, service amounts, and proof values before clearing the shelter and medical-capacity fields. If another writer replaces the service with exactly the same amounts/proofs before cleanup, those values cannot distinguish the replacement from the Gods-owned write. The existing Migration adapter handoff already identifies this provenance limitation; no ordinary cleanup collision was established.

9. **Low / confirmation needed — Event 012 adapter pays before mission activation without a postcondition check.** `natural_disaster_offer_neighbor_relief_for_gods_of_africa` selects an eligible card before charging and charges only inside the successful selection branch, which closes the no-card charge path for the new adapter. It then pays before `activate_mission` and records the donor receipt without checking that the recipient actually has the expected active mission afterward. Normal recipient/inbound preflight makes a failed activation path unlikely in the inspected source, and vanilla documentation notes that `activate_mission` cannot activate an already-active mission, but source inspection cannot establish the engine outcome under inconsistent state. Treat this as a narrow residual risk, not a confirmed paid-without-mission defect.

## Cost, requirement, AI, and route audit

- **Base price and gates:** Event 012 protection charges 500 infantry equipment, 500 fuel, and 10 political power; the host's common defense reserve ledger is also reduced by 500. The shared availability trigger requires at least 500 host infantry equipment, 500 fuel, 10 political power, and reserve ledger 500, so the base resource checks align with the charge. The reserve ledger can reach zero after a valid transaction; no second post-payment reserve floor is required by the inspected gate.
- **Target availability:** `gods_of_africa_protect_partner` uses `target_array = gods_of_africa_participants`. Registration, current host/generation, non-defiant state, successful-transaction reliability, host validity, peace with the host, and cooldown are all checked by the shared protection trigger in both availability and target filtering. This closes the stale/unregistered-target and participant-at-war-with-host cases. The peace gate is specifically peace with the host, not peace with every country.
- **Cooldown and reserve focus:** the participant cooldown is 180 days; the reserve focus reduces it by 60 days (120 days). The due-day gate prevents repeat transactions before expiry; cleanup clears the timer on cancellation/archive/finalization/settlement, while defiance/reconciliation retains it to prevent reset abuse.
- **Separate Event 013 price:** the Foreign Disaster Relief choice retains the original manpower, support equipment, trucks, convoys, fuel, stability, war-support, and temporary construction costs. Event 012 protection neither pays nor displays those costs as part of its transaction. The separate choice preflights recipient eligibility, relationship/aftermath state, inbound vacancy, and a selectable card before payment. Its failure to open does not cancel the separately valid Event 012 protection transaction.
- **Transport and reserve:** under logistics focus, a participant below 20 receives 20 convoys if the host has more than 60; otherwise it may receive 20 trains if available under the branch. The host retains more than the 40-unit floor. The current protection cost row names the conditional convoy/train type, amount, host floor, and the separate common-defence reserve debit. Decision-window wrapping and fit remain unverified.
- **Texticon coverage:** the Event 012 base and conditional transport cost row uses texticons for its displayed resource costs. It no longer lists Event 013 stability or war-support charges. The separate Event 013 owner cost text's stability and war-support presentation remains a localization finding for that owner choice, not an Event 012 cap issue. No ordinary decision render was available to confirm the displayed icons.
- **AI:** the Event 012 protection decision and both Event 012 mission weights are static `base = 1` entries; source availability conditions constrain which targets/missions can be considered. The existing Event 013 neighbor-convoy-relief owner decision retains its own relationship/card AI modifiers. The required `chaosx_ai_probability_auditor` subagent was launched read-only for all current Event 012 decision/mission weights and the relevant Event 013 owner action, but it had not returned after two bounded waits when this handoff was written. Therefore no scenario-specific probability conclusion is claimed, and the AI/probability audit remains incomplete pending that evidence.
- **Other route locks:** AAT market access is gated by the Arms Against Tyranny DLC; La Resistance intelligence is gated by La Resistance, agency availability, host-war status, and valid current host enemies. Intelligence adds five points per category to current non-capitulated host enemies that are not already at war with the participant. Relations are receipt-tracked only when created by the compact, and cleanup removes only those still present. Intelligence, sent supplies, and completed works are historical and not clawed back.

## Cleanup and exploit-risk notes

- Event 012's `gods_of_africa_withdraw_protection_package` cleans its own relation receipts, Migration services, donor offer marker, and protected-state marker. It is reached by defiance, invalid-host archive, participant cleanup/cancel, unifier loss, finalization, and settlement paths. The cooldown is intentionally retained through defiance but retired by cancellation/archive/finalization/settlement.
- Event 012 does not cancel an already-dispatched Event 013 mission or recover costs after delivery was offered; the Event 012 localization explicitly says a live disaster mission and supplies/works/intelligence already delivered persist. Event 013 remains responsible for success, timeout, refusal, recipient invalidation, state transfer, and release cleanup. This is a deliberate owner boundary, not an identified Event 012 cleanup bug.
- The Migration adapter records shelter and medical capacity through Migration-owned setters/proofs only when the participant's capital and food-safety/stage requirements pass; it does not move population or alter population/cohort counts. If either service setup fails, its local rollback avoids retaining a partial Gods receipt.
- Migration cleanup uses the exact stored state and matching capacities/proofs and preserves fields if the owner/controller or recorded values no longer match, while retiring the Gods receipt. Reinstallation after cleanup is possible.
- The generic Event 013 charge-before-selection path was corrected in current source, and the combined-cost finding was superseded by the explicit transaction split. Remaining balance watches are repeat capital reconstruction up to infrastructure 5 and recurring intelligence/service benefits after the 120/180-day protection cooldown. No free unit loop, stockpile creation loop, war-goal spam, core spam, or cooldown reset path was established in the reviewed sources.

## Localization and recommended fixes

- Add the missing `gods_of_africa_protection_cost_blocked` and `gods_of_africa_protection_cost_tooltip` entries and provide a useful blocked reason without exposing raw compound triggers; consider keeping unaffordable registered partners targetable but disabled if HOI4 target-decision semantics allow it.
- **Superseded by user decision:** do not apply Event 013's full price to the Event 012 four-type cap. Keep Event 013 as its own choice at the existing price, with all charges disclosed.
- **Corrected in current source:** `natural_disaster_offer_neighbor_convoy_relief` now aligns its target predicate with the selectable-card rules and selects before payment or inbound flags. The separate post-`activate_mission` outcome check remains a defensive open question.
- In the Event 012 bridge, verify the expected recipient mission after `activate_mission`; on failure, make the owner transaction and inbound/donor receipt atomic or restore the pre-payment state. This is a defensive recommendation because the inspected normal path did not prove an activation failure.
- Reduce the host category's simultaneously exposed primary actions to six or fewer through local phase/visibility consolidation that preserves the accepted design; avoid adding a new GUI or storage category.
- Clarify in protection localization the actual reliability threshold, base consequences and amounts, which host stockpile pays for transport, service DLC gates, cooldown/reserve effect, and which effects persist after compact closure. Keep the copy concise and avoid one prose wall containing every branch.
- Update Event 013 mission localization to state the 45-day deadline and material timeout consequences, and replace literal stability/war-support resource names with the correct texticons and dynamic constants.
- Confirm the intended balance of repeatable capital reconstruction and per-category intelligence gains against the existing cooldown and resource price before any balance target is changed.
