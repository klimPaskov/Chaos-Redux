## Decision and mission lifecycle

The Event 012 Charter category at `common/decisions/categories/012_africa_categories.txt:9-14` owns `africa_charter_window`. Selector decisions are intentionally cost-free navigation/quote controls. The actual execution decisions at `common/decisions/012_africa_decisions.txt:447-483` require the current quote, target/state contract, dynamic cost trigger and cost text, then re-quote and revalidate through `africa_begin_quoted_action_against_target`.

The shared action record is created by `africa_create_action_record` on the selected target with host generation, action generation, immutable duration, objective, target mode, risk, reservations, and every quoted resource cost. `africa_pay_current_action_quote` debits political power, command power, manpower, fuel, stability, war support, infantry/support/motorized equipment, trains, convoys, civilian capacity, and intelligence capacity only after the same quote passes `africa_can_pay_action_quote`. Active capacity, target cooldown, generation, and relationship validity prevent duplicate starts.

The four shared missions are `mission_africa_action_short`, `mission_africa_action_medium`, `mission_africa_action_long`, and `mission_africa_action_epic` at `common/decisions/012_africa_decisions.txt:488-566`. Each is activated on the target through `activate_targeted_decision`, checks the matching active flag and duration band, exposes the recorded objective, resolves on success, cancels on stale generation/contract/event closure, and dispatches timeout failure through the target response event. Their timeout now reads the target-local recorded duration with `var:africa_active_action_duration_days`.

`africa_resolve_action`, `africa_cancel_action`, and `africa_timeout_current_action` dispatch the row-specific full/partial/failure disposition and then call generation-aware `africa_cleanup_action`. Cleanup removes the exact mission, target/state arrays, reservations, active flags, disease/disaster/diaspora state, and capacity reservations, then applies the target cooldown. The result event preserves the row-specific objective before active variables are cleared.
