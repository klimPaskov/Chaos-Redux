# Event 012 authored elephant operations final handoff

Date: 2026-08-10.

## Outcome

The Event 012 elephant achievement row now has three player-visible operation surfaces rather than a passive scan or a country-level proxy. `africa_elephant_register_terrain_band` binds one real `chaosx_elephant` division to the locked and one-division `Africa Elephant Operations Roster`, stamps that exact division with `africa_elephant_operation_roster_marker`, and records one explicit African state terrain band. `africa_elephant_open_logistics_contract` debits an actual equipment, truck, train, and fuel commitment and settles only after the selected controlled supply-node state still contains the named division target, the host generation remains current, and the sealed operation ledger survives the 180-day mission. `africa_elephant_open_protection_expedition` can target only a protected current-generation African partner whose controlled African capital already contains the marked roster, records participation only after that exact state check, and settles only after the authoritative protection-war-settled receipt exists without capitulation while the authored roster remains in the bound capital state.

No daily, weekly, monthly, or other global scan was added. All achievement writes are owned by these decisions and their mission effects. The achievement row trigger contains only the matrix DQs, and no writer for the structurally impossible unthreatened-target flag was invented.

## Exact positive and DQ owners

`africa_elephant_record_selected_terrain_band` calls `africa_achievement_record_elephant_formation` and `africa_achievement_record_elephant_terrain_region` only after a state-targeted decision proves owner/control, African terrain registry membership, an elephant formation, an unrecorded band, and the exact marked roster division when the roster is already bound. The explicit state registry covers desert, savanna, forest, highland, marsh, and coast. The achievement's existing count and desert requirements remain authoritative.

`africa_elephant_complete_logistics_contract` calls `africa_achievement_record_elephant_supply_proof` only after the timed mission sees the current host generation, selected state still owned and controlled by the host with a live supply node, the saved division scope still exists with the generation marker and elephant battalion in that exact state, and all four sealed commitment variables still equal their operation constants.

`africa_elephant_complete_protection_expedition` calls `africa_achievement_record_elephant_protection_victory` only after the saved protected partner remains a current-generation protected African relationship, is not capitulated, has the exact `africa_achievement_protection_war_settled` receipt and no war, and the named roster division target plus authored participation witness remain in the bound capital state. The partner's defensive-war start is recorded by the existing protection-war helper only after the targeted decision has proved that exact state deployment.

`africa_elephant_fail_logistics_contract` is the only owner of the row's operation failure writers for logistics. If the saved division target scope disappears, `africa_achievement_elephant_formation_destroyed` is set. A moving division retains its saved scope, but it leaves the saved depot-state contract and therefore cannot earn the supply proof; movement does not itself trigger the formation DQ. If the selected supply-node depot is no longer owned and controlled, its supply node is removed, the marked roster leaves that state, or the debited operation ledger is mutated, `africa_achievement_elephant_supply_failed` is set. An authored timeout with an otherwise intact operation contract also resolves as supply failure. No national stockpile or fuel value is read as evidence of live division supply.

`africa_elephant_fail_protection_expedition` writes `africa_achievement_elephant_formation_destroyed` only when the saved roster division scope disappears during that active authored expedition. Partner peace is a success path only when the existing protection-war callback has left the exact `africa_achievement_protection_war_settled` receipt; the mission contract explicitly permits that settled/no-war state so cancellation cannot race completion. Capitulation, relationship loss, or loss of the bound capital-state deployment clears the operation without inventing a protection-failed achievement flag because that flag is absent from the row matrix. The operation has no writer for the unthreatened-target flag because `has_war = yes` plus `has_defensive_war = yes` and the protected-partner gate make that route structurally unavailable.

## Decision and mission lifecycle

The ordinary category is `africa_elephant_operations_category` in `common/decisions/categories/012_africa_elephant_operations_categories.txt` and `common/decisions/012_africa_elephant_operations_decisions.txt`. The terrain decision is state-targeted, costs `constant:africa_elephant_operation.terrain_band_command_power_cost`, and has a constant cooldown. The logistics decision is state-targeted, displays a custom material cost, debits `chaosx_elephant_equipment_1`, `motorized_equipment`, `train_equipment`, and fuel, and activates `africa_elephant_logistics_mission`. The protection decision targets `africa_relationship_countries`, requires `africa_elephant_protection_target_is_valid`, and activates `africa_elephant_protection_mission` only after the supply proof exists.

This package declares no `scripted_gui` binding and introduces no dedicated decision-owned window. It uses the ordinary HOI4 decision shell, so `hoi4.gui_inspect` and `hoi4.gui_render` have no in-scope named surface and were not run; no GUI rewrite or visual claim is made.

Both missions use the supported `days_mission_timeout = var:...` pattern, matching the installed Event 012 RSA mission precedent. The logistics mission uses `africa_elephant_logistics_timeout_days`, set from the shared script constant when the operation starts. The protection mission uses `africa_elephant_protection_timeout_days`. Completion, cancellation, and timeout effects all route through the authored operation effects; there is no hidden passive cleanup path.

## Costs, AI, and exploit controls

Shared tuning is in `common/script_constants/012_africa_elephant_operations_constants.txt` under `africa_elephant_operation`. The constants centralize command-power costs, cooldown, duration, material commitments, timeout windows, required band/division counts, and AI bases. The logistics start trigger checks the actual equipment and fuel reserve before the debit. The operation then seals the exact four committed values in country variables and checks equality against the same constants during the mission; no free reactivation or stockpile-floor loop is available.

The three decisions and two missions have `ai_will_do` blocks. Terrain registration uses the low base, logistics uses the medium base and a war modifier, and protection uses the highest base but is multiplied to zero when its target contract is invalid. Mission AI is multiplied to zero when its own settlement contract is not intact. Every player-facing trigger is mirrored by a custom tooltip and every new decision, mission, cost, effect, and mission-requirement key is present in `localisation/english/012_africa_elephant_operations_l_english.yml` with UTF-8 BOM encoding.

The one-division template is locked, recruiting-disabled, and capped at one. A division-scoped generation marker prevents a different surviving elephant division from satisfying later terrain, logistics, or protection checks. The global division event target is retained through the operation lifecycle and is not replaced by a country-level surviving-elephant query. State and partner targets are explicitly cleared after settlement or cancellation, while the roster target remains available for the later operation phase.
