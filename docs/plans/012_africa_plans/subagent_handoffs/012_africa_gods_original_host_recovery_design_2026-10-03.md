## Current permission-and-date clock contract

Permission is established by a trusted initial activation path or the explicit recovery milestone.
An event callback never establishes it.
An initial legacy migration is allowed only when the current committed host has valid existing active/consolidation state and no cancellation or terminal receipt.
Cancelled original hosts remain cancelled through migration.
Bind live legacy participants/contracts once through a bounded current roster only after source validation.
Do not grant permission because a queued event arrived.

### `.600` activation wake

Require all of the following before any mutation:

- Native ROOT equals the committed current owner and the exact epoch permission is current.
- Existing consolidation pending and activation-schedule receipts are present.
- A current `gods_of_africa_consolidation_due_day` exists.
- `global.num_days` is greater than or equal to that due day.
- Current physical/terminal gates and renewed mandate remain valid.

Only then consume the schedule receipt, commit activation once, recompute real Strength, onboard the current candidate roster and arm current active clocks.
For `now < current_due`, return with no writes and no replacement queue.
For missing permission, missing due date, former host, cancellation, or terminal state, return with no writes.
Remove callback fallback initialization from `africa_gods_of_africa_commit_activation`.
An explicit trusted owner action may repair a missing clock from its existing due date.
That repair must not reset the date or start another 180 days.

### `.606` owner wake

Require active/committed current epoch permission, the current schedule receipt, a present current owner due date, and `now >= due` before clearing anything or invoking `gods_of_africa_run_owner_tick`.
This outer check covers dispatch, expired-contract handling, need-profile refresh and punishment/reconciliation work as a unit.
The inner tick check alone is insufficient because dispatch and other work sit outside it.
After work, recheck authority because settlement or loss may have ended it.
If still current, set next due to `now + owner_tick_days`, set its receipt, calculate delay, and queue exactly once.
Another hint delivered the same day sees a future current due date and does nothing.

### `.607` registry wake

Require active/committed current epoch permission, its current schedule receipt, a present review due date, and `now >= due` before clearing anything or reviewing the registry.
Review only the current candidate and participant arrays.
After work, recheck permission and arm one next review.
Remove the invalid-host branch that clears a possibly current future receipt from a stale hint.
Explicit loss/terminal cleanup owns revocation and schedule cleanup.

### Direct mission timeouts

Demand timeout requires current live authority, current participant-array membership, host ID/shared generation/epoch, active demand status, a present current deadline and `global.num_days >= gods_of_africa_demand_deadline`.
Reconciliation timeout requires equivalent active authority and reconciliation epoch/pending state plus its present current deadline.
Before these checks pass, do not remove a mission, alter Wrath, clear pending flags, write history, punish, or emit a failure receipt.
These guards intentionally let an old timeout serve as a due hint for an actually expired current contract.
They cannot fail a future contract early.
Early `.604` or other presentation receipts remain separately current-receipt gated.
