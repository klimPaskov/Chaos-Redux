# Generic national reform preflight and Administration action

Status: implemented in package source; live effect and receipt remain unproved.
Acceptance basis: the user's approved shared availability, quote, debit and effect contract, exact survivors and no paid no-op requirement.

The generic `generic_dismantle_detention_network` decision and the Administration right action both use `camp_admin_generic_reform_available`, then `camp_admin_generic_reform` rechecks that trigger before a single Political Power debit.
The national order's `all_of_scopes` loop now requires each registered site to pass `camp_admin_site_authority_is_valid`, the same authority gate used by `camp_admin_reform_site` before closing the site and releasing surviving custody.
This closes a source-level gap where a subject-controlled site could pass the broader dismantlement target test yet lack the explicit `camp_admin_subject_authority` flag needed by the later release effect.
The availability gate still checks every site is initialized, open, a valid dismantlement target and recorded under the actor, and rejects an ongoing closure or dismantlement.
Availability now calls `camp_admin_site_rows_reconciled` for every registered site. The scripted trigger checks aligned row lengths, authority and status, rebuilds living custody with temporary variables inside `all_of`, and rejects a mismatch with the state's living-custody total. At execution, the order independently calls the existing aligned-row validator and live-row counter before the Political Power debit. Either guard rejects a malformed or changed ledger without payment or lifecycle change.

| Source scenario | Preflight conclusion |
| --- | --- |
| One directly controlled, otherwise valid registered site, 15.75 Political Power | The exact current quote is affordable and the site authority gate passes. |
| One subject-controlled registered site without the explicit subject-authority flag | The new site authority gate rejects the national debit. |
| The same subject site with the flag and otherwise valid state | The authority predicate can pass; the other site and resource gates still apply. |
| Two registered sites, one failing the site authority gate | `all_of_scopes` rejects the whole order before payment. |
| One valid site, 15.74 Political Power | The inclusive fresh-quote check rejects payment. |
| One otherwise valid site with an invalid aligned custody row | Parsed production availability rejects the order; effect-time execution also rejects a debit if rows change later. |
| Two sites with one invalid custody row | `all_of_scopes` rejects national availability; effect-time execution also rejects the whole debit. |

The one-site quote is `(5 + 0.25) × 3 = 15.75` Political Power from `camp_admin_command` constants. The GUI shows the refreshed display cache with `|2`; the native decision's custom-cost text now uses `|2` on the fresh temporary quote. Both show 15.75 rather than rounding to 16. The effect computes its own fresh quote immediately before debiting, so the display cache is never the debit authority.
The generic tooltip describes the debit as occurring when the order executes, before the release effects. No engine receipt proves that every cohort row is valid or that a particular save releases a nonzero number of survivors.
The current 33-group `foundation_source_tests.py` run executes the production row trigger and generic-order debit with external occupation and lifecycle consumers mocked. It checks valid, mismatched, foreign-authority, inactive-live and misaligned rows, one- and two-site country availability, and direct versus flagged subject authority. A valid one-site effect pays 15.75 Political Power once; malformed one-site and two-site effect scenarios leave the stock unchanged. Nine later groups cover legacy dismantlement, colonial start, enemy liberation, named report selection, custody-receipt retry, fixed-cost quote boundaries, the native selected-site closure state partition, monthly cancellation isolation, and the site timer grace in `legacy_dismantlement_cutover_handoff_2026-09-27.md`. These are parsed-source scenarios, not engine clicks.
The same suite now verifies release ordering after an external population drop: a state with 80 thousand held but only 50 thousand host headroom records 30 thousand external attrition, releases the 50 thousand actual survivors, and derives its 32.5-thousand civilian target from those survivors. The previous order derived 52 thousand before reconciliation. No people are created and no camp death is inferred from the outside loss.
The shared site reform helper also checks row reconciliation after refreshing capacity before it sets a civilian target or closes the site. A separate 10-thousand aggregate / 9-thousand live-row source case previously closed the site with a false 6.5-thousand target; it now leaves the site open with custody and target unchanged. The generic national decision preflights all sites before payment. Major and civil national reform callers now use the bounded country preflight before policy flags or occupation closure, and the shared reform helper checks again. Legacy dismantlement callers remain under separate audit for their timed flags and history order.
The earlier audit's selectable uncharged no-op arose because row validity was checked only inside the effect. The availability trigger now rebuilds and checks each site's live row sum before showing an enabled order, and the locked GUI action has a distinct custody-records reason. The effect-time pass still protects a ledger that changes between availability and execution. Engine interpretation of the trigger and a live click remain unproved, so source-model removal of that no-op is not a live-game completion claim.
The same audit found `ai_hint_pp_cost = 60` as a static maximum estimate while the current quote ranges from 15 to 60; AI eligibility and debit still use the fresh quote. The native decision cost now uses a Political Power texticon and two-decimal quote. No AI weight was changed in this narrow patch.
The native decision's custom cost trigger now calls `camp_admin_generic_reform_can_pay`, the same fresh-quote affordability helper used by availability. It turns the cost red only for insufficient Political Power; closure, control and site failures stay in the separate availability check. Normal, blocked and hover cost keys are all defined with the icon and two-decimal quote. A localized `custom_trigger_tooltip` explains the site and authority requirements without exposing raw scripted-trigger names.
