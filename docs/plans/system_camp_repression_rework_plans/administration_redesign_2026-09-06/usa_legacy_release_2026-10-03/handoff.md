## Before and after behavior

Before, availability used strict `support_equipment_1 > quote`, so exactly 180 units could not pay a 180-unit quote. It accepted a selected active camp without proving initialized living custody rows or current administration authority. The effect removed support equipment and changed country pressure before asking the release helper to act, then marked the site reforming regardless of the helper's actual receipt. The shared action router also set its scripted slot cooldown unconditionally, and a rejected native decision kept its up-front PP payment.

After, native and legacy GUI action entry points use the same country/target predicate and the same `camp_rework_equipment_cost.support_equipment` quote. The stock gate is inclusive (`NOT = { has_equipment = { support_equipment_1 < quote } }`). Eligibility requires the original USA authority, a USA-responsible directly controlled active site, an initialized operational site, reconciled positive living custody rows, current authority/provenance, an authorized review or civil-liberties policy, and the absence of `camp_admin_civil_initialized`.

The AI selector scans only the existing `camp_active_site_states` registry and selects a target only through `camp_rework_usa_release_site_ready`. The release helper rechecks the selected target after PP payment, resets and reads the shared release receipt, and publishes the release history, 180-support-equipment debit, pressure relief, site-reform flag, and scripted cooldown only after a positive measured release.

The positive branch applies relief before the existing USA monthly bridge. That bridge projects `wartime_security_reach` from `camp_active_site_count` and clamps reach, displacement, and court pressure. The current tooltip explains that security administration continues while sites are active; the implementation does not create a persistent reach-reduction policy.

The native PP charge remains the decision's single automatic payment; a rejected route refunds that one amount and performs no equipment debit. The native `days_re_enable` was removed because it would create an unconditional engine cooldown for a rejected click; accepted actions keep the same `standard_action_days` duration through the existing success-only scripted cooldown. The GUI route manually pays the same PP quote and refunds it on a failed positive-receipt check.

## Cost, lifecycle, and AI contract

The order spends two resource types: the native political-power quote (`camp_rework_cost.guard_pp`, currently 20) and support equipment (`camp_rework_equipment_cost.support_equipment`, currently 180). The native row displays the PP cost; the support quote in the decision effect tooltip uses a dynamic script constant and the correct texticon. The legacy Ledger cost package remains `support_only`; it uses the same constant. No third hidden resource debit was added.

On rejection, the helper leaves support stock, relief values, release history, intake closure, site reform, and the scripted slot cooldown unchanged. A stale native PP charge is refunded once. The 150-day scripted cooldown is recorded after an accepted receipt, and the replay case verifies that an emptied ledger cannot pay or publish a second release.
