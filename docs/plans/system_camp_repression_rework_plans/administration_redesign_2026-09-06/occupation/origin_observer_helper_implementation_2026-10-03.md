## Implemented APIs

`camp_origin_initialize_host` initializes once and never rebases a previously initialized host from current totals.
An empty aligned host starts normally before admission.
A living host adopts its existing nonnegative occupation observation pair when available and preserves its pending interval.
A live custody-only host without that pair, or a host carrying inherited proportional estimates, gets `camp_origin_baseline_unverified` and sticky ambiguity without an observed loss amount.

`camp_origin_inspect_host_rows` and `camp_origin_host_rows_valid` read existing state custody and immutable-authority occupation arrays.
They check alignment, counts, append-only monotonic IDs, statuses, original state objects, roots, responsible authorities, host filtering and row/aggregate equality.
They export family sums, live row count, mixed lineage and first-row identity/history using only temporary variables.
Each `all_of` scan is guarded at 1,000 rows, matching the vanilla effect-loop bound.
A 1,001-row registry rejects without treating a prefix as complete.
No new registry or target is created.

`camp_origin_observe_host` detects net population decline, new shared territorial Deaths including growth-masked loss, current combined membership headroom mismatch and shared-counter regression.
It records net decline and shared loss separately because they can overlap.
Headroom shortfall is current evidence rather than a repeatedly accumulated death.
Multiple positive rows or lineages with an outside signal/headroom mismatch get sticky `camp_origin_ambiguous` before any owner row mutation.
The first ambiguity sequence remains stable, and original row data stays untouched.
Malformed records get `camp_origin_records_unresolved` and containment.
The module never attributes an original cohort's deaths or creates another physical debit/shared entry.

`camp_origin_host_provenance_ready` supplies a read-only fresh preview.
It rejects sticky ambiguity, unverified or malformed records, pending unique-row reconciliation, an unobserved physical decline, any unobserved shared-counter change and current physical shortfall.
Current authority, route, actor, equipment, costs and target selection remain the owning callers' existing responsibility.

`camp_origin_adjust_known_receipt` consumes the complete one-shot temporary contract:

- `camp_origin_known_contract`
- `camp_origin_known_observation_sequence`
- `camp_origin_known_before_population_k`
- `camp_origin_known_after_population_k`
- `camp_origin_known_before_state_deaths_people`
- `camp_origin_known_after_state_deaths_people`

It verifies the expected common sequence and original baseline, bounded whole-person deltas, nonnegative after image and monotonic measured shared receipt.
It rebases only to the measured after image and observes any remaining current residual.
`camp_origin_known_adjustment_accepted` is baseline acceptance, not a transfer/death/bind success result.
The parent must bind the fields to actual existing physical measurements, commit rows before residual observation and preserve distinct source/destination opening receipts.
Complete zero-net inverse is supported and guarded against replay by the sequence.
Failed inverse quarantine, source/destination residual retention and destructive-operation ordering remain parent-owned.
The fresh preview rejects the existing transfer/custody rollback-failure flags, and observation promotes them into sticky `camp_origin_transaction_unresolved` and ambiguity without inventing an outside death.
The parent must still persist destination containment because the existing source rollback flag alone does not identify every affected endpoint.
This helper never clears ambiguity, including after a measured unrelated credit or known inverse.

## Unique-origin boundary found during implementation

Rebasing an observation interval can otherwise make a second observer forget an unconsumed unique-origin conservative-retirement signal.
The module therefore retains `camp_origin_single_origin_reconciliation_pending`, a before image for the sole exact row and the bounded `camp_origin_pending_single_removal_k` request.
This is a non-spendable request for one proved row, not a mixed unknown-origin population pool.
The readiness preview remains false until the existing owner completes its conservative ledger-only retirement.

`camp_origin_acknowledge_single_origin_reconciliation` consumes `camp_origin_single_reconcile_contract`, `camp_origin_single_reconcile_sequence` and `camp_origin_single_reconcile_amount_k`.
It requires the exact recorded row ID/original/root/authority, the completed before-minus-retired surviving amount, the corresponding outside-removal increment, unchanged row deaths/releases, a valid current aggregate and no new pending physical/shared loss.
It clears only the unique-row pending record and never clears mixed ambiguity.
A partial amount, changed cause history or other false acknowledgment remains rejected.
The owner still performs all row retirement, aggregate/country outside-removal accounting and UI refresh in existing files.
That production owner path is not wired by this worker.
