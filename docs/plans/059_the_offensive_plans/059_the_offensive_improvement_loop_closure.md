# Event 059 improvement-loop closure

## Review mode

This is a manual closure handoff based on the complete `chaosx_improvement_loop_planner` contract. The custom subagent runtime was unavailable during planning. A fresh subagent pass remains mandatory near implementation completion.

## Core question

Does Event 059 need more playable systems, or does its current design already provide enough depth for a permanent global AI behavior event?

## Accepted expansion items

### Distinct strategic layers

The original brief mixed front aggression, production, war declarations, intervention, and risk into one broad instruction. The revised design separates them into baseline conduct, operational persistence, strategic predation, and total-scale risk. This gives each evolution a clear identity and allows independent toggles.

### Material safety envelope

The event now defines supply, fuel, replacement, manpower, reserve, transport, homeland, legal-path, subject, and owner-plan constraints. This is required to prevent the concept from becoming a suicidal-AI switch.

### Country archetype scaling

Majors, regional powers, weak minors, maritime states, landlocked states, subjects, exiles, and special actors now receive different practical expressions of the same posture.

### Dynamic control contract

The design now covers player takeover, co-op control, hotjoin, AI handback, later country creation, release, civil wars, restoration, and save reload without a recurring global scan.

### Evolution entry paths

Each evolution now supports active-event MTTH activation and a pre-fire evolved opening. A late first firing can reflect current Chaos without refiring the event or sending several consecutive popups.

### Cluster correction

The event now has the accepted primary cluster, Diplomacy, with High member severity. The required or optional role, participation chance, and member minimum tier follow the authoritative Diplomacy defaults after repository inspection, with no event-specific participation override.

### Chaos feedback

The event now adds one bounded Chaos gain at the global doctrinal manifestation. Later shared war and death consequences are not counted twice.

### Weighted-behavior proof

The implementation handoff now contains 46 named AI scenarios, rank expectations, veto cases, sweeps, comparisons, and uncertainty rules.

### Player mastery hook

One difficult achievement gives the human player a meaningful event-specific challenge without changing the event's AI-only gameplay premise.

## Rejected expansion items

| Candidate | Disposition | Reason |
| --- | --- | --- |
| Global aggression meter | Rejected | Exposes internal AI data and gives the player no control over it |
| Offensive command scripted GUI | Rejected | Duplicates normal war interfaces and adds no player action |
| Player emergency decision category | Rejected | Existing military and diplomatic systems already provide responses |
| Free defensive bonuses for players | Rejected | Weakens the event and violates the AI-behavior-only rule |
| Baseline random war generation | Rejected | Duplicates Random War and collapses the evolution distinction |
| Direct attack or breakthrough bonuses | Rejected | Replaces strategic difficulty with hidden statistics |
| National focus route overrides | Rejected | Damages country identity and can force invalid paths |
| Research-path overrides | Rejected | Not required by the supplied premise and risks homogenising countries |
| New public mechanic values | Rejected | Hidden conditional scoring is sufficient and more readable through outcomes |
| Dedicated super-event | Rejected | Presentation scale would exceed a Minor Fire-Once doctrine shift |
| Unique audio track | Rejected | A normal report does not justify a separate music package |
| Separate art for every evolution | Rejected | One image is enough to identify a single developing doctrine |
| Event-created country or faction | Rejected | Unrelated to the premise |
| Triggerable setup system | Rejected | Manual event controls already cover deterministic testing |

## Closure test

The event now has:

- a clear activation and persistence model
- a meaningful baseline
- three distinct evolution layers
- strong country and campaign variation
- a full safety and exploit model
- an interaction map
- a Chaos map
- a complete AI scenario matrix
- a player-facing report package
- a difficult achievement
- bounded asset needs
- implementation and audit prompts

Further expansion would mostly add interfaces or content families that do not improve the event's central player experience.

## Closure disposition

Close the planning expansion loop. Carry the accepted items into implementation. Do not add rejected surfaces unless live testing proves that a specific missing behavior cannot be communicated or controlled through existing systems.

Before implementation completion, run the real `chaosx_improvement_loop_planner` subagent with current code, assets, logs, and live evidence. Resolve any new code-specific finding before the final completion claim.
