## Binding user decisions

Doctor Wu remains Event 089, Minor Fire-Once, Chaos level 1, Scientific Research, High member. One valid player or major host receives the doctor, with deduplication and meaningful relocation after refusal. The doctor is fictional and demonstrates his ability before the state selects his mandate.

All compatible technologies belong to baseline progression. There are exactly four evolution milestones at 200, 400, 600, and 800 Chaos. Activation gives zero Chaos, and each needs an active-chain entry and an evolved first-opening form. Disabling evolutions cannot block ordinary research. The detailed evolution design is still awaiting a later part.

Cures address biological disease in eligible living populations. They do not resurrect the dead, erase records, delete independent countries, or replace the owners of famine, migration, contamination, unit families, or shared consequences.

The approved scope includes fictional military biology, engineered zombies, soldier enhancement, cloning, Wu continuity, designed life, Kruger rivalry, and foreign competition. These are retained as requirements for later full-depth parts, not silently removed because this stage concentrates on medicine.

## Conflicts requiring an explicit disposition

### D01. Event 089 already owns technology sharing

P05 calls Event 89 `Tech sharing`. R02 confirms that `chaosx.nr89.1` currently distributes technology-sharing invitations and that later events award group-related political and opinion results. Several choices call Kruger technology-sharing acceptance or refusal effects.

The user explicitly requests Doctor Wu as the new Event 089. The new design therefore keeps that identity, but implementation must not inherit technology-sharing rewards or reinterpret a Wu appointment as joining a research group. Existing group memberships, Kruger posture receipts, and historical logs need an explicit migration decision.

A new campaign can use the reworked root. Existing saves in which the old Event 089 already fired need a separately accepted migration policy. This package does not clear the old fire-once receipt, silently relabel old history as a Wu appointment, or assign the displaced content to an invented event ID.

### D02. The supplied cluster name differs

The supplied cluster catalogue's row 9 is `National Breakthroughs` and lists 89 as its High member. The user's brief instead assigns Doctor Wu to `Scientific Research`, High. The user requirement is preserved in the new design.

This does not authorize renaming the entire existing cluster or moving all its other members. The cluster owner and editable catalogue need an explicit update. The package records the conflict instead of choosing a hidden alias or claiming that Scientific Research is already registered in the supplied snapshot.

### D03. The event catalogue contains displaced descriptions

The supplied row for 89 combines the `Tech sharing` name with a kamikaze-related description, while neighbouring rows also show mismatched descriptions. R02 establishes the inspected code's actual purpose. The new Wu design is grounded in U01, not inferred from those descriptions.

No neighbouring event is rewritten by this task. The catalogue source workbook was not supplied, and exported CSV files remain unchanged. A later editable-workbook update must correct the accepted row without treating the current CSV as the editable authority.

### D04. Shared clones already create reserve manpower

R03 documents ten weekly manpower per full stockpiled clone-equipment cohort, with deployed equipment excluded and captured or transferred stocks benefiting their current holder. It also documents provider refinements that are normally exclusive.

The user forbids an unlimited free-manpower loop. Wu must not award a second manpower stream for the same physical stock. The later replication design must settle paid sustainment, production bounds, continuity, refinement compatibility, and any necessary shared-owner amendment. This stage preserves the documented system and the user constraint without claiming that the tension is already resolved in code.

### D05. Older Kruger biological ledgers are retired in the reviewed amendment

R04's 20 September amendment states that actual equipment and native biological raids own the current biological operation lifecycle. It explicitly retires the earlier separate quantity and reservation ledgers. The same overview reports unresolved source and MCP acceptance work.

The future Wu integration must read the biological-operations owner document and the binding completion contract in full before choosing its interface. It must not resurrect an obsolete parallel ledger based on an older project summary. This is an ownership and accounting requirement for fictional gameplay, not a request for real biological procedures.

### D06. A universal medical interface is a proposal, not an inspected implementation

The user requests dynamic future-proof disease integration. The provided materials do not establish a complete, verified Wu medical registry that already satisfies that request. Parts 3 and 4 therefore describe the required semantic contract and clinical outcomes as proposed design.

Before implementation acceptance, every supported disease needs a verified owner entry and treatment result. Existing treatments, stocks, prospective losses, actors, and contamination owners must be inspected. The fictional medical coverage scale also needs a suitable stock representation and a precise treatment-allocation granularity. None of those runtime checks has been performed here.

### D07. Documentation and tool declarations are not execution evidence

R01 places event implementation summaries under event folders and separates specs, plans, shared systems, and asset evidence. This staged package follows that separation.

The supplied role definitions and tool configuration describe intended workflows. No specialist subagent was spawned, no HOI4 MCP probability or rendering audit was performed, and no live game was run. Mandatory independent improvement-loop and completion reviews remain open. A direct parent review is recorded under its own name and does not substitute for those gates.

## Fictional biological design boundary

The later military and engineered-organism branches must remain non-operational game design. They can define fictional capability categories, strategic costs, control dependencies, deployment permissions, political consequences, and recovery choices. They must not add real agent-level optimization, experimental protocols, cultivation or preparation instructions, real delivery methods, or other practical biological weaponization guidance.

The original user brief is retained unchanged as input. This boundary governs the new expansion, rather than claiming that every scientific statement in the brief has been independently verified.
