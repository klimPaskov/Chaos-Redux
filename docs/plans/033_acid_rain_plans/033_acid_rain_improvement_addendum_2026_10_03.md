## Proposed deterministic aftermath classifier

This is a complete tuning recommendation, not a claim about existing accepted numbers.
Put the proposed fields in one `acid_rain_aftermath` constants group in the existing Event 033 constants file.
Use whole score points and exact elapsed days, retaining fractional protection averages until their specified conversion.
Keep the current tier ceiling of 3, six-day ordinary episode gap, three-day worker cadence and accepted achievement deadlines.

For one consequence window, calculate:

`score = max(0, exposure_points + intensity_points + severe_points + building_points + other_disaster_points + unresolved_transport_points - water_credit)`

| Constant or component | Proposed value and exact meaning |
| --- | --- |
| `exposure_block_days`, `exposure_points_max` | 12 days, 6 points. `min(6, floor(union_acute_days / 12))`. Forecast days and inactive gaps contribute zero. |
| `intensity_weak`, `intensity_standard`, `intensity_strong`, `intensity_extreme` | 0, 1, 2, 3 points for the highest committed intensity in this window. Translate the existing intensity constants, not display text. |
| `severe_points`, `superstorm_points` | 3 and 4. Use the greater applicable value once per window, requiring actual acute impact. No addition for merely forecast, cancelled or retired-before-impact targets. |
| `damage_points_per_score`, `damage_score_max` | 4 actual building-damage points per score point, maximum 4. Count only successful physical applications, not fractional unspent pressure or a target attempt. Preserve family counters for recovery and reports. |
| `other_disaster_points` | 1 if a separately owned, currently unresolved disaster aftermath is proven in this exact state. Never count Event 033's own retained burden again. |
| `unresolved_transport_points` | 2 when current damaged infrastructure/rail or a verified broken operational route is proven. Low nominal railway level is not proof of damage. |
| `water_tier_per_credit`, `water_credit_max`, `emergency_water_tier_bonus` | 2, 2, 1. Accumulate effective water-tier days across actual exposure intervals, average over union exposure days, then credit `min(2, floor(average / 2))`. A live paid water action adds one effective tier capped at tier 4 during its actual effective interval. |
| `tier_one_score`, `tier_two_score`, `tier_three_score` | 3, 6, 10. Scores 0 to 2 give tier 0, 3 to 5 tier 1, 6 to 9 tier 2, and 10 or more tier 3. Equality enters the higher band. |

Sample water and other-disaster context at entry and material transaction edges.
For the existing Event 013 component, read `natural_disaster_state_has_open_card` in `013_natural_disasters_triggers.txt:590`, which requires `natural_disaster_aftermath_active`, family/severity facts and a card state below Closed.
This is a read-only other-owner input and does not permit clearing its card or source.
Integrate protection over the preceding interval before replacing it on a controller or project change, so an instantaneous capture or last-minute water upgrade cannot rewrite earlier exposure.
Do not invent a damage-sensitive native reader where no documented one is available.
If actual damaged transport cannot be proven, retain that component and its acceptance scenario as unresolved rather than substitute `rail_way < 2` or a generic wartime flag.
