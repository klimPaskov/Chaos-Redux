## Dependency order

Resolve native and repository capabilities with the explorer and architect first. After an implementation exists, run country, decision, probability, localization, and completion audits on the actual source. Art roles can work from the accepted asset prompt only after their references are available. Documentation and workbook alignment follow actual accepted results and final text.

The independent improvement-loop planner is mandatory after the design is assembled and again where the implementation workflow requires it. The prepared prompt is not a closure report. The parent must resolve any returned addendum with an explicit accepted, rejected, superseded, queued, or blocked disposition.

The shared UI must remain with the parent and its appropriate framework workflow. The event UI worker is not a generic renderer for shared Event Details or settings.

Conditional roles are not permission to add assets or mechanics simply to employ every profile. Their definitions were read and their relevance assessed. The absence of custom 3D, portraits, focus trees, or super-event audio is an intentional design boundary, not an unreported production shortcut.
