# Mengele improvement-loop addendum

This addendum is a finish-pass improvement loop, not a request to inflate the chain. Use it after the main implementation tranche is in place and before the completion audit.

## Improvement goal

Make the path readable, reactive, and complete. The strongest improvements should connect existing surfaces: Auschwitz authorization, report pressure, camp discovery, the Directorate coup, Tibet Expedition claims, foreign reactions, clone-network decisions, and super-event presentation.

## Improvement pass 1: visible pressure without spoilers

The current source lists several values: `mengele_autonomy`, `mengele_permission_level`, `ss_archive_control`, `ahnenerbe_influence`, `foreign_atrocity_awareness`, and `aryan_origin_preparation`.

The player should see enough to understand the public pressure of the route without seeing hidden future outcomes. Use decision-category scripted localisation, idea tooltips, or a small dossier-style scripted GUI only if the repo already supports that pattern.

Minimum visible summaries:

- Program control status.
- Archive control status.
- Expedition preparation status.
- Foreign awareness status.
- Active closure, review, purge, or escalation options.

Avoid exposing exact coup formula numbers if the current design treats them as hidden.

## Improvement pass 2: discovery and foreign reaction clarity

The genocide crisis system depends on discovery. Make the Mengele path feel connected to this rule.

Improve or verify:

- Discoverer event text and effects when a Mengele-linked site is captured.
- Responsible-country event text and effects after exposure.
- Targeted reactions from the Soviet Union, democratic majors, fascist allies, neutral majors, and Holy Realm when conditions exist.
- Foreign reaction ideas and opinion modifiers that are strong enough to matter.
- No recurring spam for every discovered site.

## Improvement pass 3: decisions with risk and cleanup

Review decisions for passive button-store behavior. Actions that strengthen SS autonomy, classify records, move prisoners, expand facilities, or prepare Tibet should carry fitting costs and risks.

Good costs can include political power for bureaucracy, command or army XP for military review, trains or convoys for transport, equipment for security formations, stability or war support for public strain, and temporary facility or state requirements.

Every decision family needs cleanup after rejection, closure, ideology change, civil war outcome, expedition loss, or final world-order launch.

## Improvement pass 4: super-event quality

The Angel Directorate super-event should carry the moment when the hidden laboratory structure becomes a campaign-scale actor. It should be serious, documentary, and restrained. It should not use gore, perpetrator glamour, or victim spectacle.

Research final quote, button, and audio through the super-event workflow. Replace default art with a final image or record the current final image evidence if the repo already changed.

## Improvement pass 5: clone world-order route validation

If `MCL_the_numbered_world` is live, test the full high-chaos path. The world-end branch must require real network size, strength, major status, ranking, and the replacement-map focus. It should not be reachable through a single focus click or debug-only path during ordinary play.

## What not to add

- Do not add graphic atrocity event art.
- Do not add jokes that reward atrocity escalation.
- Do not add a new random event row unless the repo already has one.
- Do not add a large custom GUI if decision-category text can make the mechanic readable.
- Do not add another expansion addendum while this one is unresolved.

## Closure condition

After these passes, run a completion audit. If the audit finds only small localisation, docs, asset handoff, or validation tasks, write a closure handoff. If it finds missing chain logic, placeholder assets, untested super-events, broken decisions, or unresolved plans, fix those before claiming completion.
