# Dynamic Severity-Aware Cluster Runtime Handoff

## Changed files

- `common/script_constants/event_cluster_constants.txt` centralizes cluster IDs, stable logical row IDs, duplicate-row primary markers, severity floors, cooldowns, Event 013 context slots, activation factors, participation matrix, decay, probability-state bounds, result/status codes, and catalogue sort modes.
- `common/scripted_effects/chaosx_event_cluster_effects.txt` owns the non-UI runtime implementation, including member loading, authoritative eligibility, dynamic activation, persistent probability memory, synchronous trigger dispatch, overlap-safe delayed queueing, history snapshots, and catalogue metrics.
- This handoff is the only documentation file changed by this tranche.

## Runtime interfaces and implementation

- `event_cluster_scan_members_for_activation` is the shared two-pass snapshot. It loads aligned stable row metadata, calls `evaluate_random_event_selection_candidate` for every automatic-context row, matches the existing Settings force context for manual-force rows, applies effective severity floors and High/Severe support only outside force mode, resolves the selected trigger by stable row ID with deterministic duplicate-row primary fallback, and returns canonical status/reason arrays plus eligible and optional counts.
- Cluster-only member-floor and escalation-support failures keep the canonical event-system reason at `none` and use their own member statuses, including `skipped_escalation_support`, so the UI does not misreport a cluster floor as the event's independent Chaos Level.
- Unique trigger-capable rows are marked primary for Wars Events 004/007, Liberations Event 005, Diplomatic Events 008/017, Formables Event 012, Economy Event 018, and Diseases Events 020/002. Duplicate Events 006, 009, and 013 have only their opening logical row marked primary.
- `event_cluster_get_activation_chance` implements the accepted T0-T5 bases, trigger-severity factors, eligible-count factors, fatigue factors, prior optional-participation factors, integer rounding, and 1..90 clamping.
- `event_cluster_get_member_final_participation_chance` implements the accepted six-tier by four-severity matrix, eligible-count scaling, accepted-optional decay, and 1..100 clamping. Trigger and required rows become guaranteed only after authoritative eligibility.
- `event_cluster_get_current_activation_breakdown` is side-effect-free with respect to rolls, history, queues, and persistent probability memory. It accepts an explicit trigger row ID or loaded row index and returns `event_cluster_activation_chance` and `event_cluster_trigger_row_is_eligible` for event-details callers.
- `event_cluster_get_live_trigger_weighted_roll` computes the catalogue By Roll value as the automatic-pool-weighted mean of distinct eligible primary trigger event weights without initializing probability memory.
- `event_cluster_ensure_probability_state` is versioned, lazy, idempotent, non-destructive, aligned to the stable cluster registry, and preserves existing cooldown, history, and fired arrays. It appends missing state entries and marks state not ready when registry or value-array alignment is unsafe.
- `fire_event_cluster_by_temp_id` performs cluster-gate and shared eligibility checks, runtime preflight, synchronous trigger dispatch, automatic fatigue commit, provisional history capture, one cluster pacing update, and delayed queue creation. Queued member status, reason, final chance, and roll settle as the batch dispatches; the completed batch is then immutable and never recomputed from current state. Transactional preflight can legitimately change trigger state, so the trigger is not evaluated again after preflight; every delayed row is evaluated immediately before dispatch. Manual force matches the Settings single-event force context by bypassing automatic-pool and cluster-only restrictions, then relies on the normal event-specific dispatcher to reject invalid runtime context; it never changes automatic memory.
- Queue entries retain batch ID, cluster ID, row ID, order index, trigger flag, history sequence, role, manual mode, optional counters, fired/skipped counters, and Event 013 context. `event_cluster_fire_next_pending_member` rechecks authoritative event fireability immediately before each delayed dispatch, records `skipped_runtime` with a non-`none` canonical reason when invalid, replaces its saved final chance and roll with the numeric N/A sentinel, updates only the matching batch/history row, and finalizes a batch without clearing unrelated overlapping batches.
- The queue preserves the caller-provided start index, so the synchronous trigger is not queued a second time. Automatic optional fired/eligible participation is finalized only after the batch completes, and the trigger is excluded from optional decay and participation accounting.
- History records activation chance, activation roll, manual mode, batch ID, eligible count, and per-row ID, role, severity, declared/effective tier, chance, roll, trigger, status, and canonical reason arrays. Delayed required successes retain `guaranteed`; optional successes use `fired`; manual rows use `manual`; delayed invalidations use `skipped_runtime`. These per-row settlement fields become immutable when their batch completes.
- Cluster catalogue sorting includes live Unlock Tier and Member Count modes and gives unavailable or zero-weight rows sort-last independently of ascending or descending metric direction.

## Validation and evidence

- Source-level review covered the owned constants/effects, resolver, two-pass scan, activation formula, queue lifecycle, history snapshot/update paths, catalogue sort path, and all owned legacy helper call sites.
- The adapter-list discovery route returned `PROBABILITY_ADAPTERS_LISTED`, but the required source-specific `hoi4.probability_inspect` calls for both runtime and constants were blocked by `ARTIFACT_MANIFEST_INTEGRITY_FAILED` before they could produce usable candidates or artifacts.
- The required event MCP route was attempted with `hoi4.event_inspect`; it was blocked by the exact error `ARTIFACT_MANIFEST_INTEGRITY_FAILED`.
- The baseline and post-implementation probability audit routes were assigned to `chaosx_ai_probability_auditor`; the same manifest-integrity failure prevented inspect, evaluate, sweep, seeded simulation, and comparison evidence, so no MCP probability comparison or live engine validation is claimed.

## Remaining risks and limitations

- The Clausewitz engine and the blocked MCP artifact prevented live parse, save-migration, delayed-event, and overlap execution validation.
- The pure weighted catalogue helper avoids probability-state initialization, but the authoritative event evaluator may refresh its own event-specific transient candidate registries while probing a member; no persistent cluster probability memory is written by that helper.
- Legacy helper definitions remain renamed and unreachable for compatibility review; active runtime call sites use the shared scan/evaluator path.
- Legacy pending rows without stable row IDs are migrated with neutral metadata and resolve through the deterministic primary-row fallback, so an old duplicate logical row cannot be reconstructed beyond the information present in the save.
- Parent-owned UI/localisation/event-details files must consume the stabilized detail arrays and selected variables: `global.events_log_cluster_detail_member_role_entries`, `global.events_log_cluster_detail_member_effective_min_tier_entries`, `global.events_log_cluster_detail_member_final_chance_entries`, `global.events_log_cluster_detail_member_trigger_entries`, `events_log_selected_cluster_eligible_count`, `events_log_selected_cluster_roll`, `events_log_selected_cluster_manual`, and status `skipped_runtime`.
