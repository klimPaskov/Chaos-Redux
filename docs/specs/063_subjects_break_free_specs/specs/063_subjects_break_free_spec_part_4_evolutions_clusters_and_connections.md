# Event 063: Subjects Break Free

## Part 4: Evolutions, clusters, Chaos, and event connections

## Evolution structure

Event 063 has three evolution tracks. They change the event's capability. They do not replace ordinary settlement progression and they do not add Chaos merely because they activate.

| Evolution | Chaos requirement | Main change |
| --- | ---: | --- |
| I: Coordinated Breakaways | 200+ | A same-overlord cohort can leave together, increasing batch size and immediate cooperation. |
| II: War of Independence | 400+ | Refused cohorts can enter one compound independence war, and other liberated states can intervene. |
| III: Liberation Pact | 600+ | The shared network can hold a congress and create a formal defensive bloc. |

Each evolution follows the shared enable and disable controls. Disabling one evolution removes only its gated behavior. Baseline independence, recognition, and informal cooperation remain functional.

## Evolution entry paths

Each evolution supports two entry paths.

### Active-event evolution

If Event 063 has already fired, the evolution becomes eligible after the Chaos threshold is reached. A paced milestone then activates it. The normal base pacing should be around ninety days, adjusted by the campaign state.

### Pre-fire evolved opening

If the Chaos threshold is already met when Event 063 first fires, the event can activate the eligible evolution before building that firing's release plan. The first firing then uses the evolved rules immediately.

Pre-fire activation still respects the evolution toggle. It does not create a separate opening event that delays the actual release.

## Evolution I: Coordinated Breakaways

### Activation pacing

Target pacing: roughly `75 to 105` days after eligibility.

Faster factors:

- one overlord has at least three valid subjects
- an Event 063 country was recently freed
- an Independence Wave or Soviet Collapse success has created visible precedent
- several subjects have high autonomy
- a large overlord is losing a war

Slower factors:

- only one or two valid subjects remain worldwide
- all subjects are politically close to their overlords
- recent Event 063 firings already affected most large subject systems

### Immediate change for an active event

Once active, the next Event 063 firing can deliberately construct one same-overlord cohort. Existing independent countries are not retroactively grouped.

### Evolved opening

When activated before the first firing, the release plan first selects an eligible cohort host, then chooses two to five subjects under that overlord. Any remaining release slots use the global pool.

### Cohort rules

A valid cohort requires:

- one former overlord with at least two valid subjects
- at least two subjects that can be released in the same transaction
- no protected conflict between their owner systems
- at least one practical cooperation link, such as shared geography, common war, similar relations, or a common threat

The cohort receives immediate mutual recognition opportunities. Members can exchange access, guarantee one another, prepare joint defense, or coordinate a settlement. They do not automatically join a faction.

The baseline batch range rises by one. Large valid pools can gain one additional upper-end slot. The total hard cap is eight.

### Cohort diversity

Evolution I should not always choose the largest empire. Host selection considers eligible subject count, autonomy pressure, overlord weakness, and recent breakaways, while preserving a nonzero chance for smaller systems.

Only one coordinated cohort is created in a firing. Remaining selections should restore geographic and overlord diversity where possible.

### Failure behavior

If the chosen cohort falls below two valid reservations before release, the plan reverts to ordinary global selection from frozen fallbacks. The evolution remains active for later firings.

## Evolution II: War of Independence

### Activation pacing

Target pacing: roughly `80 to 120` days after eligibility.

Faster factors:

- an unresolved contested settlement exists
- a former overlord has refused several subjects
- a valid coordinated cohort exists
- a released country has mobilized
- the Liberation network has begun guaranteeing breakaways

Slower factors:

- no safe former-overlord war topology exists
- most recent separations were recognized
- the valid subject pool is very small

### Immediate change for an active event

Contested settlements gain an escalation route. The next refused cohort can enter a compound independence war if safe. Existing contested states can receive a later ultimatum or mediation sequence, but the activation itself does not start a war.

### Evolved opening

The first firing at this evolution uses stronger military evaluation. Armed refusal becomes a meaningful outcome for viable cohorts, and the event prepares intervention requests before war begins.

### Compound-war rules

- one compound war for the refused coordinated cohort
- other armed refusals against different overlords can open individual independence-war theaters
- at most two new independence-war theaters per firing across compound and individual wars
- one breakaway war leader
- one restore-subject objective for the former-overlord side
- unsafe cohort members remain contested outside the war
- no duplicate pair wars
- no broad annexation or conquest goal
- no direct war if both sides are trapped on the same side of an external war

### Intervention rules

The network and Pact use a support ladder:

1. recognition
2. equipment, fuel, convoys, or industrial burden
3. advisers or volunteers
4. guarantee
5. direct war entry

Most supporters should choose levels two or three. A theater can have no more than three direct liberated-state interveners. A large faction can still become involved through ordinary war rules, but Event 063 should not force a global call.

### War resolution

- breakaway victory or a white peace that preserves independence produces recognition
- former-overlord victory normally restores subject status
- former-overlord disappearance produces recognition
- long stalemate opens mediation
- event-created temporary claims and goals are cleaned after settlement
- support fulfillment and abandonment affect later network trust and Pact cohesion

## Evolution III: Liberation Pact

### Activation pacing

Target pacing: roughly `100 to 150` days after eligibility.

Faster factors:

- at least four compatible active liberated states exist
- several liberation origins are represented
- an independence war is active
- multiple guarantees or aid links already exist
- repeated former-overlord pressure has raised demand for collective defense

Slower factors:

- fewer than three viable network states exist
- all active states are already bound to unrelated factions
- severe disputes divide the available candidates

### Immediate change for an active event

Eligible liberated countries gain access to congress preparation and Pact invitation logic. The evolution does not create the faction automatically.

### Evolved opening

When active before Event 063 first fires, newly released countries enter the network with congress eligibility already available. The Pact still requires real compatible members and a successful congress.

### Pact behavior

The formal Pact uses the design in Part 3. It gains one public value, Liberation Cohesion. It can defend members, recognize breakaways, coordinate material support, mediate disputes, and pressure remaining subject systems without directly freeing countries.

## Evolution logging

Each evolution logs one milestone through the shared evolution pipeline.

### Evolution actor

- Evolution I actor: the strongest or most diplomatically central member of the first coordinated cohort
- Evolution II actor: the breakaway war leader in the first compound independence war
- Evolution III actor: the Pact founder after a successful congress

If an evolution activates but its defining outcome has not happened, the activation can be recorded without a country actor only when the shared event log treats the evolution state itself as the milestone. A later defining incident should not duplicate the same stage. The preferred design is to log the first concrete use of each evolution with the actor above.

### Evolution display direction

The event-detail catalog should explain the capability of each evolution. The history views should show the actual date, actor, tier, and stage of the logged milestone. Catalog previews must not display fake history dates or sequence numbers.

### Chaos design conclusion

Event 063 is destabilizing, but its central outcomes are already first-class shared Chaos sources. A separate Event 063 premium would count the same liberation, war, faction, or puppeting fact twice. The event's anti-farming work therefore belongs in target cooldowns, actual-transition checks, one war opening per theater, and one origin write per successful release.

## Liberations cluster

Event 063 is a Medium member of the `Liberations` cluster, Cluster ID `2`.

The current cluster contains:

- Event 005 Soviet Union Collapse, High member
- Event 006 Independence Wave, Medium member
- Event 063 Subjects Break Free, Medium member

### Cluster role

Event 063 contributes the existing-subject release surface. Event 005 handles Soviet republic collapse. Event 006 creates new countries from valid liberation candidates. These three members can produce one connected liberation crisis without sharing private release code.

### Cluster transaction coordination

Before any member performs a release:

1. the cluster prepares one shared release-coordinator generation
2. each member builds its own candidates
3. each member reserves its own subjects, tags, anchors, or states
4. conflicts are resolved before country changes begin
5. members execute their own release logic and history
6. joint presentation summarizes the combined incident
7. the cluster counts as one global pacing event

Event 063 does not use Event 006 fallback tags or state assignments. Event 006 should exclude countries and states held by Event 063 relations only when they overlap a protected transaction.

### Member participation

The event is normally an optional Medium member. It can participate when at least one valid subject exists. When no subject exists, the cluster records an ineligible reason and does not fire an empty Event 063 report.

A cluster firing can use Event 063's active evolution rules. The cluster does not bypass evolution toggles or turn an inactive evolution on.

### Cluster presentation

The cluster report should group the results by member event:

- Soviet successor releases
- Independence Wave country creations
- subject states that became independent

The report should not flatten all countries into one ownerless release list. Each event keeps its own actor, origin, and history.

## Domestic Unrest secondary cluster

The user-assigned secondary classification is `Domestic Unrest`, Medium member. The current cluster catalog export contains no registered Domestic Unrest row or stable ID.

Event 063 should join that cluster when the cluster is formally registered. The event specification does not invent an ID.

### Intended secondary role

In a Domestic Unrest cluster, Event 063 represents unrest reaching a dependent government and turning autonomy pressure into full separation.

The Event 063 member is eligible when:

- at least one valid subject exists
- the current Domestic Unrest incident has an overlord or region that can provide relevant pressure
- the release coordinator can reserve the subject safely

The cluster can bias the candidate pool toward subjects of an unstable overlord. It cannot bypass the frozen transaction, release cooldowns, or owner-system exclusions.

### Primary mapping rule

Until the project supports one event initiating several clusters, Event 063 remains primarily mapped to Liberations. Domestic Unrest can list Event 063 as an optional member when another unrest event starts that cluster. One selected event should never expand into two clusters during the same random-event resolution.

## Connections with existing and planned events

## Event 005: Soviet Union Collapse

Compatible Soviet successor states can join the liberation network and Pact. Event 005 retains ownership of republic release, splinter identities, authority, crisis values, military packages, and the Free Republics' League.

Event 063 can later free a Soviet successor that became a subject. It preserves the Soviet first origin and records Event 063 as the latest liberation.

## Event 006: Independence Wave

The events share neutral provenance, compatibility, recognition, aid, and Pact eligibility. Event 063 never writes the Event 006 release ledger, creates an Event 006 country package, assigns an Event 006 anchor, or unlocks its formables.

A country created through Event 006 can later be freed through Event 063 after becoming a subject. Its original package and first origin remain intact.

## Event 062: Allies Backstab

A country reserved for expulsion and war through Allies Backstab cannot be processed simultaneously by Event 063. The release coordinator resolves ownership before either event changes faction or subject status.

A former subject already freed by Event 063 can later be expelled from an alliance through Event 062. The events should not treat that ordinary later sequence as a collision.

## Event 077: Equipment Aid

A later equipment-aid design can recognize threatened liberated states as high-value recipients. It must transfer real donor equipment and use its own targeting logic. Event 063 should not invoke Event 077 directly or fabricate the donation.

## Event 078: Border Conflict

A contested settlement can open an Event 078-compatible border incident only when the former subject and overlord share a land border and are not already at war with each other. Event 078 retains ownership of its incident mechanics.

The countries may be fighting other wars. Only a direct existing war between the pair blocks the border-conflict route.

## Event 095: Occupation Revolt

Occupation Revolt concerns occupied territory and exiled or dormant claimants. Event 063 concerns existing subject countries. Their candidate pools should not overlap during a protected transaction.

A future owner-approved adapter can register a successful occupation revolt in the liberation network. Event 063 does not assume this connection before Event 095 defines it.

## Event 119: Random New Alliance

Random alliance creation should treat the Liberation Pact as an existing faction. It should not create a duplicate alliance from current Pact members or force a Pact partner to leave another faction.

## Event 121: The Pact

The planned generic guarantee pact remains separate. Event 063's Pact is origin-gated, congress-based, and focused on liberation security. Event 121 should not overwrite its faction, cohesion, or membership rules.

## Event 127: Warlords

Subject demands for greater autonomy can raise Event 063 candidate pressure, especially when the overlord refuses. Event 127 cannot directly release a country through an Event 063 helper.

## Event 128: Autonomy

A global autonomy increase raises the weight of subjects that approach independence. Event 063 still performs its own frozen candidate selection and settlement.

## Event 133: Gandhi

Event 133 concerns independence movements in non-core occupied territory. It can later register successful independent countries through an owner-approved neutral adapter. Event 063 does not convert occupation movements into subject countries or assume Event 133's nonviolence rules.

## Event 144: Freedom or Death

Event 144 remains a separate mass crisis in which subjects across the world declare independence and form the National Liberation Front. Event 063 must not absorb that identity.

The boundary is:

- Event 063 uses a bounded recurring release batch
- Event 063 preserves mixed peaceful and hostile settlements
- Event 063 builds an origin-based network and optional Liberation Pact
- Event 144 is reserved for a near-universal declaration, a named National Liberation Front, and simultaneous mass wars

Event 063 evolutions should not become a disguised implementation of Event 144.

## Event 153: Random Guarantee

Freed countries can be valid guarantee targets through ordinary rules. Event 153 should not duplicate an existing Pact guarantee or select a country whose current war makes the guarantee meaningless.

## Cross-event acceptance

- no two events release or replace the same country in one transaction generation
- every owner writes only its own private ledger
- first origin is preserved across later re-release
- current network status follows the country's live independence
- cross-event aid and recognition are bounded and compatibility-gated
- generic alliance events recognize the existing Pact
- Event 144 retains its separate mass-crisis concept
- no unregistered Domestic Unrest cluster ID is guessed
