## Living MAC integration contract

There are three explicit country entry modes. **Event-created** means the legitimate MAC identity did not exist as an active country and Event 110 owns its new setup. **Existing IMRO government** means a live MAC already has compatible IMRO government and receives missing event systems once. **Existing other government** means IMRO begins as an internal political movement and external territorial network within the living country's retained constitutional context.

Store an overlay receipt with actual tag, original tag, current tree owner, source package, current route, completed and active focus identity, character ownership, existing institution ideas, native ledgers, forces and active missions. It is a provenance map, not a rollback snapshot that authorises restoring an old world after real changes.

Pre-country IMRO is an event-owned NPC territorial organisation, not a temporary tag. Its autonomous operations consume only actual local support, cadres, time and physically sourced matériel. Any PP, CP, factory or national manpower payment has a real country payer that explicitly chose the action. A foreign sponsor's panel controls its own contribution and can recommend a rising, but cannot select the movement's political response as if it owned the country. Existing non-IMRO MAC opposition cannot charge the incumbent treasury without a lawful coalition or reform commitment. Optional human country switching occurs only after a real IMRO country exists.

Author IMRO-specific focus groups as shared-focus modules that the current framework owner includes conditionally for the reconciled MAC overlay. The integration uses static native graph inclusion verified against current syntax and observed focus rendering. It does not call a runtime tree replacement on a living Event 006 country. A dedicated full IMRO tree is assigned only to Event 110-owned creation with the setup receipt proving that right.

## Population and terminal correctness

The pinned `apply_exact_state_civilian_population_loss` helper computes its apparent applied result before mutation and can route logging with `chaos_deaths_apply_state_pop = 1`. The supplied newer documentation promises stronger measured behaviour. Existing camp and transfer callers show a safer compatible adapter: turn direct helper logging off, measure population before and after the one physical debit, then register only the observed loss with `chaos_deaths_apply_state_pop = 0` and `chaos_deaths_record_state_ledger = 1`.

Do not use `damage_buildings_in_random_states` as a shortcut for this campaign's population branch. Audit its actual shared semantics before any population use. Ordinary war casualties must not be charged twice when the native military owner already registered them. Death-linked Chaos remains with the shared Deaths owner.

The current Deaths-disable flag suppresses the shared ledger, not merely its window. The required owner change separates optional display from authoritative campaign accounting, retains documented death-linked Chaos behaviour and does not temporarily change global user settings around a call. No Fallout override flag is an acceptable substitute. If the actual setting is intentionally defined to disable the ledger entirely, the implementation must expose and resolve that contract through the shared owner before claiming the full campaign works.

The complete-human census needs carrier ownership evidence. Country classification alone cannot erase humans living in territory occupied by an actual nonhuman country. A human extremist regime is always human. A genuine transformation into a nonhuman population can change accounting only through its own measured, documented owner, with no unexplained disappearance. Unknown biology or overlapping cohorts block extinction.

Normal resident and migration updates invalidate affected census records at their actual transaction boundaries. Military recruitment, demobilisation, casualty, surrender and transfer need proven current-engine hooks and a documented overlap model. The design uses a sparse set of active carriers and affected states. A final complete world census is an event-triggered verification when the maintained total approaches a candidate zero, not a new daily or monthly whole-world maintenance scan. A later birth, arrival, rescue or surviving-person creation invalidates the candidate before the terminal receipt.

## DLC and capability parity

Core uprising, autonomy, country politics, the global subject breakaway, Front membership, master response, conquest, population losses, resistance and defeat must work without DLC. Optional espionage, native raids, faction features or subject-system enhancements may improve the presentation and interactions, but they cannot be the sole path to a required outcome.

Where an optional native feature is absent, provide an equivalent ordinary decision or event transaction with the same cost, time, consent, risk and outcome. This is an intentional platform parity route, not permission to omit a mechanic. Do not use DLC-only covert operations as the only way to oppose the radical regime. Native raids, if included for a specific military operation, require their own actual schema and equivalent base-game route. No custom raid is mandatory merely because its skill was supplied.

## Implementation order and release gates

First reconcile IDs, country ownership, exact map bindings and the current native release, faction and peace semantics. Prove selective master acceptance and the complete living-human accounting model before declaring the full feature technically achievable. Build neutral receipt and population adapters with their owners, then the local movement, country and focus modules, then regional and worldwide transactions, then the radical and terminal systems. Presentation, assets, localisation and AI proceed against stable accepted contracts with continuous parent review.

The required production gates are complete historical identity and source rights, current installed tag and map audit, native GUI and focus evidence, sourced portraits and audio, full custom-unit model and counter package, exact action and treaty receipts, calibrated route-aware AI, current workbook migration and a complete spec-to-source crosswalk. No implementation may be called complete with a renamed generic branch, silent fallback, missing asset state, unresolved accepted addendum or unproven required transaction.

Planning completion means this package specifies the intended mechanics and honestly identifies the remaining evidence gates. It does not mean those gates have already passed. The source-reading record and final review disposition document what was actually read, reviewed and produced.
