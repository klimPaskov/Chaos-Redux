## Architecture findings and dispositions

| ID | Finding | Disposition and resulting contract |
| --- | --- | --- |
| AR01 | An unknown write result cannot be treated like a clean failed candidate. | Implemented in Parts 2 and 4 and the handoff. An ambiguous or unintended native result stops further writes, preserves incident evidence, and persists quarantine across reload. Every Rule write route remains blocked until verified reconciliation. |
| AR02 | A later transition could mask an earlier successful transition and tempt the implementation to repair the batch after irreversible writes. | Implemented in Part 2. Prospective compatibility filters destinations before the random draw and write. Every accepted prefix row must retain a material consumer. When that prospective proof is unavailable, use a conservative directed incompatibility exclusion. |
| AR03 | A claim of globally uniform selection would be inaccurate after recency and IV categories are applied. | Implemented in Parts 1 and 2. Selection is uniform among rules in the active category and recency stratum, followed by uniform choice among that rule's prefiltered valid destinations. |
| AR04 | Persistence omitted several pieces of same-day and deferred-presentation state. | Implemented in Part 4 and the handoff. Durable state includes the increasing request counter, rejected IDs, immutable receipts, pending delivery, pinned acknowledgement context where used, and quarantine. |
| AR05 | A newly touched rule could accidentally inflate IV's revision footprint or be treated as a same-request revision. | Implemented in Part 3. Freeze initial fresh and revisable identities, quota inputs, and each row's provenance before the batch writes anything. One native identity can be attempted only once in a request. |
| AR06 | Globally authoritative storage for country AI rule settings had been expressed too strongly. | Implemented in Part 4. Shared native authority is an admission requirement that must be proved for each accepted rule. It is not assumed from a country-oriented name or a script consumer. |
| AR07 | Once-only wording could be read as forbidding later legitimate changes to the same rule. | Implemented in Part 4. Each committed transition applies once to native state regardless of recipient count. Later authorised firings may create new transitions under the revision rules. |
| AR08 | Request rejection could precede unique identity allocation in one handoff diagram. | Implemented in the handoff and coding prompt. An actual dispatch request receives its durable identity before reject-capable execution gates. Repeated pure availability checks allocate nothing and consume no random draws. |
| AR09 | Reducing a confirmed subset after an incident could erase provenance that had already been verified and committed. | Implemented in Part 2 and the handoff. Preserve the earlier row's immutable evidence, touched membership, and visited destination under incident or reconciliation status. Ordinary outcome counts, achievement credit, and Chaos use only the final safely confirmed meaningful subset. Reconciliation cannot silently double-award or reset novelty. |

The first seven architecture findings were closed in the architect's narrow follow-up review.

The parent applied both, and the improvement planner and documentation curator subsequently checked the updated Part 2 and handoff.
The transaction remains a finite best effort batch with verified mutation before successful shared accounting.

## Retained design depth

The planner's review retained the four distinct evolution roles.
The baseline accumulates first-time changes.
I adds a small chance of another rule.
II introduces genuine revisions.
III increases count with current Chaos.
IV reshuffles a larger mixed set and uses the size of the currently revisable footprint.
Each stage has independent settings and a durable unlock, while all destinations stay non-default and different from current.

The twelve candidate families define a broad investigation and admission scope.
The evidence distinguishes exact option names found in inspected sources from a certified production allowlist.
Strict non-default destinations make binary rules exhaustible, so the later stages depend on a genuinely revisable native pool.
The maximum eight-rule fixture and four-revisable-rule breadth target expose that dependency explicitly.

Repeated firings use current native state, material consumer witnesses, compatibility, finite selection, and soft previous-batch respite.
Distinct campaigns can therefore develop different rule combinations without the event needing permanent management mechanics.
The Chaos award uses bounded first-touch and destination novelty, with no repeated oscillation reward and no extra award merely for an evolution or acknowledgement.

Campaign interaction contracts keep actual diplomacy, partition, and warlord consumers responsible for legal actions and pending objectives.
They preserve completed outcomes and give newly impossible pending work an accepted alternate or neutral closure through its owning system.
The three achievements reward sustained military or coalition accomplishments under changed rules and use the existing achievement framework.
The presentation uses the existing report, history, and achievement surfaces.
The asset plan is bounded to one report texture and nine achievement-state textures.

No additional focus tree, event-owned news system, auxiliary currency, player rule-selection menu, or permanent Rule screen is needed to supply the requested depth.
No improvement was deferred merely to keep the document short.
