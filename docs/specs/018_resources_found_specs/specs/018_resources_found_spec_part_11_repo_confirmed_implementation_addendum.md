## Source-of-truth corrections from public repo evidence

### Keep the existing event identity stable

Implementation should start from the existing Event 018 id and namespace unless the local repo has already migrated it. Renaming the internal file to `018_resources_found` is optional and risky unless all event log, localisation, sprite, news, and registration references are updated in the same pass. The cleanest implementation route is likely to rework `events/018_random_resource.txt`, keep the stable namespace, and introduce event-owned companion files for the new mechanics.

### Preserve the new baseline over the old amount

The old public file adds 200 of a resource. The user requested around 100 of one random resource. The canonical design now distinguishes three resource amounts:

| Layer | Resource amount direction | Reason |
| --- | --- | --- |
| Baseline discovery | Around 100 of one random resource in one valid state. | Preserves the user request and keeps the event a positive economy-cluster minor repeatable event before exploitation begins. |
| Exploited field | Additional deposits through decisions, missions, and investment, with increasing safety risk. | Lets the player choose greed, safety, trade, concessions, or closure. |
| Evolved opening or repeated rich discovery | Multiple large deposits or every resource type only when the evolution stage justifies it. | Keeps evolved chaos from replacing the ordinary baseline. |

## Public repo-derived helper decisions

### Use shared nonhuman classification

The Cave Host must be added to the shared special-country and nonhuman-country triggers. It should not get only an event-local check. The implementation should register it through the same shared surfaces that already classify zombies, the Death country, and other nonhuman chaos actors.

### Fold into shared world threat state

Once the Cave Host is public and aggressive, it should contribute to the shared world-threat framework. The likely pattern is a source flag such as `world_threat_source_cave_host` read by the shared refresh effect, then cleared when the Host is defeated or no longer meets threat rules. This avoids creating a parallel global threat system.

### Use or improve existing population-loss helpers

The public repo contains a state-scope population modification helper. The implementation should inspect current local semantics and decide whether to use it for worker sickness, cave-site deaths, city attacks, and evacuation losses. If the helper logs debug output or has unsuitable defaults, the coding agent should improve or wrap it before using it broadly.
