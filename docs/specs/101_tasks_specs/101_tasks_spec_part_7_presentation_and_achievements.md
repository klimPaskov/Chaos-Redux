# Event 101: Presentation and achievements

## One readable commitment

Use one ordinary decision category for the active task. It contains one non-selectable timed mission. The six task families are internal content choices, not six visible tabs or buttons. The selected design has zero Event 101 gameplay buttons and zero Event 101 spendable entry costs. Existing military, construction, diplomatic and crisis actions retain their own interfaces and costs.

The category presents one primary progress or status summary and the native remaining time. Prefer a meaningful count where it describes the objective clearly. Use a percentage only for truly divisible work. A strict protection task shows its protected target and uninterrupted window rather than an invented percentage of safety.

The category closes after the task report is acknowledged and the active mission is retired. A recent result can remain in the shared event history. It must not leave empty obsolete missions or a wall of old task rows. Task achievements and anti-repeat history remain private tracking, not another management panel.

## Information by surface

| Surface | Required content | Presentation rule |
| --- | --- | --- |
| Assignment report | The in-world situation and the country receiving an urgent task | Brief narrative, family-appropriate report image, informational acknowledgement |
| Mission row | Objective identity, one progress measure and native countdown | Useful short wording, correct family icon, no raw trigger dump |
| Mission tooltip | Exact targets, permitted methods, requirement, hold rule, deadline, reward, failure and partial rule | State facts in a consistent order, keep costs separate from retained requirements |
| Category description | Why the task matters and where to act | A few concise lines, no second copy of every tooltip value |
| Map highlight | Exact named states or supported position | Highlight the committed targets, not every candidate in the generator |
| Result report | Actual success, partial result, failure or neutral external closure | Name the real result and actual applied effects, avoid claiming work that was not proved |
| Shared event history | Assignment actor and terminal task outcome | One committed assignment and one exact terminal result, stable identities |
| Event Details and catalog Details | The event's premise | Do not list the full effect, tuning or technical contract |

Long country or state names must wrap or fit within the native surface without hiding the requirement. Large numbers use integer formatting where the unit is indivisible. Dates use the actual shared calendar consumer. Progress descriptions distinguish delivered, built, produced, fielded, controlled and maintained conditions.

The light report background uses plain text without embedded color codes. Supported dark mission tooltips can use native emphasis and texticons. A missing texticon is a production defect, not a reason to replace it with a long literal resource label.

## Text direction

All player-facing prose is to be written during implementation. This package deliberately contains directions rather than pasteable localisation.

Assignment text should identify the concrete pressure or opportunity, the institution or command issuing the task where appropriate, and the expected public result. The voice should fit an urgent government report from the campaign period. It should not invent an omniscient supernatural taskmaster for the baseline event.

The mission wording should make the exact action and target obvious. Avoid vague administrative nouns, dramatic slogans, repeated headings, incomplete fragments and claims that a successful declaration proves delivery or construction. The objective must describe the predicate that the script actually tests.

Success text should connect the country's completed work to its reward. Partial text should acknowledge the useful result and the remaining shortfall. Failure text should name the missed objective and the resulting limited setback. Neutral cancellation text should explain the external change without blaming the player or pretending it was success.

Every report option is an acknowledgement with no gameplay effect. Its reaction direction follows the family: professional commitment for offensive work, resolve under pressure for defense, practical readiness for preparation, confidence in useful work for industry, measured responsibility for diplomacy and focused recovery for crises. Terminal acknowledgements react to the actual outcome and never imply a paid choice, a new order or a reward claim. Write the final concise option text only during localisation.

Higher Stakes should sound more demanding through the actual assignment. Trials Under Pressure should refer to the pressure that exists. Chaos Tasks can reflect an unusual owner episode, but should not overwrite that event's established voice or reveal hidden future phases.

Do not use em dashes or semicolons in authored player prose. Use concrete complete sentences, preserve correct campaign names and native dynamic tokens, and keep technical state, tuning, patches and implementation history outside the game text.

## Visual identity

The task family should be recognizable from its mission icon. Use original, compact period-appropriate symbols with clear silhouettes at native size. Related families can share material treatment while keeping distinct subjects. Do not create all six by recoloring one icon.

| Family | Icon direction | Report-image direction |
| --- | --- | --- |
| Offensive | A captured field objective or compact forward marker with an unmistakable military silhouette | Period troops securing a road junction or position, without modern equipment or spectacle |
| Defensive | A protected position represented by a strong defensive object | A prepared defensive position being maintained under real pressure |
| Preparation | Equipment and formation readiness expressed through one clear combined symbol | Crews preparing equipment or training a usable force |
| Industrial | A substantial tool or active industrial component | Workers commissioning useful industrial or transport capacity |
| Diplomatic | A concrete exchange or agreement symbol | A practical diplomatic or aid exchange with period-appropriate setting |
| Crisis | A recognizable emergency-response symbol | A grounded recovery or emergency-coordination scene suited to multiple owner episodes |

Use six family report images. They may serve assignment and outcome reports for their family when the scene remains truthful to both. Their text communicates the actual outcome. Do not place a triumphant scene behind a report of failed defense. Select neutral operational compositions that support both uses.

The ordinary category uses one restrained icon and one static picture. The picture can show period dispatch materials and an analog time cue without readable invented text. It remains decorative. All counts, dates and actions are native text or controls. A static picture is appropriate because the category contains only ordinary text and one native mission.

The two visible temporary outcome carriers use separate original idea icons. The positive carrier depicts a fulfilled national commitment through one compact practical symbol. The negative carrier depicts a missed commitment and resulting administrative burden without looking like national collapse. Their effect tooltips identify the actual currently selected capability. Do not shrink a mission icon to create either idea icon.

## Achievement eligibility

Achievements belong in the existing shared achievement registry and its actual ID reservation workflow. The logical identifiers below are proposed Event 101 identifiers. They are not a claim that numeric registry IDs have been reserved.

All achievements require a valid country identity, human control throughout the credited task, full success and a natural Event 101 assignment. The exact task opportunity must not come from a forced event start, manual scenario shortcut, CXT grant or debug alteration that made the requirement achievable. Follow any stricter existing shared campaign-wide achievement disqualifier as well.

Partial success, failure, neutral cancellation, invalid setup and AI resolution never grant full-success credit. Reloading does not erase disqualifiers or repeat awards. A country restored under a reused tag cannot inherit another country's achievement progress. Legitimate cosmetic changes of the same country preserve it.

Each full result writes a compact country-owned achievement fact once, bound to the task generation and owner outcome where relevant. Use bounded sets or fixed counters for family and owner coverage. These values are internal achievement tracking, not public task currency.

Six achievements are visible as locked goals when Event 101 is enabled in a supported campaign. The three-crisis achievement remains hidden until Chaos Tasks first activates in the campaign, then becomes a visible locked goal. Follow stricter registry visibility rules where they govern an unsupported or ineligible campaign. None unlocks merely from enabling the event.

The capital-defense and three-crisis goals are Very Hard. The other five are Hard. These labels describe the intended difficulty, which still requires natural-campaign opportunity testing.

## Presentation acceptance

Inspect the native mission and report sources and use available renders for meaningful states: assignment, no progress, intermediate progress, ready to complete, last day, full success, partial result, failure, external cancellation, missing owner and long names. Verify the countdown and tooltip contracts through pertinent references and task-specific checks, disclosing any unobserved native behavior. Follow [current authority and workflow](README.md#current-authority-and-workflow) for retry limits and source review when optional renders are unavailable.

Use the smallest actual native surface that communicates the task. Source-only screenshots, an unrelated report render or a mockup with painted controls do not prove the production state. The implementation handoff records available evidence, meaningful verification limits and the owner responsible for each check. User-owned live-game validation is not an awaited delivery step.
