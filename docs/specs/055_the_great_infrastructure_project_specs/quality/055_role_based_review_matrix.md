# Role-Based Review Matrix

## Improvement loop planner review

### Playable promise

The player receives an extraordinary immediate infrastructure transformation and then manages national or multinational megaprojects that respond to geography, diplomacy, supply, war, and maintenance.

### Initial weakness found

The rough concept listed many project families but did not yet define a common project object, candidate generation, failure recovery, repeat-firing value, operational status, or limits on visible decisions.

### Improvement applied

The final design adds:

- one public National Works Capacity value
- stable geographic proposals
- staged construction
- partner agreements
- project status and repair
- route persistence
- repeat-firing assistance
- same-actor resource cluster synergy
- humanitarian and embargo adapters

### Stop decision

Broad expansion should stop after these systems. A focus tree, new country, dedicated GUI, super-event, portrait, 3D bridge model, or animated category would add maintenance without improving the core loop.

## Decision and mission auditor review

### Category clarity

- one ordinary decision category
- one public custom value
- three normal proposals
- one to three active missions
- no more than six primary actions in one state

### Cost clarity

- no action exceeds four spendable cost types
- costs fit the project stage
- political power is used for charters and agreements, not as the only generic price
- trains, trucks, convoys, support equipment, fuel, and civilian burden have distinct roles
- steel is modeled through access and industrial diversion because it is not a stockpile

### Mission quality

- survey, negotiation, construction, commissioning, repair, and rerouting require real route conditions
- main construction auto-completes after conditions and time are met
- passive stockpile checks alone do not count as project objectives

### Exploit findings addressed

- survey cooldown
- stage-based salvage
- no experience from abandonment
- no duplicate family counting
- no partner contribution refund loop
- no future conquest infrastructure grant

## Scripted system architect review

### Ownership

Event 55 owns project lifecycle, route identities, proposal generation, capacity, partner receipts, and cleanup.

Shared classifiers answer only ordinary civilian and nonhuman routing.

Famine, Migration, Embargo, Natural Disasters, and Resources Found keep their ledgers.

### State model

Persistent state needs:

- recipient record
- proposal generation
- project generation
- project family
- route nodes
- critical states
- partner roles and receipts
- construction method
- stage
- status
- completion and transfer history

### Performance

- sparse registered recipient list
- bounded critical-node lists
- monthly recipient refresh rather than whole-world scan
- event-driven route invalidation where possible

### Public API direction

Event-owned adapters should publish route capacity and status to Famine and Migration and consume embargo, disaster, and resource facts.

No shared dynamic helper should be added unless several unrelated systems need the same neutral operation.

## AI probability auditor review

The package defines named target, project, method, partner, and failure-response scenarios.

Hard zero cases are separated from weighted preference.

No exact probabilities are claimed before a complete pool exists.

Implementation requires inspect, evaluate, owner patch, and compare against the same scenarios.
