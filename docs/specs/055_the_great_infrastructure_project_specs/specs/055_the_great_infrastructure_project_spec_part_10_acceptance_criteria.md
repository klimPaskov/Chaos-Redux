# Event 55 Specification, Part 10

## Acceptance Criteria and Completion Contract

## Completion meaning

Event 55 is complete only when the opening grant, project program, candidate generation, lifecycle, evolutions, AI, integrations, assets, achievements, event logs, documentation, and catalog agree.

A popup plus maximum infrastructure is not a complete implementation. A decision category with generic construction buttons is not a complete implementation. A large set of project decisions without route persistence, AI, damage, and cleanup is also incomplete.

## Event identity

- Event ID remains `55`.
- Entry event remains in the `chaosx.nr55.*` namespace with canonical root `chaosx.nr55.1`.
- Event type is Minor Repeatable.
- Chaos level is `1`.
- Cluster is Positive Economy, cluster ID `7`.
- Member severity is Medium.
- Event name and identity match the user's brief.
- The stale shifted catalog description is corrected through the authoritative workbook.

## Targeting

- The event selects one valid random ordinary country.
- Player and AI countries can be selected.
- Ordinary civilian-system and nonhuman exclusions are respected.
- Fully capitulated and unusable project actors are excluded.
- A first-time recipient has at least one valid project family.
- Never-served countries are strongly preferred.
- Recent recipients have zero target weight for a long cooldown.
- Existing recipients remain eligible after the cooldown.
- Weighted target behavior has named probability scenarios and compare evidence.

## Opening grant

- Every state owned by the first-time recipient receives maximum constructed infrastructure.
- The grant is based on ownership at firing time.
- Future conquests do not receive automatic maximum infrastructure.
- Active damage is not erased unless the supported engine effect unavoidably treats it that way and the final implementation documents the exact behavior.
- No other building is granted through the opening effect.
- The same country cannot receive the opening grant twice.
- A repeat firing never uses state acquisition to create another grant.

## Persistent category

- The recipient receives a persistent Event 55 decision category.
- The category uses an ordinary category surface with a static picture and compact status header.
- The category has no dedicated event-owned scripted GUI unless a later accepted design replaces this specification.
- The category remains readable at supported resolutions.
- One state shows no more than six primary actions.
- Active missions normally remain between one and three.
- Obsolete, invalid, and over-slot project decisions hide.
- Completed projects do not create an unbounded wall of rows.

## National Works Capacity

- Event 55 exposes one persistent public custom value.
- The value is a readiness score, not a spendable currency.
- It uses a readable `0` to `100` scale or an equivalent four-stage model with the same meaning.
- It responds to industry, stability, logistics reserves, war, embargo, active burden, completion history, and evolutions.
- The player can identify the current stage, next important threshold, and material contributors.
- Hidden calculation components do not become extra persistent public counters.
- Project progress remains in mission progress.
- Route condition remains qualitative.

## Candidate generation

- A normal proposal set contains three diverse candidates.
- Candidates use real origin, destination, route, facility, partner, and purpose data.
- Candidate families are selected from current geography and evolution access.
- Hard invalid routes have zero chance.
- Proposal diversity prevents one family from filling the set without necessity.
- Proposals remain stable until accepted, refreshed, or invalidated.
- Paid survey refresh has a cooldown and real cost.
- Invalid sets refresh without charging the player.
- New proposals hide at the active project limit.
- Candidate generation occurs at bounded moments and does not run through a whole-world daily scan.

## Project families

- Continental railway builds or upgrades a real route.
- Continental highway provides route-specific strategic road effects above maximum ordinary infrastructure.
- International trade corridor includes physical route segments and an operating agreement.
- Underwater tunnel and great bridge use only validated crossing registry entries.
- Grand port changes a real coastal logistics node.
- Resource corridor connects an existing resource source to industry, supply, or port.
- Evolution III network is a linked set of real segments and nodes.
- Each family has distinct costs, risks, incidents, rewards, reduced completion, damage, repair, and AI behavior.
- A multimodal project has one primary family for counting and achievements.

## Project lifecycle

- Authorization records a stable project object.
- The player selects one construction method.
- Costs are staged.
- No single action uses more than four spendable cost types.
- Steel and other non-stockpiled resources use access, import, or industrial diversion rather than a fictional stockpile debit.
- Domestic and foreign right-of-way are handled.
- International partners receive explicit invitations.
- Negotiation has a deadline.
- Main construction uses a clear timed mission.
- Milestone incidents are bounded and materially change the project.
- Overrun risk responds to visible choices and conditions.
- Full, reduced, suspended, and abandoned outcomes exist.
- Salvage depends on stage and cannot produce equipment.
- Commissioning verifies physical and legal operation.
- Completed projects persist with operational status.
- Maintenance appears only when needed.
- Repair, rerouting, renegotiation, and transfer exist.
- Cleanup is idempotent.

## International corridors

- Foreign territory is never used without consent.
- Partner roles, shares, costs, and benefits are coherent.
- Every invitation and receipt uses project generation proof.
- Late responses cannot mutate a newer proposal.
- Counteroffers change material terms.
- Partner withdrawal has stage-specific consequences.
- War among core participants suspends the agreement.
- Physical infrastructure remains subject to ordinary control and damage.
- Embargo reduces international benefits without deleting domestic segments.
- A physically intact route can become Dormant when its agreement fails.
- Surviving partners can renegotiate or appoint a new host.
- Annexation and government change do not duplicate benefits.

## Crossings

- Every fixed link comes from a curated map registry.
- Each registry row identifies terminal states, link type, engine consumer, approach rules, naval treatment, and blocking conditions.
- Map inspection and comparison evidence exists for every implemented crossing.
- The player is never offered a fixed link that cannot provide the promised movement and supply behavior.
- Damage can disable and repair can restore the same crossing.
- A crossing does not close unrelated sea routes or remove the wider need for naval control.

## Evolutions

- Evolution I requires `200+` Chaos.
- Evolution II requires `400+` Chaos.
- Evolution III requires `600+` Chaos.
- Evolution activation itself changes no Chaos.
- Evolution timing uses the shared paced evolution contract.
- Disabled evolutions set no recorded or unlock state.
- Evolution I expands national works, difficult routes, and limited second-project access.
- Evolution II unlocks validated extreme engineering and fixed links.
- Evolution III unlocks multi-country continental networks.
- High-Chaos first recipients enter the active evolution state correctly.
- Evolution logs, Event Details, candidate pools, AI, assets, and documentation stay aligned.

## Repeat firings

- The event remains useful after a country has the program.
- A repeat firing chooses assistance according to current project state.
- Possible outcomes include repair support, construction breakthrough, survey renewal, international opening, and maintenance renewal.
- Repeat assistance is bounded.
- It cannot complete an early project for free.
- It cannot bypass partner consent.
- It cannot grant another maximum infrastructure effect to the same country.
- It cannot create more equipment than a project needs.

## AI

- AI can use every ordinary project family available to humans.
- AI has an equivalent path for every category action.
- AI understands project slots, capacity, costs, duration, urgency, and route validity.
- AI selects construction method by strategic situation.
- AI partners compare contribution and benefit.
- AI prioritizes repair and near-complete recovery over weak new proposals.
- AI abandons permanently invalid projects.
- AI avoids consuming critical trains, trucks, convoys, or fuel without strategic reason.
- Every weighted surface receives inspect, scenario evaluation, owner patch, and comparison evidence.
- Exact percentages are claimed only from complete pools.

## Integrations

- Event 18 can seed a same-actor Resource Corridor proposal.
- Positive Economy cluster treats Event 55 as a Medium member.
- Cluster firing counts as one pacing event.
- Famine and Migration consume route facts through versioned adapters.
- Event 55 does not edit their primary ledgers or population.
- Natural disasters, bombing, combat, sabotage, and state control can disrupt real projects.
- Great Embargo can suspend international benefits and create domestic substitute pressure.
- Shared systems retain ownership of deaths, famine, migration, embargo, disasters, and generic Chaos.

## Chaos

- Opening, construction, failure, completion, and evolution give zero direct Event 55 Chaos.
- Wars, annexations, deaths, disasters, contamination, and embargo effects are not double counted.
- The optional cooperation reversal is at most `-2` Chaos once per campaign.
- The reversal requires a three-country network that remains fully operational for `365` days.
- The reversal is omitted when a shared cooperation source already covers the same outcome.

## Persistence and cleanup

- Program, recipient, proposal, project, route, partner, method, status, and completion data survive save and reload.
- Temporary event targets are not the sole storage for long-lived project scopes.
- Annexation, release, civil war, state loss, state recovery, government change, and partner collapse have defined handling.
- Visible category state rebuilds correctly after reload.
- Every project cleanup path removes active burden, missions, invitations, stale decisions, and temporary markers exactly once.

## Event system surfaces

- Event 55 is registered in the repeatable event array.
- Event type lookup resolves it.
- Default enabled status changes only when the rework is implementation-ready.
- Event name mappings and actor mappings are aligned.
- History records each firing and its role.
- Event Details describes the premise and evolution previews.
- Evolution history records three milestones.
- Cluster history records fired and skipped member reasons.
- Event level `1` and live weight display correctly.

## Writing and localisation

- Final localisation is written in world-facing language.
- No developer, debug, update-history, cap, or implementation wording appears.
- Dynamic project text names actual states, ports, resources, and partners.
- Costs use correct texticons.
- Requirements use concise custom tooltips.
- No raw trigger blocks or variable names appear.
- Working labels in this package receive a final writing pass before becoming localisation.
- Localisation, Event Details, docs, and spreadsheet wording agree.

## Assets

- Opening report image exists and is wired.
- First major Evolution III network news image exists and is wired.
- Category icon and static category picture exist.
- National works institution icon family exists.
- Every project family has a distinct decision icon.
- Mission roles have mission-specific icons.
- Required state or dynamic modifier icons exist.
- All achievement icon triplets exist.
- Every asset follows the correct reference family, source mode, dimensions, alpha treatment, folder, sprite, manifest, and handoff.
- No placeholder, primitive drawing, or resized unrelated icon remains.

## Achievements

- All five mapped achievements are implemented unless the final achievement audit documents a specific rejected design with user approval.
- Every achievement has a stable ID, hard conditions, disqualifiers, tracking, localisation, and icon triplet.
- Continuous operational periods reset when disrupted.
- Transferred projects do not satisfy host-built conditions.
- One project cannot count as several families.
- No achievement unlocks merely because the event fired.

## Documentation and catalog

- Event documentation explains the complete current mechanic.
- Source specs remain under the Event 55 spec folder.
- Accepted improvement content is folded into source specs.
- The authoritative catalog workbook is updated.
- The CSV exporter is run after the workbook update.
- Event 55 row, Positive Economy row, Event Details, and in-game localisation use aligned player-facing wording.
- The stale shifted descriptions around Events 54 to 58 are reviewed so Event 55 correction does not move the error into another row.

The final implementation report should list:

- event system and log surfaces changed
- decision and mission families implemented
- project families and crossing registry entries implemented
- AI scenarios evaluated
- assets created and wired
- achievements implemented
- adapters completed

- every simplification, fallback, omission, or unresolved accepted plan

If any mapped system remains missing, the event is incomplete.
