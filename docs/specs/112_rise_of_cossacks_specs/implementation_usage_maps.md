## Future Subagent Usage Map

### Common prompt and handoff contract

Every future role prompt must be self-contained and must not rely on inherited conversation context.
Use the canonical role definition and the current no-inheritance routing contract from S69.
The prompt must state the event and accepted requirement IDs, why the role is needed, the requested mode, exact source and destination paths, source revision, supporting references to read, permitted and forbidden edits, scenario names, inputs from other owners, required outputs and handoff path.
For a named event-owned GUI it must also identify the exact GUI IDs, entry point, files, states, supported resolutions, assets and the proof that the event owns that window.
For a probability audit it must identify the actual weighted source, adapter, saved scenario set, immutable baseline copies and intended targets chosen by the parent.
For an asset task it must enumerate the authorized rows and consumers instead of asking for an open-ended asset set.

A role handoff records changed files and identifiers, what actually ran, source and artifact hashes, scenario IDs, exact evidence, skipped checks and reasons, blockers, upstream dependencies and parent-owned wiring.
Read-only roles never patch gameplay.
Patch-capable auditors can repair only small local issues already inside their assigned surface.
A new country package, whole focus route, new shared GUI or broader mechanic design belongs to the parent and accepted planning process.
Every row below requires parent review of both the output and the evidence cited for it.
No child output establishes final completion by itself.
