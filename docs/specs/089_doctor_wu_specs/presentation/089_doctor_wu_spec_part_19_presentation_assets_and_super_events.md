# Doctor Wu: presentation, assets, and major announcements

## A medical institution the player can understand

The ordinary entry point remains the dedicated decision category described in the original brief. Its header shows Wu's current portrait, mandate, Authority, research direction, the selected active project, and the most important current medical problem. Most of these are qualitative identity or context. The player does not manage a new permanent number for every laboratory, sample, agreement, and scientist.

One primary mechanic value is Wu Authority. The current phase can show at most two supporting values, such as available project capacity and current care continuity. National supplied reach replaces an irrelevant supporting value when that is the active question. Four simultaneous meaningful mechanic values is the hard ceiling, not a target. No third permanent rivalry meter or global scientific-prestige currency is introduced.

The visible phase normally contains three to five primary actions and never more than six. One to three urgent objectives can share the surface. Choosing a project or agreement shows the actions relevant to that object. Record browsers may contain many historical entries, but historical rows do not remain active missions or consume resources.

This part specifies the final asset and presentation coverage. The named files and sprites are proposed stable identifiers to be verified against existing consumers before implementation. No image, model, sound recording, native GUI, or finished localisation is claimed to have been produced by this planning package.

## Layout and native controls

The planned baseline is an ordinary decision category with an attached Authority display and a compact context header. A full separate window is not needed merely to browse many possible projects. The category can phase current actions and use the existing target-selection pattern.

If implementation proves a dedicated window is necessary to manage the accepted objects, the parent must record that evidence, authorize the exact event-owned window, and create an ImageGen compositional reference before layout work. Shared event logs, settings, and super-event frames remain parent-owned. The event UI worker must not redesign those shared systems.

A native reference and actual source controls must be inspected at 1920×1080, UI scale 1, with supported smaller and wider resolution cases. Long country and institution names, maximum cost strings, no selected target, several active contracts, a missing person, disabled evolutions, and full record lists require explicit review scenarios. Rendered clipping, false states, dead buttons, and overlays that block clicks are defects that must be corrected.

The reference-to-native map must identify every interactive control. Generated text or painted buttons cannot replace live localisation and controls. Decorative art must remain distinguishable from an action. The ordinary category picture is omitted from any later layout state where it competes with an approved full-window composition.

## Text and historical direction

All route, action, project, achievement, and announcement labels in this package are working labels. Final text is written during implementation. It must describe the current actor, object, visible consequence, and uncertainty. The event's clinical success is established through patients and working services rather than a long invented biography.

Public medicine uses professional confidence and practical responsibility. Military medicine uses operational need and the limits of care. Classified work uses restricted access and specific missing information. Sovereignty uses the institutions and people that obey, refuse, depend, or negotiate. A clinical failure should be serious. Humour can target official vanity or an extravagant claim, never patients or victims.

Cultural allusions, quotations, song fragments, and historical references require actual research. No line from a song is supplied as finished dialogue. No unsupported quotation is attributed to a historical doctor. Event Details describe the premise and current situation, while costs and actual visible effects belong in decisions and tooltips. Hidden achievements and future branches stay out of the public premise text.

## Limited animation package

Two proposed animation families are justified by visible state changes. The qualified-continuity portrait can show a subtle physiological or expression loop distinguishing active living continuity from an archive. The sovereign Authority emblem can show genuine frame changes when an actual institutional confrontation is active. Ordinary static medicine and every small project icon do not need animation.

The portrait target is twelve genuine source frames at 156×210, giving a 1872×210 horizontal sheet, with a proposed six frames per second loop. The emblem target is twelve genuine source frames at 64×64, giving a 768×64 sheet, with a proposed six frames per second loop. These frame counts are planning targets subject to actual consumer and smoothness review. A static fallback is mandatory for both.

Every frame must be a real generated or sourced visual state with stable identity, framing, palette, and anchors. Moving, scaling, recolouring, blurring, or filtering one still does not satisfy the requirement. Native transparency is required for the emblem. The portrait background follows its confirmed consumer. The current image workflow's named model preference applies when selection exists, but the worker reports only the actual exposed tool path.

Planned sprite families are `GFX_089_wu_continuity_static`, `GFX_089_wu_continuity_animated`, `GFX_089_wu_authority_static`, and `GFX_089_wu_authority_animated`. Their exact `.gfx` and presentation consumer must be verified before wiring. An animated portrait must not silently appear on a different qualified Wu or a country without that office.

## Asset acceptance and workspace lifecycle

The production worker must inspect the matching canonical reference family and actual vanilla consumer before generation or sourcing. Fictional art uses native ImageGen. Historical symbols or grounded people use the required sourced identity and rights workflow. Every new flag is a clean flat design, with sourced constraints where a real symbol is used.

Final runtime files are placed in engine-facing folders, never referenced from `docs/assets`. Durable provenance and portrait source archives are retained according to the owning skill before any authorized workspace cleanup.

Visual completion requires exact sprites, files, live consumers, all required states, source/rights evidence, and parent review. In-game validation belongs to the user. The final coding and asset prompts include these requirements as work to execute, not evidence that this planning pass already produced the assets.
