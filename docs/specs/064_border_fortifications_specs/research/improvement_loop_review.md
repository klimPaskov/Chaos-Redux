# Event 064 Parent-Led Improvement Review

## Review status

The mandatory independent `chaosx_improvement_loop_planner` could not be spawned because the available tool registry exposed no subagent execution function. The full planner definition was read and used as a review contract. This parent-led pass is recorded for design quality, but it is not a substitute for the required independent implementation-stage run.

The tooling blocker is preserved under:

`docs/plans/064_border_fortifications_plans/subagent_handoffs/064_border_fortifications_improvement_loop_tooling_blocker.md`

## Review question

Does the Event 064 package turn the global fort grant into a coherent, replayable, bounded, AI-usable system that remains proportional to a Minor Repeatable event?

## Finding 1: The original baseline was too flat

The rough idea and current repository shell could produce a single global building grant with no local use decision.

Accepted improvement:

- construction moves to one hidden global transaction
- each country receives saved local results
- every affected country chooses defense, logistics, or breach response
- one active project turns the posture into a concrete local commitment

This gives the player agency after the anomaly without letting the player reject a world rule that has already occurred.

## Finding 2: Repeated global forts risk permanent stalemate

A repeatable two-level grant with no cap can create level-ten lines quickly and can overwhelm AI offensive behavior.

Accepted improvement:

- one ordinary level per wave
- caps below level ten
- strategic anchors receive at most one extra automatic level
- high-tier strength comes from selected geometry and support systems
- natural cooldown limits rapid world passes
- Study the Breach provides direct offensive counterplay
- AI probability scenarios test actual use

This preserves the event's effect while keeping normal engineers, air power, supply, multi-direction attacks, and maneuver relevant.

## Finding 3: Evolutions needed different geography, not larger numbers

Simply increasing fort level at 200, 400, and 600 Chaos would make the stages hard to distinguish.

Accepted improvement:

- Defense in Depth adds anchors and secondary positions
- Fortress States adds integrated state packages
- Fortress World adds internal national redoubts
- each stage has separate targeting, report counts, asset and text direction, materialization history, and Chaos milestone

Each evolution now changes how the map is defended.

## Finding 4: Supply hubs could become uncontrolled free economy

A literal reading of supply-related construction could place free hubs in every border state.

Accepted improvement:

- automatic work repairs or improves existing networks first
- infrastructure and verified rail changes are bounded
- new supply hubs remain exceptional and need separate proof
- player logistics decisions pay trains, trucks, support equipment, industry, and time

This keeps the package defensive and avoids a free global logistics overhaul.

## Finding 5: Island countries needed a defined experience

The baseline has no local border target for land-borderless countries.

Accepted improvement:

- all human countries can receive the global report
- island countries can choose breach study when a continental target exists
- Fortress World can create capital, port, supply, or victory-point redoubts
- false Evolution II land-border packages remain excluded

This gives islands a valid high-tier result without changing the border definition.

## Finding 6: Multi-cluster membership was ambiguous

The user assigns Event 064 to Sudden Abundance and Military Preparation. A single-cluster runtime could ignore or duplicate one membership.

Accepted improvement:

- one automatic event selection can enter at most one cluster context
- both memberships remain eligible through shared arbitration
- manual cluster launch chooses exact context
- one cluster incident can execute Event 064 once
- normal event history and cluster member history remain separate
- missing shared multi-cluster runtime is a hard blocker

This preserves both accepted roles without double application.

## Finding 7: The Chaos map needed stronger footprint logic

A global impossible manifestation should affect Chaos, but ordinary building and combat consequences already have shared sources.

Accepted improvement:

- one abnormal first-wave premium scales with actual global footprint
- repeat premiums are small and protected by cooldown and minimum footprint
- each evolution pays only at first concrete materialization
- cluster premium requires a distinct combined military-abundance result
- eligibility, posture choice, no-op waves, and debug waves pay zero
- no false demolition refund is added
- shared military buildup and building sources must be audited

This makes Event 064 an active Chaos source without paying twice for later wars and casualties.

## Finding 8: The asset package could become excessive

A global fort event could accumulate visual requirements that do not improve its core loop.

Accepted improvement:

- use existing HOI4 map buildings
- keep one report image
- keep one static category picture and category icon
- create three posture icons
- create five decision icons
- create four achievement icon families

This is enough visual identity for the actual player surfaces.

## Finding 9: Achievement ideas needed scriptable proof

Simple conditions such as owning many forts would be easy to farm and could be completed without using the event.

Accepted improvement:

- achievements arm only after natural Event 064 context
- each uses stored challenge targets
- each requires war, hold, offensive sequence, or recovery
- transfers, subjects, factions, debug, and third-party shortcuts are handled
- repeated world scans are avoided
- ambiguous order detection is replaced by a stored land-objective sequence

The achievements now test use of the mechanic.

## Finding 10: The spec needed stronger performance boundaries

The baseline requires a large one-time map operation. Evolved scoring and achievements could add hidden recurring cost.

Accepted improvement:

- one world snapshot per incident
- one country pass with temporary bounded candidate data
- no recurring border maintenance
- player-only challenge ledgers
- decision evaluation only while the category is active
- next wave handles new borders
- large-world acceptance scenario is mandatory

## Scope review

The accepted event loop contains:

- one global transaction
- three evolution packages
- three temporary response postures
- five bounded project families
- AI strategy and probability scenarios
- a complete Chaos map
- two cluster memberships
- four difficult achievements
- a restrained static asset family
- catalog and documentation work

This scope is proportionate to a global repeatable event with three evolutions.

## Closure judgment

No further design expansion is accepted in this parent-led pass. The current package has a clear baseline, differentiated evolutions, counterplay, local choice, AI logic, performance limits, assets, achievements, Chaos feedback, cluster behavior, and completion gates.

The unresolved item is procedural. An independent `chaosx_improvement_loop_planner` must inspect the implemented event near completion. Its expansion addendum or closure handoff must be resolved before Event 064 can be called complete.
