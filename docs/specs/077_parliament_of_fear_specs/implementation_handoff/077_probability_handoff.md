# Probability and AI audit handoff

The proposed tuning is not a verified probability model. No MCP probability operation was run. This handoff defines what must be inspected once actual script and a complete set of weighted pools exist.

Use the read-only `chaosx_ai_probability_auditor` role. Begin with `hoi4.probability_inspect` to locate real in-scope surfaces. Use evaluate, sweep, simulate, compare, and render operations according to the discovered contracts and the relevant question. Distinguish exact, bounded, sampled, score-only, and unresolved results.

Do not interpret `ai_will_do` as a literal click probability. Do not normalize a partial list while pretending it is the complete candidate pool. Country-selection weights, incident hazards, investigation outcomes, plot formation, arrest results, evolution timing, and AI choices are separate surfaces.

The 18 scenario rows in `077_probability_scenarios.csv` require complete source or explicit manifests. Sequence analysis is permitted only after the manifest includes cadence, recovery, caps, cooldowns, removals, resets, timer changes, and terminal states. The JSON tuning anchors alone are not sufficient for a valid sequence call.

For comparisons, use actual before and after source objects or complete before and after manifests under the same scenario set. A cached analysis ID is not a valid replacement for a source identifier.

The critical questions are whether careful baseline play is normally containable, whether the low-resource route is reachable, whether broad purge and unconditional protection have meaningful disadvantages, whether incident caps prevent spam, whether the fixed majority closes the purge-all exploit, and whether later crises remain recoverable.

The parent chooses balance changes after reading the evidence. The auditor reports findings without editing source. A source-only review or the included Python reference tests cannot close this MCP gate.
