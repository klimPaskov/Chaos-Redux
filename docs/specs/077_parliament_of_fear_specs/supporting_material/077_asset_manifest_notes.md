# Asset manifest notes

The manifest contains 48 production records. Some records are multi-state families or conditional portrait and flag roles. This count is not the number of finished textures.

All records are planned and unproduced. Runtime paths are proposed placements that must be reconciled with the live repository's existing naming and consumer patterns. Exact GUI dimensions are reference-gated. Native dimensions for established report, news, portrait, decision, idea, achievement, super-event, and flag families come from the supplied project skills.

The 8 achievement records each require the normal, grey, and not-eligible output. Follow the existing flat `gfx/achievements/` scheme and the dedicated achievement processor. A family cannot be replaced by three independently generated pictures.

Before art generation, build a contact sheet from the relevant existing family and select the approved source or generation mode. Use the report processor for report assets and the skill's prescribed converter for final DDS output. Inspect the actual converter implementation and templates, which were not included in the supplied archive.

Decode final DDS outputs, check their native dimensions and alpha behavior, compare them to the approved source composition, and record their runtime consumers. Use separate compositions for reports and monochrome news. A displayable PNG preview does not prove a valid runtime DDS.

The interface reference image and element map are required production inputs. The plan does not substitute a manually drawn placeholder diagram for final native art or a verified GUI render.

The sound is tracked separately by the super-event research handoff. Its final file, source, recording rights, excerpt timing, and shared-framework consumer are still unresolved.
