# Design decision register

## User-fixed direction

The title, identity, type, status, Chaos level, cluster and member role, random major-or-player target, repeat-after-resolution behavior, dynamic institution and seats, Paranoia, four main actions, persistent character consequences, three named evolutions and thresholds, Great Purge possibility, ending conditions, named cross-event connections, and chamber presentation come directly from the user's concept.

## Design choices introduced by this package

The 100-seat influence scale, six-to-eight bloc target, 12 notable-figure limit, separate support/evidence/occupancy dimensions, fixed 51-seat majority, 55-seat safe support target, 80-seat functioning target, 21-day stable closure interval, bounded case and queue capacities, low-resource recovery modes, one Great Purge per instance, purge-wave safeguards, exact achievement conditions, and starting numerical anchors are parent-authored design choices.

They are internally specified so that implementation does not have to invent core behavior. They are not described as values personally approved by the user or verified by a live game test. Balance changes must preserve the intended choices and be recorded against the relevant design condition.

## Evidence-derived constraints

The project supplies the crisis-slot limit, repeatable-event framework, evolution timing framework, public-value and action budgets, direction-only localisation policy, asset family rules, MCP and subagent requirements, and read-only CSV policy. The legacy Event 077 purpose and namespace were confirmed through the supplied catalog and partial connected repository evidence.

## Unresolved evidence gates

Actual runtime API support, government adapter details, full legacy migration coverage, native-purge coexistence, exact GUI layout, asset production, final super-event sources, workbook operations, complete probability sequences, and independent review remain open until the corresponding evidence is obtained.

A document's inclusion in the ZIP does not mark those gates as passed. Supporting material and handoff plans do not silently change the user-fixed direction.
