# Parent design review and unresolved decisions

This is a parent-authored review, not an independent specialist audit. It was written after the full supplied text set had been read and the main design was drafted. No subagent execution, native engine validation, visual approval, or playtest is implied.

## Design issues resolved in this draft

The old Germany-only planet-wide claim effect is replaced by universal owned-frontier discovery. First-ring coverage is uncapped. Advanced expansion cannot recursively use newly added targets beyond its frozen depth, and V uses only the old connected network for its extra layer.

Compliance is an entitlement floor, not an additive repeat reward. Higher existing values survive. Equal ceilings do not repeat. The ledger is claimant-specific and a new occupier cannot inherit the event benefit. Native isolation remains an engine proof rather than an assumed consequence of a setter.

Core eligibility has actual control and high-Compliance intervals. Occupation cores do not transfer ownership or broaden the claim seed. Connection credit has hard physical minima. Existing native cores and other claimants' cores are preserved.

Ambition envelopes freeze at adoption and formation checks remain live. Native formable prerequisites survive integration. Dynamic names and flags use prepared resources while territorial combinations remain map-derived. Generic formation preserves the country's actual package and cannot reset its history through a cosmetic change.

The interface has one selected ambition, limited primary actions, four payment types, two project slots, informational exact-state pieces, and required category attachments. Large envelopes use prepared pages rather than fabricated runtime geometry. Country and AI rules share qualification.

## Deliberate interpretations added by the parent

The user supplied control but did not require legal ownership for WC cores, so this design allows an earned core under occupation while preserving ownership. Generic dynamic proclamation is stricter: direct ownership, direct control and independence. Native providers keep their genuine different rules.

“Starting Compliance” is interpreted as a one-time floor per numerical entitlement. Repeat firings can discover new targets and deliver a higher unlocked ceiling, but cannot refill an already consumed ceiling after recapture or normal decay. This avoids infinite Compliance farming while preserving the specified stage values.

Dynamic names and flags are interpreted as runtime selection from prepared engine-compatible resources. Exact unlimited free-form text and image generation during a running game are not promised. The territory resolver remains genuinely dynamic, including connected-conquest shapes outside the illustrative six region names.

Automatic claims remain strictly land-geographic. Maritime ambitions can describe future objectives and use actual held islands, but do not give a land-neighbor-less country a claim-wave exception. Native provider claim rewards remain provider-owned. This is a conscious resolution of the tension between maritime ambitions and the user's no-land-neighbor rule.

All exact budgets, holding durations, formation thresholds, prices, missions, Chaos contributions, and achievement conditions beyond the user-fixed values are proposed design expansion. They have not been playtested. The tuning file identifies their ownership and distinguishes fixed user values.

## Mandatory blockers

G1 claimant-specific Compliance and G2 exact continuity are particularly important. The abstract Python tests model the required behavior but cannot prove the engine supports it. No claim of universal gameplay completion is permitted without a tested native implementation.

The exact installed state registry, all geographic memberships, complete flag-family inventory, full native-provider bridges, UI reference images, native layout, and map/GUI/DDS evidence are not produced here. They remain production and verification work. No invented state list or generic flag is included as a substitute.

Every supplied text file was read, including all 20 profiles. Some referenced must-read files outside the upload were not fully read or available. The explicit source audit governs that limitation. Independent planner, decision, country, localisation, probability and completion reviews remain unrun because no specialist-spawning tool was exposed.

## Review conclusion

The draft covers the user's full gameplay arc and supplies a concrete implementation contract with visible gates. It does not justify the labels implemented, validated, playtested, visually approved, or fully compliant with every external-read and independent-review requirement. Keep the catalog status To Be Reworked until the actual appropriate runtime review changes it.
