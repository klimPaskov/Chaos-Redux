# Event 050 presentation choice and scope review

## Selected presentation layer

Event 50 uses an ordinary decision category with:

- one category icon
- one static category picture
- one Embargo Pressure display
- one short status summary
- three to five visible primary actions
- one active mission at most
- selected-country targeting for coalition members and intermediaries
- normal report events for material changes

## Why this layer is sufficient

The player manages one public value and a small number of actions. Normal decisions already provide costs, requirements, targets, timers, tooltips, and AI equivalents. A separate window would duplicate those functions and increase maintenance.

The static category picture gives the crisis a strong visual identity without drawing fake controls. Threshold reports provide feedback when the crisis changes stage.

## Rejected expansion surfaces

### Dedicated scripted GUI

Rejected because the event has one value, no board, no map puzzle, no competing internal factions, and no repeated spatial interaction that requires a custom window.

### Animation

Rejected because Pressure stage and action availability are clearer through text, icons, modifiers, and reports. Motion would add production and wiring cost without improving a decision.

### Super-event

Rejected because an ordinary firing is a medium-severity repeatable economic crisis. Evolution II can become globally important, but it remains a network of concurrent minor crises and does not mark a terminal campaign threshold.

### Focus tree

Rejected because the event targets existing countries dynamically. A target-specific focus tree would conflict with current national content and make a repeatable incident too invasive.

### Country package

Rejected because no new state actor is needed. The coalition and sanction-breaker network are temporary event roles.

### 3D model

Rejected because the mechanic has no unit, vehicle, building entity, creature, aircraft, or ship consumer.

### Character portraits

Rejected because no named character or new officeholder is central to the event.

### Manual scenario

Rejected because the supplied scenario catalog contains no Event 50 scenario and the user did not request one. The event's ordinary and evolved firing paths already cover its intended use.

## Reconsideration gates

A future implementation audit can reconsider a custom display only if normal decisions cannot show separate concurrent targets cleanly. The first response should still be a compact attached display or selected-target category flow. A full window requires evidence that the lighter surfaces fail.

A future super-event is justified only if Event 50 gains a true world-order threshold, permanent economic camps, or a terminal branch accepted by the user. It should not be added only because several embargoes overlap.
