# Gods of Africa parent improvement-loop review

## Review status

This is a parent-authored improvement review based on the supplied `chaos-redux-improvement-loop` skill and the provided `chaosx_improvement_loop_planner` definition.

The custom subagent was not executed. The configured outer Codex route returned an HTTP 404 during tool discovery and invocation. This document must not be cited as an executed subagent handoff.

## Playable promise reviewed

The system promises a persistent relationship where Africa gains material power from foreign tribute, foreign countries judge whether its threats are credible, and long-term conduct changes protection, punishment, and final diplomacy.

The earlier concept already had strong identity. Its main design risks were:

- repetitive tribute popups
- arbitrary punishment disconnected from African capability
- a hidden friendship result with too little feedback
- a one-way extortion loop with weak rewards for compliance
- a broad demand list without capacity proof
- an overly large interface
- treatment of African religions as one historical pantheon
- lack of active play after permanent defiance
- no clear Africa-side decisions
- unclear integration with Event 012 pacing and victory

## Improvements accepted into the source spec

### One frozen active contract

Each participant can hold one ordinary demand at a time. The demand family, amount, deadline, substitutes, and contract ID are frozen until resolution.

This prevents popup spam, reroll exploits, and unclear overlapping obligations.

### Separate desired punishment and capability ceiling

Punishment intent comes from Wrath, offense, failure history, demand severity, and Chaos.

Punishment capability comes from Strength, African capability, and Event 012 evolution access.

The applied result cannot exceed the capability ceiling.

This is the most important balance improvement.

### Real reciprocity

Compliance can produce protection, aid, negotiation goodwill, better final settlements, and World Is One privileges.

Africa pays real resources when it protects a partner.

This gives the obedience route strategic value without erasing its cost.

### Africa-side agency

The African player can set a continental need priority, grant leniency, mark a proven offender, protect a reliable partner, issue a pardon, and escalate a valid offense.

The player cannot enter arbitrary amounts or bypass the dynamic validity rules.

### Defiance as a campaign route

Permanent defiance stops ordinary demands and opens threat-response decisions. It does not delete Wrath or punishment.

A rare reconciliation route exists under strict conditions and returns the country as distrusted, not favored.

### Fictional plural doctrine

The Gods are a new Event 012 doctrine interpreted through a politically and religiously diverse continent. The system avoids declaring that real African religions form one universal pantheon.

### Compact presentation

The default surface uses two meters, one mission, and up to five actions.

A full GUI is deferred behind a clear acceptance gate.

### Needs and capacity matching

Africa builds a hidden need profile. Each target builds a hidden capacity profile with protected operating floors.

This prevents meaningless demands and connects tribute to Africa's actual campaign.

### Escalation with recovery

Repeated failure raises punishment intent. Renewed compliance can reduce Wrath and move the participant away from catastrophe.

Permanent grievance marks still affect the final outcome.

### Event 012 integration

The system uses the unifier, continent-control, evolution, aid, guarantee, base, sanctions, scenario, and final-victory state already owned by Event 012.

Routine demand calls remain owner-managed and do not enter the random event pool.

## Expansion rejected as bloat

### Separate Gods event identity

Rejected because it would conflict with the user's Event 012 ownership decision and duplicate random-event pacing.

### Third public loyalty meter

Rejected because Wrath, Strength, and qualitative feedback already cover the necessary player decisions.

### One named god for every demand family

Rejected because a large roster would increase localisation and asset scope without changing play. A small set of fictional voice roles gives enough personality.

### State-by-state global tribute map

Rejected because the mechanic is country-based and the map would create a large UI burden.

### Full scripted GUI by default

Rejected because the normal decision category can carry two values and one contract. The African target selector can use the selected-target pattern.

### Independent world-end route

Rejected because Event 012 already owns World Is One. Relationship history should feed that route.

### Custom 3D units or deity models

Rejected because the system's core is diplomacy, tribute, and consequence. A model would add asset cost without changing the loop.

### Mandatory animated presentation

Rejected because animation does not improve the default category enough to justify a frame package. One optional warning loop remains conditional on a later GUI decision.

### Constant catastrophe escalation

Rejected because repeated major disasters would become monotonous and would undermine Strength as a credible ceiling.

## Remaining design risks

### Hidden friendship fairness

The exact final calculation remains hidden, as required. The player still needs directional feedback. Implementation should provide qualitative relationship lines, remembered-conduct reports, and visible African behavior.

### Extreme population punishment

The concept permits death of most of a target country's population at the highest valid extreme. This route needs strict gating, an emergency ultimatum, staged exact accounting, a protected floor, and long cooldowns. Without those controls it would dominate the entire system.

### Africa-side workload

A human African player could face too many foreign records. Grouped reports and one selected-target workflow are required.

### AI validity

The AI has many weighted surfaces. Completion requires a full probability audit with complete candidate pools. Source-only review is insufficient.

### Cultural review

Final visuals and wording need a specific review against religious flattening, colonial stereotypes, fake proverbs, and decontextualized sacred imagery.

## Stop condition

The design is deep enough for implementation. Broad expansion is no longer recommended before a live Event 012 repository audit.

Further planning should focus only on issues discovered from:

- Event 012 source constraints
- engine capability
- probability evidence
- focus layout evidence
- decision clutter evidence
- cultural review
- implementation audit

Adding more public values, voice characters, demand families, punishment tiers, or GUI tabs would add maintenance burden without improving the core loop.
