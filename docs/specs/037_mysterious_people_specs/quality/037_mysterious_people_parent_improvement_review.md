# Event 037 parent-led improvement and anti-bloat review

## Review status

This is a parent-led review based on the complete uploaded project bundle. It is not a custom subagent output and does not claim that `chaosx_improvement_loop_planner` was executed. A final implementation still requires the mandatory project improvement-loop agent when that runtime is available.

## Playable promise reviewed

The event promises an unexplained population gift that becomes a management crisis through repetition. The design must make three experiences work:

1. The first manifestation is beneficial enough to welcome.
2. Repeated manifestations create real support decisions and strategic tradeoffs.
3. High-chaos failure can produce famine, displacement, repression, and atrocity without creating duplicate humanitarian systems.

## Gaps found in the supplied rough design

The supplied concept established the premise and evolution direction, but implementation would still have needed to invent several important contracts:

- exact valid-state logic
- bounded dynamic grant shape
- provenance accounting after ordinary deaths
- provenance transfer through Migration
- ownership and occupation behavior
- one readable public pressure value
- evolution pacing and disabled-stage behavior
- pre-fire evolved opening
- decision visibility and selected-state control
- AI profiles and atrocity suppression
- direct Chaos milestones
- event and flavour structure
- performance ownership
- catalog replacement
- asset and achievement coverage

These gaps have been resolved in the source specification.

## Improvements accepted

### Real population and provenance

The event now has a clear distinction between authoritative real population and Event 037 provenance. This makes every later death, migration, recruitment, and ownership change meaningful.

### One public pressure value

Overpopulation Pressure replaces a possible collection of housing, food, service, integration, migration, and density counters. Hidden inputs remain detailed, while the player sees one actionable result.

### Strong first firing

Baseline remains a demographic gift. It does not start as automatic famine or panic. This protects the event's identity and gives repeated firings a meaningful escalation curve.

### Existing humanitarian ownership

Famine and Migration retain their public values, decisions, routes, and mortality. Event 037 supplies burden and receives proof. Camps and Condemnation retain atrocity ownership. This avoids parallel mechanics and contradictory ledgers.

### Selected-state decisions

The category uses one selected target and a phase budget. The player sees the highest-priority work without a wall of decisions.

### Constructive Evolution III

Evolution III includes new cities, national food expansion, and international settlement. Extreme measures exist, but they do not become the only high-chaos route.

### Atrocity consequence

Systematic killing is integrated fully with real deaths, provenance, evidence, resistance, Migration, Condemnation, sanctions, and perpetrator history. The design does not sanitize it as a pressure button.

### Direct Chaos restraint

Event 037 uses one-shot demographic milestones. It does not add farmable Chaos for every firing or duplicate deaths, famine, war, or atrocity sources.

### Mystery preservation

The event has a written explanation firewall and a large flavour pool that deepens uncertainty without solving it.

### Performance shape

The design accepts one global firing pass and uses sparse recurring registries. It avoids an unauthorized recurring whole-world scan.

## Expansion ideas rejected


### Additional public meters

Separate housing, food, integration, registration, density, and migration values would exceed the mechanic clarity budget. Their useful parts are internal contributors or existing shared values.

### New food system

Famine already owns food security, reserves, relief, mortality, and routes. A second Event 037 food meter would create conflicting results.

### New refugee system

Migration already owns cohorts, routes, borders, reception, settlement, trapped people, and movement deaths.






### Canonical origin route

A final explanation would weaken replay value and contradict the accepted premise.

### Automatic universal collapse

Prepared countries must be able to exploit the population. Universal famine would turn player choices into decoration.

### Unmapped presentation and country expansion

Additional presentation layers, country content, and unrelated asset systems were rejected because the accepted demographic loop is already clear through ordinary events, decisions, shared humanitarian systems, state targeting, and static assets. Any later expansion requires a specific observed gameplay gap.

## Closure judgement

The source design is deep enough for implementation. Broad expansion is no longer recommended. Additional mechanics would mainly duplicate existing systems or add maintenance without changing the player loop.

The next meaningful work is implementation, owner audits, probability evidence, localisation review, final assets, workbook alignment, completion audit, and live user testing. The mandatory implementation-time improvement-loop planner should return either a narrow addendum based on new evidence or a closure handoff. Any new broad expansion should require a specific observed gameplay gap.
