# Event 037 implementation and subagent routing

## Status

This is a routing handoff derived from the complete uploaded subagent definitions. No custom project subagent was executed in the current planning environment.

All future subagents must receive a complete self-contained prompt with no inherited conversation context. In Codex that means `fork_context=false`.

## Recommended sequence

### 1. Parent repository preflight

The parent reads the source specs, current Event 037 files, Famine, Migration, Deaths, Camp and Repression, Event Logs, classification, achievements, asset references, workbook, offline wiki, vanilla documentation, and relevant precedents.

Use `chaosx_repo_explorer` only if file locations or implementation order remain uncertain. The final prompt should name the exact repository root, source files, accepted design, and report path.

### 2. Scripted-system architecture

Use `chaosx_scripted_system_architect` for:

- exact positive state-population gain contract
- provenance variables and invariants
- country and world totals
- sparse active registries
- pressure calculation
- ownership and control refresh
- ordinary loss provenance adapter
- Migration composition adapter
- Camp and atrocity provenance adapter
- script constants
- one-shot Chaos milestones
- idempotence and reconciliation

The architect may make narrow implementation changes inside the accepted scope. Broad redesign returns a plan.

### 3. Parent event implementation

The parent owns:

- entry and follow-up event chain
- event registration and pacing
- evolution activation and logging
- Event Details
- manifestation transaction
- cross-system integration
- final docs
- spreadsheet routing
- final validation and completion claim

Use mandatory HOI4 MCP event inspection, rendering, and comparison.

### 4. Probability baseline

Use `chaosx_ai_probability_auditor` before patching any weighted AI, MTTH, random list, target selector, or policy score.

Pass the named scenarios from the probability matrix. The auditor remains read-only.

### 5. Decisions and missions

Use `chaosx_decision_mission_auditor` after the first complete decision implementation.

It should inspect and may narrowly patch:

- category lifecycle
- public value clarity
- selected-state workflow
- visibility budget
- costs and texticons
- active mission cap
- success, partial success, and failure
- AI validity
- cleanup
- Famine and Migration ownership
- exploit risk

Any AI weight patch requires the probability compare cycle.

### 6. Localisation

Use `chaosx_localisation_auditor` after broad text exists.

It should inspect and may patch:

- final event and option wording
- Event Details
- evolution text
- decisions and missions
- tooltips and blocked reasons
- dynamic population, state, country, pressure, and policy text
- achievements
- missing or duplicate keys
- encoding
- developer-facing or update-history wording

### 7. Visual assets

Use `chaosx_generated_event_art` for the report image and static category picture.

Use `chaosx_icon_artist` for category, decision, modifier, state, and achievement assets.

Prompts must name target size, reference family, source mode, final paths, sprite names when registered, transparency, contact sheets, manifests, and forbidden substitutions.

### 8. Spreadsheet alignment

Use `chaosx_spreadsheet_doc_worker` only after final Event Details and evolution wording exist.

It edits the authoritative XLSX and runs the CSV exporter. It does not edit CSVs directly.

### 9. Completion audit

Use `chaosx_event_completion_auditor` after implementation, assets, docs, localisation, achievements, Event Logs, adapters, and workbook alignment are complete.

Pass every source spec, prompt, plan disposition, asset handoff, probability report, and meaningful validation result.

### 10. Final improvement loop

Use `chaosx_improvement_loop_planner` near completion as required by the planning skill.

It reads the implemented feature and accepted specs. It should return a narrow addendum only for a real observed design gap. Otherwise it should return a closure handoff.

Resolve the result before completion.

### 11. Final probability compare

After every weight patch, rerun `chaosx_ai_probability_auditor` with the same scenario IDs and mandatory comparison evidence.

## Scope boundary

Route only the agents named in the recommended sequence. Any additional specialist requires a newly accepted surface and a context-complete parent brief.

## Parent review requirements

Before relying on any handoff, the parent checks:

- scope stayed bounded
- changed files and identifiers are listed
- probability evidence matches final source
- accepted plans are implemented, promoted, queued, or rejected with reason
- assets have final consumers
- docs and workbook match final localisation
- temporary workspaces follow retention rules
- unresolved simplifications are reported
- completion evidence reflects the final repository state
