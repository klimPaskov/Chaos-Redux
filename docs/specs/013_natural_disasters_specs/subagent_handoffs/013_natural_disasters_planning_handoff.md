# Planning Handoff — Event 013 Natural Disasters

## Design problem

The old catalog entry was too shallow: a random natural disaster damages industry and population, with a note that Evolution IV adds meteor showers and intense disasters. The rework expands it into a repeatable disaster family system with warning, impact, aftermath, recovery, regional evolution, chained consequences, abnormal high-chaos variants, and a manual scenario.

## Proposed source spec disposition

Promote this whole package into `docs/specs/013_natural_disasters_specs/` as the accepted source design. Do not leave the evolution, decision, asset, super-event, and achievement plans as loose notes.

## Implementation surfaces affected

- Event 13 script and subevents.
- Random event registration and repeatable classification.
- Natural Disasters cluster registration with only Event 13 as current member.
- Event log history, event details, evolution details, cluster details.
- Scripted effects, scripted triggers, script constants, and event targets for disaster helpers.
- Decision category and missions for warning/recovery/aid.
- Ideas or state modifiers for aftermath families.
- Manual triggerable scenario registry, type controls, intensity controls, localisation, confirmation flow, launch helpers, cleanup.
- Event 46 placeholder/unknown cleanup.
- Optional Evolution IV super-event and required research/audio/image assets if implemented.
- Asset manifest and `.gfx` handoffs.
- Achievements and achievement icons.
- Event doc and spreadsheet alignment after localisation exists.

## No focus/country package surfaces

This event does not create countries, focus trees, formables, or leaders. Focus and country package skills were applied as negative checks. If implementation creates a disaster-response country, releasable, or focus tree later, that is a design change and needs a new accepted addendum.

## Open questions for implementation

- Exact HOI4 state groups for volcanic regions and physical macro-regions need repo/vanilla state-map inspection.
- Exact disaster modifier values should be implemented as script constants after checking existing modifier patterns.
- Super-event final title, quote, button remark, and audio are blocked until researched by the super-event workflow.
- Asset source mode can be generated by default; archival alternatives need source/license review.
- Event 46 placeholder convention should follow the existing project pattern for removed/superseded catalog events.

## Completion warning

Do not claim Event 13 complete unless Event 46 duplicate gameplay is removed, Event 13 has all four evolutions, the manual scenario exists, recovery decisions/missions are playable, warnings identify affected areas, AI uses the system, event log/details are aligned, assets and achievements are handled, and spreadsheet update is completed or handed to the spreadsheet worker after final localisation.
