# Event 42 parent improvement review

## Review status

This is a parent-performed provisional improvement-loop review. The configured project subagent could not be launched in this interface because no spawn action was exposed after the tool-registry request failed with an MCP 429 response.

Implementation must still run `chaosx_improvement_loop_planner` after a meaningful tranche and reconcile its handoff before completion.

## Playable promise

The event promises one clear experience. An arbitrary country gains an arsenal so large and poorly matched that it can change the campaign while creating a new planning problem.

The design succeeds when:

- the recipient selection feels genuinely indifferent to power
- the quantity is large enough to matter immediately
- the equipment appears as a physical event across the map
- the mix is useful but not optimized
- later evolutions change the nature of the arsenal
- special equipment does not silently trigger unrelated event systems
- the player can exploit the windfall through ordinary military choices

## Depth gap found in the rough idea

The rough idea defined strong spectacle and escalation, but it left several implementation-critical questions open:

- how a delivery is composed without optimizing for the recipient
- how report events avoid duplicating the grant
- how designer equipment remains usable across DLC states
- how nuclear weapons become usable without granting production
- how special equipment can be fielded without starting its owner event
- how AI handles an absurd stockpile
- how Event 42 affects Chaos without repeat farming
- how the event differs from equipment aid and unit-spawn events
- how the unregistered Various Anomalies cluster assignment is reconciled

The source specification now answers those questions through the manifest architecture, report transaction, compatibility registry, nuclear contract, AI assessment, Chaos map, identity boundaries, and catalog gate.

## Expansion ideas considered

### Dedicated scripted GUI

A manifest window with crates, cards, and family meters was considered. It was rejected because the player does not manage a persistent Event 42 system. The normal stockpile, division designer, air interface, logistics, Event Details, and concise manifest tooltip already expose the useful state.

A custom window would add duplicate information, ongoing maintenance, and an event-owned UI worker requirement without changing the player's decisions.

### Persistent skyfall pressure value

A recurring Skyfall Activity or Provenance score was considered. It was rejected because the event has no containment, investigation, or prevention loop that would make the value actionable. The hidden provenance signature creates variety without adding a counter.

### Investigation and source-reveal route

An investigation chain that reveals aliens, time travelers, divine intervention, or a secret state program was considered. It was rejected because the event's identity depends on unresolved provenance. A definitive answer would reduce replay value and force other anomaly events into one explanation.

### Recovery decision category

A category for cataloguing, guarding, moving, scrapping, or distributing crates was considered. It was rejected because those actions would duplicate ordinary stockpile and army management. Short landing-zone modifiers already communicate physical recovery.

### Global scramble for the cargo

Foreign seizure, raids, sanctions, and invasion decisions were considered. They were rejected because they would turn a Low anomaly member into a persistent international crisis and overlap known aid, espionage, and war events.

### Country focus or route package

A focus branch built around the unexpected arsenal was rejected. Event 42 can select any ordinary country and can repeat. A generic focus overlay for every possible recipient would be shallow and would outlive the incident.

### New special equipment families

New Event 42 weapons were rejected. Evolution III is stronger when it exposes existing Chaos Redux systems under strict isolation rules. Inventing generic sky weapons would violate the accepted brief and create new equipment, assets, units, sound, counters, CXT, and 3D obligations.

## Accepted improvements

The following additions materially improve play without inflating the event:

- one anchor, support, and mismatch manifest architecture
- magnitude bands that preserve absurd scale
- complete conventional variant registry across DLC configurations
- three to seven non-pacing physical landing reports
- hidden provenance signatures for repeat variety
- one persisted manifest transaction
- ordered evolutions with evolved first-firing behavior
- substantial nuclear caches with launch-only compatibility
- repository-backed special-equipment allowlist
- minimum fielding and captured-payload receipts
- owner-event pre-state and post-state isolation tests
- bounded AI post-delivery assessment
- one-time guarded Chaos milestones
- three skill-based achievement routes
- explicit cluster and catalog reconciliation
- named probability and acceptance scenarios

## Anti-bloat conclusion

Broad design expansion is not recommended after the accepted improvements are implemented. The event has a clear loop, strong replay variance, meaningful ordinary-game consequences, AI coverage, physical presentation, escalation, and cross-event integration.

Further large additions would likely weaken the event by turning a sudden anomaly into a permanent management system. Future work should focus on implementation proof, special-family variety, balance, localisation, assets, and validation.

## Closure tasks for the real planner pass

The implementation-stage planner should verify:

- at least several special families can be safely allowlisted
- the nuclear launch-only contract is genuinely narrow
- clone reserve manpower does not become an infinite dominant reward
- landing reports remain concise and do not create popup fatigue
- the manifest remains visibly absurd after balance review
- Event 42 does not overlap Event 19, Event 77, Event 92, or missile events
- no accepted safety or AI gap remains

If those checks pass, the planner should return a closure handoff rather than another broad expansion.
