# 071 Persia: integration and acceptance contracts

## Event ownership

Event 071 remains a Minor Fire-Once member of Formables with a Medium role. It contributes one member event to the shared cluster behavior. It must not obtain a second independent timer roll merely because its new tree is large.

The event root is `chaosx.nr71.1`. The restored country is the verified existing Iranian identity. The receiver must remain the same country through root effects, foreign reactions, and delegated scopes. A scoped foreign recipient cannot accidentally become the root actor of the Persian restoration.

Registration includes the event's name direction, valid actor selection, pre-fire actor history, event details, all three evolution entries, cluster membership, and once-only state. Exact repository structures must be inspected before implementation. This package does not provide unverified script recipes.

## Catalog source conflict

It does not contain the full new routes, army, evolutions, and cluster treatment. The supplied cluster CSV identifies Formables as cluster 6 and does not yet list Event 071 among its exported members.

The user's attached brief is the design authority for this rework. The implementation must update the authoritative workbook and then regenerate exports through the normal workflow. The workbook is absent from the supplied archive. Do not edit only the CSV snapshot or mark the event implemented because this plan exists. The catalog status remains To Be Reworked until the implementation's accepted status transition.

## Iran and DLC compatibility

The official Graveyard of Empires product description already includes Iranian content and a modern Persian restoration path. [H06](071_persia_research_notes.md#h06-existing-iranian-dlc-content) The installed focus trees, restoration flags, country identity, and DLC checks must therefore be inspected before Event 071 is integrated.

An already completed equivalent restoration blocks the root. An incomplete vanilla restoration path needs an explicit transition contract. Completed factual projects can carry into the new tree without paying their rewards twice. Existing government, research, units, characters, and valid national systems remain intact.

The event's dedicated large tree is mandatory. The transition must preserve useful progress and disable or reconcile conflicting old restoration systems. It cannot blindly replace a meaningful tree and strand active missions or advisers. A transition preview should explain the accepted carryover and any superseded political commitments to the human player.

The no-DLC case must also work through legal base-game systems. A feature that fundamentally depends on an unsupported DLC mechanic needs an explicit resolved design. A placeholder modifier is not a complete satrapy contract or market system.

## Human-country classification

Persia is an ordinary human imperial formable. It retains normal civilian, famine, migration, casualty, contamination, and diplomacy behavior. Its event ownership does not make its population nonhuman.

Some supplied guidance broadly classifies event-created special countries. The implementation must resolve the actual registration policy with the country-package auditor. If an event-managed marker is required, it must not imply nonhuman status or civilian-system exemptions. No cleanup helper should remove ordinary civilian consequences merely because Persia received a large army.

Imperial expansion alone does not make Persia a scripted existential world threat. Do not attach a shared world-threat marker without a separately approved threshold and purpose.

The root's tier amounts describe one manifestation shock. Do not additionally charge an Event 071 army-growth premium for every granted division. A peaceful subject agreement alone does not trigger the coercive-submission premium. A specialization switch cannot recreate the first network milestone. Repeated release and annexation, capital trading, unit disbanding, and save reload cannot repeat unique contributions.

The negative contributions reward a distinct resolution, not the automatic absence of war. A paid hearing that fails does not receive the resolution reduction. The shared meter's existing bounds and application helpers remain authoritative.

## Existing system connections

The common unit-family system must own guard registration, capacity, unlocks, and consumer behavior where applicable. The event cannot create an incompatible parallel special-unit framework. The actual source and API contract are absent from this archive and must be read in the repository.

Research Failure can affect ordinary Persian research and production. The event does not secretly immunize its technology. Existing guard formations remain real units, while future recruitment and equipment replacement follow the current legal unlocks. Any special handling must be consistent with the research system's actual contract.

Border Fortifications and infrastructure events can complete relevant physical prerequisites. They do not pay a second Persian construction reward for buildings already present. Abundance can affect an applicable ordinary or safely registered event value, but cannot change the root-fired flag, duplicate first-completion records, or directly bypass the guard-cap integrity rules.

Other formables keep their own identity and tree. Persia must not overwrite another event's country package merely because it expands into the same region. Where competing claims exist, ordinary ownership and diplomacy decide the result unless a documented cross-event agreement is added.

## Shared helper considerations

The supplied dynamic effect documentation is a contract reference, not evidence that implementation files are available. Economy-scaled factory helpers calculate an allocation and do not themselves prove that buildings were placed. Material-removal helpers that negate a temporary value in place must not corrupt a saved cost quote or a later debit. Country and state scopes must be checked before each shared call.

Use the shared desert-state classifier for a desert program where its actual registry fits. A random global sea-region selector is not a Gulf selector. A world-threat refresh helper is not a reason to classify Persia as a world threat. A technology-union helper must respect incompatible research and cannot justify copying all major-power technology.

Keep these details in implementation notes and tests. They do not need to become player-facing mechanics or extra interface values.

## Performance and persistence

Event 071 uses event-owned updates, existing project scheduling, and relevant state-change callbacks where available. It does not add a new daily or weekly world-wide scan for every country and state without explicit justification and approval.

The interface refreshes selected targets and changed regions. Political obligations are evaluated at their defined intervals. Guard capacity is refreshed when relevant forces or institutions change, using the shared unit system. Legitimacy changes follow discrete meaningful consequences.

All once-only records, charters, project stages, cost transactions, recruitment reservations, duration checks, and crisis assignments survive save and reload. A receiver that is annexed or disappears cannot continue sending payments from an invalid country scope.

## Country-package acceptance

The restored Iranian identity has correct names, flags, government continuity, leaders, advisers, military assets, tree transition, decisions, AI, and documentation. Each satrapy retains a viable identity and its actual diplomatic relationship. Any optional new tag remains blocked until a full vanilla, Chaos Redux, Workshop, and local-mod collision audit and a complete package exist.

The root force is recorded and delivered once. It is legal and useful in normal, late, remnant, landlocked, and already-at-war cases. Guard units have a true custom family, a production and reinforcement path, legal assets, and an enforced manpower ceiling.
