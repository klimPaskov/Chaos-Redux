# 071 Persia: country-package matrix

This companion defines which identities and transitions require review. It does not allocate new country tags or invent historical leaders. All labels are design labels.

| Package or state | Identity policy | Government and characters | Military and tree | Required acceptance |
|---|---|---|---|---|
| Root Persian restoration | Reuse the actual Iranian identity | Preserve current living government, advisers, and officers | One opening package and dedicated tree transition | No duplicate tag, no reset of existing assets or wars |
| Provisional imperial administration | Cosmetic and institutional stage of Iran | Existing executive with explicit settlement choices | Common trunk and initial projects | Works for monarchy, republic, and remnant |
| Achaemenid settlement | Route-specific cosmetic and ideology variants | Real eligible crown or explicit constitutional imperial office | Charter, road, regional, and guard branches | No resurrected ancient ruler or forced invented biography |
| Sasanian settlement | Route-specific cosmetic and ideology variants | Explicit central executive and command institutions | Frontier, armor, command, and guard branches | Commands remain institutions until a genuine split |
| Modern settlement | Modern imperial identity adapted to executive form | Non-monarchical completion supported | Industry, clients, transport, mechanization, and bloc | No forced emperor or silent ideological reset |
| Basic satrapy | Existing viable regional identity preferred | Preserve useful regional institutions and eligible leaders | Existing meaningful tree with accepted subject integration | Valid capital, territory, access, obligations, and recipient choice |
| Specialized satrapy | Charter change, not a new copy of the country | Actual satrap or institutional delegation | Specialized obligations and local projects | No duplicate levy, first-charter reward, or destroyed history |
| Treaty partner or client | Retain independent identity unless a deeper agreement is accepted | Recipient remains politically distinct | Defined access, investment, and defense agreements | Not counted as a satrapy without actual subordination |
| Relocated central government | Same Iranian country | Existing executive unless an actual political transition occurs | Recovery missions and surviving route | No refunded opening army or teleported industry |
| Command revolt | Existing legal identity if appropriate, otherwise a blocked custom package | Existing commander or clearly defined institution | Bounded assigned forces and territory | Full tag audit if needed, no default half-country split |
| Fragmented surviving center | Same recorded root receiver where legally supported | Successor executive through an explicit crisis settlement | Reduced route and recovery path | Persistent once-only records and finite asset allocation |
| Negotiated post-crisis empire | Same country and route history | Revised charter or command settlement | Restore lost institutions without replaying first rewards | Current ownership and actual agreements determine milestones |

## Optional new-country gate

No new tag is required by the basic design. If a command revolt or regional administration cannot be represented coherently through existing identities and supported systems, the implementation must propose a complete country package and inspect all installed tag sources before proceeding. The proposal must name the territory, capital, government, characters, ideology variants, flags, tree, units, assets, diplomacy, AI, and exit behavior.

A generic tag reserved in a planning document is not a collision audit. The archive contains neither the installed tag registry nor Workshop and local-mod inventories.

## Tree carryover contract

Carry over existing facts such as completed construction, recovered territory, researched equipment, valid characters, and functioning institutions. Do not carry over mutually exclusive political rewards into incompatible routes. A completed equivalent imperial restoration blocks the root altogether.

Before replacing a tree, resolve active focuses, missions, inherited problems, decisions, and adviser dependencies. The player should not lose access to a government or production system that the new tree never replaces. The exact mapping belongs to the installed-tree audit.
