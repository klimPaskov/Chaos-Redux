# Achievement design and evidence

## Award policy

These are eight proposed Event 108 achievement routes.
Their labels below identify implementation work and are not final achievement titles, descriptions or localisation.
The writing worker must produce distinct concise final copy after the exact conditions and consumers are wired.

Use the existing shared achievement framework and its real eligibility, one-time grant, visibility and persistence conventions.
Proposed event-owned keys require collision inspection before registration.
Do not reserve a numeric shared identifier merely because this event's number is 108.
Each grant has a stable achievement ID, country recipient, relevant wrestler ID, edition ID or sequence, rule version and proof receipt.

Positive championship achievements wait until the ten-day final settlement finishes and the title is ratified.
An interrupted edition, vacant title, unresolved final or provisional winner cannot complete them.
A bye, walkover, forfeiture or restored advancement after a ruling is not a contested victory for a difficulty condition.
An actual contest whose current official result is overturned cannot supply a required win.
Use the official standing effective when the achievement is evaluated and retain its dated evidence.

When a country no longer exists, preserve the athlete's sporting record but do not grant a country achievement to an annexer or an unrelated later holder of the same tag.
The ordinary observer interface cannot grant achievements by selecting a historic result.
Repeated scheduler calls, reports, loading and multiplayer commands cannot grant twice.

The achievements grant the framework's recognition only.
They do not add a second championship PP prize or a permanent military advantage.

## Condition composition and compatibility

Each route uses explicit inclusive boundaries for field count, probability and number of wins.
The minor giant-killer probability test is `P_at_freeze <= .30`.
The deep qualifier field test is `N >= 65` and original seed `> 32`.
Avoid text that promises a threshold different from the predicate.
If the native implementation quantizes probability to integer weights, compare the stored equivalent exact threshold in that representation.

The same title may satisfy several routes when all their independent conditions are true.
That is legitimate recognition, not a reason to pay several champion prizes.
The recipient is the actual valid country participant and the proof identifies the wrestler who achieved the condition.
No multiplayer observer is credited for following the winner.

Late title sanctions update current archive standing and future achievement eligibility.
Do not promise to revoke a platform achievement or shared persistent unlock that the framework cannot retract.
Store the evidence and rule version of the original unlock and show the current corrected sporting standing separately.
A direct-final title transfer after ratification can update the recipient's career, but it does not retroactively create played wins needed by an achievement.

## Icon production contract

Every achievement requires the same original subject rendered as the project's completed, grey and not-eligible states.
Use the immutable achievement template and `process_achievement_icons.py` from the actual repository after reading its current usage.
Do not generate three unrelated pictures, recolor the final DDS by guesswork or overwrite template layers to make a shortcut.

Runtime files belong directly in `gfx/achievements/` with the final registered achievement ID and the required `_grey` and `_not_eligible` suffixes.
The target icon size is 64 x 64.
The icon artist supplies source image, template and pipeline version, all three source and runtime outputs, hashes, contact sheet and native-size review.
The parent registers the actual icons and shared achievement predicates.

The visual subjects must remain legible at 64 pixels and differ from one another.
Do not insert tiny unreadable bracket text, fabricated national flags, medals from unrelated historical competitions or an anonymous face presented as a named historical wrestler.
If a named athlete appears, use that athlete's approved portrait identity and authorized source route.
Abstract sporting subjects usually make the small icons clearer.

## Acceptance fixtures

| Fixture | Expected result |
| --- | --- |
| Valid clean 16-person champion with four contested wins | Clean title achievement grants once at settlement |
| Same record with one required win changed to a walkover | Four-contest condition fails |
| Accused but cleared clean wrestler | Allegation alone does not block clean conditions |
| Actual hidden banned aid without discovery | Clean-route condition fails, while public player information still follows its disclosure policy |
| Minor at lock becomes a major before the final | Snapshotted minor status governs that edition's giant-killer rule |
| Two major favorites, one victory by DQ | Does not satisfy two contested major-favorite wins |
| Human clone in a special-country tag | Actual human classification governs the Open human route |
| Three titled editions with a vacant completed edition between them | Consecutive-title route fails |
| Same champion ID but a recycled different person's portrait or identity | Identity defect blocks acceptance and requires repair |
| Seed 65 advances into a route formerly held by seed 1 | Deep qualifier condition still sees original seed 65 |
| National funding bought then cancelled | Community-only route fails through the immutable purchase ledger |
| Honest network exposure and clean title, repeated ruling callback | One qualifying exposure and one achievement receipt |
| Champion annexed before settlement or tag reused | No grant to annexer or unrelated actor |
| Title corrected after ratification | Current standings amend, no second PP prize and no invented contested wins |
| Load or two clients evaluate the same award | One shared unlock and one proof record |

The implementation auditor must validate the predicates, runtime icon triplets, localisation, visibility, source context and exactly-once receipts together.
This planning package defines the achievement conditions and asset work.
It contains no registered achievements, produced icon triplets or native validation result.
