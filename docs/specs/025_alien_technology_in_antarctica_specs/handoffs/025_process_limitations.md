# Process limitations and continuation handoff

## Completed in this package

- Every supplied project source file was fully read.
- All three supplied catalog CSV snapshots were fully parsed.
- `subagents.zip` was extracted and all 20 project subagent TOML files were fully read.
- Focused external research used official Antarctic institutions and government archives.
- Fourteen source-spec files were written.
- Eight implementation matrices were written.
- Historical research, catalog audit, reading ledger, and parent improvement review were written.
- Context-complete prompts were prepared for the relevant implementation and audit agents.
- The design was reviewed for scope bloat and conflicting event ownership.

## Unavailable capabilities

This interface did not expose:

- the live Chaos Redux repository
- the project custom Codex subagent launcher
- `hoi4-agent-tools` MCP functions
- the offline Paradox wiki snapshot
- installed vanilla Hearts of Iron IV files and documentation
- the current authoritative event-catalog XLSX
- Git state or commit access
- Hearts of Iron IV runtime control

## Consequences

The package does not claim:

- live repository inspection
- source implementation
- actual subagent execution
- MCP event, GUI, technology, or probability evidence
- vanilla or offline-wiki syntax verification
- workbook editing or CSV regeneration
- Git commit creation
- in-game validation

## Independent subagent status

The supplied subagent definitions were used to set scope, prompts, ownership, and acceptance criteria. They were not executable in this interface.

The mandatory independent improvement-loop and completion-audit passes therefore remain open process gates.

## Required continuation order

1. Mount the live repository and verify its branch and current Event 016, Event 025, Event 036, super-event, achievement, and GUI state.
2. Read the required offline wiki and vanilla documentation.
3. Run the repository explorer prompt if file locations or precedents differ from the package.
4. Run the independent improvement-loop planner prompt and disposition its findings.
5. Run the scripted-system architect for the participant registry, duplicate-safe Event 016 reward helper, and Event 036 arbitration ledger.
6. Implement the event chain, decisions, missions, ideas, AI, logs, and cleanup.
7. Run the event UI worker with mandatory MCP before-and-after evidence.
8. Produce the bounded visual and audio packages.
9. Run probability audits before and after weighted changes.
10. Run localisation, decision, event-completion, documentation, and spreadsheet passes.
11. Update the authoritative XLSX and regenerate CSV exports.
12. Run task-specific validation and user-owned in-game testing.
13. Commit only the completed Event 025 implementation.

## Simplification statement

No accepted event route was deliberately simplified or truncated for speed.

The package deliberately excludes countries, focus trees, custom units, portraits, flags, and required 3D models because the design review found no direct gameplay consumer that justified those systems.

The unavailable capabilities listed above are process blockers, not hidden fallbacks.
