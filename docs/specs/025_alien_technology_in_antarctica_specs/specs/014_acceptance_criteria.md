# Acceptance criteria

## Completion rule

Event 025 can be claimed complete only when every accepted surface below is implemented, wired, documented, audited, and free of unreported fallback.

A working opening popup or one visible GUI does not satisfy the event.

## 1. Event identity and registration

- Event ID `25` remains stable.
- Canonical entry is `chaosx.nr25.1`.
- Event is registered as Major.
- Major weight accumulation and reset behavior use the shared system.
- Minimum Chaos level is Calm World.
- Event is not launched through a minor-event cluster path.
- Event-list name and debug mappings exist.
- Event Details row exists.
- Event remains disabled by default until the full rework passes completion review.
- Event shows `N/A` when a valid setup cannot be built.

## 2. Participant eligibility

- Every valid human-controlled country receives a participation choice.
- Landlocked and small human countries have valid expensive routes.
- Human countries are never removed to make room for AI participants.
- AI participants come from a bounded valid-major pool.
- The Kruger State exception is explicit and narrow.
- Human-controlled special chaos and actual nonhuman countries are not excluded solely by classification.
- Actor-appropriate expedition and casualty text is used when a human-controlled special actor participates.
- AI-controlled special chaos and actual nonhuman countries remain excluded except for the accepted narrow Kruger State route.
- Participant registry arrays remain aligned.
- Invalid participants clean up without breaking the race.

## 3. Baseline race

- Entry window works.
- Route selection works.
- Gateway access and route burden work.
- Material commitments debit real resources.
- Outpost construction works.
- Survey and sector confirmation work.
- Final recovery requires valid phase state.
- One winner is declared.
- Same-day tie resolution is deterministic.
- Race can be won with every evolution disabled.
- Race normally resolves within the accepted timing band under representative scenarios.
- A country cannot win through sabotage alone.

## 4. Visible mechanic values

- Expedition Progress is visible and meaningful.
- Logistics Readiness is visible and meaningful.
- Exposure Risk is visible and meaningful.
- Alien Dependence replaces Exposure Risk only for the proper aftermath state.
- Main values have meters, stages, thresholds, icons, and concise tooltips.
- Route, outpost, survey, crew, and fragment state use supporting icons or labels.
- No fourth unrelated main value is exposed.
- Every visible value states cause, consequence, next threshold, and response.

## 5. Decisions and missions

- Each phase exposes three to five primary actions.
- No phase exposes more than six primary actions.
- No action has more than four spendable cost types.
- Costs use matching texticons.
- Personnel, operator, and scientist requirements are not hidden fifth costs.
- Missions have varied and appropriate durations.
- Success, partial success, and failure use distinct logic where specified.
- Selected-rival actions clear invalid targets.
- Hostile actions have cooldowns, evidence states, and counterplay.
- AI uses the same action helpers and costs.
- Obsolete decisions disappear after phase change or closure.

## 6. Evolutions

### Evolution I

- Minimum tier and MTTH are implemented.
- Active signal changes search and risk without blocking baseline completion.
- Remote study, shielding, direct tracking, and jamming routes work.
- Milestone records once.
- Disabled state prevents all gated behavior and recorded flags.

### Evolution II

- Survivor profile is selected from valid supported profiles.
- Tracks, missing personnel, opened compartments, or attacks use the chosen profile consistently.
- Avoid, observe, communicate, capture, and escort responses have valid gates.
- Prepared expeditions can still reach the wreck.
- Milestone records once.

### Evolution III

- Military escort, patrol, blockade, seizure, and demilitarisation actions follow the design.
- Armed incidents use evidence, opinion, tension, and casualty systems.
- An incident does not automatically create a global war.
- Milestone records once.

### Evolution IV

- Wreck integrity and fragment sites work.
- Core-versus-fragments choice is real.
- Delay can bury or destroy material.
- Stabilization can preserve more material at real cost.
- Main core remains the ordinary winner condition.
- Milestone records once.

### Evolution V

- Dependence appears for valid technology holders.
- Contain, destroy, transfer, conceal, and integrate routes work.
- Dependence has accidents, thresholds, and recovery paths.
- The route remains non-terminal and recoverable.
- Global milestone records once without flooding the log with every country stage.

## 7. Winner reward

- Winner reward uses the Event 016 external-grant owner contract.
- Event 025 does not copy custom technology effects.
- Random valid base family grant works.
- Duplicate-safe upgrade fallback works.
- Full-pool Alien Systems Integration result works.
- Reward application returns a clear success result.
- Reward applies once.
- Player-facing text calls the result alien-derived.
- No player-facing Event 025 text names Kruger as the source.
- No Kruger character, Kruger State, Event 016 project history, or Event 016 evolution is created.

## 8. Losing rewards and fragments

- Non-participants receive no reward.
- Failed departures receive no research reward.
- Survey data, minor fragment, and major fragment tiers use verified contribution.
- Losing rewards remain below the main winner reward.
- Fragment categories are stable.
- One fragment has one owner at a time.
- Transfer clears previous ownership.
- Fragment totals survive save and reload.

## 9. Event 036 arbitration

- Shared country ledger exists.
- Shared global repeated-recovery state exists.
- Event 025 first and Event 036 first both resolve safely.
- Exact overlap converts into an upgrade or another valid result.
- Duplicate base reward cannot apply silently.
- Different countries can receive separate outcomes.
- Event 036 being unavailable does not block Event 025.
- Cross-event achievement proves a real converted reward.

## 10. Expedition Board

- Board opens only for participants.
- Header shows current phase and urgent state.
- Three main values render correctly.
- Antarctic sector map renders and updates.
- Sector click regions match visible shapes.
- Rival cards use public or intelligence-derived bands.
- Selected target is clear.
- Action tray changes by phase.
- Costs, disabled reasons, cooldowns, and warnings are readable.
- Confirmation windows repeat target and consequence.
- Resolved winner and loser states work.
- Observer state does not expose the board.
- Multiplayer privacy is preserved.
- Decorative layers do not intercept input.
- Supported resolutions pass render review.
- Mandatory MCP before-and-after evidence exists.

## 11. AI and probability

- Participant weights are audited.
- Route choice is audited.
- Phase action weights are audited.
- Rival targeting is audited.
- Withdrawal logic is audited.
- Evolution action weights are audited.
- Reward fallback selection is audited where weighted.
- Baseline scenarios P01 through P15 are evaluated or marked with exact evidence limits.
- Post-patch comparisons use the same scenarios.
- Human participation has no probability gate.
- AI preserves post-spend reserves.
- AI cannot launch invalid final recovery.
- AI does not spam one hostile action.
- AI can cooperate and rescue when useful.

## 12. Shared systems

- Expedition deaths use the shared Deaths system when enabled.
- World tension rises only from public escalatory actions.
- Opinion modifiers distinguish cooperation, suspicion, exposure, seizure, and armed clash.
- Ordinary expedition activity does not add Air Cleanliness pressure.
- Condemnation is not misused for ordinary sabotage.
- Event 025 does not register an existential world-threat source.
- Cleanup remains safe when another event enters a terminal state.

## 13. Event logs and details

- History records one opening row.
- Winner and resolution state are visible in Event Details.
- Five evolution milestones use the shared context and enabled checks.
- Actor is supplied only for actor-owned milestones.
- Main Evolutions tab shows correct event, stage, tier, date, and actor.
- selected History detail shows related evolutions correctly.
- Event Details evolution catalog does not show fake history metadata.
- Private coordinates, progress, sabotage authors, and internal tech keys remain hidden.

## 14. Super-event

- Opening role is clear.
- Slot is verified and unique.
- Image is final and wired.
- Title, description, button, and quote are final.
- Quote is verified and attributed.
- Audio is a real licensed or public-domain musical recording.
- Final WAV exists in the event sound folder.
- Unique audio ID and volume wrappers exist.
- Settings-aware playback works.
- Audio catalogue and research note are updated.
- No placeholder image, quote, or audio remains.

## 15. Visual assets

- Winner news image exists.
- Required report images exist or approved exact reuse is documented.
- Full board background exists.
- Main value icons exist.
- route, outpost, sector, rival, and action states exist.
- Decision, idea, and achievement icon types use independent art.
- Transparent icons have clean alpha.
- Period fit is reviewed.
- No modern polar equipment or digital UI appears.
- No generated readable text appears.
- Every final asset has DDS output and a live consumer.
- Temporary asset workspace is removed only after permanent evidence promotion and runtime wiring.

## 16. Animation

- Every accepted loop has a brief and frame plan.
- Every frame has real source artwork.
- Static fallbacks exist.
- Horizontal sheet PNG and DDS exist.
- Frame count and sheet dimensions match.
- `frameAnimatedSpriteType` is verified for the target surface.
- Preview GIF is review-only.
- No transform-only mockup is presented as final animation.

## 17. Achievements

- All 14 achievement routes are implemented or any accepted removal is reported before implementation closure.
- Tracking flags and counters exist.
- Disqualifiers work.
- Timed achievements survive save and reload.
- Event 036 achievement verifies overlap conversion.
- Every achievement has final localisation and DDS triplet.
- Achievement test cases exist.

## 18. Localisation

- Every visible key exists.
- Localisation uses UTF-8 with BOM.
- No raw keys appear.
- No player-facing text names internal variables or helper functions.
- No Event 025 text calls the reward Kruger technology.
- Dynamic country, route, rival, sector, fragment, field, and winner text resolves safely.
- Tooltips explain nonstandard costs and blocked states.
- Text follows the project style rules.
- Broad localisation audit is complete.

## 19. Technology graph

- External reward helper and all affected Event 016 technologies are inspected.
- Dependencies and upgrades are valid.
- Event 025 does not create disconnected or duplicate technology definitions.
- Tech render shows required icons and consumers.
- Tech compare confirms only intended graph changes.
- Event 036 overlap conversion maps to valid technologies or aircraft consumers.

## 20. Performance and persistence

- No recurring whole-world daily, weekly, or monthly scan is added.
- Active pulse iterates stored participants only.
- Pulse cadence is centralized.
- Participant count is bounded.
- GUI rebuild is scoped to the current viewer and event state.
- Save and reload preserve phase, missions, values, fragments, winner, and aftermath.
- Cleanup is idempotent.
- No repeated report or reward spam occurs.

## 21. Documentation and catalog

- Event documentation matches final behavior.
- Expedition Board system doc exists.
- Event 016 helper docs are updated when the shared helper is extended.
- Event 036 integration doc exists.
- Super-event research note exists.
- Asset coverage and provenance are permanent.
- Achievement documentation exists.
- Authoritative event-catalog XLSX row is updated.
- CSV exports are regenerated through the repository tool.
- CSV snapshots are not edited directly.
- Plan and handoff dispositions are recorded.

## 24. Simplification reporting

Any of the following must be reported as a simplification or blocker:

- reduced phase count
- removed evolution route
- flat technology reward in place of duplicate-safe arbitration
- generic research bonus in place of the main custom technology
- missing AI strategy
- missing rival counterplay
- omitted GUI state
- placeholder image or audio
- missing achievement
- static substitute for an accepted animation
- copied icon across different asset types
- direct CSV edit
- source-only review in place of mandatory MCP evidence
- skipped independent improvement or completion audit

## Final acceptance statement

The event is ready for completion only when the final report can state that every accepted route is implemented, every asset is final and wired, every weighted surface has comparison evidence, every required document agrees with runtime behavior, and no simplification or fallback remains undisclosed.
