# Improvement-loop review

## Review purpose

This parent review applies the Chaos Redux improvement-loop standard to the completed Event 025 specification package.

The project custom `chaosx_improvement_loop_planner` could not be launched in this interface. Its context-complete prompt is included in the package for the required independent pass before implementation closure.

## Feature promise

The event promises an international race for an unknown Antarctic wreck.

A player should expect:

- a difficult expedition
- a visible race
- route and supply choices
- uncertain search information
- rivalry and cooperation
- a major scientific reward
- escalating strange behavior at higher Chaos

The package delivers those expectations through one integrated loop and avoids disconnected systems.

## Depth review

### Player action

The player enters immediately, chooses a route, commits material, builds an outpost, surveys sectors, manages three visible values, selects rivals, and decides when to attempt recovery.

Result:

Sufficient depth.

### Pressure

Logistics Readiness and Exposure Risk create immediate pressure. Rival progress, active missions, route interruption, seasonal timing, and evolution hazards create additional consequences without adding more main meters.

Result:

Sufficient depth.

### Replayability

Replayability comes from:

- different participant rosters
- route families
- hidden crash sector
- reward family
- rival behavior
- five independently enabled evolutions
- survivor profile
- fragment distribution
- Event 036 order
- Evolution V policy

Result:

Sufficient depth.

### AI

The package defines participant, route, action, target, withdrawal, and evolution behavior with named audit scenarios.

Result:

Design complete, independent probability evidence remains an implementation gate.

### Presentation

The Expedition Board is justified by repeated target selection, sector state, three values, rival cards, and evolution overlays. Ordinary decision categories remain the entry and mission layer.

Result:

Appropriate GUI depth.

### Assets

The package authorizes a bounded set of super-event, news, report, GUI, icon, achievement, animation, and audio assets. It rejects portraits, flags, focus icons, units, and required 3D work.

Result:

Sufficient visual depth without unrelated production.

## Anti-bloat decisions

### No new country

An Antarctic expedition authority or alien state would shift the event away from the race and require territory, forces, leaders, politics, flags, and cleanup without improving the main loop.

Decision:

Do not add.

### No focus tree

The expedition is a temporary international system available to many countries. A bespoke tree cannot fit every participant. Decisions and the board are the correct surfaces.

Decision:

Do not add.

### No custom combat unit

Expedition escorts are requirements and commitments. A new Antarctic battalion would add Event 019 integration, equipment, counters, models, sounds, templates, and AI without a strong battlefield role.

Decision:

Do not add.

### No required 3D craft

The craft has no direct map, aircraft, building, or combat consumer in Event 025. Event and GUI art communicate it better. Event 036 can own a future reusable aircraft or spacecraft model.

Decision:

Do not add.

### No fourth main meter

Survey certainty, outpost integrity, crew condition, intelligence, and wreck integrity remain supporting states. Adding all of them as main meters would overload the board.

Decision:

Keep three main visible values.

### No active cluster membership

Scientific Research is a useful theme. Runtime cluster membership creates pacing risk for a Major event.

Decision:

Keep Event 025 standalone.

## Remaining design questions for the independent planner

The independent improvement planner should confirm or challenge these focused points:

1. whether six Antarctic sectors create the clearest board geometry
2. whether fourteen achievements are distinct enough to keep
3. whether the Alien Systems Integration capstone is the right full-pool fallback owner
4. whether Evolution V needs one rare public international commission route beyond country policies
5. whether the Kruger State AI exception should remain
6. whether a direct southern-access table can be defined from live map data without brittle tag lists

The planner should avoid adding countries, focus trees, units, or unrelated end-state content unless it identifies a concrete playable gap that the current loop cannot cover.

## Stop recommendation

Broad expansion is not recommended.

The design has a clear loop, real choices, AI requirements, presentation, replayability, cross-event integration, failure states, partial outcomes, assets, and completion gates.

Further broad mechanics would likely duplicate values, increase action clutter, or move attention away from the expedition race.

The next work should be independent review, live repository inspection, implementation, asset production, weighted audits, GUI rendering, documentation reconciliation, and completion testing.

This is a parent closure recommendation. It is not a substitute for the mandatory independent planner and completion auditor passes.
