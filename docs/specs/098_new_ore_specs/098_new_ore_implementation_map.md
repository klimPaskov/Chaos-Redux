### Concrete execution order and file boundaries

P0 is source/native feasibility. P1 is accepted helper and lifecycle implementation. P2 is decisions, AI, art, and presentation integration. P3 is matched validation and wording review. P4 is documentation/catalog reconciliation, improvement-loop closure, and final acceptance. A blocked upstream gate stops only the consumers that depend on it. Independent reading, research, and asset-reference work can proceed.

All roles read the accepted pack and current role/skill instructions. All handoffs are named Event 098 Markdown files in `docs/plans/098_new_ore_plans/subagent_handoffs/`. Read-only roles write only their own reports. A role may not edit another worker's owned output, accepted source specs, shared framework/index files, another event's private files, or the authoritative catalog unless its row explicitly permits that surface. Proposed file globs below are ownership boundaries for the future implementation and do not assert that every file already exists. The parent freezes exact filenames before spawning a patch-capable worker.

## Parent-owned integration

The Super-Alloy presentation reserves slot `119` in `super_event_visible` under the [central identifier ledger](../shared_identifier_registry.md).
Recheck presentation occupancy before runtime wiring, including constant-based selectors.
Audio ID allocation is independent, and final text, art, recording and runtime acceptance remain separate from this identity reservation.

The coding parent owns public `chaosx.nr98.1` compatibility, accepted source changes, event/idea/state/decision connections, shared event log and details, evolution controls, super-event framework integration, shared registries, and final combination of worker outputs.

Each event-specific helper must have a paired implementation/documentation contract naming caller scope, target scope, persistent inputs, temporary outputs, zero/failure defaults, modifiers and other side effects, receipt ownership, reentrancy, cleanup, and consumers. Register genuinely reusable owner APIs in the shared index without moving another event's private state into a generic helper.

The source-state registry, country aggregate entitlement, contract records, and finite confrontation records need distinct ownership. State validity is not a country `exists` test. A country-to-state helper call cannot assume that ROOT, FROM, PREV, or a prior temporary return still identifies the payer or supplier after nesting. Freeze and verify explicit context before work, then initialize returned fields on every path.

Use the current Event 029 registered-mine lifecycle as the source precedent for bounded territorial callbacks. Use current Event 018 strategy consumers as an inspected precedent for state-oriented AI. Review the actual implementation revision and native semantics before adoption. Source similarity alone does not prove coverage or authorize global recurring scans.
