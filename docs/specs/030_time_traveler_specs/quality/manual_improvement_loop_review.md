# Event 030 Manual Improvement Loop Review

This is the original planning session's manual closure review, kept as design history with disposition `unresolved` until the package is accepted.
The 2026-10-10 spec audit in the [README changelog](../README.md#changelog) later reduced several surfaces, so counts below that differ from the specification parts are historical.

## Review result

Broad design expansion is no longer recommended before implementation. The package already gives Event 030 a complete baseline, five evolutions, one terminal branch, one manual scenario, bounded international play, durable outcomes, AI plans, visual direction, and integration contracts. Additional large mechanics would increase maintenance and player load without repairing a known design gap.

This conclusion is about planning depth. It is not an implementation completion claim.

## Playable promise under review

The event promises useful future knowledge, political risk, foreign competition, and a timeline that becomes less reliable as countries act on it. The player should make decisions about access, verification, custody, consultation, secrecy, and temporal policy. The event should remain playable if the original traveler dies, defects, or disappears because copied knowledge and timeline consequences survive.

The source brief already contained a strong escalation ladder. Its weak point was the absence of strict limits and the risk that every later idea would become another meter, country, focus tree, or global popup. The improvement pass therefore focused on creating deeper play with fewer exposed systems.

## Initial design gaps and accepted corrections

| Gap in the rough concept | Proposed correction | Resulting player effect |
| --- | --- | --- |
| baseline bonuses could become a large passive modifier package | strongest advice is delivered through six consultation mission families | the player must act on advice and can fail, partially succeed, or discover forgery |
| three values existed without precise ownership or thresholds | Credibility is host-local, Exposure and Divergence are global, and all three have staged consequences | each value changes a distinct decision |
| foreign competition was broad and potentially unbounded | interested countries use a sparse registry, operation maturity, target selection, and cooldowns | rival action is readable and does not scan the world continuously |
| traveler loss risked ending the event | custody and institutional knowledge are separate | the character can be lost while copied knowledge and temporal consequences continue |
| every historical figure could become a full country or tree | figures begin as characters and movements, with countries created only after durable territorial control | claimants can matter without flooding the map with weak tags |
| modern visitors risked partisan or current-news treatment | named figures use neutral, campaign-dependent institutional packages and require implementation research | no route presumes one canonical political judgment |
| Epoch Breakdown could become random spectacle | incidents use eight bounded families, local lifecycles, caps, and cleanup | anomalies create decisions and consequences without constant popup spam |
| Temporal Stability could become a fourth meter | it is derived from Divergence and replaces the displayed label in Evolution V | the event remains within the three-value budget |
| machine apocalypse risked copying a known franchise | Closed Future, Consensus Engine, Causal Monopoly, and strategic portal nodes define an original antagonist | the terminal route has its own motive, institutions, units, and visual language |
| maximum scenario intensity could bypass terminal rules | maximum setup can raise Chaos above 1000 and prepare machine readiness, but it cannot set `world_end` | manual setup remains powerful while preserving branch gates |
| a custom window could be built only because the event is large | normal decisions, a category picture, compact display, selected targets, and map highlights are sufficient | implementation avoids an expensive UI surface with little added clarity |

## Pressure and consequence test

The baseline now contains several connected pressures.

- Higher Credibility opens better consultations and political access, while failed public predictions can reduce trust sharply.
- Higher Exposure increases foreign operations, domestic faction competition, public pressure, and later portal visibility.
- Higher Divergence weakens exact forecasts and increases strange outcomes, while some aggressive routes deliberately raise it for short-term advantage.
- Strong custody protects direct advice but can make the traveler a prisoner, political rival, or foreign target.
- Wide institutional copying protects the host from total loss but increases Exposure and the number of people able to steal or distort the knowledge.

These pressures create real choices without requiring another currency.

## Replayability test

Replayability comes from changing hosts, traveler profile, access arrangement, consultation targets, foreign rivals, custody outcomes, ambition routes, selected historical figures, selected future visitors, anomaly families, temporal alignment, and machine readiness. The normal campaign does not attempt to display every figure or incident in one run.

The manual scenario provides controlled breadth. Its maximum setting activates every category and a bounded representative selection. It does not force every named person into the same campaign.

## AI test

The AI design covers host policy, consultation choice, counterintelligence, foreign operations, claimant handling, anomaly response, temporal stance, machine collaboration, and terminal strategy. Each choice reads current war, stability, industry, stockpiles, ideology, threat, distance, target validity, and route state where relevant.

All probability-bearing decisions remain implementation evidence gaps until the named scenarios receive the required HOI4 MCP probability workflow.

## Visual and text test

The package has a clear visual hierarchy.

- baseline uses one category picture, one original traveler portrait family, three value icons, consultation icons, and custody or exposure status variants
- historical and future visitors use sourced portrait packages and distinct movement or claimant art only when they appear
- Evolution IV uses report art for incidents and does not require a 3D model for every anomaly
- Evolution V adds future-faction symbols and strategic node art
- the terminal branch adds the complete machine visual, unit, counter, model, sound, and super-event package

Final player-facing wording remains an implementation task. The specification gives direction and research gates without supplying copy-ready localisation that could bypass review.

## Closure handoff

Implementation should now focus on exact source review, script ownership, portrait and asset production, final figure research, probability evidence, and testable integration. A new broad improvement addendum should be written only after a meaningful implementation tranche exposes a different design problem.

The improvement loop can stop at this stage. Further expansion before implementation would add bloat.
