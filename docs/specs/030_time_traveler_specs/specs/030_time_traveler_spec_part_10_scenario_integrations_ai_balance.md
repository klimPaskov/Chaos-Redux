# Event 030 Time Traveler Specification Part 10: Triggerable Scenario, Integrations, AI, Balance, and Cleanup

## Triggerable scenario

Working scenario ID: `SCN-015`

Working scenario name: All Times at Once

The ID is available in the supplied CSV export and no indexed repository match was found. Implementation must still confirm the authoritative XLSX and live registry before reserving it.

The scenario has one type. It uses the shared Low, Medium, High, and Maximum intensity slider.

The launch bypasses normal Event 030 timing, source-event history, evolution pacing, date, and Chaos-tier prerequisites needed to create the requested temporal setup. It retains valid host, target, actor, country, territory, and terminal conflict gates. Setup flags are cleared before ordinary event behavior resumes.

The scenario does not fabricate an automatic Event 030 history row. It records only the scenario launch surfaces and the actual events or evolutions that the launch is designed to create.

## Scenario setup sequence

1. Select a valid original traveler host from existing majors and player countries.
2. Create and verify the original traveler.
3. Apply an intensity-specific access and Exposure state.
4. Activate the requested evolution layers.
5. Select eligible past and future visitor packages.
6. Create bounded anomaly and machine incident registries.
7. Initialize Temporal Stability when Evolution V is active.
8. Begin claimant, coup, or civil-war setups only where their support and territory contracts are valid.
9. Apply the intensity Chaos change.
10. Clear the scenario bypass and hand control to ordinary Event 030 systems.

## Intensity profiles

### Low

- one original traveler
- one historical figure
- no more than one future visitor
- two local anomaly incidents
- one minor machine scout incident at most
- no forced full civil war
- modest Exposure and Timeline Divergence
- proposed `+75` Chaos

Low intensity demonstrates the system without opening a global temporal war.

### Medium

- one original traveler
- two historical figures
- one future visitor
- four anomaly incidents across at least two regions
- one machine foothold
- one claimant or coup crisis where valid
- Temporal Stability remains above the severe-fracture band
- proposed `+200` Chaos

### High

- one original traveler
- up to four historical figures
- up to three future visitors
- six to eight anomaly incidents across several regions
- three machine footholds
- several claimant crises and up to three full civil wars where valid
- Evolution V can activate if its non-Chaos conditions are met
- proposed `+450` Chaos

### Maximum

- one original traveler
- every eligible temporal category is represented
- up to six historical figures and five future visitors, bounded by valid packages and performance
- the largest safe active anomaly registry
- multiple machine footholds and one prepared industrial node
- widespread claimant crises and several valid civil wars
- Evolution V begins active
- Temporal Stability begins near collapse
- Chaos is raised to at least `1050` if it is lower
- all non-toggle Machine Extinction War readiness conditions are prepared
- the world-end branch is not fired during setup

Maximum intensity makes the machine route eligible after setup. It still respects the public branch toggle, the shared no-other-world-end gate, and its own delayed readiness check.

## Scenario safeguards

- Do not spawn a visitor into a nonexistent polity with no valid legacy route.
- Do not create more claimant wars than the active cap.
- Do not create a new country without viable territory, capital, force, economy, and cleanup.
- Do not duplicate a real-person character token.
- Do not use a setup bypass after the scenario initialization ends.
- Do not launch the same scenario twice in one campaign unless a future explicit reset route is designed.
- Do not automatically set `world_end`.

## System integrations

### Event 005 Soviet Collapse

A future Russian visitor can react to an active or completed Soviet collapse. Their route can defend the Union, organize a Russian successor, or contest one of the existing successors. Event 030 must use Event 005's actual countries and ledgers and must not create duplicate successor tags.

### Event 006 Independence Wave

Historical and future claimants can recognize, oppose, or exploit released countries. A temporal restoration must not annex Event 006 carriers without using the established territorial and provenance contracts.

### Event 011 Secret Alliance

The host can share future knowledge with a secret coalition. A coalition can also coordinate an abduction or protection plan. Event 030 reads the coalition result and does not recreate the alliance system.

### Event 013 Natural Disasters

A traveler may warn of a proven disaster sequence only through the Event 013 public gateway and its target proofs. Event 030 does not predict or start an unsupported disaster directly.

### Event 016 Brilliant Scientist

A scientific consultation can identify a scientist, project, or valid custom technology route. Any custom grant uses the owner API. Event 030 does not copy the full Event 016 project system.

### Event 019 Soldiers from Nowhere

Displaced temporal formations may use compatible formation and provider patterns. Event 030 keeps temporal provenance and incident cleanup under its own owner. It does not mislabel every temporal formation as Event 019 history.

### Event 027 Doctrine Research

A military consultation can grant one valid doctrine mastery result or doctrine choice through the established doctrine system. This is preferred when a full technology grant would be excessive.

### Event 032 Missiles Giveaway and nuclear systems

Future visitors and machines can identify missile or strategic weapon sites. The owning missile and nuclear systems control technology, stockpiles, use, fallout, and condemnation.

### Event 039 Murder Mystery and Assassin Network

A traveler assassination can connect to the existing investigation or assassin-network logic when that package is active. Event 030 still owns custody, traveler survival, and knowledge consequences.

### Event 044 Space Race

Future space knowledge can improve a valid space project, reveal a later risk, or attract a future visitor. The space system owns its projects and rewards.

### Event 052 Intel Leaked

A broad leak can expose traveler records, visitor files, or portal locations. Event 052 owns its leak event, while Event 030 receives Exposure and custody consequences.

### Event 151 Teleportation Experiment

A successful or failed teleportation project can shorten portal evolution pacing. The teleportation system owns its experiment effects. Event 030 reads a stable result flag or API output.

## Shared civilian and humanitarian systems

### Deaths

Every direct civilian loss uses exact state population transactions and the shared Deaths tracker. Event 030 defines distinct cause labels only where the shared taxonomy needs them, such as temporal incident or machine extermination.

### Migration

Evacuation, displaced populations, returned settlements, unsafe forced return, and machine attacks use proof-carrying Migration requests. Movement is not a death. Route deaths remain part of the same origin debit.

### Famine

Machine attacks on food systems, isolated anomaly zones, temporal disease, and blocked refugee concentrations can submit proven famine incidents. Event 030 does not write directly into the famine primary ledger.

### Air Cleanliness

Temporal activity does not raise contamination by itself. Chemical, biological, wildfire, volcanic, nuclear, and fallout sources remain owner-controlled. Future technology or machine warfare changes Air Cleanliness only when it actually produces one of those sources.

### Condemnation

Public preventive repression, assassinations, concealed temporal disease, attacks on civilians, and machine collaboration can create public condemnation through the existing source model. Hidden evidence stays hidden until disclosed.

## Balance principles

### Baseline power

The initial national spirit is useful but restrained. It should not make the host superior in every system. One active consultation at a time creates meaningful bursts of advantage.

### Advice strength

A completed consultation should change a plan, unlock an action, improve a real map or production surface, or provide a strong temporary advantage. Small modifier dust is unacceptable. The reward remains bounded by one active consultation and a cooldown.

### Technology limits

No baseline option grants unrestricted ahead-of-time technology. Future knowledge must pass through research bonuses, doctrine mastery, special projects, custom technology APIs, limited equipment batches, or adaptation missions.

### Traveler government

A traveler leader is powerful in coordination and intelligence. Political resistance, divergence, foreign containment, and loss of specialized consultation capacity offset the gain. The leader should not grant an all-stat maximum trait.

### Historical figures

Historical commanders and rulers have strong identity and leadership. Modernity limits, institutional conflict, and political opposition prevent free super-generals.

### Future visitors

Later methods require current-era institutions and equipment. A visitor cannot use social media, satellites, precision weapons, modern finance, or digital surveillance without the needed infrastructure.

### Temporal incidents

Study and exploitation provide meaningful rewards. Containment and closure provide stability and safety. Neither route should dominate every campaign.

### Machine war

The Closed Future begins with strong regional forces and industrial conversion. It needs supply, factories, and nodes. Human players receive warnings, targetable infrastructure, alliance tools, and a feasible counteroffensive path.

## Cleanup and invalidation

### Host annexed or destroyed

If the current custodian ceases to exist, custody passes to a valid controller, occupier, ally, captor, or saved safe destination according to the active situation. If no valid path exists, the traveler disappears. The old country keeps no active decisions.

### Traveler dies

Remove direct access, active character roles, and future consultations. Convert the institutional spirit to the correct legacy stage. Close Evolution I if no reappearance path exists.

### Visitor or claimant dies

Close personal decisions, remove movement actions that require the person, resolve supporter state, and retain any durable political movement or restored state that can survive independently.

### Country changes tag or ideology

Use saved country identity and event targets where possible. Re-evaluate route validity without deleting completed records.

### Portal closes

Remove active missions, modifiers, targets, and node entries. Apply one closure result. Do not process the state again.

### Machine node recaptured

Remove or downgrade Automated Conversion, reconcile factories, close machine production, update the machine footprint, and make the state ineligible for duplicate node creation.

### World end begins

Stop normal Event 030 evolution and incident generation. Preserve only the machine-war systems, relevant visitors, resistance, humanitarian processing, and aftermath prerequisites.

### World end defeated

Close machine production and target systems, remove terminal combat actions, retain approved aftermath content, and preserve permanent historical consequences.

## Save and multiplayer persistence

All custody, public values, active visitors, resolved figure identities, operation cooldowns, portal nodes, machine footprint, scenario launch state, branch toggles, and world-end state must survive save and reload.

The original traveler cannot duplicate through player tag switching, annexation, release, or multiplayer reconnect. Human players who gain or lose custody receive the correct category and legacy state on the next bounded synchronization.
