# 14. Achievement design

The following achievement concepts use working labels, not final localisation. They require the shared eligibility framework and one-time history records. Debug fixtures, forced test starts, hotjoin reseeding, and repeated liberation of the same target cannot qualify.

## Shared restrictions

Normal automatic Event 79 opening is required. A later ordinary race in a save that used unrelated debugging is governed by the shared achievement eligibility owner, not a new local guess. Package fixtures explicitly mark their own forced races ineligible.

A target can contribute to an Event 79 achievement only on its first qualifying natural takeover by that player in the campaign. Releasing and retargeting the same country cannot supply another distinct subject or another competition count. A target that changes its cosmetic name is still the same historical country identity for this purpose.

A rival must have actually paid and completed the stated actions. Registration, free seeds, cancelled attempts, and failed zero-loss interference do not establish meaningful competition. Material actions count when delivery occurs. Coalition support payments can count as rival participation only when the shared coalition operation completes with a nonzero effect, and they do not count as two actions.

The player must be the winning sponsor, not its overlord, faction leader, or co-op observer. If a player subject wins through a proven nested-subject path, the same direct winner identity applies. Unsupported nested relationships cannot be granted an achievement to conceal a failed takeover.

## Award ordering

Evaluate awards only after the takeover postcondition confirms the intended puppet relationship. Record achievement-specific qualifying facts before active race arrays are cleaned. Award each achievement through the shared registry and eligibility contract once.

The multi-subject achievement reads current direct subjects alongside historical race receipts. A later independence event can prevent an unearned award but does not revoke an already earned achievement unless the shared system explicitly does so.

## Assets and writing

Each achievement has one earned subject and two derived states at 64×64. The standard templates and overlay are immutable. Register the six IDs in the shared achievement file with its existing unique ID. Do not create an unrelated parallel achievement namespace file that the game will not consume.

Final titles should emphasize the player's concrete result. Descriptions must state the restrictive conditions clearly. Avoid vague claims about becoming the world's master, cultural quotations, or allusions that have not been researched.
