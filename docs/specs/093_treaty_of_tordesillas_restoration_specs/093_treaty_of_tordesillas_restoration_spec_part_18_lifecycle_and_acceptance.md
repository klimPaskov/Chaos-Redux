# Treaty of Tordesillas Restoration: continuity and acceptance


## What must survive a long campaign

The event must remember one initiating firing, the actual Portuguese and Spanish authorities, the Galician settlement, the signed aid contract, its credited deliveries, the treaty's political agreements, the geography version, regional project enrollment, and the world-end's ownership and outcome.

This is a continuity requirement, not a request for a large custom control panel. The player sees the facts needed for the next decision. Supporting records must be durable enough that a save reload, cosmetic rename, or temporary occupation does not produce a second bargain or forget a breach.

## Country changes

A verified national successor may inherit the country's rights and obligations. A living country with the same cosmetic name is not enough. A newly released Portugal cannot automatically receive every old project reward unless its continuity and ownership are valid.

A new Spanish civil war can suspend national treaty authority. The event identifies which actual national claimant can reaffirm the agreement and which cannot. It does not let all splinters operate the same integration queue or count the same sphere territory several times.

Capitulation stops actions requiring effective national control. Annexation or subordination threatens the two-power premise. The ordinary treaty can enter suspension, while an active world-end uses the explicit recovery and failure periods. No invisible puppet is promoted to sovereign co-ruler just to keep an interface open.

## Territory changes

Every delayed transfer or project completion rechecks current legal ownership, control, participant validity, and the agreed exception rules. An expired offer cannot transfer land from a new owner that never accepted it.

A state lost during integration pauses or invalidates the enrolled project. A newly conquered state cannot join a nearly finished project. A partner transfer preserves actual population and shared records. A state already cored by another valid system is not awarded a duplicate project reward.

Map changes need a versioned compatibility review. A state ID reused for different geometry must not inherit a previous treaty assignment or Galician status. The installed map's actual identities remain a release gate.

## Simultaneous decisions and payment

Two human governments may answer proposals at nearly the same time. One accepted transaction must have one authoritative result. A second confirmation cannot repeat the state transfer, deliver a second equipment copy, or award another relationship gain.

The same rule applies to cancellation and refund. A completed payment record cannot be treated as unpaid after a reload. A stale displayed quote is recalculated before the actual transaction. If a required component is unavailable, the transaction does not produce a partial territorial reward.

The engine does not provide a universal atomic rollback across arbitrary effects. The implementation must prove its preflight, receipt, and compensating behavior. This specification does not replace that proof with the word 'atomic.'

## Settings and disabled states

An ineligible root is not logged as a successful firing. Disabling Event 093 prevents a new automatic selection. The unreworked repository event remains disabled by default until the complete implementation and required proof justify release.

Evolution and world-end settings are separate. A Galicia-only campaign remains valid. A limited treaty can continue without universal partition. Existing country ownership and legitimate cores are not deleted because a player changes a setting.

The event must not leave dead missions, permanently reserved project slots, stale country targets, or a world-end ownership flag after its legitimate resolution. Cleanup affects Event 093-owned duties and presentation, not unrelated wars, achievements, or third-party claims.

## Performance and update discipline

The worldwide geography and initial weighting are prepared once for a supported map and campaign activation. Runtime work should use the two main actors, registered projects, relevant treaty members, and bounded target sets. The interface must not scan every country and every state on each frame.

Do not introduce all-country daily, weekly, or monthly on-actions or repeated whole-world scans without the project's explicit approval. Use established shared ownership, treaty, and ledger update routes where available, and inspect them before making compatibility claims.

Readiness changes when the relevant ownership, control, core, or patron status changes. A bounded authoritative refresh can reconcile the result where the shared framework supports it. The exact installed update route and its performance must be measured. A synthetic Python calculation is not runtime performance evidence.

## Completion standards

Design acceptance means the original brief has a complete route through the specifications and every added mechanic has a purpose, cost, consequence, and exit. Implementation acceptance additionally needs installed-source inspection, compatible country and focus handling, actual probability evidence, valid assets, localization, performance checks, and live tests.

The package includes design-level tests for selected arithmetic and ownership rules. Those tests can catch internal contradictions in the proposed rules. They cannot verify Clausewitz behavior, the current game map, native equipment delivery, faction transition, UI rendering, or the actual coring benchmark.

The provided specialist definitions were read but could not be launched here. Main-agent review is reported as such. Required independent role checks and the near-completion improvement-loop planner remain open. A future implementer must not convert that tooling limitation into a claim that the specialist reviews passed.

## Final boundary

The delivered files are a source-specification package. They do not implement Event 093, change the live repository, update the authoritative workbook, produce final art or sound, or establish release readiness. The exact missing evidence and unperformed work are listed in the delivery reports rather than hidden inside gameplay prose.
