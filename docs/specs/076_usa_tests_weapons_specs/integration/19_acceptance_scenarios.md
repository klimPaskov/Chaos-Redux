# 19 · Acceptance scenarios

## What a completed implementation must demonstrate

These are required test cases, not executed results. Each actual run must name the repository revision, game version, DLC and mod settings, fixture, relevant country and state, expected result, observed result and evidence location. Store actual reports in `docs/plans/076_usa_tests_weapons_plans/`.

Static script analysis, probability analysis, live gameplay, visual review and audio review answer different questions. Passing a syntax check does not prove correct military casualty registration. A screenshot does not prove that a reward cannot be granted twice. An unavailable tool is a reported gap, not an automatic pass.

## Required completion review

Run the supplied event-completion and relevant specialist checks against the actual implementation. Near completion, run the independent improvement-loop planner with clean context and the full current design and evidence. Resolve findings through real fixes and repeat the applicable tests. A parent-written summary or a prepared agent prompt is not a replacement for that independent run.

No case in this file was executed in HOI4 during this planning task. The package's own structural checks are listed separately in [23](../reference/23_package_checks.md).
