# Blockers and Uncertainty

## Process blocker

The custom Chaos Redux subagent runtime was not available. No required project subagent was actually spawned. Manual role-equivalent reviews are included, but implementation must run the real agents with `fork_context=false`.

## Repository and engine access blocker

The full local Chaos Redux repository, offline Paradox wiki snapshot, installed Hearts of Iron IV documentation, and vanilla files were not mounted in this planning environment.

Consequences:

- exact current local file paths are not guaranteed
- existing helper names and call patterns need verification
- safe dynamic-country and civil-war syntax needs local precedent
- exact GUI dimensions and parent windows are unknown
- exact script constants and effect-field support are unknown

## Golem identifiers

The current public inspection did not establish the final golem parent system, unit identifiers, flags, or counts. The registry entry and parent isolation design are complete at concept level, but implementation must locate and verify the real system.

## Helicopter availability

The user requested possible helicopter-only formations. This is included only when the installed game and Chaos Redux define a valid land battalion or support type. The generator must not invent a missing token.

## Random template limits

The design target is one to 25 combat battalions and zero to five support companies. The final safe range and template-construction method must be tested against the installed game version and current mod helpers.

## Dynamic country model

A dynamic creation model is preferred so the event can produce regional offshoots without exhausting a fixed tag pool. If the engine or current repository pattern cannot safely support the required identity, focus loading, flags, and former-parent tracking, implementation must stop and request approval for a fixed-tag fallback.

## Parent isolation

Public inspection confirmed significant parent zombie and Death identity logic. A full local audit is still required for every tag, original tag, country flag, unit type, idea, count, state marker, and super-event trigger. No derivative package is complete until those checks prove isolation.

## Assets

This package plans assets but does not generate them. The 20 portraits, flags, icons, report images, UI, animations, and achievement triplets remain implementation-time deliverables.

## Localisation

The package intentionally provides direction rather than final player-facing text. Final localisation remains implementation work.

## Spreadsheet

No workbook was modified. Final catalog entries must mirror implemented in-game localisation and therefore belong after implementation.

## Simplification statement

The planning design was not intentionally shortened into a minimal outline. It includes every requested evolution, dynamic unit behavior, claimant system, derivative family, triggerable scenario, AI layer, asset family, and acceptance surface. The unavailable subagent runtime and unavailable local engine references are process and verification blockers, not hidden simplifications.
