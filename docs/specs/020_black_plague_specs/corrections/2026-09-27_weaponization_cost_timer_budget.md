# Black Plague weaponization cost and factory-timer correction

**Disposition: implemented in source; native decision-row and timed-factory behavior remain unverified.** The user's accepted CBRN overhaul requires a short, readable cost row, payments and affordability shown once, exact-cost selection, and production commitments with real factory time. The three Event 020 production families previously paid four resources in addition to factory use or hid one payment in a repeated cost hover. This correction is the parent's budget choice within that accepted design; the individual material amounts were not separately specified by the user.

| Action | Upfront payment | Native factory commitment | Removed payment |
| --- | --- | --- | --- |
| Four project postures | 35 support equipment; 20 Command Power | One civilian factory for 30 days | 20 motorized equipment; 250 fuel |
| Expand Payload Stockpile | 40 support equipment; 400 fuel | Two civilian factories for 60 days | 20 motorized equipment; 20 Command Power |
| Destroy Payload Stockpile | 20 support equipment; 10 Command Power | One civilian factory for 30 days | 100 fuel |

Each custom cost row quotes both upfront amounts and the full factory commitment with working support, Command Power, fuel, and factory texticons. The hover explains duration and that materials already spent are not refunded if work ends early; it does not repeat the amounts. The displayed numbers bind to the same script constants as the inclusive pre-click stock, Command Power, fuel, and factory checks and the effect-side material debit. A separate pre-selection predicate checks free factories, while the click-time effect rechecks only the resource payment because the native factory may already be reserved at that point. Holding exactly the displayed amount passes each source comparison.

The `available` checks are wrapped in `hidden_trigger` so the cost row is the single ordinary payment display. The shared posture predicate excludes all four active posture decisions; the stockpile predicates exclude their own active instance and the opposite work order. Each `custom_cost_trigger` accepts either this pre-click affordability predicate or its own settled active decision receipt. This prevents an active but unsettled decision from reopening selection and keeps an already-paid, visible timed row from switching to the red blocked variant solely because its start gate closed. The native `_blocked` variant still colors all three amounts red when the combined pre-click gate fails; it does not identify which component is short. Native visual inspection remains necessary to judge whether that treatment is clear enough.

The four posture decisions set `black_plague_weaponization_approach_chosen` when selected. Expansion and destruction set their own cooldown flags on selection. Their former `cancel_trigger` clauses negated start predicates requiring those flags to be absent, so the active decisions could cancel themselves and release their factories before the stated duration. The new continuation triggers use the actual ongoing project or valid completed programme plus a positive action receipt instead of start-only stock or cooldown absence. The receipt makes a click whose effect failed to settle cancel promptly rather than hold an unpaid factory timer. They permit a selected Defensive Conversion posture to retain its 30-day factory commitment. World end, project termination, or invalid actor can still end the relevant timer. Materials are spent only once in `complete_effect`, and the production or destruction outcome is applied there; the timed decision holds factory capacity afterward. No new worldwide periodic callback is added.

An active posture decision remains visible through its own `has_decision` branch after the posture flag closes new choices. An active destruction decision likewise remains visible after its click removes the last payload. The active timer can therefore remain legible while the factory is committed without reopening a second purchase.

Expansion and destruction cannot be started while the other timed stockpile action is active. This prevents contradictory simultaneous work orders against the same payload reserve; it does not alter either action's already-paid outcome or refund policy.

The correction changes affordability and the economic price, not the six existing `ai_will_do` weight expressions. AI decision eligibility and actual factory-duration behavior still need scenario evidence. The full disease category remains crowded; this cost repair does not satisfy the separate Event 020 six-lane interaction addendum. The project-entry minimum support, trucks, and fuel prerequisites are not payment for these three actions and remain a separate research-access question.
