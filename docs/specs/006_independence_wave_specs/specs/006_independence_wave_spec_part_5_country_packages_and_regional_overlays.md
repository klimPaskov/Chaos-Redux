# Independence Wave, Part 5: Country packages and regional overlays

All names in this file are working labels, not final localisation.

## Country package contract

Every released country is assembled from a package registry. A package is more than a territorial release definition.

Every package must define:

- candidate identity
- registered tag reuse, custom `X` tag, or exact vanilla route-overlay policy
- region and overlay
- earliest candidate pool layer
- unique anchor territory
- compact territory
- optional extended territory
- ambition territory and formable families
- protected host interactions
- government archetype pool
- starting leader or institutional leadership method
- party and ideology direction
- starting idea profile
- starting force archetype
- economic and logistics problem
- former host relationship profile
- patron interest profile
- recognition difficulty
- league preference
- country-specific ambition depth
- source mode for flags, symbols, and portraits
- research confidence and sensitivity notes

The candidate registry supplies this data for the initial planning pool. Implementation can add researched candidates later without rewriting the shared event system.

## Package depth levels

### Level 1: Framework country

Receives:

- full common survival system
- regional overlay
- package archetype
- regional ambition family
- dynamic leader or institutional body
- dynamic starting forces
- complete flag and localisation coverage

Level 1 is the minimum acceptable package. It is not an empty tag.

### Level 2: Featured regional country

Receives everything in Level 1 plus:

- one country-specific focus group
- one bespoke decision family
- one distinctive starting problem
- one unique leader, council, or traditional institution path
- one special formable or regional leadership angle
- several unique incidents and assets

### Level 3: Signature country

Receives everything in Level 2 plus:

- major country-specific ambition module
- bespoke government conflict or balance-of-power layer
- several route-specific leaders or institutions
- unique military or economic system
- important formable, league, or super-event relevance
- high-priority achievement coverage

Signature countries include the highlighted packages in Part 4.

## Leadership model

The event cannot create hundreds of convincing historical leaders without
research. The same source gate applies to country leaders, route leaders,
commanders, and named officeholders. It therefore uses three leadership modes.

### Sourced real leader or institution

Required whenever the country, movement, dynasty, institution, autonomy claim,
regional identity, indigenous polity, separatist project, or restoration has a
real historical basis. The package must use a real male person appropriate to
the place and period, or sourced archival material for the actual institution
when the leader identity is collective.

Requirements:

- reliable identity research
- sourced portrait
- source and license notes
- correct party and political context
- no fabricated quotes or biography
- no invented officeholder or generated face
- a blocked status when no defensible person and usable source image can be found

### Generated fictional high-chaos leader

Permitted only when both the country and leader are truly fictional and belong
to a high-chaos package. A generated leader is never a substitute for missing
research on a real or plausibly historical country.

`high_chaos_only` or a Layer D/E pool position does not by itself make a
country fictional. Every one of the current 206 registry rows describes a real
community, historical polity, restoration, regional movement, or otherwise
grounded political identity and therefore remains in sourced mode. Generated
fictional portraits require a later explicit source-design classification of a
new truly fictional high-chaos country or route; agents must not infer that
classification from chaos intensity, tag novelty, or alternate borders.

Requirements:

- generated portrait in the canonical HOI4 style
- small male name pool belonging to the invented setting
- male portrait presentation matched to name and metadata
- plausible personal name rather than generic office title
- route-specific traits and background
- memorable, internally coherent high-chaos design using extraordinary invented
  ceremonial dress, regalia, body adornment, ritual objects, altered uniforms,
  or similarly distinctive fictional cultural motifs
- no generic face, modern prop, meme treatment, gore, or stereotype or
  caricature of a real culture

For Event 6, the 2026-07-16 user direction supersedes the earlier mixed-gender
pool: no female leader, commander, collective portrait subject, or character
metadata is used.

### Institutional leadership

Used for councils, assemblies, juntas, congresses, traditional bodies,
committees, regencies, or collective authorities. A collective authority in a
real or plausibly historical country must use sourced real archival material.
Generated institutional art is limited to truly fictional high-chaos countries.

Requirements:

- institutional name
- sourced all-male collective portrait or real institutional image for a
  historically grounded package
- distinctive generated institutional art only for a truly fictional
  high-chaos package
- no personal random name
- route that can later preserve the institution or replace it with a personal leader

Institutional leadership does not bypass source research. If neither a suitable
real leader nor authentic institutional source can be established for a
historically grounded package, that package remains blocked.

## Party and ideology adaptation

The shared framework does not use identical party names everywhere.

Each package defines:

- provisional governing coalition
- democratic or constitutional movement
- socialist, labor, peasant, or council movement where plausible
- nationalist or restoration movement
- military and security faction
- traditional, religious, royal, or customary faction where plausible
- foreign client movement when a patron route exists
- high-chaos movement for suitable packages only

Party names should come from regional political language and researched institutions. Generic names are temporary implementation fallbacks and cannot remain in the final package.

## Starting force model

Every fighting country receives a dynamic military package.

### Force budget inputs

- population in released states
- local industry
- depots and arsenals
- railways and ports
- host army size and current weakness
- war state
- chaos band
- opening legitimacy
- package military tradition
- patron support
- prior network support
- released territory size

### Force budget outputs

- number of militia or regular divisions
- unit strength and experience
- equipment percentage
- support company access
- officers and commanders
- train, convoy, truck, and fuel stocks
- air or naval inheritance where appropriate
- militia political power
- reinforcement pathway

### Opening force tiers

#### Fragile

- one or more understrength local defense formations
- severe equipment gaps
- officer shortage
- strong capital defense need

#### Viable

- several militia or border formations
- limited reserves
- one functioning command structure
- enough equipment to survive a short crisis

#### Armed

- defecting regular formations or organized movement forces
- captured depots
- stronger officers
- immediate host tension

#### High-chaos

- unusually strong, strange, ideologically mobilized, or foreign-backed force
- severe instability, dependency, or military political cost
- access to rare units or aggressive routes

### Reinforcement pathways

Every package identifies at least three appropriate growth methods from this list:

- integrate militias
- recruit regional guards
- secure depots
- convert defecting host units
- open volunteer corridors
- train league cadres
- mobilize factory or railway guards
- recruit mountain, desert, island, frontier, or cavalry units
- accept foreign arms missions
- create a professional officer corps
- complete capital and border defense missions

## Economic package archetypes

### Urban administrative state

Strengths:

- higher Government Capacity
- tax and civil service base
- communication hub

Weaknesses:

- low food security
- small manpower
- dependence on external trade

### Industrial breakaway

Strengths:

- factories, workers, rail, and technical personnel

Weaknesses:

- host claims strategic assets
- food and raw material dependence
- militant workplace factions

### Agrarian regional state

Strengths:

- manpower and local food base
- community institutions

Weaknesses:

- low industry
- transport problems
- land and elite disputes

### Port or island state

Strengths:

- trade access
- maritime identity
- outside recognition routes

Weaknesses:

- convoy dependence
- naval vulnerability
- limited strategic depth

### Mountain or frontier state

Strengths:

- defensible terrain
- local armed networks
- strong regional identity

Weaknesses:

- low capacity
- transport isolation
- contested borders

### River and corridor state

Strengths:

- trade route and transport leverage
- strategic towns

Weaknesses:

- several neighbors
- border disputes
- dependency on uninterrupted navigation

### Nomadic, pastoral, or dispersed-territory state

Strengths:

- mobility
- local networks
- difficult frontier control

Weaknesses:

- fixed administration and industry challenges
- overlapping land claims
- risk of inappropriate centralized borders

Packages using this archetype require careful territorial and cultural research.

## Binding package research disposition

Every package has a binding research row in `research/006_package_research_resolution.csv`. The row fixes its public-name direction, tag, tag source, automatic-pool disposition, baseline anchor, reservation group, modern political bridge, leadership rule, symbol rule, sensitivity rule, and source packet. Signature packages use `research/006_signature_country_research_dossiers.md`. Broad and sensitive packages use `research/006_sensitive_package_resolution.md`.

A package marked `specific_community_variant_only`, `formable_or_route_only`, or `scenario_variant_only` is fully resolved by that restriction. It cannot be promoted into the automatic pool merely to fill a wave. A conditional package enters only when the installed map provides the named unique state and the host survival planner succeeds.

The current architecture records 9 automatic, 44 automatic if not living, 73 automatic if unique, 27 high-chaos, 7 route-only, 30 specific-community, 3 scenario, and 13 vanilla-route-overlay-only packages. The dated 2026-07-14 all-row map audit under `../../../plans/006_independence_wave_plans/package_bindings/` recorded 149 bound and 57 unbound rows before overlay classification. Eleven overlays were bound and two were unbound in that ledger. The selectable country pool is therefore 138 bound and 55 unbound packages. An unbound row is unavailable, not permission to use nearby broad geography. An overlay row is also unavailable to the release selector because it activates only through its exact vanilla carrier or route.

## Candidate selection equity

The global candidate registry should not become Europe-heavy merely because European tags are easier to implement.

Implementation targets:

- every broad region has low, middle, and high-chaos candidates
- every region has at least one featured package
- Africa, Asia, the Americas, and Oceania receive research and asset budgets equal to their design importance
- historical states and local polities are not restricted to cosmetic flavor
- sensitive packages use their resolved conditional, formable, scenario, or specific-community disposition and are never replaced by a generic placeholder

## Candidate package validation

Before a selectable country package is marked ready, verify:

- unique anchor territory
- host survival
- no overlap with another selected package
- plausible capital
- complete custom-tag or registered-tag reuse path
- country name and adjective direction
- party and government direction
- leader mode
- flags and source mode
- starting ideas
- starting forces
- reinforcement path
- regional overlay
- formable families
- AI behavior
- origin checks
- focus tree or overlay assignment
- decision and mechanic access
- localisation coverage
- documentation

The package must be skipped at runtime or disabled in the registry when any blocking surface is missing.

Before an overlay package is marked ready, verify its exact carrier or route, one-time activation hook, package flag, route-state gate, origin separation, AI access, localisation, documentation, and preservation of the carrier's existing focus tree, history, cores, autonomy, state transfers, and formable effects. An overlay must not register a country, create a standalone history package, or enter the selectable release pool. The thirteen overlay adapters remain implementation obligations until those hooks and preservation rules are present in gameplay.
