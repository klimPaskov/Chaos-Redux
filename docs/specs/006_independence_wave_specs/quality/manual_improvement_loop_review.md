# Manual improvement-loop review

## Review status

This is a manual depth and anti-bloat review of the completed Event 6 source specification. The project-defined `chaosx_improvement_loop_planner` was not executed because this environment did not expose a custom subagent execution tool. Its full instructions and the `chaos-redux-improvement-loop` standard were read and applied.

This review evaluates design completeness only. It does not claim gameplay implementation, asset production, localisation completion, or repository validation.

## Playable promise tested

Independence Wave promises a sudden group of new states that must prove they can govern, survive, gain recognition, manage patrons, settle borders, cooperate with other released countries, and pursue larger regional identities. Higher chaos should create larger, stranger, more militarized, and more ambitious waves without turning every country into the same generic tag.

The completed source design supports that promise through five connected layers:

1. A synchronized release planner chooses valid candidates, reserves territory, protects host remnants, and executes the entire wave together.
2. A common survival system gives every Event 6 country meaningful statehood pressures.
3. A shared focus framework adapts through fourteen regional overlays, package archetypes, and signature modules.
4. A data-driven formable and league layer creates long-term regional play.
5. Evolutions and the triggerable scenario change opening conditions without replacing the baseline event identity.

## Depth review by system

### Release system

The release logic is deep enough for planning. It defines exact automatic wave counts of 6, 8, 10, 14, and 20, layered candidate pools, territory package levels, unique anchor reservation, host capital protection, overlap resolution, synchronized execution, failed-slot replacement, repeat memory, regional spread, and re-release behavior. A later design decision also adds a scoped crisis surface for badly occupied states and low-stability countries; its release handoff must use the same frozen allocator rather than a shortcut.

No additional release subtype is needed before implementation. More variants would duplicate the existing distributed, imperial, colonial, federal, restoration, indigenous, armed, and patron wave families.

### Origin separation

The source design treats release origin as a first-class country state. It covers Event 6, Soviet Collapse, pre-existing countries, tag collisions, annexation, later return, and concurrent cluster reservation. This is sufficient to prevent a reused tag from inheriting the wrong focus tree, decisions, AI, or country package.

The implementation still needs a repository-level flag and helper audit. That is an implementation dependency, not a missing design route.

### Country survival mechanics

The five main values create distinct pressures:

- Founding Legitimacy
- International Recognition
- Government Capacity
- Security Readiness
- Post-Release Instability

Former-host relations, patron influence, dependency pressure, network standing, and league standing add relationship layers. These values affect decisions, focus branches, government outcomes, military development, recognition, formables, and league behavior.

Adding more top-level meters would create interface noise. Cultural autonomy, rights guarantees, border confidence, and institutional factions should remain components, modifiers, or route states rather than separate universal meters.

### Focus tree architecture

The tree design includes survival, six government route families, internal power struggle, economy, military, diplomacy, former-host policy, borders, expansion, regional identity, league leadership, formables, and high-chaos ambitions. It also defines assignment rules for new tags, existing tags with meaningful trees, existing tags with minimal trees, and formed countries.

A fully bespoke tree for every registry row is not recommended. The shared framework becomes country-specific through overlay gates, signature content, leaders, institutions, decisions, AI, state targets, formables, and visible identity. Creating 206 unrelated full trees would increase maintenance and weaken consistency without improving every package.

### Decisions and missions

The decision design is active rather than store-like. It uses capital security, revenue, census, assembly, civil service, recognition, depots, officers, borders, patrons, host settlements, league goals, claims, formables, and high-chaos actions. Costs include equipment, manpower, factories, trains, convoys, XP, tied units, legitimacy, recognition, dependency, instability, and time.

The category uses phase gates and active mission caps. No additional universal decision family is needed. Package-specific decisions belong in regional and signature overlays.

### Regional and country coverage

The registry contains 206 candidate packages, fourteen regional overlays, package depth levels, resolved registered or X-ending tags, territorial anchors, government pools, force archetypes, formable links, source modes, final research dispositions, and sensitivity rules.

This is broad enough to account for normal releasables and niche high-chaos identities. The design-level package research is complete. Installed-map rebinding, current repository verification, final asset provenance, and gameplay implementation remain. Expanding the registry further before implementation would add names faster than usable content.

### Formables

The forty-eight formable families cover negotiated federation, traditional union, revolutionary union, military settlement, league transformation, and hidden high-chaos proclamation. Territory proof, core policy, reveal routes, integration, AI willingness, identity changes, and super-event relevance are defined.

No universal larger empire layer should be added. Regional formables are sufficient, and maximal cultural maps are deliberately avoided.

### League

The league has prerequisites, charter pillars, values, route families, membership rules, refusal, expulsion, leadership, shared goals, rescue behavior, failure states, faction mechanics, and a dedicated super-event threshold. It can become defensive, developmental, equality-focused, armed, or revisionist.

A second universal faction for moderate countries is not needed. Failed congresses and regional caucuses already provide weaker alternatives.

### Evolutions

The five evolutions add prepared institutions, dormant nations, armed openings, a sovereign congress, and open sovereignty. Each supports active-event and pre-fire entry paths. The exact wave count remains a separate chaos-tier rule.

The evolution set is complete. A sixth evolution would conflict with the five-stage project limit and would likely duplicate the triggerable scenario or league endgame.

### Triggerable scenario

The scenario attempts every viable candidate at every intensity. Intensity changes territory and forces. Scenario types change diplomatic structure, faction setup, patron alignment, and war state. This matches the sandbox requirement without tying completeness to maximum intensity.

No additional scenario type is needed before implementation. The six types already cover dispersed sovereignty, a common league, host wars, universal war, patron blocs, and territorial partition.

### AI, assets, achievements, and text

The design includes actor profiles, route validity, resource safety, league behavior, opening balance, host balance, mechanic balance, formable balance, asset families, real frame-based animation direction, source modes, sixteen difficult achievements, localisation direction, completed research dispositions, documentation, staging, and acceptance criteria.

The planned asset volume is large but justified by visible country identity and mechanic states. Asset production should be staged by core system, signature packages, and broader registry coverage rather than generated as one unreviewed batch.

## Anti-bloat decisions

The following additions are rejected for the source design:

- a bespoke universal mechanic for every candidate country
- a super-event for ordinary release waves
- instant full cores for broad formables
- maximal homeland release maps
- a separate patron meter for every major power shown at all times
- a new evolution beyond the five-stage limit
- a second generic focus tree detached from the shared statehood system
- a full custom scripted GUI for every regional overlay
- generic content that ignores a package’s resolved identity, consent, or territorial restrictions
- automatic league membership for every Event 6 country
- terminal campaign-ending content

## Remaining design risks

The main risks are implementation scale and historical verification, not missing system design.

- The candidate registry must be reconciled with actual registered tags and state geography.
- Sensitive packages may remain disabled until sources, leaders, symbols, and territorial assumptions are verified.
- Shared-tree overlays must be materially different in play rather than simple localisation swaps.
- The league interface must remain readable and must not duplicate ordinary faction UI.
- The scenario needs a deterministic conflict resolver because releasing all viable packages can create many overlapping claims.
- High-chaos strength must come with instability, host hostility, patron pressure, and coalition risk.

## Closure handoff

The source specification has enough depth to enter implementation. Further broad planning before the first implementation tranche is not recommended. Additional mechanics would add bloat or repeat an existing system.

The next improvement-loop pass should occur only after the release planner, origin tracking, core survival mechanics, first regional overlay set, and first country packages exist in the repository. That pass should judge actual play connections, AI validity, UI clarity, and whether the shared framework feels sufficiently regional.
