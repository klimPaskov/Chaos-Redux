# Event 131: Immigrations

## Package purpose

This package develops the user-directed Event 131 brief into a complete design handoff for a repeatable migration starter. It is installed as `docs/specs/131_immigrations_specs/`, and its historical import records are under `docs/plans/131_immigrations_plans/`.

The [original brief](131_immigrations_original_brief.md) is preserved verbatim for provenance. Its former catalog identity 149 is recorded there as provenance only.

The central design is a new, bounded request to move real people toward a plausible foreign country. The existing migration system owns every population obligation, route, refusal, reception action, settlement, and return. Event 131 supplies the episode's cause and provenance.

The brief's restoration of Event 131 is the governing user direction. Classification, cluster membership, numerical tuning, and the design refinements in this package remain proposals. They are distinguished from current implementation evidence. All branch, response, and art labels in this package are working labels, not final localisation. Existing script identifiers and existing interface labels are identified as such where needed.

## Decisions that matter most

1. Preserve foreign destination intent through a migration-owned accepted request. The current cross-border wrapper alone does not guarantee it, because downstream spontaneous movement uses internal-first selection.
2. Reserve only additional, uncommitted origin population. A retry, a reroute, an existing famine cohort, or an existing war-capture flight cannot become a new event wave.
3. Treat a request, host consent, and an actual arrival as separate facts. Closed borders preserve living obligations at their real location.
4. Preserve exact conservation and the current owner's distinction between a reduced conserved primitive result and a prospective contract that requires full headroom.
5. Use the existing Migration panel, national policy laws, response owners, and achievements. Prepared reception can succeed without unrest.
6. Treat Event 131 as the canonical identity. Widespread Mutiny is catalog 120 after the 24 October migration, and 149 is the former identity, superseded by 131. The registry adoption of 25 October 2026 and the CSV export already record that state, and implementation verifies it in the workbook before registration.
