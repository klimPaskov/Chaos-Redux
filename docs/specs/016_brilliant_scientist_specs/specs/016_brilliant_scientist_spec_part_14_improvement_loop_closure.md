# Event 16 Brilliant Scientist, improvement-loop closure

This file is the planning closure for the canonical improvement-loop pass. It does not claim implementation completion.

## Closure decision

Broad design expansion should stop after the second-pass design unless implementation reveals a new structural gap.

The first-pass design established the full event concept, baseline mechanics, evolutions, Kruger country package, focus-tree architecture, foreign reactions, super-events, world-end logic, assets, achievements, and implementation prompts. The second-pass design deepened the areas that were still too broad:

- project-by-project balance, dynamic cost formulas, risks, AI weights, and memory outputs
- Kruger State route groups, locks, rewards, and AI priorities
- host overlay branch groups for public, military, security, restraint, sealed-project, and final confrontation paths
- Kruger identity route packages with country names, party directions, leaders, ideas, armies, reinforcements, and assets
- custom scripted GUI recommendation and state model
- second-pass route-specific achievement coverage

Further expansion before implementation would likely add maintenance burden without making the design clearer. The next useful work is repository implementation, source research for assets and super-events, and audits against real files.

## Anti-bloat notes

Do not add another parallel science system for every country. The event is about one country’s relationship with Kruger and the consequences of transferring authority to him.

Do not add a second Kruger-like scientist unless a future event explicitly creates a rival. Foreign reactions should use theft, observers, sabotage, rival institutes, and containment coalitions.

Do not add more project families until the existing families are implemented and tested. The current set already covers public science, computation, industry, medicine, rocketry, nuclear work, clones, robots, specimens, dinosaurs, xenotech, teleportation, time, and the final device.

Do not add more super-events before the three Part 1 super-event roles are researched and implemented. Sovereignty, final device, and costly defeat aftermath are enough.

Do not add more achievements before route implementation proves which route conditions can be tracked cleanly.
