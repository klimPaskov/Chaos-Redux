# Asset prompt for Event 16 Brilliant Scientist

Use the Chaos Redux event asset workflow, with the frame animation workflow for animated assets. Inspect the relevant reference folders before creating or processing anything. Do not wire `.gfx`, GUI, gameplay, localisation, focus, decision, country, or spreadsheet files unless the parent explicitly expands scope.

## Event identity

Event ID: 16. Event slug: brilliant_scientist. Main fictional character: Doctor Warren Kruger.

## Source mode rules

Copy and rename `portrait_generic_biowarfare_europe_male_01` as the baseline Kruger portrait. Later Kruger portraits, route portraits, Kruger flags, fictional event scenes, UI pieces, and icon families use generated fictional art. Real historical assets are needed only if implementation later adds real people, real symbols, or real archival material. Do not generate real leader portraits or historical flags.

## Required portrait family

Create stage 0 through stage 4 Kruger portrait assets. Stage 0 is the copied base portrait. Stage 1 shows public fame while still human. Stage 2 shows secret-project strain. Stage 3 shows severe unnatural changes while still disguised. Stage 4 is the sovereign or alien reveal. Stage 4 needs a static non-animated counterpart and an animated portrait package with real source frames, a horizontal frame sheet DDS, a preview GIF for review, a contact sheet, and a manifest entry.

## Required route identity assets

Create flags, portraits, ideas, focus icons, decision icons, report or news images, and UI state art for these identities where implementation uses them: baseline laboratory state, public sovereign science state, military laboratory state, clone route, machine route, specimen and dinosaur route, xenotech route, temporal route, nuclear route, and final device route. Each route flag must be a distinct design, not a recolor.

## Icon families

Produce separate source art for idea icons, decision icons, focus icons, achievement icons, and special-project or technology icons. Do not resize one icon type into another. Use transparent backgrounds where the target asset type expects transparency. Validate no fake checkerboard, no white halo, no opaque square background, and clear readability at target size.

## Event and super-event images

Create generated period-authentic documentary images for Kruger arrival, security crisis, anomaly incidents, sovereign state announcement, final device, and costly defeat aftermath. Report images target 210x176 and need report-card processing. News images target 397x153 and must be black and white. Super-event images target 457x328 and need strong central composition.

## GUI and animation assets

Only create the full custom GUI asset family if implementation builds the hybrid GUI. Required state assets include portrait panel frame, meter row backgrounds, locked project card, active project card, safe completion stamp, dangerous completion stamp, incident frame, security alert, confrontation warning, final-device progress frame, and aftermath panel treatment. Animated assets need real source frames, static non-animated counterpart DDS, sheet DDS, preview GIF, contact sheet, manifest, and `gfx_handoff.md`.

## Achievement icons

Create one unique completed 64x64 icon for every implemented achievement. Produce grey and not-eligible variants only through the standard achievement workflow. Do not create route achievement icons for routes that are not implemented.

## Manifest and handoff

Write `docs/assets/016_brilliant_scientist/manifest.md` and `docs/assets/016_brilliant_scientist/gfx_handoff.md`. Every entry needs source mode, prompt or source note, target size, final path, proposed sprite name, reference folder inspected, status, and uncertainty. Animated entries also need frame count, fps, loop behavior, sheet size, static non-animated counterpart, preview path, and frame-source notes.
