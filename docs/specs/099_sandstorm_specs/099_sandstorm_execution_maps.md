## Before and after evidence contract

Follow the current [chaos-redux-subagents MCP evidence contract](../../../.claude/skills/chaos-redux-subagents/SKILL.md#mcp-evidence-in-handoffs) and inspect each connected live schema for argument shapes and immutable snapshot support.

An analysis URI, current-file self-comparison or after-only hash does not replace the before file.

GUI comparison likewise retains before and after source, assets, resolution, UI scale, language, exact state and target binding.
A fixture named comparisonScenario does not itself save old source.

An audit cannot promote one into another because the output looks plausible.

## Gate order and handoff sequence

First resolve the measured-population primitive and the local military, air and geography feasibility questions.
Those determine whether the accepted effects have a valid engine implementation.
Do not build a polished response panel around a country-wide substitute and call the core complete.

Next implement the finite season, swept geography, union exposure, exact population and physical-damage receipts, then the owner adapters.
Demonstrate baseline movement and cleanup before adding cumulative evolution behavior.
Preserve both active and pre-fire evolution entry as each stage becomes implemented.
Responses and AI can then consume stable forecast, exposure, payment and authority facts.

Before closing the lifecycle tranche, wire the bounded aftermath observation contract into the existing recovery, achievement and migration owners.
The front scheduler must terminate by day 360 while legitimate fourteen-day recovery and twenty-one-day restoration or settlement windows finish from retained receipts and their original clocks.
The parent owns cross-owner retention and final cleanup, with the architect checking sparse observers and immutable identities and the achievement owner verifying terminal outcomes.
Use the [bounded observation contract](099_sandstorm_implementation_contracts.md#bounded-observation-after-the-front-closes) for exact windows and owner boundaries.
This requires a late-season acceptance fixture and never authorizes continued acute weather or an added global scan.

Produce art and the dedicated UI from the actual consumer bounds, then integrate researched super-event presentation and the eight observation-backed achievements.
The parent reconciles final localisation, shared framework wiring, documentation, workbook and exports.
Run the final completion and improvement reviews and resolve each finding with a destination and reason.

Native validation remains under the user's control.
The implementation prompt does not authorize launching HOI4, requesting error logs or manufacturing observer evidence.
Use available supported read-only tooling and any genuine user-provided live evidence, and identify the remaining proof honestly.
This does not limit the autonomous completion of already authorized design, source, artifact and review work.
