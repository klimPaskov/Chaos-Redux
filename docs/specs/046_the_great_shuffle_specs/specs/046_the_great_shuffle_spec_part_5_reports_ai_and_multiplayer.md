# Event 046: Reports, AI, and multiplayer

## Presentation choice

The Great Shuffle uses the ordinary event and report surfaces.

The player responds after the transaction through normal country systems.

The presentation centers on one global transformation followed by a concise personalized report.

The standard event image gives the firing a clear identity.

## Entry and report sequence

The entry event begins the global transaction without asking one player to choose for the world.

No option can cancel, redirect, protect against, or reroll the firing.

After commit, every human player receives one Shuffle Report.

The report uses the same global transaction and does not create player-specific results.

AI countries receive effects without a popup.

The report has one acknowledgement option whose final wording can use dry disbelief, official restraint, or resigned irony.

It must not imply that the player can restore the old world.

## Report structure

The report contains four possible layers.

### Global summary

The summary identifies the highest active evolution capability, number of committed families, number of rejected selected families, valid country count, valid state count, valid unit or commander count when relevant, and owner-adapter count.

It does not list every scope.

### National changes

The report prioritizes the human country's largest changes among Stability, War Support, political resources, military experience, manpower, fuel, stores, politics, research, and production.

Each shown row gives a clear before and after state.

### Territorial changes

When state families committed, the report shows the most important owned or controlled state changes.

Population and industry are listed separately.

A state can appear in both when both changes were among the player's largest results.

The report names the state and the family.

### Military and mechanic changes

When unit, commander, production, research, or owner-adapter families committed, the report shows a small number of high-impact results.

An owner adapter supplies its own public label and value format.

Hidden internal values never become report rows merely because they changed.

## Information budget

The report is concise by design.

At Baseline and Evolution I, it normally shows four to six national rows plus the global summary.

At Evolution II and III, it can show grouped sections with two or three rows per relevant section.

At Evolution IV and V, it can show the strongest rows from each committed domain and an omitted-count line.

A report should not exceed the amount of information a player can act on immediately after closing it.

Full audit data belongs in debug evidence, not player text.

## Importance scoring

A report row competes through family-normalized importance.

Numeric values compare the absolute change with that family's legal or planned range.

Categorical values use an owner-declared severity score.

Structural values use a declared impact class.

The score is for presentation only.

It does not change family selection, result generation, Chaos gain, or later Shuffle weights.

A small raw change can outrank a larger one when the small change crossed a meaningful threshold.

Examples include Stability crossing into collapse, fuel reaching zero, a law entering an extreme category, or an owner value crossing a crisis stage.

## Honest before and after text

The report uses the exact value or qualitative state that existed immediately before the Event 46 transaction and the exact committed result.

It does not compare against a historical baseline from an older firing.

It does not describe a value as stolen, transferred, refunded, or restored.

State population changes are described as changed reality, census discontinuity, or another in-world anomaly direction.

They are not described as deaths or migration.

## Dynamic actor and scope text

Player-facing text names the current country, affected state, unit, commander, production object, or owner mechanic where useful.

The report avoids raw IDs, variable names, registry labels, enum names, family IDs, and implementation terms such as commit, adapter, seed, array, or reconciliation.

A family rejected for safety is summarized in plain language only when the omission matters to the player.

## Event Log

One successful firing creates one Event 46 history entry.

It uses global or no-actor presentation so no country appears to have caused the event.

The row records the date, Event 46 identity, repeatable type, and global context supported by the shared logger.

A cluster firing still records Event 46 as a fired member while the cluster records one pacing incident.

A transaction that commits no family creates no false Event 46 history entry.

## Event Details

Event Details presents the event premise, Minor Repeatable type, Chaos level 1, Randomizations membership, Medium severity, fired count, current weight, enabled state, and five evolution capabilities.

The premise explains permanent global rewriting and adaptation.

It does not list raw ranges or implementation contracts.

Evolution descriptions explain which part of the world becomes eligible without revealing hidden selection weights.

Evolution toggles control only their gated capability.

Disabling a later evolution leaves the earlier family pool functional.

A disabled evolution cannot set its recorded flag, add its families, or award its evolution-specific achievement proof.

## AI principle

AI countries receive no favorable range, protected minimum, pity roll, compensation, recovery grant, or family exemption merely because they are AI controlled.

The result is allowed to ruin an AI country.

The result is allowed to make an AI minor unusually powerful.

Balance comes from legal ranges, ordinary event rarity, repeatable cap decay, family selection, and world-wide exposure.

## AI reconciliation

Legality repair is not protection.

After a family changes a value, the owner refreshes the AI systems that depend on it.

Examples include strategy recalculation after ruling ideology, production evaluation after line efficiency changes, supply evaluation after fuel and train changes, research choice reevaluation after progress changes, and owner-mechanic strategy refresh after a registered pressure changes.

The refresh cannot refill stores, reverse a bad law, repair low Stability, or choose a better random result.

## AI adaptation expectations

Ordinary AI should react through its normal systems wherever those systems already understand the changed state.

A fuel-poor AI should reduce fuel pressure or seek fuel.

An equipment-rich AI should use its stores.

An industrially transformed country should update construction and production priorities.

A country with low Stability and War Support should face its normal political and military limits.

A country with a changed law or ideology should use the route and diplomacy available to that state.

When vanilla AI cannot recognize a newly exposed owner mechanic, the owner adapter must supply the equivalent AI refresh or action path.

## Recovery through ordinary systems

Countries recover through ordinary gameplay and the systems already responsible for the changed value.

A country can build factories, change laws, produce equipment, train units, restore Stability, import fuel, or use owner-mechanic actions.

Recovery changes the new world through normal play and never restores a hidden pre-shuffle state.

## Multiplayer transaction

One global transaction is authoritative.

The host or authoritative game state rolls the family set and results once.

Human players cannot receive different random worlds from the same firing.

Every report references that shared result.

No option pauses the transaction while one player decides for everyone.

## Concurrent player state

A player who changes country before the report is built receives the report for the country controlled when the report scope is finalized.

The old country still retains its results.

A player who disconnects during the transaction does not block completion.

A reconnect does not replay the event.

A late join sees the saved world state and ordinary Event Log history.

## Cluster multiplayer behavior

When Event 46 fires as a Randomizations cluster member, the cluster does not create a second Great Shuffle transaction.

The same transaction ID is attached to the member result and the cluster history record.

A one-member Randomizations cluster cannot cause Event 46 to apply twice.

## Repeat firing reports

Every later firing creates a new report from that firing's immediate before and after values.

The report does not compare with the first campaign setup or calculate a cumulative Shuffle score.

Achievement tracking can compare specific consecutive firings under protected event-owned proof.

That proof never changes selection or report priority.

## Visual direction

The report image should depict reality visibly reordered through period-authentic documentary photography or a generated documentary-style scene.

The visual center should be people, industry, military material, and a familiar place made impossible through sudden mismatching.

It should not be a modern game interface, a clean map diagram, a ledger screen, a collage of flags, or a text-heavy newspaper.

The image remains static.
