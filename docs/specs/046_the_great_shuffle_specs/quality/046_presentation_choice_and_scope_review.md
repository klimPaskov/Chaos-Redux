# Event 046 presentation choice and scope review

## Playable action

The Great Shuffle has one immediate player task.

The player reads what changed and adapts through normal country systems.

There is no Event 46 resource to spend, target to choose, route to manage, or timed objective to complete after the transaction.

## Considered presentation layers

### Ordinary report event

This layer can present the global incident, show the player's largest before and after changes, group higher-tier domains, and close cleanly.

It uses the shared event and Event Details framework and has a real gameplay purpose.

### Decision category

A decision category would have no accepted recurring actions.

Adding generic recovery buttons would contradict permanence and duplicate the systems that already govern politics, production, fuel, industry, armies, and owner mechanics.

This layer was rejected.

### Static decision-category picture

A category picture requires a decision category consumer.

No such category is accepted.

This layer was rejected.

### Animated category picture or frame animation

Event 46 has no persistent changing presentation state.

Animation would decorate a completed transaction and would not clarify an active mechanic.

This layer was rejected.

### Compact attached display

A persistent display would become a history panel or full ledger of changed values.

The player does not need to monitor Event 46 between firings.

This layer was rejected.

### Full scripted GUI

A custom window would be costly, broad, and noninteractive.

It would also create a second event-history surface beside Event Log.

This layer was rejected.

### Super-event

The event is globally disruptive, but it remains Minor Repeatable and can fire several times.

None of its capability activations is a separate campaign threshold that justifies a unique slot, quote, final audio track, and super-event image.

A super-event would make later firings repetitive or require several unsupported presentation packages.

This layer was rejected.

## Accepted presentation

Use one static report-event image, one concise report event per human player, one shared Event 46 history entry, Event Details integration, and normal evolution history.

The report is personalized, while the underlying result is global.

At high capability, the report groups changes by domain and shows an omitted count.

Debug evidence can retain full transaction detail outside player-facing text.

## Public value budget

Event 46 exposes no persistent custom value.

The report shows temporary before and after values that already belong to the country or an owner mechanic.

These values do not become a new Event 46 meter.

## Asset scope

The accepted visual package is one report image and six achievement icon packages.

No portrait, flag, focus icon, decision icon, idea icon, cluster icon, UI panel, animation, 3D model, counter, unit sound, or super-event asset is authorized without a new proven consumer.

## Scope conclusion

The standard report is the least complex surface that communicates the event fully.

Adding a management layer would add clutter and weaken the core promise of sudden permanent adaptation.
