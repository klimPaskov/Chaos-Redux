# Event 046 design risk register

| Risk | Why it matters | Required control | Completion blocker |
| --- | --- | --- | --- |
| False atomicity claim | Clausewitz script may not support general rollback | Use immutable preplanning and idempotent completion, describe it as logical family atomicity | Yes |
| Save bloat from world result plans | Evolution V can touch many scopes | Benchmark supported storage, clear every plan, prove post-transaction cleanup | Yes |
| Long single-frame processing | Country, state, unit, and adapter pools can be large | One-shot bounded processing, approved batching, no periodic world scan | Yes |
| Order-dependent ranges | Earlier state changes could alter later legal caps | Freeze range inputs and scope lists before commit | Yes |
| Population creates false deaths | Negative state population effects can affect manpower and ledgers | Event-owned absolute rewrite, Deaths bypass, side-effect reconciliation | Yes |
| Population creates free manpower | Positive or negative state mutations can affect national reserves | Observe and reconcile engine side effects, keep reserve family separate | Yes |
| Generic Chaos double count | Ideology or structural setters can trigger shared sources | Bounded Event 46 source marker and one declared source owner | Yes |
| Technology graph corruption | Research and doctrine dependencies are sensitive | Limit core family to proven current progress, protect completed graph | Yes |
| Production object corruption | Lines, items, variants, and MIOs have stable identity | Change approved numeric state only | Yes |
| Invalid building geography | Ports, dockyards, railways, and hubs need map proof | Coastal, province, capacity, and graph contracts | Yes |
| Owner adapter abuse | Owner could expose history or inflate Chaos | Event 46 approval, protected-state audit, disruption caps | Yes |
| Owner adapter starvation | Large core pool can make adapters unreachable | Evolution IV quota and probability audit | Yes |
| Scope identity changes during commit | Units, pairs, and owner objects can disappear | Freeze stable scope proof, exclude transitions, idempotent recovery | Yes |
| Multiplayer divergence | Local random rolls would create different worlds | One authoritative transaction and shared result | Yes |
| World Collapse makes Evolution V unreachable | Current guide says automatic events freeze at 1000 | Audit live order and implement the bounded pre-freeze path when needed | Yes |
| One-member cluster duplicates Event 46 | Cluster expansion can call the only member again | Distinct-member gate or another non-duplicating cluster rule | Yes |
| Multi-cluster catalog loss | Current export shows one Cluster ID field | Preserve normalized relationships and relation-specific severity | Yes |
| Stale Event 43 identity | Current task and export disagree | Resolve from accepted source before workbook change | Yes |
| Report overload | High-tier transaction can produce hundreds of changes | Family-normalized top rows, grouped sections, omitted count | Yes |
| Achievement farming | Force mode and easy bulk values can trivialize feats | Detect supported test markers, normalized scores, hard recovery and survival proof | Yes |
| Conditional-family inflation | Calling accepted candidates implemented would mislead users | Separate core, conditional, adapter-only, and protected status in docs and completion report | Yes |
| Event bloat | A GUI, decisions, super-event, or recovery store could grow without purpose | Keep accepted report-only presentation and ordinary recovery | No, unless added |
