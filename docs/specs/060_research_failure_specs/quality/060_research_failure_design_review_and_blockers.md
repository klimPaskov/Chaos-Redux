# Event 60 design review and blockers

## Review result

The planning pack preserves the accepted event identity: Minor Repeatable, Chaos level 1, Scientific Research cluster, High member role, one valid major or player-controlled target, two-slot baseline, one-slot Knowledge Collapse, technology regression, reconstruction, and the Kruger slot-preservation exception.

The design is ready for repository implementation planning.
It is not engine-verified implementation evidence.

## Review method

The configured specialist definitions were read and their written review contracts were applied as separate parent passes.
A live subagent run was attempted through the supplied Codex bridge and failed with an HTTP 404 response.
No specialist output is claimed.

The review passes were:

1. Improvement-loop pass for playable promise, pressure, route identity, replay value, connection depth, and anti-bloat.
2. Scripted-system pass for transaction ownership, technology registry structure, slot ledgers, event targets, idempotence, cleanup, and fail-closed behavior.
3. Decision and mission pass for action quality, phase visibility, cost limits, mission deadlines, AI equivalents, and exploit control.
4. AI and probability pass for named scenarios, candidate pools, dynamic factors, evolution timing, and later MCP evidence.
5. Presentation and asset pass for the least complex useful interface, asset-family separation, runtime consumers, and authorization boundaries.
6. Completion pass against the user brief, event skills, catalog duties, Event Log duties, documentation, assets, AI, evolutions, Chaos, and connections.

## Strong design decisions

### Institutional recovery and technological recovery are separate

Restoring laboratories, personnel, archives, standards, and research slots resolves the national institutional crisis.
Lost technologies remain in a residual ledger until the country researches or validly recovers them.
This preserves the user's rule that restored slots do not refund the technological position.

### Technology regression uses an owner-owned registry

Event 60 must never scan every technology and remove whatever looks advanced.
Each eligible branch record defines predecessors, protected roots, mutual exclusion, bundle rules, equipment relationships, DLC conditions, owner policy, and rediscovery category.
Unknown or unsafe technologies remain protected.

### Two public values are enough

Scientific Capacity represents institutions, people, facilities, and coordination.
Archive Recovery represents records, methods, standards, calibration chains, and rediscovery support.
Operational slots, active project, and priority domain appear as state labels and do not become more persistent custom meters.

### Reconstruction is an action system

The category uses phases, real projects, active missions, resource commitments, foreign channels, specialist return, standards work, and an institutional settlement.
It does not become a political-power shop.
A phase normally exposes three to five primary actions and one to three active missions.

### Existing material survives

Regression removes reliable reproducibility and future development.
Existing deployed units, stockpiles, buildings, completed ships, and captured equipment are not deleted.
Production-line continuity must follow the verified engine result and the registry's explicit grandfathering policy.

### Evolutions apply one transaction

An opening incident uses the highest enabled severity valid at firing time.
An unresolved incident that later evolves receives only the additional delta from its current severity.
This prevents repeated slot suppression, repeated active-project loss, and duplicate technology removal.

### Kruger protection has a price

The Emergency Kruger Mandate preserves the recorded operational slot count only when Event 16 confirms a valid Directorate and accepts the authority transfer.
All other Event 60 damage remains.
The Directorate route cannot serve as a free popup option or generic special-country immunity.

## Rejected expansions

The event does not need a separate mechanic window.
A normal decision category with a static picture communicates the two values and current phase more clearly.

The event does not need a country package, focus tree, portrait set, flag set, 3D model, unit family, or animated asset.
Those additions would increase maintenance without improving the scientific reconstruction loop.

The event does not need every technology to have a bespoke recovery event.
The domain ledger and priority system provide enough variation without hundreds of shallow popups.

## Hard implementation blockers and evidence gates

### Technology removal and graph integrity

The local repository, installed vanilla files, and technology MCP route were unavailable in this environment.
Implementation must prove that a researched technology can be removed safely in the current engine and determine what happens to descendants, mutual exclusions, equipment access, modules, variants, production lines, licenses, special projects, and research bonuses.

If real technology removal is unsupported for a family, that family remains protected until an owner-approved degradation model exists.
A flat national research penalty cannot replace the event's verified safe regression set.

### Active research progress

The current engine access to active research slots, partial progress, cancellation, and progress-specific compensation must be inspected.
The event should clear or invalidate active projects where supported.
Where exact progress is inaccessible, implementation must use the nearest verified bounded behavior and report the deviation before completion.

### Research-slot accounting

The source of each country's slots may include national effects, focuses, technologies, characters, DLC systems, or mod mechanics.
Event 60 must record an operational ceiling and suppress only the amount owed by its own incident.
It must restore each owed slot once and never permanently overwrite unrelated later slot gains.

### Event 16 Kruger API

The current Directorate markers, authority state, political cost, technology policies, and settlement ownership must be inspected in the live Event 16 files.
The Event 60 option stays unavailable until that contract is verified.

### Scientific Research cluster

The supplied cluster export marks Scientific Research unavailable and does not provide a stable cluster ID.
Implementation must update the authoritative workbook and current cluster registry without inventing an ID from the CSV snapshot.

### Required MCP evidence

Technology and doctrine surfaces require `hoi4.tech_inspect`, `hoi4.tech_render`, and `hoi4.tech_compare` against the final registry and any source changes.
Every weighted target, option, incident, foreign offer, route, research priority, and evolution timing surface requires the probability audit cycle defined in the matrix.
The final event chain requires event inspect, render, and compare evidence where the installed server supports it.

## Balance concerns for implementation

The stated recovery horizons are severe and appropriate for a High cluster member, but they can become unplayable for a country at war or with a small economy.
Dynamic affordability, exile recovery, minimum useful action availability, and staged slot restoration need scenario sweeps.

The most dangerous exploit is direct technology-grant farming after a repeat firing.
Every grant path must reconcile one exact lost-node receipt, while ordinary gifts outside the ledger remain unchanged.

The most dangerous failure state is an orphaned technology graph that leaves descendants researched after a required predecessor was removed.
The regression closure and final graph audit must block that result.

The most dangerous multiplayer issue is an unanswered foreign aid event.
Every foreign request needs a timeout and a valid target-side continuation.

## Simplifications and omissions

No requested design surface was intentionally simplified or omitted from the planning pack.
Exact technology IDs, final numerical tuning, exact script identifiers, and engine syntax remain open because their required repository and engine references were unavailable.
Those items are evidence-bound implementation work, not permission to weaken the accepted behavior.

Live specialist subagents did not run because the supplied execution bridge failed.
The written specialist contracts were applied by the parent planning pass, and the missing runtime review remains disclosed.
