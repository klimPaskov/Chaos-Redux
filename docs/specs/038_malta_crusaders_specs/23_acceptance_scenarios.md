# Acceptance scenarios and completion contract

## Completion standard

Event 38 cannot be marked complete because the entry popup works or because Malta appears on the map. Completion requires every accepted baseline, evolution, country, focus, decision, unit, asset, hidden route, terminal route, scenario, log, catalog, AI, and cleanup surface.

The parent implementation agent owns final review and completion claims.

## Evidence categories

The completion report separates:

- source implementation
- MCP inspection and comparison
- static validation
- asset and provenance review
- probability evidence
- user-owned live in-game validation
- blocked or not covered evidence

A passing source check is not live-game proof.

## Final completion report

The report must include:

- files changed
- systems touched
- route coverage
- country-package coverage
- unit-family coverage
- decisions and missions
- AI and probability evidence
- focus and GUI MCP evidence
- assets, portraits, audio, models, counters, and manifests
- super-events
- docs, workbook, and exports
- meaningful acceptance scenarios
- user-owned live validation status
- simplifications, omissions, and blockers

If no simplifications were made, say so and support the claim with evidence. If any accepted surface remains missing, the goal is incomplete.
