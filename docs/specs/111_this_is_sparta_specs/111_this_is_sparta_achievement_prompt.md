## Complete achievement records

The package contains twenty achievements. Keys are proposed unique event-owned keys, subject to the installed achievement registry audit. Every title and description below is a direction. The implementation must write final localisation from those directions and produce a separate completed 64×64 icon for each record.

All achievements use the mod's actual eligibility and debug rules. Forced debug completion, unauthorized copied achievement flags and incomplete migration cannot unlock them. A historical completion receipt is distinct from a live holding condition. Conditions that require 180 days of stability use durable start and breach records, with changes observed through bounded event-owned callbacks.

Default country eligibility is the original Event 111 Spartan actor or a validated same-identity restoration. A cosmetic change is still the same country. ACH20 is the outsider exception. Late restoration never invents a missing original-cohort achievement receipt.

### ACH01: Civic reconstruction direction

**Key:** `chaosx_111_ach_civic_reconstruction`. **Difficulty:** Hard. **Visibility:** Visible. **Eligible country:** Sparta.

The title direction concerns making the revived state sustainable for modern people. The description should explain the demanding institutional result. Unlock after any normal route charter, the wider-citizenship political settlement, Civic Settlement at least 85, Military Adaptation at least 80, at least four research slots and 180 continuous days without a failed civic obligation or emergency coercive relapse.

Disqualifiers are a current unresolved domestic crisis, a false route-completion receipt or a breached required regional settlement during the holding period. Track the political stage, authentic route receipt, research count and a 180-day stability episode. This rewards a developed state after conquest, rather than one early reform. Icon direction: an open civic assembly joined to a restrained Spartan shield and a modern workshop.

## Achievement implementation priorities

All twenty records belong to the accepted specification. Priority is an implementation order, not permission to omit the rest. The first implementation group is ACH01, ACH02, ACH06, ACH08, ACH10, ACH11 and ACH12, because it proves ordinary institutional, cohort and route tracking. The next group covers the mythic lifecycle through ACH13 and ACH15–ACH18. ACH03–ACH05, ACH07, ACH09, ACH14, ACH19 and ACH20 exercise more specialized provenance, optional extensions or cross-event outcomes.

Each achievement uses shared authoritative route and action helpers. It does not maintain a second slightly different list of states. The final conditions are evaluated when a relevant owned event occurs and at the limited registered holding-period deadline. Owner/control changes, treaty breaches and value transactions invalidate the relevant period promptly.

An impossible or unsupported native condition is an implementation blocker for that record. It must be resolved through actual source inspection and a concrete design revision. The implementation may not turn a difficult achievement into an easy click, silently drop it or claim it completed from a Python-only simulation.
