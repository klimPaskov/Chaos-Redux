event_compare requires a valid graph-bearing artifact, source overlay or other supported input. A report-only trace or rendered image is not automatically a valid graph. If the tool cannot compare the actual source, report the exact blocker.

### 6.3 Probability evidence

Create one frozen baseline per changed owner source before changing its weights. Record the engine-relative logical path, copied bytes, actual hash, candidate identifiers and the scenario set. A cached analysisId belongs to supported rendering uses and is not a before-source identity.

When the live schema supports it, a source snapshot can preserve the logical engine path with path, snapshotPath and expectedSourceHash. This avoids an adapter treating a copy under docs as an unrelated document. If the schema lacks those fields, use the actual supported comparison input and retain the limitation.

Inspect both revisions after renamed options or shifted line-based candidates. A current-only filter can empty the baseline. Use the union of verified IDs or each side's exact local selector where supported. Event-option pools include every option qualified by its parent event. Target decisions and missions retain their own adapters.

Every scenario states which facts are observed, supplied or assumed. Include the exact date where supported, typed country/state bindings, ownership/controller maps, authority, resource stockpiles, current route, enabled evolution state, active manifestation IDs and scheduled changes required by that adapter. Family fixtures include every owner's live consumer, paid reservation, stored survivor, origin, custody/site access and global allowance. Warning fixtures include the original episode deadline, current exposure, actual MY10 removal/custody status, MY11 completion date, dormant state and continuous days below 50. Unsupported context remains unresolved. Candidate overrides are declared assumptions rather than native eligibility proof.

Cadre fixtures carry O, p, Q, M, E and P with the exact Part 4 inclusion rules, per-consumer conservative original attribution, deduplicated gross losses, pending admissions and native refill control. Include loss plus replacement within one net-strength interval, ordinary casualties that lower Q, ally-commanded Spartan-owned formations and an attempted ownership/template loop. Declare an unavailable native input as unresolved rather than supplying a guessed casualty history.

Do not tune to a target invented by the auditor. The parent states intended preferences and reviews results. Source scores, normalized conditional shares and simulated whole-campaign frequencies remain separate quantities.

The coverage register keys every scenario to its Part 8 section 8.4 ledger row and exact actual candidate IDs. Include depleted reserves, a full work queue, a refusing or vanished counterpart, unavailable targets, overdue warning mitigation, constrained family allowance, hero-duty conflict and valid versus invalid containment authority where relevant. No row is silently omitted because its adapter cannot model the context. Record that boundary explicitly and assign the remaining evidence to the correct lifecycle or native gate.

### 6.4 GUI and map evidence

Review the actual attached decision-category window, not only a state-piece crop. Bind every render to the exact source hash, language, game resolution and UI scale. Include baseline 1920x1080 at scale 1 and supported smaller/larger cases needed to expose clipping. Inspect every route overlay, partial completion, loss of the Laconian anchor, invalid client, missing owner/controller, hover and long text.

Use explicit fixtures when auditing exact states. Where supported, generatedScenarios uses an object such as { enabled: false }, not a guessed boolean. Keep immutable before source. comparisonScenario changes a scenario and is not an old source snapshot.

Native tooltip text and control state must come from actual source and supplied context. Do not invent engine-expanded tooltip text or treat an unresolved amber potential-control overlay as a fully enabled button. Production render is the visual acceptance surface under the supplied GUI skill. Fix visible defects instead of labeling them renderer differences.

Map evidence must use the actual combined map after the Laconia split and rebuilt registry. A source manifest hash alone does not prove province geometry, supply or capital playability. Keep map source facts, generated pieces and GUI attachments on the same revision.

### 6.5 Artifacts, jobs and native results

Read long artifacts through bounded continuation rather than accepting truncated content. Respect declared encoding and verify reconstructed length, hash and format before inspecting an image. Treat unavailable or unobserved job results as unknown. Inspect job state before repeating a potentially expensive or mutating operation.

Mesh and animation reimport proves a bounded asset round trip. It does not prove native action selection, scale, sound routing, save/load identity or live combat. User-supplied in-game evidence is reviewed separately under the actual testing workflow. Ordinary implementation agents do not launch HOI4 or solicit logs as a substitute for their source work.

## 8. Closing rules

Keep the final package aligned with actual evidence and accepted scope. Resolve every improvement-loop and completion finding with an explicit disposition. Do not hide a missing Laconia map, blocked compiler, absent model, incomplete provider, broken route or unavailable probability audit behind a broad completion claim.

The current observed workbook remains a pointer until materialized. The current tag and new state remain unallocated. The current HOI4 MCP availability is absent. These facts are limitations of this planning environment. They are neither permission to fabricate an implementation result nor reasons to reduce the accepted design silently.
