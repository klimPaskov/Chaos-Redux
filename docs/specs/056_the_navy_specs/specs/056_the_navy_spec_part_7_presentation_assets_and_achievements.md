# Event 056: Presentation, Assets, and Achievements

## Presentation structure

Event 56 needs two report layers:

1. one global report for the manifestation
2. one personal commissioning report for each eligible human recipient

AI countries resolve their package without a visible popup. The Event Log records one global event firing rather than one entry per country.

## Global report direction

### Viewpoint

The report should focus on ports, sailors, dockworkers, coastal commands, and ordinary naval routines disrupted by complete fleets that no government ordered.

The emotional center should be the physical arrival of ships. Harbors are full, mooring plans no longer match reality, crews present records that cannot be verified, and naval authorities must begin handling the force immediately.

### Information visible to the player

The report should establish that:

- the phenomenon is worldwide
- landlocked countries did not receive fleets
- packages differ sharply between countries
- the ships are functional enough to enter service
- no convincing source has been established

The report should avoid listing package formulas, exact world totals, internal eligibility rules, or evolution mechanics.

### Uncertainty

The source remains unresolved. Rumors can include hidden wartime construction, abandoned foreign orders, mass deception, impossible transfers, or fabricated archives. None is confirmed.

The event should not imply one secret answer that later content is required to reveal.

### Tone

Use concrete disbelief and practical urgency. The report can contain restrained absurdity because officials are being asked to accept fleets as an administrative fact. It should not become broad comedy.

### Avoid

- generic statements that the world has changed forever
- map-centered narration
- a staff room studying arrows on a chart
- a report framed as an explicit warning
- unexplained dramatic filler
- technical or development language
- a definitive supernatural, alien, or time-travel explanation

## Personal commissioning report direction

### Viewpoint

The personal report comes from the recipient's naval command and port authorities. It should read as an operational summary prepared after the first inspection.

### Dynamic information

The report should identify:

- recipient country
- package identity
- scale band
- rough combat hull count
- defining ship types
- convoy support
- aircraft support where relevant
- commissioning port or ports
- whether an emergency facility is needed
- whether part of the fleet is unsupported or delayed
- the main fuel, repair, or basing burden

The report should use compact descriptive language. It should not print a long ship inventory.

### Choice direction

The three working choice labels are not final localisation.

#### Full Commissioning

The reaction should sound confident and forceful. It represents a naval command that intends to use the whole gift immediately and accepts the operational burden.

The visible consequence direction should make immediate activation, support delivery, and full fuel or repair pressure clear.

#### Phased Commissioning

The reaction should use cautious logistics language. It represents a command that wants the fleet but refuses to overload its ports and fuel system.

The visible consequence direction should state which ships enter service now, which are delayed, and what condition protects the later tranche.

#### Break Up the Package

The reaction should use practical austerity with restrained irony. It represents a government that values the gift but considers part of it more useful as transport, fuel, repair capacity, and experience.

The visible consequence direction should make the lossy conversion and achievement consequences clear without exposing internal values.

## Repeat report direction

Later global reports can acknowledge that governments recognize the pattern and maintain contingency procedures. The report should still show new surprise because package identities, coastlines, and recipients have changed.

Personal reports should identify the country receipt count in natural language where useful. They should emphasize the new package rather than summarizing every earlier fleet.

## Evolution presentation direction

### Evolution I

The public direction should show harbors receiving fleets far larger or more lopsided than the first known pattern. The concern comes from scale and specialization.

### Evolution II

The public direction should show unfamiliar hulls, equipment, and service procedures entering national fleets. The text should not spoil the lore of the owning experimental systems.

### Evolution III

The public direction should show formations whose combined capabilities and silhouettes no normal procurement program would assemble. The fleet remains physically legible and operational rather than becoming abstract fantasy.

## Event Details direction

Event Details should explain the premise and repeatable behavior in player-facing terms:

- coastal countries can receive different fleet packages
- packages can include ships, convoys, aircraft, fuel, and minimum port support
- later manifestations can reach newly coastal countries
- higher Chaos can widen the package pool

It should not list hull-equivalent budgets, exact random weights, global caps, AI formulas, hidden skip reasons, or achievement predicates.

## Event History direction

The global history entry should show:

- date
- Event 56 identity and type
- no actor flag
- broad number of countries that received packages
- broad fleet scale or package-stage summary
- current evolution stage

A selected human recipient can retain a compact personal summary for its most recent package. This does not become another global history row.

## Evolution history direction

Each evolution row should show Event 56, stage, tier, and date. No actor is needed.

The Event Details evolution catalog remains a preview surface. It should describe what each stage can add without displaying fake history metadata.

## Cluster presentation direction

When Event 56 fires through Sudden Abundance or Military Preparation, the cluster detail should show it as one participating member.

The member result can summarize:

- successful recipient count
- skipped recipient count
- active package stage

It should not list every country's fleet.

## Asset authorization

The accepted visual package contains four progression report images and three achievement icon triplets.

No other visual family is authorized by this specification unless implementation reveals a real missing consumer that cannot reuse these assets.

## Report image family

### Shared format

- asset type: report-event image
- source mode: generated fictional documentary scene
- final reference canvas: 210 by 176 pixels, subject to direct consumer inspection
- treatment: period-authentic black-and-white or restrained sepia photographic report art
- composition: full-canvas scene
- text: none
- time language: 1936 to 1945 technology and port environment

Generated imagery is appropriate because the event depicts a fictional global manifestation that cannot be represented by one truthful archival photograph.

### Image 1: Baseline manifestation

Working asset role: baseline fleet arrival.

Show a crowded period harbor containing a visibly mixed but ordinary fleet. Dockworkers, sailors, cranes, warehouses, and mooring congestion should establish scale. The ships should read as destroyers, cruisers, submarines, and limited heavy units from the period.

The scene should feel photographed from a dock, quay, harbor office, or elevated industrial position. Avoid a clean fleet parade.

### Image 2: Larger and stranger fleets

Working asset role: Evolution I.

Show a harbor or roadstead overwhelmed by an unusually dense, sharply specialized formation. A destroyer mass, convoy armada, submarine concentration, or carrier group can provide the central identity.

The image should communicate excessive scale while keeping individual ship roles readable.

### Image 3: Experimental naval forces

Working asset role: Evolution II.

Show service crews inspecting one or more unfamiliar but mechanically credible ships among ordinary escorts. Unusual silhouettes, protected equipment, strange launch systems, or experimental submarine forms can establish the stage.

Do not show modern electronics, postwar missile cruisers, science-fiction lighting, readable technical labels, or a fantasy vehicle detached from the period setting.

### Image 4: Impossible fleets

Working asset role: Evolution III.

Show a vast harbor or roadstead where carriers, advanced submarines, capital ships, unusual experimental hulls, and dense support groups coexist in one operational formation.

The scene can be surreal in scale and combination. It must retain documentary realism, period crews, period infrastructure, and physically plausible water contact.

### Image consistency

All four images should share:

- the same broad photographic era
- similar contrast and grain treatment
- clear ship silhouettes at final size
- no readable generated text
- no modern port cranes, containers, electronics, or uniforms
- no duplicated or fused ships
- no impossible mast, hull, wake, or water geometry that distracts at final size

## Achievement set

Achievement titles below are working labels. Final localisation should follow the direction and fit existing Chaos Redux achievement tone.

### Achievement 1: `the_navy_from_steppe_to_sea`

#### Working label

From Steppe to Sea

#### Player promise

Begin outside the naval world, gain a real coast later, receive the anomaly's first fleet, and prove that the new navy can fight.

#### Eligible countries

A player country that is directly landlocked when Event 56 first manifests globally.

A country does not qualify merely because a subject has coast. It must later gain direct owned and controlled usable coast.

#### Unlock conditions

- the country was recorded as landlocked during the first global Event 56 firing
- the same playable country later directly owns and controls usable coast
- a later Event 56 firing grants it a package
- at least one defining ship from that granted cohort participates in a meaningful naval victory
- the victory includes a real enemy loss or another nontrivial combat threshold

The final battle threshold should follow the achievement framework and available naval combat evidence. A harmless encounter with no meaningful result should not unlock it.

#### Disqualifiers

- losing stable country identity through an invalid tag replacement
- qualifying only through subject-controlled coast
- receiving no actual package
- using a battle that did not include a surviving or valid granted defining ship

Ordinary ideology and cosmetic changes do not disqualify the run.

#### Difficulty

Very hard. The player depends on at least two Event 56 firings, territorial change, and a meaningful naval result.

#### Visibility

Visible.

#### Tracking notes

Record the first-manifestation landlocked state once. Preserve the proof through save and reload. Link the later package cohort to the battle check without keeping an unlimited battle ledger.

#### Icon direction

A flat achievement composition that transitions from open steppe or an inland horizon into an anchor, ship wake, or naval bow. Do not use a literal country flag or detailed map.

### Achievement 2: `the_navy_three_gifts_one_admiralty`

#### Working label

Three Gifts, One Admiralty

#### Player promise

Absorb three different naval surprises, keep them alive, and turn them into one functioning global navy.

#### Eligible countries

Any player country that can receive Event 56 packages.

#### Unlock conditions

- receive packages from three separate Event 56 firings
- all three packages have distinct primary identities
- choose Full or Phased Commissioning for each package
- retain at least 75 percent of the combined granted hull-equivalent value one year after the third receipt
- win meaningful naval battles in at least two different strategic regions using defining ships from the tracked cohorts

The retention threshold is measured from ships actually delivered, excluding cancelled delayed tranches.

#### Disqualifiers

- use Break Up the Package on any of the three tracked receipts
- lose the proof that a qualifying battle involved a tracked cohort
- fall below the retention threshold at the one-year check

A failed attempt can restart with a later set of three distinct receipts only if bounded achievement tracking can support it safely. Otherwise, the achievement should lock to the first valid three-package sequence and state that rule clearly.

#### Difficulty

Very hard. Event repeat weights decline, identities must differ, the player must preserve the fleet, and combat must occur across separate regions.

#### Visibility

Visible.

#### Tracking notes

Store three package identity slots, receipt dates, delivered cohort value, breakup state, and region-victory proof. Do not store every battle.

#### Icon direction

Three clearly different naval silhouettes arranged under one admiralty star, command pennant, or wreath. The icon must remain readable at 64 by 64.

### Achievement 3: `the_navy_wrong_fleet_right_war`

#### Working label

Wrong Fleet, Right War

#### Player promise

Receive a fleet that conflicts with the country's pre-event naval posture and achieve a real strategic result before the opportunity fades.

#### Eligible countries

Any player country that receives a package marked by an objective mismatch predicate at the moment of receipt.

#### Objective mismatch examples

The mismatch must be determined before the package changes the country's force structure.

Possible predicates include:

- carrier package when the country has no operational carriers, no active carrier-air production, and no established carrier force
- capital package when the country has no operational capital ships and severe fuel or port constraints
- invasion-support package when the country has no marine or amphibious force and no active invasion preparation
- submarine package when the existing navy is overwhelmingly surface-oriented and has no operational submarine arm
- convoy-escort package when the country has almost no overseas naval activity and no active convoy defense pressure

The implementation should use a small registered set of objective predicates. It should not make a subjective judgment from hidden strategy labels alone.

#### Unlock window

The player has 540 days from receipt to complete one qualifying result.

#### Qualifying results

At least one of these must be achieved with direct participation or support from granted defining ships:

- maintain naval supremacy in a contested strategic region for a sustained period
- complete a successful naval invasion whose support force includes the granted cohort
- sink enemy capital-ship value above a meaningful threshold
- defeat a materially stronger enemy task force through a battle where the granted cohort has a central role

The implementation should choose the result set that can be proven reliably by the engine and shared systems.

#### Disqualifiers

- choose Break Up the Package
- fail to commission the defining core
- complete the result without participation by the granted cohort
- exceed the 540-day window

#### Difficulty

Hard. The package is objectively mismatched, the result is time-limited, and the player must use the gift rather than convert it.

#### Visibility

Visible.

#### Tracking notes

Store the mismatch type, receipt date, qualifying cohort, and deadline. Clear the active attempt on success, failure, annexation, or invalid country transition.

#### Icon direction

A mismatched ship silhouette or naval tool turned toward a victory wreath, target marker, or broken enemy line. Avoid a comic visual. The icon should show adaptation rather than ridicule.

## Achievement icon package

Each achievement needs the full Chaos Redux achievement triplet:

- unlocked icon
- grey icon
- not-eligible icon

The filenames must match the final achievement IDs and the repository's root-only achievement asset convention.

The icons should be designed as achievement art from the start. They must not be resized report images or reused decision icons.

## Localisation handoff inventory

Implementation must write final text for:

- global event title and description
- personal commissioning title and description
- three commissioning option families
- package identity labels and short summaries
- package scale labels
- commissioning port and support summary fragments
- invalid or cancelled delayed-delivery report
- repeat-firing report direction
- three evolution names and descriptions
- Event Details premise and evolution previews
- Event History summary
- cluster member result summary
- achievement titles, descriptions, requirements, and failure tooltips
- asset accessibility and hover text where the consumer supports it

Dynamic text should use actual country, port, package, ship-role, count-band, and stage information. It should never expose raw variable names or development notes.
