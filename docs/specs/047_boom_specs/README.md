## Design summary

BOOM selects one eligible state and applies an unexplained regional blast. The camera moves to the first epicenter and a large mushroom-cloud effect appears before the main report. The blast removes real civilian population, damages existing buildings, disrupts forces inside the affected states, and records exact deaths through the shared Deaths system. It never calls the nuclear-strike path and never creates a weapon owner, fallout, condemnation, Air Cleanliness pressure, or nuclear history.

Evolution I widens and strengthens the blast. Evolution II permits two or three distant epicenters during one Event 47 firing. All states, blast rings, and overlap priorities are frozen before damage begins. A state touched by several blast zones receives one population transaction and one damage package at the strongest applicable intensity.

The event remains self-contained. It introduces no player-facing meter, decision category, investigation, persistent crisis, country package, focus tree, scripted GUI, or super-event. Every later firing is a new incident and can revisit an earlier state when that state remains eligible.

## Important reconciliations

The current exported event catalog describes a random province and gives Event 47 no cluster assignment. The accepted design uses states because population, buildings, adjacency, and Deaths accounting are state-owned.

The current cluster export contains an unavailable Various Anomalies row with no stable cluster ID. Event 47 can be planned as a prospective member, but runtime cluster wiring must wait until the cluster receives a stable registry identity.

The submitted catalog entry labels Event 47 as a Low member. This package recommends Severe. A repeatable incident that can kill most of a state's population, destroy regional infrastructure, and strike several continents does not fit the Low severity label. The event type and Chaos level remain unchanged.
