# 113 The Partition: Acceptance matrix

This matrix defines implementation acceptance criteria for the complete specification.
Every gameplay, engine, probability, rendering and live-campaign row is unexecuted in this planning delivery.
The final package check records only the document and source-evidence checks actually performed.

The implementation must record the exact source revision, fixture, actual result, supporting artifact and remaining limitation for every applicable row.
A passed source parse does not establish a passed war outcome, GUI render, probability analysis or campaign test.
A proposed asset row is not complete until the required source, processed output, runtime consumer and review evidence exist.

## Completion contract

The implementation reviewer maintains a route-coverage table against all ten specification parts and the supporting prompts.
Every omitted, renamed, merged, simplified, substituted, blocked or unimplemented row is listed explicitly.
No passing subset is presented as full event completion.

The parent performs the mandatory fresh improvement-loop pass near completion, resolves its addendum or closure, and then runs the completion auditor.
The live in-game campaign scenarios belong to the user's normal gameplay-test workflow.
They are not launched automatically merely because this planning package exists.
