# Canonical subagent usage map

## Delegation contract

Use the current repository canonical agent definitions through [chaos-redux-subagents](../../../../.agents/skills/chaos-redux-subagents/SKILL.md). The supplied definitions are historical evidence. Spawn each bounded task with `collaboration.spawn_agent` and `fork_turns="none"`. The parent passes the event ID and slug, accepted spec paths, current source revision, exact question, permitted input files, exact output ownership, forbidden areas, dependencies, required evidence, and known blockers. Do not rely on inherited conversation history or replace a canonical role with an invented general-purpose agent.

Model and reasoning settings follow the current canonical definition in the implementation environment. The parent reviews every returned file and claim before integration. An agent's status label is not proof of scope acceptance, engine validation, or user approval.

The table below maps every supplied role to a concrete use or an explicit conditional use. Asset production and runtime roles are future implementation work. The completion report separately records which agents actually ran in this planning pass.

## Dependencies and integration order

The parent reads named files directly. Use the repository explorer only for an unclear file location, pattern, caller or dependency question. Use the architect for actual reusable logic and transaction work. The parent owns shared selection, global history, terminal-state, world-threat, population, and cross-event integration unless exact bounded changes are delegated. The country, focus, decision, and AI roles work from the same accepted state and role contract.

Portrait research is separate from generated fictional event art. The portrait creator owns Lenin's actual likeness and grounded workflow. The generated-art owner may compose a fictional scene using the approved identity inputs, but cannot replace the portrait source with an invented face. The icon artist receives the final function of each asset before production. The model pipeline receives accepted family and scale briefs before spending provider attempts.

Super-event text and audio research can run in parallel after their narrow briefs and the current music catalog are supplied. Both produce reviewable choices before final wiring. The parent resolves source, rights, role fit, and namespace collisions. File existence alone does not make a cue approved or a quote safe to use.

After substantial new implementation, run one bounded improvement review when it answers a concrete depth question, resolve its recommendations, then complete relevant auditors. Reuse the imported completed planning closure rather than rerunning it solely because the package was imported. Recheck only the affected surfaces after repairs. The final parent report states what was actually inspected, what was implemented, what remains blocked, and how each accepted route is covered.

## Forbidden shortcuts

No agent may silently alter the proportional rule, erase 001 history, force Trotsky into absorption, remove an army family, replace a real portrait, reuse unrelated music, skip a required visual consumer, or introduce a large management window to avoid native work. No agent may rename an unknown engine behavior as an implemented helper and call it verified.

If a specialist cannot produce a required output because a consumer or production provider is unsupported, it returns that missing output and indispensable capability. If an optional review tool is unavailable, it performs permitted source/local review and records the observation limit under AGENTS.md. The parent can complete independent planning or implementation around that boundary, but does not mark the missing surface complete.
