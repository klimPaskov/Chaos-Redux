# Acceptance scenarios and evidence plan

## Evidence status

This document specifies validation for the eventual implementation. The planning pass has performed source coverage verification, targeted repository inspection, historical and rights research, design review, and package consistency checks. It has not run HOI4, native MCP inspection, asset production, audio audition, installed tag scans, or multiplayer tests.

This is an active future scenario plan. Historical audit and package receipts remain unchanged. Apply the [README verification policy](../README.md#verification-and-remaining-implementation-work) to its evidence column: unavailable optional MCP/render/live observations limit claims and do not require user testing as a delivery gate. Missing implementation, known defects and indispensable unresolved capabilities remain open.

Each future result must identify the exact source revision, installed game and DLC context, relevant scenario state, tool or runtime surface, expected outcome, actual outcome, and retained evidence. A screenshot of one successful path does not validate every route. A focused helper trace does not prove the full event lifecycle.

## Performance and robustness

Test a modded map larger than the native loop limit. The opening may use a single global snapshot, but its batches must preserve every unvisited state and country with a continuation record. There is no permanent whole-world daily, weekly, or monthly 091 scan. Later updates use registered actors, changed states, and bounded active operations.

Temporary helper outputs are initialized before every call boundary. Inputs that must survive nested helpers are frozen. Persistent country references use the approved pointer contract. Timers use the documented encoded-date helper. Repeated receipts, stale generations, country deletion, controller changes, expired missions, and partial native mutations each have a defined no-op, recovery, or failure result.

Stop broadening validation once a concrete risk is resolved and the required gate is satisfied. Additional tests must address a real remaining uncertainty. The completion report distinguishes static proof, native tool proof, actual runtime evidence, and any blocked surface.
