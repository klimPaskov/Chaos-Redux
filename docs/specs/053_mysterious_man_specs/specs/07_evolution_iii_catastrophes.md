# 7. Evolution III Catastrophes

## Evolution III activation

Evolution III becomes eligible at `1000+` Chaos.

The milestone uses the same target-local activation and logging rules as earlier evolutions. It gives zero Chaos by itself.

If Event 53 first fires at World Collapse and Evolution III is enabled, the first appearance can use the full demand and consequence behavior immediately.

Evolution III continues to ask for one main sacrifice per visit. Refusal adds catastrophe-class packages to the equal pool.

## Catastrophe registry additions

### `mm_iii01_nationwide_nuclear_annihilation`

**Owner:** an Event 53 catastrophe adapter that calls the real nuclear destruction, population, Deaths, fallout, and Air Cleanliness primitives without creating an attacker.

Every unique valid state owned or controlled by the selected country is struck with nuclear-scale destruction. A state present in both sets is processed once. Already invalid, empty, or terminal wasteland states are skipped with receipts.

The package must create:

- an immediate population-death spike scaled through the exact civilian population-loss pipeline
- severe building and infrastructure destruction
- heavy damage to national industrial and logistical capacity
- severe local fallout or contamination through the real atmospheric system
- military damage where the verified nuclear package supports it
- nationwide economic and command collapse consistent with the physical destruction

The effect is not attributed to any attacker country. It must not create nuclear Condemnation for an innocent actor, fabricate a war, assign a hidden launch owner, or use a dummy country as blame carrier.

The selected country is the victim. Event 53 is the origin of the consequence transaction.

The package does not directly set `world_end`. It can create enough real fallout and Air Cleanliness pressure for the atmosphere system to submit a valid Fallout request later. That downstream result comes from ordinary contamination thresholds, not from firing another event's terminal route automatically.

The adapter must process large countries in bounded batches when engine safety requires it. Batching cannot reduce coverage. Every valid owned or controlled state must receive one final processed or skipped receipt.

The package is invalid if the implementation cannot apply nuclear-scale state destruction without false attacker attribution.

### `mm_iii02_total_national_fracture`

**Owner:** Independence Wave and any required country-package providers.

A large number of valid independence movements become independent in one frozen national-fracture transaction. Every viable movement begins armed and enters war with the former host unless a specific release package proves another immediate relation is required.

The target can be left controlling a small remnant around its capital. The owner should preserve at least one viable government state when possible, but the package can leave the government in a desperate position.

Requirements:

- enough valid movements to create a mosaic beyond an ordinary release wave
- complete state reservation before release
- no duplicate ownership grants
- viable capitals and territorial packages
- real force, equipment, manpower, leader, flag, focus, claim, and AI packages
- conflict setup that does not merge all breakaways into one accidental faction
- Event 53 marker retained on the original government unless a later legal-successor adapter proves transfer

This package does not count as Event 006 firing and does not progress an Independence Wave terminal route.

### `mm_iii03_maximum_civil_fracture`

**Owner:** a multi-government civil-fracture system.

The country splits into several rival governments or regional commands that each claim national authority. This package differs from total national fracture because the rivals are competing governments of the same collapsing state, not a collection of distinct independence movements.

The owner should create three or more viable rival actors when geography and package availability allow it. The transaction divides states, units, equipment, leaders, industrial capacity, supply, claims, and diplomatic status.

The original Event 53 target remains attached to the legally continuing government identified before the split. The package cannot duplicate the target marker across rivals.

### `mm_iii04_multiple_epidemics`

**Owner:** the disease system.

Several severe outbreaks begin in distant parts of the selected country. The owner can use several agents when compatible, or separated outbreaks of one severe agent when distinct agents would conflict.

Requirements:

- several valid and separated seed regions
- no duplicate state seed transactions
- real spread, mortality, containment, treatment, and cleanup
- exact Deaths integration
- Air Cleanliness integration where the agents contribute
- compatibility with active outbreaks and immunity states

The package does not automatically activate a disease source event's evolution, super-event, special country, or world-end route.

### `mm_iii05_state_collapse_sequence`

**Owners:** civil fracture, Intel Leaked, and Great Embargo.

A major civil fracture begins. Classified material then spreads abroad while a severe international embargo isolates the surviving legal government.

Execution order:

1. reserve the civil-fracture transaction
2. reserve valid intelligence recipients and embargo participants against the projected post-split state
3. create the civil fracture
4. identify the continuing Event 53 target government
5. apply severe intelligence exposure
6. commit the embargo coalition
7. aggregate receipts and cleanup ownership

The package is invalid unless every component can use the same projected government scope safely.

### `mm_iii06_pestilence_hunger_and_flight`

**Owners:** disease, famine, and migration.

Multiple severe outbreaks create a broad food-security and displacement collapse. Disease, famine, and migration keep separate primary ledgers while exchanging versioned proof through their approved adapters.

Execution order:

1. reserve separated outbreak regions
2. reserve famine states and migration origin or reception paths
3. prove that population transactions will not overlap
4. seed the outbreaks
5. register high food-security pressure
6. submit proven survivor movement or trapped-population requests
7. aggregate receipts

Every removed person is recorded once. Migration transfers survivors and route deaths through its own exact transaction. Famine and disease own their own mortality.

### `mm_iii07_war_on_every_front`

**Owners:** military fracture, external-war crisis, and Event 53 stockpile destruction.

A mass military mutiny tears through the armed forces, several valid foreign actors attack, and a large strategic reserve disappears.

Execution order:

1. reserve mutiny commands and post-mutiny force state
2. reserve several valid foreign actors and reachable fronts
3. lock one strategic reserve type and amount
4. apply the mutiny
5. reconcile the selected target and military state
6. start the external wars
7. debit the locked reserve once
8. aggregate receipts

This package is invalid when the resulting conflict cannot remain playable or structurally valid.

## Nationwide annihilation state processing

The nuclear catastrophe requires special care because one target can own or control many states.

### Unique state ledger

Build a unique state ledger from:

- every owned state
- every controlled state not already present

Each state receives one sequence ID and one final status:

- processed
- skipped because already terminal wasteland
- skipped because no valid population or buildings remain
- rejected before transaction due invalid scope

A state cannot be struck twice because it is both owned and controlled.

### Damage profile

The damage profile should recognize state role without reducing the nationwide promise:

- capitals and major population centers receive the strongest direct destruction
- industrial centers receive severe factory and infrastructure loss
- ports, rail hubs, airbases, and supply centers receive severe logistics damage
- rural states receive lower absolute deaths but still suffer nuclear-scale population and building loss
- already devastated states receive only the remaining valid damage and fallout

Protection systems can reduce harm only where the real nuclear, shelter, disaster, or population systems already support them. No Event 53-specific defense is added.

### Deaths integration

Every civilian population loss uses the exact population transaction and enters the Deaths system once under an Event 53 nuclear-annihilation reason or a shared unknown-origin nuclear reason approved by the Deaths owner.

The transaction must not leave recruitable-manpower credit behind after reducing state population.

Military casualties use the established military casualty path when available. They cannot be estimated twice from both unit damage and a separate Event 53 addition.

### Air Cleanliness and Fallout

Every struck state contributes through the real fallout-intensity and Air Cleanliness system. The catastrophe does not apply one arbitrary global contamination number in place of state fallout.

If the accumulated atmosphere reaches the irreversible threshold, the Air Cleanliness owner can submit its normal Fallout request when that route is enabled and valid. Event 53 does not force the request, bypass its toggles, or count the Fallout source event as fired.

### Diplomatic attribution

No attacking country exists. Condemnation cannot be assigned to:

- the selected target
- a random rival
- the current faction enemy
- the country with the most nuclear weapons
- a dummy Chaos actor
- the last country to use a nuclear weapon

Diplomatic reactions can express fear, relief efforts, border closures, opportunism, or uncertainty without assigning false responsibility.

## Catastrophe presentation

Evolution III consequences can produce their own owner-system reports when needed. Event 53 should avoid opening a duplicate super-event or a second full report that repeats the same destruction.

The visible sequence should preserve the cause link. The player refused, the man disappeared, and the catastrophe followed. The text does not explain how he caused it.

## Equal-weight rule at World Collapse

Catastrophe packages remain equal to every other valid package in the pool. They do not receive bonus weight merely because Evolution III is active.

Their aggregate chance comes from the number of valid catastrophe entries compared with the complete valid pool. This is intentional and must be measured through the probability audit.

If all seven catastrophe packages and forty earlier packages are valid, each of the forty-seven packages has `1 / 47` probability. The catastrophe family has `7 / 47` aggregate probability only because it contains seven substantively distinct valid outcomes.

## Evolution III severity changes to earlier packages

Earlier packages can use their maximum nonterminal safe severity when Evolution III behavior is active. They remain meaningful even when a catastrophe package is not selected.

Examples:

- a baseline stability collapse can reduce the government to a prolonged legitimacy crisis
- an ordinary external war can involve a much stronger attacker
- stockpile catastrophe can remove most of one reserve
- factory or infrastructure destruction can affect the national network
- a baseline disaster can use the owner's maximum single-disaster profile
- occupation revolt can spread across most qualifying territory

Earlier packages still receive one ballot each.
