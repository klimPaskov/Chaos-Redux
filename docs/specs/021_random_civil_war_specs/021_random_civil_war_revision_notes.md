# Event 021 Revision Notes

## Purpose

A previous Event 021 planning package dated July 25, 2026 was reviewed before this package was written. The earlier package already established many strong foundations, including the Event 006 reuse contract, multi-front wars, Regional Contagion, Global Fracture, a manual scenario, role-specific AI, achievements, and a full implementation handoff.

This package retains those foundations where they remain compatible with the current project skills and the user's latest design.

## Retained design

The following parts remain central:

- Event 021 is a Minor Repeatable event available from Calm World
- it belongs to Cluster 1, Wars, with Medium severity
- ordinary claimants preserve the parent country's national content
- complete human Event 006 packages can appear through Event 021
- Event 021 origin never consumes Event 006 event state
- Evolution I creates viable multi-front wars and allows majors at reduced weight
- Evolution II creates regional exposure, neighboring actions, foreign support, and rare strange incidents
- Evolution III creates a nonterminal global fracture system
- human Event 006 countries remain vulnerable
- actual nonhuman countries are the universal immunity class
- one-state countries use a same-tag contest when a second country cannot be made safely
- the triggerable scenario has Political Fracture, Independence Cascade, Command Collapse, and Universal Fragmentation types
- decisions use equipment, manpower, factories, experience, supply, diplomacy, state control, and time
- the event requires settlement, successor memory, recurrence logic, cleanup, AI, event logs, cluster handling, probability review, and performance review

## Main revisions

### One visible value

The previous design exposed Fracture Pressure as a public mechanic.

The revised design keeps Fracture Pressure as hidden selection and severity logic. The affected country's one visible value is State Authority.

Reason:

- the player acts on authority during a crisis
- the hidden score can remain detailed without exposing a long component ledger
- the category can show one stage, one meter or compact value, and the next important threshold
- the decision skill limits player-facing cognitive load and favors one primary value

### Standard decision category

The previous design proposed an attached selected-front surface and an animated fracture seal.

The revised design uses a standard decision category with:

- one static category picture
- concise dynamic category text
- phase-based decisions
- one to three active missions
- targeted dynamic localisation for the current front

Reason:

- normal decisions already carry the gameplay
- a custom interface would add layout, click-region, animation, and resolution risk
- a static picture gives the category identity without painting fake controls
- the framework remains reusable across many countries and multiplayer contexts

### Static presentation

The animated seal is removed from the accepted asset inventory.

Reason:

- no living visual state requires frame-by-frame communication
- State Authority can use normal text, icon, mission, and threshold presentation
- the project animation skill forbids transform-only motion and requires real per-frame art
- the cost of a real animation package is not justified for this surface

### No default super-event

The previous package also omitted a super-event. This decision remains.

Reason:

- Event 021 is repeatable
- Evolution III is a persistent system, not one unique terminal moment
- a global news event can explain the activation
- a future separately accepted milestone may justify a super-event, but it is outside this package

### Bounded global scheduling

The revised Evolution III strengthens the scheduler contract.

It requires:

- event-driven eligibility updates
- staggered review dates
- a Critical queue
- a tested global theater cap
- a descendant generation cap
- no unrestricted default daily, weekly, or monthly country iteration without explicit user approval

### Reduced achievement count

The previous package planned ten achievements. The revised package uses six.

Reason:

- each achievement now tests a distinct part of the event
- overlapping or easy achievements were removed
- the asset burden is lower
- tracking remains meaningful and reviewable

## Superseded elements

The following earlier elements are not part of the accepted design unless a later addendum restores them:

- public Fracture Pressure as the main visible value
- dedicated selected-front scripted GUI
- animated fracture seal
- static lower-state and animated critical-state seal family
- ten-achievement inventory
- GUI-specific subagent work
- GUI MCP work for a new event-owned window

## Compatibility rule

When the earlier package and this package differ, this package controls.

The earlier compiled master remains useful background for ideas that were retained, but it is not an implementation source after this package is installed under `docs/specs/021_random_civil_war_specs/`.
