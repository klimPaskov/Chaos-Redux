## Host playbook acceptance

The host overlay is not a cosmetic bonus bundle. For every eligible start used in testing or release:

- preserve the original host identity after later tag changes
- assign the correct regional council and host depth
- apply the mapped starting weakness
- expose a first proof mission that requires action
- connect the host’s economic leverage to the common development system
- connect the host’s regional risk to membership and rival behavior
- mutate relevant focus and decision families without duplicating the full tree
- give AI an equivalent proof and route plan
- remove or transform host-only opening content after settlement

A compact signature is acceptable only when it remains recognisable in play. A full playbook is incomplete if it amounts to a stronger national spirit and a few renamed focuses.

## Constitutional route acceptance

Each route must implement the governing questions mapped in part 8 and the 78-row payoff matrix:

- who is represented
- how the executive is selected, limited, and removed
- how resources and revenue are shared
- how military command works
- whether and how members can withdraw
- what causes constitutional crisis
- how failure changes the route
- what government remains after Africa is one

The common economic, military, diplomatic, diaspora, restoration, integration, and expansion lanes must react to the constitution. A route does not count as distinct when only names, flags, or modifiers change.

## Priority member package acceptance

For each selected one of the 16 priority packages:

- use a safe and reviewable territorial scope
- define valid formation or release origin
- provide politics, one adult male ruler, parties, flags, and localisation
- implement the distinct mechanic or decision family
- provide starting forces and reinforcement paths if expected to fight
- implement League accession, bargaining, refusal, withdrawal, and rivalry
- provide focus or overlay content with a real payoff
- preserve post-settlement play instead of instant absorption
- add route-aware AI
- dispose every required asset

All 16 priority package rows have installed package records on approved existing carriers. Final positive and negative scenarios, localisation, AI, and completion audits remain required, and controlled-pool rows retain their explicit dispositions.

## Evolution acceptance

Event 12 starts at Chaos tier 4. The accepted interpretation is:

- Baseline at the event opening
- Evolution I for continental consolidation
- Evolution II for stronger integration and strange formations
- Evolution III for high-chaos actors and world-order access
- requested Evolution IV content preserved as post-unification escalation

This preserves the requested content while respecting the current evolution-tier framework. If implementation expands the shared framework, it may promote the post-unification layer to a formal logged evolution, but the event log, skills, docs, and catalog must change in the same implementation tranche.

## Polity catalog acceptance

The 215-row catalog is a candidate pool, not an instruction to create 215 full tags at once.

- Tier A rows require full package treatment when selected.
- Tier B rows require a strong subject, regional actor, or focused restoration package when selected.
- Tier C rows are rare, local, city-state, court, cultural-centre, or hidden restoration candidates.
- Every selected row receives a disposition.
- No package may be an empty tag expected to fight.
- Overlap groups must prevent contradictory simultaneous full claims.
- Promotion must create continuing play rather than a ceremonial name and flag.

## Anti-bloat acceptance

Implementation must preserve the bounded structure of the source design:

- one shared Charter League and integration system
- one common continental tree with host and constitutional overlays
- parameterised decision families instead of country duplicates
- selected full country packages instead of universal tag promotion
- four super-event roles with limited justified variants
- asset families that communicate mechanic states rather than one complete set per host

A simplification that removes distinct play is not anti-bloat. A merge is acceptable only when it preserves the mapped choice, risk, AI behaviour, and payoff.

## Player-facing text acceptance

- final localisation is reviewed against the installed implementation during the release-candidate audit
- planning labels are not pasteable copy
- Event Details describes the situation rather than effects
- options, focuses, decisions, and tooltips explain visible choices and requirements
- no final super-event quote, remark, title, or audio appears without research
- no em dash, semicolon sentence, staged contrast formula, dialectical hedge, or staccato filler
- hidden routes and implementation history remain hidden
- host and route text should use dynamic actor and institution names where useful

## Language and naming acceptance

The two required Afaan Oromoo strings can appear only as untranslated fictional ruler, court, regnal, council, or title flavour. They never appear in technical identifiers, filenames, tags, sprite names, or asset names.

No additional obscene source-language string should be added without full-string verification and native-speaker review.

Public country names remain direct. Administrative institutions can name mechanics and internal bodies, not map countries.

## Required audits before completion

- focus tree audit
- decision and mission audit
- country package audit
- localisation audit
- documentation curation
- improvement-loop pass with every accepted addendum resolved
- event completion audit
- spreadsheet update from final in-game text

The final parent report must include every missing, merged, queued, rejected, or simplified item. A loading game, working entry event, complete-looking tree, or large asset folder does not prove package completion.
