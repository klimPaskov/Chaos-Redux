## Public API direction

The owner should provide read-only triggers and bounded request effects for cross-event use.

Suggested read-only capabilities:

- target has active Event 52 incident
- target's qualitative Exposure stage
- archive domain class is active
- foreign country is named exploiter against target
- deception is active for pair
- sequence has consumed named external adapter

Suggested request capabilities:

- bounded Exposure adjustment with reason and target proof
- bounded Reliance adjustment with target-recipient proof
- cooperative copy registration
- named-exploiter candidate registration under cap
- contradiction registration for one domain

Every public request should fail closed, return a result, clear one-shot inputs, and leave private ledgers owner-controlled.

## Intelligence effect ownership

The legacy permanent `add_intel` block must be removed.

The replacement must prove:

- temporary broad foreign intelligence exists while Exposure is above zero
- effect strength follows Exposure and domains
- every applied amount or modifier has a matching removal path
- new recipients added during an incident receive only the current stage
- invalid recipients are removed
- cleanup reaches zero without underflow or permanent residue

The exact engine approach must follow installed documentation and a vanilla or current Chaos Redux precedent.
