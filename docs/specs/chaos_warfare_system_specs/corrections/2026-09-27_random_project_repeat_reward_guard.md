# Random CBRN project repeat-reward guard

**Disposition: implemented in source; native project outcome and probability comparison remain unverified.** The user's accepted overhaul requires event and research discovery routes to grant the same capabilities without duplicate rewards. This correction applies that requirement to the existing nine-entry random CBRN special-project reward without changing its pool weights, eligibility, or any facility selection.

`common/scripted_effects/cbrn_project_effects.txt` now tests completion immediately before each ordinary biological or Sarin/Soman `complete_special_project` call. A selected candidate still grants an absent delivery technology, so a completed project with missing technology remains a useful reward without repeating completion outputs. The selected weaponized-zombie branch skips its profile rerandomization when `sp:weaponize_the_zombies` was already completed, while still restoring the missing delivery technology. Black Plague and D'Rhondan already exclude completed projects in their availability logic and are unchanged. The helper's scope, inputs, outputs, and exact-state limitation are documented in `common/scripted_effects/cbrn_project_effects.md`.

This does not fabricate an arsenal for a scripted biological completion. The [facility-provenance audit](../../../plans/chaos_warfare_system_plans/2026-09-27_random_biological_grant_facility_scope.md) remains blocked until a caller provides an exact valid facility state. No project, technology, AI candidate, stock, policy, CXT grant, icon, or localised reward promise is added.

Source cases distinguish incomplete project/absent technology, completed project/absent technology, completed project/present technology, already completed zombie profile, and independent Sarin/Soman completion. The weighted pool's nine candidate blocks, numerical weights, and `modifier` gates are unchanged; the pre/post probability route must report its actual analysis coverage rather than infer engine selection from source alone. Native project-reward repetition, technology restoration, and saved-state persistence remain unverified.
