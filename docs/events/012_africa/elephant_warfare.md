# Event 012 armoured elephant warfare

Event 012 opens the armoured elephant capability as a visible force consequence of the preserved host's protection-first charter. The host receives the custom `chaosx_elephant` technology bridge and a named Africa Charter Elephant Guard on owned, controlled territory. The bridge also grants vanilla `elephantry` for compatibility with the installed vanilla roster, but the Event 012 formations use the custom subunit and its custom equipment line.

The custom equipment archetype is `chaosx_elephant_equipment` with buildable variant `chaosx_elephant_equipment_1`. It is gated by `africa_elephant_warfare_unlocked`, consumes steel, chromium, rubber, and fuel, and provides the armour, hardness, piercing, breakthrough, defence, and attack values used by the subunit. The equipment icon is the approved 131x52 DDS at `gfx/interface/technologies/012_africa/chaosx_elephant_equipment.dds`; `interface/012_africa_elephant.gfx` registers the equipment and technology tokens.

The `chaosx_elephant` subunit is active only through `chaosx_africa_elephant_warfare_tech`. It is a mobile front-line armoured formation with a combat width of four, a real `armor_value`, and a need for `chaosx_elephant_equipment_1`. Every host and member division template explicitly overrides its entity to `chaosx_elephant_shared_base_entity`, so each spawned consumer uses the same oversized elephant with rider, six skeletal actions, licensed source audio, and bespoke two-frame counter package.

Action 102 member registration calls `africa_elephant_prepare_member_guard` before the existing package force initializer. The five structural templates—royal guard, river guard, mobile guard, highland guard, and coastal guard—each add one `chaosx_elephant` regiment while preserving their package-specific infantry, cavalry, support, names, readiness, and reserve logic. The helper is idempotent and gives each package one seed equipment stockpile; later reinforcement remains governed by the existing package force actions.

No recurring world scan was added. The host and member helpers only execute from the Event 012 opening and Action 102 package activation surfaces, respectively. The shared entity, sound, animation, counter, equipment, unit, technology, and localisation identifiers are all parent-wired in the same tranche.

## Authored achievement operations

The row-36 proof is owned by three ordinary decisions in `africa_elephant_operations_category`: `africa_elephant_register_terrain_band`, `africa_elephant_open_logistics_contract`, and `africa_elephant_open_protection_expedition`. The first is a state-targeted, command-power-paid registration that requires an elephant battalion in the selected controlled African state and records one unrecorded map terrain band. Desert, savanna, forest, highland, marsh, and coastal bands use the explicit Event 012 state registry in `common/scripted_triggers/012_africa_elephant_operation_triggers.txt`; no country-level terrain proxy is used.

The logistics decision removes the committed `chaosx_elephant_equipment_1`, motorized, train, and fuel reserve, then activates `africa_elephant_logistics_mission` for the 180-day contract window. The selected state must contain an actual supply node and the marked roster, and remains a live event-target together with the host generation, locked operation roster, and sealed reserve ledger. The first terrain registration saves the exact division scope and stamps it with `africa_elephant_operation_roster_marker`; later state checks require that division-scoped marker in the selected state, so another surviving elephant cannot substitute. If the saved division scope disappears during the active operation, the operation writes the matrix's `africa_achievement_elephant_formation_destroyed` DQ; movement leaves the scope alive but breaks the selected-state contract and cannot earn supply proof. If the selected depot loses its supply node or ownership/control, the marked roster leaves the state, or the sealed commitment variables are mutated, the operation writes `africa_achievement_elephant_supply_failed`; an authored timeout also resolves as supply failure. No national stockpile or fuel value is read as proof of live division supply. Only a settled mission calls `africa_achievement_record_elephant_supply_proof`.

The protection decision targets only an existing protected African partner in a current-generation defensive war whose controlled African capital already contains the marked roster. Dispatch saves the partner and its capital state as operation targets, writes a participation witness only after the exact state check, and activates `africa_elephant_protection_mission`. Its settlement witness is that same partner remains protected, not capitulated, has the authoritative protection-war-settled receipt, and no longer has a war while the marked roster remains in the bound capital state. This authored dispatch contract is the authoritative elephant-participation witness available in current scopes; the engine exposes no generic combat-participation callback. If the saved roster division disappears during the protection mission, the operation writes the same formation-destruction DQ. Partner peace is a success path only through the settled receipt; capitulation, relationship loss, or loss of the bound capital-state deployment cancels without writing an unlisted protection-failure achievement flag. The operation does not create a writer for `africa_achievement_elephant_used_against_unthreatened_african`, because its defensive-war target gate makes that route structurally unavailable.

These operations use no daily, weekly, or monthly world iteration. Their player-visible decisions and timed missions are the only owners of the formation, terrain, logistics, protection, success, failure, and cleanup writes. Vanilla exposes no documented `is_same_value` division-identity comparison, so the implementation uses the supported pattern of an exact saved division target plus a division-scoped generation marker, matching the installed Event 019 achievement and Independence Wave package precedents. It also exposes no generic division movement, combat-participation, supply-state, or destruction callback; the saved-target disappearance check and authored contract settlement are therefore the narrow engine witnesses used here.

## Future extensions

Additional elephant loadouts can reuse the body and counter bytes while changing only equipment variants or package-owned formation roles. Any such extension must retain the protection-first consent gates, avoid new country tags, and add its own documented runtime consumer before its ledger row is promoted.
