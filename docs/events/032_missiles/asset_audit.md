# Event 32 — Missiles visual asset audit

This is the implementation-level visual audit for every Event 32 runtime DDS consumer. It supersedes the parent-owned portions of the earlier asset handoffs, which were written before runtime installation and registration.

## Audit scope and method

The audit covered all 82 Event 32 runtime DDS files: 58 non-achievement assets and 24 achievement-state assets. Each file was decoded with Pillow from the final DDS, checked for declared dimensions and pixel format, opened individually at the decoded resolution, and included in a labelled family contact sheet. The final images were reviewed for subject coverage, crop/overflow, transparent-edge bleed, alpha treatment, aspect-ratio fit, native-size readability, family consistency, and sprite-path wiring.

Three full-canvas surfaces, one decision category picture, one category button, 27 ordinary decision icons, seven mission icons, five guidance icons, four retaliation-posture icons, three program-idea icons, five launch-site state-modifier icons, three status texticons, and eight achievement triplets are present. All 82 decoded successfully; no image had a blocking visual defect.

The original global-news image was rejected during review because it showed only one launch column. It was replaced by the current generated scene with multiple contained launch/smoke columns and a separate transporter, then reprocessed, promoted to runtime, decoded, and reopened.

## Runtime registration and consumer audit

The runtime registry is [interface/032_missiles.gfx](../../../interface/032_missiles.gfx). The three full-canvas aliases are registered in the existing shared picture registries, and the category picture is registered separately from the category button. Source references resolve to runtime paths; no runtime consumer points into docs/assets. Event32 decision and mission files contain no generic Brilliant Scientist icon references.

The category is one ordinary decision category with a static picture. No dedicated scripted GUI, portrait, flag, focus art, super-event art, scenario-specific picture, 3D model, skeletal animation, or frame-animation family was introduced because those consumers are excluded by the accepted Event32 asset contract.

## Reused, omitted, and blocked surfaces

The native missile-delivery operation uses the existing raid operation framework where the installed native raid namespace supplies the needed behavior. The repository has no exact Event32 missile-delivery raid icon consumer in that namespace, so no unrelated CBRN/nuclear icon was substituted; this is an explicit asset-scope blocker, not an untracked orphan.

The three generated full-canvas assets use the official built-in ImageGen workflow and preserve their canonical consumer treatments. The icon families were authored as transparent where the inspected consumer has unused canvas. No background-removal fallback was used. The achievement icons are complete completed/grey/not-eligible triplets for all eight achievements.
